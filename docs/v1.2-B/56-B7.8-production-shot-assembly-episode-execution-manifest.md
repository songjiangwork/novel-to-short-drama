# B7.8 — ProductionShot Assembly + Episode Execution Manifest

状态：**FROZEN**

## 1. 职责

B7.8 是 B7 最后的 deterministic materialization / assembly stage。

它只从 exact B7.7 validated bundle 物化：

```text
existing v1.1 ProductionShot × N
+
EpisodeExecutionManifest
```

核心原则：

```text
B7.8 assembles validated decisions.
B7.8 does not compile them again.
```

## 2. 正式输入

B7.8 只能消费：

```text
ExecutionCompilationValidationReport
result = PASS or PASS_WITH_DIAGNOSTICS
+
validated_execution_compilation_bundle_hash
```

并从 validated bundle解析 exact：

```text
ExecutionCompilationContext
EpisodeProductionShotSegmentationPlan
EpisodeProductionShotTimingProjectionPlan
EpisodeProductionShotAssetProjectionPlan
EpisodeBackendReferenceLayoutPlan
EpisodeBackendExecutionSpecificationPlan
```

不得从 loose/unvalidated IR assembly。

## 3. No recompilation firewall

B7.8 不得：

```text
rerun segmentation
move seam
recompute timing projection
reselect/drop assets
reorder refs
renumber Picture N
rerender prompt
change workflow parameters
resolve semantic ambiguity
```

如果这些需要改变：回 owning B7/upstream stage → B7.7 revalidate → B7.8 again。

## 4. 两个正式输出

B7.8 输出：

```text
1. ProductionShot × N
2. EpisodeExecutionManifest
```

`ProductionShot` 就是现有 v1.1 execution object。

禁止再创建平行 hierarchy：

```text
ExecutionShot
CompiledShot
H3ProductionShot
ProductionShotV2
```

## 5. Object chain closure

最终正式对象仍严格分离：

```text
AdaptedStoryBeat
≠ ScreenplayScene
≠ ProductionUnit
≠ PlannedShot
≠ ProductionShot
```

其中：

```text
PlannedShot
= backend-agnostic editorial-camera semantic unit

ProductionShot
= exact release-specific + asset-resolved + backend-profile-compiled
  execution-ready generation unit
```

## 6. ProductionShot 是 final execution payload，不是 IR dump

B7.2–B7.6属于 compiler IR。

ProductionShot应：

```text
materialize what execution requires
reference what audit/reconstruction requires
```

不应把每个 IR全文复制进 final object，避免 duplicated source-of-truth。

## 7. Required provenance pins

每个 ProductionShot 至少必须 pin：

```text
EpisodeShotPlan
  id / revision / content_hash / approval_record_id
planned_shot_id

EpisodeReleaseVariant
  id / revision / content_hash / approval_record_id
  ReleaseVariantIdentity

EpisodeResolvedAssetPlan
  id / revision / content_hash
  asset_resolution_approval_record_id

ExecutionProfile
  id / revision / content_hash
```

以及 B7 provenance：

```text
ExecutionCompilationContext hash
B7.2 segmentation ref/hash
B7.3 timing projection ref/hash
B7.4 asset projection ref/hash
B7.5 reference layout ref/hash
B7.6 execution specification ref/hash
ExecutionCompilationValidationReport ref/hash
validated_execution_compilation_bundle_hash
```

由任何 ProductionShot都可以完整追溯 canonical Shot → release → asset authority → backend compilation → validation。

## 8. ProductionShot execution-critical payload

概念上 final object materialize：

```text
identity / revision / content_hash
provenance
segment spec / semantic window
timing execution spec
projected approved source assets
execution asset roles
backend reference layout
rendered backend prompt
render/context envelopes
runtime-derived input requirements
workflow binding spec
backend request spec
attempt variable contract
```

具体 Python schema留 implementation 阶段。

## 9. Attempt-specific values不得固化

ProductionShot不得固定：

```text
actual seed
actual ComfyUI endpoint
queue id
temporary staged path
output mp4 path
actual predecessor derived frame hash
GPU / worker / PID
```

这些属于 `GenerationAttempt`。

ProductionShot只保存 symbolic dependency policy与 `AttemptVariableContract`。

## 10. ProductionShotIdentity

B7.8直接复用 B7.2 frozen identity：

```text
ProductionShotIdentity
=
episode
+
ReleaseVariantIdentity
+
planned_shot
+
segment identity
+
ExecutionProfile ID
```

B7.8不得因 prompt/assets/workflow/profile revision变化重新定义 logical identity；这些通常产生同 identity的新 compiled revision。

## 11. ProductionShot revision

正式定义：

```text
ProductionShot revision
= revision of the exact immutable compiled execution specification
  for one ProductionShotIdentity
```

典型 revision-changing内容：

```text
projected source asset subset
reference ordering / Picture mapping
rendered prompt
render envelope
runtime dependency policy
workflow binding
execution-affecting profile revision
upstream changes that alter effective compiled payload
```

GenerationAttempt变化不产生 ProductionShot revision。

## 12. Atomic revision allocation

同一个 ProductionShotIdentity的 revision allocation必须 atomic/serialized，避免并发 compiler workers都分配相同 next revision。

具体 DB/lock implementation留后续，但 architecture要求 immutable unique revision lineage。

## 13. Identical compiled content dedupe

如果：

```text
same ProductionShotIdentity
+
same canonical compiled execution payload
```

则复用 existing immutable ProductionShot revision，不因 compiler重新运行就产生空洞 rev+1。

原则：

```text
revision represents substantive compiled state,
not number of compiler invocations
```

## 14. compiled_execution_payload_hash

B7.8正式要求可比较的 execution payload hash，用于 execution-equivalence / incremental compilation。

应覆盖 execution-affecting immutable content，例如：

```text
segment/timing
source asset refs/hashes
reference layout
rendered prompt
render/context realization
workflow binding
dependency policy
ExecutionProfile execution-affecting content
```

同时保留 final record `content_hash`：

```text
content_hash
= exact immutable ProductionShot record integrity

compiled_execution_payload_hash
= executable behavior/content equivalence
```

## 15. Provenance-only changes与 revision

Validator版本或 non-execution metadata变化但 `compiled_execution_payload_hash`完全相同，不应自动制造 execution-equivalent新 ProductionShot revision。

Source revision变化也不能凭 prompt字符串相同就 dedupe；必须由 canonical compiled payload证明 effective execution不变。

## 16. B7.8允许 / 禁止操作

允许：

```text
select exact validated IR
canonical serialization
materialize execution fields
derive hashes
reuse/allocate revision
create provenance links
construct manifest
```

禁止：

```text
semantic reasoning
prompt rendering
asset evaluation/projection
reference ordering
workflow parameter selection
segmentation/timing solving
```

## 17. EpisodeExecutionManifest

B7.8 第二个输出：

```text
EpisodeExecutionManifest
```

它回答：

> 对这个 episode + ReleaseVariantIdentity + ExecutionProfile，应该执行哪些 exact ProductionShot revisions，release顺序是什么，runtime依赖是什么？

## 18. Manifest identity

正式 identity：

```text
EpisodeExecutionManifestIdentity
=
episode_id
+
ReleaseVariantIdentity
+
ExecutionProfile ID
```

B4/B5/B6 revision、ExecutionProfile revision等变更通常产生 same identity的新 manifest revision。

`NORMAL_COMPILE` / `REPLAY_COMPILE` 不进入 manifest identity，它们表示 execution eligibility/use mode。

## 19. Manifest 内容

概念：

```text
manifest_id / revision / content_hash
episode_id
release_variant_identity
source B4/B5/B6 refs
execution_profile_ref
validation_report_ref
validated_execution_compilation_bundle_hash
production_shot_sequence[]
production_shot_refs[]
execution_dependency_graph
```

所有 ProductionShot refs必须 exact：

```text
id / revision / content_hash
```

## 20. Release sequence / dependency graph 分离

必须同时表达：

```text
release/editorial sequence
≠ execution dependency graph
```

Release sequence deterministic来自：

```text
B4 PlannedShot canonical order
↓
within each PlannedShot: B7.2 segment order
```

Runtime dependency graph只表示真实 producer/continuation等 execution prerequisites。

无 dependency的 Shots未来可被 scheduler并行，即使 release order不同。

## 21. Manifest保存 DAG，不保存 queue plan

Manifest保存：

```text
PS-B depends on exact PS-A revision
```

不保存：

```text
worker 1 / worker 2
run at 03:15
current queue position
```

这些属于 runtime scheduler。

## 22. Exact producer revision

Dependency edge必须 pin producer：

```text
ProductionShot id/revision/hash
```

不能仅写“previous shot latest”，否则 producer revision变化会 silent drift。

真正使用哪个 producer GenerationAttempt output由 consumer attempt运行时按照 dependency selection policy解析，并记录 exact artifact/hash。

## 23. Manifest as execution-set authority

B7.8不要求每个 ProductionShot维护独立 mutable `current=true`。

更简单的 authority：

```text
ProductionShot revision is normal-current
iff current EpisodeExecutionManifest references it
```

这样避免 current manifest pointer + per-shot current pointers双重状态漂移。

## 24. Normal current manifest

对于：

```text
episode
+
ReleaseVariantIdentity
+
ExecutionProfile ID
```

最多一个 normal-current `EpisodeExecutionManifest` revision。

历史 revisions immutable、auditable、replayable。

## 25. Atomic publish / supersede

一个 episode可能包含大量 ProductionShots。不能逐 Shot切 current状态。

正确：

```text
1 materialize/reuse ALL required ProductionShot revisions
2 construct complete manifest
3 perform assembly-integrity assertions
4 persist immutable manifest
5 atomically swap current manifest pointer
```

任何中途失败不得产生 mixed current execution set。

## 26. REPLAY_COMPILE

Replay可生成/复用 historical execution manifest，但默认：

```text
REPLAY_COMPILE
DOES NOT move normal-current pointer
```

避免重放旧版本反向覆盖 current production lineage。

继续保持：

```text
historical validity
≠ normal current execution eligibility
```

## 27. Manifest revision / dedupe

只要 exact execution set发生变化，如 ProductionShot topology/revision/dependency graph改变，就产生新 manifest revision。

如果 same manifest identity + same exact ordered ProductionShot refs + same dependency graph + same canonical execution-affecting payload，则复用已有 manifest revision，不因再次 compile产生重复 revision。

## 28. Incremental compilation

B7 architecture天然支持 hash-based incremental reuse。

例如 40个 Shots只有2个受 asset change影响：

```text
38 shots payload unchanged → reuse old revisions
2 shots changed → new revisions
new EpisodeExecutionManifest → references 38 old + 2 new
```

Implementation以后可优化增量 compilation，但 authoritative result仍是 exact complete manifest。

## 29. Manifest不是 generated media manifest

`EpisodeExecutionManifest` 表示：

```text
what SHALL be executed
```

不是：

```text
what WAS generated
```

不得嵌入 actual attempt/output/QC result。

GenerationAttempt / GeneratedArtifact / QC继续作为 downstream immutable records。

## 30. GenerationAttempt provenance

Canonical episode execution中的 GenerationAttempt建议同时 pin：

```text
EpisodeExecutionManifest id/revision/hash
ProductionShot id/revision/hash
```

这样可以明确某次 generation属于哪个 episode compilation checkpoint。

单 Shot调试若作为 canonical execution，也应选择来源 manifest；完全手工 ad-hoc生成应标记 `NON_CANONICAL_EXPERIMENT`。

## 31. Execution preflight boundary

B7.8完成表示：

```text
execution specification compiled + validated
```

不表示 ComfyUI在线、GPU空闲、asset已 staged。

Runtime preflight概念：

```text
load exact ProductionShot / manifest
verify current or replay eligibility
resolve B6 source asset locators + hashes
stage exact refs in B7.5 authoritative order
resolve runtime-derived dependencies
allocate attempt seed
resolve endpoint/output locator
materialize attempt workflow/request
create GenerationAttempt
```

Preflight没有 semantic decision。

## 32. Runtime不得重新 compilation

Execution preflight / `comfyui-generate` 不得：

```text
rebuild prompt
reselect refs
reorder Picture N
change workflow topology
change semantic duration
```

它只 materialize fields明确列入 `AttemptVariableContract` 的 runtime values。

## 33. Existing v1.1 execution / QC / retry

现有：

```text
comfyui-generate
QC schema
retry.py attempt+1 / deterministic_seed
```

继续保留。

未来：

```text
ProductionShot rev N
↓
GenerationAttempt 1
↓
GeneratedArtifact
↓
QC
↓
retry within AttemptVariableContract
```

如果 QC要求改 prompt/ref/asset/segmentation/timing/workflow/dependency policy，则不是 retry，而是 route owning stage → recompile → B7.7 → B7.8 → new attempt sequence。

## 34. No B7 human approval gate

B7.8 冻结：**B7 不新增 formal human approval gate**。

理由：

```text
B4 Human approves canonical Shot semantics
B5 Human approves release realization
B6 Human approves concrete asset authority
B7 deterministically compiles those approved decisions
```

Picture/slot/workflow correctness应由 B7.7 validator负责，不应让 Human充当 compiler verifier。

未来“点击 Run 才开始批量生成”属于 operational authorization，不是 semantic approval gate。

## 35. Assembly-integrity assertions

虽然 B7.7已验证，B7.8仍做轻量 structural assertions：

```text
all refs match validated bundle
all expected ProductionShot identities materialized/reused
no duplicate logical identity in manifest
all exact revisions/hashes exist
dependency graph targets manifest members
release sequence complete
canonical serialization succeeds
```

这是 assembly integrity，不是第二个 semantic validator。

## 36. Assembly failure / current pointer safety

若 B7.8发生 materialization/storage/race failure：

```text
current manifest pointer remains unchanged
```

禁止 partial publish。

典型 failure codes：

```text
VALIDATED_BUNDLE_REQUIRED
VALIDATED_BUNDLE_HASH_MISMATCH
VALIDATION_RESULT_NOT_ASSEMBLABLE
MISSING_COMPILER_ARTIFACT
PRODUCTION_SHOT_MATERIALIZATION_FAILURE
PRODUCTION_SHOT_IDENTITY_COLLISION
REVISION_ALLOCATION_CONFLICT
CANONICAL_SERIALIZATION_FAILURE
COMPILATION_PAYLOAD_HASH_MISMATCH
MANIFEST_SEQUENCE_INCOMPLETE
MANIFEST_DUPLICATE_PRODUCTION_SHOT
MANIFEST_DEPENDENCY_TARGET_MISSING
MANIFEST_DEPENDENCY_CYCLE
MANIFEST_SOURCE_LINEAGE_MISMATCH
CURRENT_MANIFEST_ATOMIC_SWAP_FAILURE
```

## 37. Canonical serialization

B7.8 final immutable artifacts必须保证：

```text
same exact semantic/execution object
→ same canonical serialized bytes
→ same content_hash
```

Hash不得受 dict order、filesystem order、YAML writer formatting等 incidental representation影响。

## 38. Lifecycle

ProductionShot / EpisodeExecutionManifest都采用：

```text
immutable revisions
+
external current manifest pointer
```

不在 immutable artifact内部维护复杂 mutable DRAFT/ACTIVE/SUPERSEDED flags。

可派生 operational状态：

```text
CURRENTLY_REFERENCED
HISTORICAL
REPLAY_SELECTED
```

## 39. Upstream supersession

当 B4/B5/B6 later approved revision supersede source lineage时，旧 ProductionShots/Manifest仍 historically valid、immutable、auditable。

但 normal new execution必须重新从 current lineage compile并 atomic publish新 manifest。

## 40. Human-readable keys

继续兼容：

```text
E01_S003_SH002
E01_S003_SH002_SEG01
...
```

用于 folder/log/output/operator display。

正式 lookup/provenance使用：

```text
ProductionShot id/revision/content_hash
```

Generated output filename不是 identity。

## 41. Python / Qwen

B7.8 revision/hash/canonical serialization/dedupe/manifest assembly/current-pointer discipline全部由 deterministic Python core负责。

Normal B7.8不需要 Qwen。Qwen可辅助 developer分析 assembler error，但不参与 revision allocation、hash、manifest authority。

## 42. 冻结原则

1. B7.8只做 deterministic materialization/assembly。
2. 只消费 exact B7.7 PASS/PASS_WITH_DIAGNOSTICS validated bundle。
3. 必须 pin validated_execution_compilation_bundle_hash。
4. 不 rerun B7.2–B7.6 compiler decisions。
5. Materialize existing v1.1 ProductionShot，不建 parallel hierarchy。
6. ProductionShot是 self-sufficient immutable execution payload + exact provenance。
7. Materialize execution-critical data；完整 compiler history以 exact refs/hashes追溯。
8. Logical identity完全复用 B7.2。
9. Revision表示 substantive compiled state，不表示 compiler运行次数。
10. Same identity + same compiled payload reuse existing revision。
11. Attempt-specific runtime values不固化在 ProductionShot。
12. B7.8同时 materialize EpisodeExecutionManifest。
13. Manifest identity = episode + ReleaseVariantIdentity + ExecutionProfile ID。
14. Release sequence与execution dependency DAG严格分离。
15. Dependency edge pin exact producer ProductionShot revision/hash，不 pin future attempt。
16. Current execution set以 current EpisodeExecutionManifest为 authority，不维护双重 per-shot current state。
17. 同 manifest identity最多一个 normal-current revision。
18. Historical artifacts immutable，historical validity与current eligibility分离。
19. REPLAY_COMPILE默认不移动 normal current pointer。
20. New manifest只有完整 materialization后才能 atomic publish。
21. Partial assembly绝不能产生 mixed current set。
22. Unchanged ProductionShot revisions可被新 manifest复用，支持 incremental compilation。
23. Manifest表示 what shall be executed，不嵌入 actual generation/QC results。
24. GenerationAttempt应 pin exact manifest + ProductionShot revisions。
25. Execution preflight只解析 runtime state，不重新 compile。
26. Existing comfyui-generate/QC/retry作为 downstream executor/evaluator保留。
27. Retry只允许 AttemptVariableContract 内变化；spec变化必须 recompile。
28. B7无 formal human approval gate；operational Run authorization另行处理。
29. B7.8只做轻量 assembly-integrity assertions，不成为第二个 validator。
30. Canonical serialization/hash deterministic，不依赖 incidental order/path。
31. Normal B7.8 deterministic，不依赖 Qwen。
