## 1. Stage responsibility

A-I5 消费 validated immutable A3 outputs：

```text
exact SourceDocument
+
exact ChunkManifest
+
validated CURRENT CandidateExtraction set
+
EntityReconciliationProfile
+
SemanticLLMProfile
+
versioned A4 prompt/schema
        ↓
candidate entity index
        ↓
deterministic normalization
        ↓
must-not-merge constraints
        ↓
candidate blocking
        ↓
safe deterministic decisions
        ↓
LLM ambiguity decisions
        ↓
graph canonicalization
        ↓
coverage/conflict validation
        ↓
canonical entity outputs
```

A4 的职责是：

```text
chunk-local character/location candidates
→ global canonical identity
```

核心原则：

```text
错误 merge 比暂时 unresolved 更危险
```

因此 A4 v1 采用：

```text
precision-first
fail-closed
explicit uncertainty
```

A4 不做：

- fact/event consolidation；
- relationship history consolidation；
- story interpretation；
- character dossier / story arc；
- adaptation / screenplay / production；
- H3 / ComfyUI。

这些属于 A5/A6/B-stage。

## 3. Input eligibility

Production A4 输入必须来自同一 exact：

- project；
- document；
- chunk profile；
- ChunkManifest；
- extraction profile。

每个参与 production A4 的 CandidateExtraction 必须：

- exact resolve；
- exact matching A3 ValidationReport；
- `ValidationResult == PASS`；
- 对其 exact A3 identity 仍为 CURRENT；
- lineage 与 exact SourceDocument / SourceChunk / ChunkManifest 一致。

完整 production A4 stage 要求 ChunkManifest 中所有 chunks 的 A3 extraction coverage 完整。

Smoke/test 可以显式使用 subset，但不得把 subset semantics 当成 whole-document production reconciliation。

不得 silently skip：

- missing extraction；
- failed A3 validation；
- stale CURRENT；
- incompatible source/chunk lineage。

## 11. Safe deterministic same-entity decisions

Python auto-same 必须极保守。

v1 只允许已被 deterministic policy 明确判为 **safe exact identity key** 的 name/alias exact match，并且：

- entity type 相同；
- 不存在 must-not-merge；
- key 不是 generic title/role-only mention；
- key 不是被 policy 判定为 insufficiently specific 的弱单词/称谓。

高层冻结示例仍成立：

```text
normalized full name exact match + no hard conflict
→ eligible for deterministic same
```

以及 source 明确给出的 alias/identity reveal 可形成 deterministic identity evidence。

以下不得仅凭字符串自动 merge：

```text
John
Mr. Smith
Captain
the teacher
Miss Carter
```

它们默认进入 ambiguity handling。

A4B 必须把 “safe exact identity key” 规则写成 deterministic, versioned policy；A4A 不实现该算法。

---

## 12. Must-not-merge constraints

Must-not-merge 高于 name similarity。

hard negative evidence 必须来自 deterministic 可证明的 source-backed distinctness。

冻结原则：

- source 明确表示两者是不同实体；
- source-backed event/relationship structure **明确**把两者作为 distinct participants/endpoints；
- explicit incompatible identity evidence。

不得仅凭以下 soft evidence 建 hard constraint：

- 年龄；
- 职业；
- 外貌；
- 性格；
- clothing；
- approximate location；
- 单纯 source proximity。

特别地：

> “两个 local candidate refs 同时出现在某个结构里”本身不是自动 hard proof；A4B 必须能从 existing typed/source evidence deterministic 证明 distinctness，才能升级为 must-not-merge。

否则只作为 blocking/semantic-resolution evidence。

---

## 13. Candidate blocking

禁止 whole-document N×N pairwise comparison。

Python deterministic 构建 ambiguity blocks。

可用 signal：

- normalized name overlap；
- alias overlap；
- normalized token overlap；
- exact descriptor overlap；
- source proximity；
- shared relationship/event neighborhood；
- negative-evidence signals。

重要：

```text
block = worth comparing
block != probably same
```

blocking 优先避免 false-negative，但不得退化成整本小说全组合。

policy identity：

```text
a4-blocking-v1
```

---

## 14. Deterministic pair state

每个 candidate pair 在 ambiguity plan 层只能是：

```text
auto_same
must_not_merge
needs_semantic_decision
not_compared
```

映射：

```text
auto_same
→ same_entity / deterministic

must_not_merge
→ different_entity / deterministic

needs_semantic_decision
→ send to LLM

not_compared
→ no identity edge
```

不得把 `not_compared` 解释为 `different_entity`。

---

## 15. A4 LLM responsibility

LLM 只处理 ambiguous identity。

固定 classification：

```text
same_entity
different_entity
uncertain
```

LLM 不得：

- create canonical IDs；
- modify candidate registry；
- merge graph directly；
- assign `char_0001` / `loc_0001`；
- invent candidates；
- perform A5 consolidation；
- perform story/production interpretation。

`uncertain` 是成功结果。

不得 retry 一个 schema/semantic-valid `uncertain`，试图逼模型选择 same/different。

Python 必须验证：

- pair 在 requested ambiguity plan 中；
- left != right；
- pair type legal；
- exact pair uniqueness；
- no missing requested pair；
- no extra returned pair；
- decision enum valid；
- evidence refs exist；
- LLM 不得 override deterministic must-not-merge；
- LLM 不得 override deterministic auto-same。

继续保持 A-I3 technical retry 与 stage semantic retry 分层。


- first semantic generation；
- at most one semantic regeneration。

## 21. Identity graph and conflicts

最终 Python graph：

```text
same_entity      → positive edge
different_entity → negative constraint
uncertain        → explicit ambiguity edge
```

先对 `same_entity` 做 connected components。

若任一 `different_entity` edge 的 endpoints 落入同一 same-component：

```text
RECONCILIATION_CONFLICT
```

fail closed。

例如：

```text
A same B
B same C
A different C
```

不得自动多数票修复。

---

## 22. Uncertain policy

A4 v1 必须真正保留 uncertainty：

```text
uncertain != different
uncertain != merge
```

流程：

1. collapse valid same-components；
2. 构建 component-level uncertain graph；
3. 由 uncertain edges 连通的 identity components 形成 explicit unresolved ambiguity group；
4. 这些 ambiguity-group members 不获得互相排他的 canonical IDs，直到 ambiguity 被后续明确解决；
5. group 保留 candidate refs + decision refs。

这会比激进 canonicalization 留下更多 unresolved，但符合 precision-first frozen architecture。

A3 unresolved passthrough 不进入此 graph，直接进入 unresolved output。
