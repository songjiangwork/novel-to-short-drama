# B2.5 — Screenplay Continuity / Coverage Validation

状态：**FROZEN**

## 1. 职责

B2.5 是只读 `EpisodeScreenplay` integrated auditor。

核心原则：

```text
verify
diagnose
route

not repair
not rewrite
not regenerate
```

它验证 exact EpisodeScreenplay revision 是否忠实、完整、连续地实现 approved adaptation truth 与 screenplay contracts。

## 2. ScreenplayValidationReport

正式引入：

```text
ScreenplayValidationReport
```

必须绑定：

```text
episode_screenplay_id
episode_screenplay_revision
episode_screenplay_hash
```

并保存 validated upstream pins、findings、coverage summary、continuity summary、duration summary、validation metadata。

任意 screenplay semantic revision 都必须重新产生 validation report。

## 3. Result / severity

Overall result 复用 B1.6：

```text
FAIL
PASS_WITH_REVIEW_ITEMS
PASS
```

Finding severity：

```text
BLOCKING
REVIEW_REQUIRED
WARNING
```

每个 finding 必须标记 `earliest_authoritative_owner`，以决定 route 到 B2.3 / B2.2 / B1.x 等正确层级。

## 4. Validation domains

B2.5 至少覆盖：

```text
A. Reference / revision integrity
B. Scene-plan realization integrity
C. Presentation coverage
D. AdaptedBeat coverage
E. Dramatic-function realization
F. Adapted continuity
G. Screenplay continuity
H. Character knowledge / reveal
I. Dialogue semantic integrity
J. Callback / promise integrity
K. Cross-scene causal continuity
L. Episode opening / ending integrity
M. Climax / hook realization
N. Duration / pacing feasibility
O. Unauthorized narrative invention
P. Production-boundary leakage
```

## 5. ScenePlan realization integrity

对每个 ScreenplayScene，验证实际 SceneRealization 与计划的：

```text
objective
conflict
turn
outcome
participants
dramatic setting
duration intent
continuity contract
```

semantic-compatible。

Structural mapping existence 不等于 semantic coverage。

## 6. Presentation / Beat coverage

每个本集 required PresentationEntry 必须被实际 screenplay realization 覆盖，并保持 B1 规定的 reveal / withholding / partial exposure / flashback timing。

每个 required AdaptedBeat 的必要 dramatic function 必须被真正 realization。

检查 duplicate reveal、missing reveal、Beat function 缺失与错误重复。

## 7. Episode dramatic realization

必须验证 EpisodePlan 的：

- dramatic goal
- core conflict
- progression
- required ending state

不是只看所有 ID 是否“出现过”。

## 8. Adapted Continuity

验证 narrative-relevant：

- knowledge
- relationship
- object possession
- status
- significant location/presence
- unresolved questions
- causal dependencies

Persistent state change 必须有 upstream authorization。

如果只是 B2.3 多写了非法内容，可 route 为 `REALIZATION_ERROR`；若剧情本身需要新增 narrative semantics，标记 `ADAPTATION_CHANGE_REQUIRED`。

## 9. Screenplay Continuity

验证 promise、phrase、conversational tension、callback seed、recent entrance/exit 等 overlay 内部一致。

Overlay 不得升级为新的 adaptation truth。

## 10. Knowledge / audience / withholding

独立验证：

```text
character knowledge
audience knowledge
reveal timing
withholding timing
```

Knowledge acquisition timing 可以在 Scene 内变化。

Action description 也可能造成 audience reveal leak，不只检查 dialogue。

## 11. Dialogue semantic integrity

对重要 dialogue 检查：

```text
DialogueIntent
surface dialogue
information payload
subtext
truth relation
```

必须 semantic-compatible。

Surface wording 默认按 semantic equivalence 验证，不做 exact string match，除非标记 wording_sensitive / quote_sensitive。

## 12. Callback / promise integrity

重要 callback 必须 resolve 到合法 source identity，并验证：

- source exists
- semantic content matches
- chronology valid

不能仅因为引用了某个 promise ID 就自动通过。

## 13. Cross-scene continuity

检查 narratively meaningful discontinuity，例如：

- impossible possession
- impossible knowledge
- meaningful location contradiction
- causal jump
- relationship state jump
- hidden emotional/state reset

不要求对厨房到客厅等 mundane movement 过度建模。

## 14. Opening / ending / anchors

Episode opening 必须兼容 B1 opening checkpoint + screenplay opening overlay。

Episode ending 必须满足 required ending state，并验证 `EpisodeScreenplayEndingCheckpoint` 与实际 screenplay reconciliation。

分别验证：

```text
EpisodeClimaxAnchor
EpisodeHookAnchor
```

Required climax/hook 根本缺失时通常 BLOCKING；强度等较主观问题可 REVIEW_REQUIRED。

## 15. Duration / pacing

整合 Scene estimates、Scene budgets 与 Episode target，检查：

- scene overrun
- aggregate overrun
- major underfill
- dramatic allocation imbalance

不仅看 total，也看明显 pacing distribution 问题。

## 16. Unauthorized narrative invention

主动检查 screenplay 中 B1 未授权的：

- new fact
- new causal event
- new knowledge transition
- new relationship change
- new major motivation
- persistent prop dependency
- new future setup
- new character dependency

同时必须容忍合法 realization invention，避免把拿杯子、坐下、自然寒暄等误报为 adaptation change。

## 17. Production-boundary leakage

可检查明显 camera / lens / shot / frame / cut / zoom / reference image / H3 / ComfyUI 等 production leakage。

但 H3/ComfyUI 是否好生成，不属于 B2.5 screenplay correctness。

## 18. Finding schema

Finding 至少表达：

```text
finding_id
severity
category
summary
affected_refs
evidence
violated_contract
earliest_authoritative_owner
recommended_route
```

Evidence 优先引用 stable IDs，不以页码/自然语言位置作为唯一证据。

Finding 不应以 replacement patch 为核心；validator 没有 canonical repair authority。

## 19. Python / Qwen

Python 主导：

- revisions/hashes
- IDs/order/mappings
- deterministic continuity mechanics
- callback resolution
- duration aggregation
- provenance integrity

Qwen 辅助：

- dramatic realization
- intent/subtext semantics
- character voice
- causal plausibility
- unauthorized semantic invention detection
- climax/hook semantic realization

Qwen validator 只有 diagnostic authority。

## 20. B2.5 → B2.6

```text
FAIL
→ 不允许进入 B2.6 approval

PASS / PASS_WITH_REVIEW_ITEMS
→ 可进入 B2.6
```

B2.5 本身不进行 human approval。

## 21. 冻结 contract

1. B2.5 是 read-only integrated auditor。
2. 正式输出 ScreenplayValidationReport，绑定 exact screenplay revision/hash。
3. 使用 FAIL / PASS_WITH_REVIEW_ITEMS / PASS 与 BLOCKING / REVIEW_REQUIRED / WARNING。
4. 每个 finding 必须 route 到 earliest authoritative owner。
5. Mapping existence 不等于 semantic coverage。
6. 必须验证 Presentation / Beat / dramatic-function realization。
7. 必须验证 Adapted Continuity 与 Screenplay Continuity 分层一致。
8. 必须独立验证 character knowledge / audience knowledge / reveal / withholding。
9. 必须验证 dialogue intent、callback source/semantics/chronology。
10. 必须验证 cross-scene causality、opening/ending、climax/hook、duration/pacing。
11. 必须检测 unauthorized narrative invention，同时容忍 realization invention。
12. B2.5 不得 silent auto-fix。
13. Deterministic checks Python 主导，semantic checks Qwen 辅助。
14. B2.5 不使用单一模糊 quality score 作为 gate。
15. FAIL 不得进入 B2.6；B2.5 不进行 approval。
