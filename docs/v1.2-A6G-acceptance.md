# A6G Alice real-provider acceptance gate

此 gate 不是 pytest 的一部分，也不会由 CLI 自动调用。它只在离线测试全绿、操作者已确认本地 Qwen runtime 可用时执行一次完整的 A6C → A6D → A6E → A6F fresh run。

前置条件：`runs/a4e_real_novel/a3e-real-novel` 的 A5 `consolidation-v1` CURRENT 必须是有效的 Alice A5 CURRENT，且目标 run root 尚无 `global-story-analysis-v1` A6 CURRENT。

```bash
PYTHONPATH=src .venv/bin/python -u scripts/a6g_alice_acceptance.py \
  --project examples/a3e_real_novel/project.yaml \
  --runs-root runs/a4e_real_novel \
  --consolidation-profile-id consolidation-v1 \
  --story-analysis-profile profiles/global_story_analysis_v1.yaml \
  --runtime-config profiles/llm_local.yaml \
  --llm-profile profiles/story_analysis_llm_v1.yaml
```

脚本会拒绝已有 A6 CURRENT，避免把 historical checkpoint 误当本次 production 结果。fresh 成功后它自动执行一次 exact rerun 和一次只变更 transport 的 rerun；两者都必须零 provider calls、零写入，并与 fresh 使用同一 A6 manifest。

若 fresh A6 CURRENT 已经发布、但旧进程在后续验收报告步骤失败或中断，则使用只读 recovery 模式。它不创建 Provider client、不运行 A6C/D/E/F，也不写入任何 artifact/pointer：

```bash
PYTHONPATH=src .venv/bin/python -u scripts/a6g_alice_acceptance.py \
  --project examples/a3e_real_novel/project.yaml \
  --runs-root runs/a4e_real_novel \
  --consolidation-profile-id consolidation-v1 \
  --story-analysis-profile profiles/global_story_analysis_v1.yaml \
  --runtime-config profiles/llm_local.yaml \
  --llm-profile profiles/story_analysis_llm_v1.yaml \
  --verification-only
```

JSON 输出以 existing whole-A6 validator 的 PASS 作为 reference-validity evidence，不虚构 invalid-ref 数量；Alice dossier 从 canonical character registry 解析，人工审阅包始终标为 pending。不得手工修改生成的 StoryBible。
