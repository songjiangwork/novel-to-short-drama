## 1. Scope and stage ownership

```text
UserDirectionSet (exact immutable members and lifecycle)
            ↓ Python deterministic effective projection
Stage-relevant EffectiveUserDirectionSet + hash
            ↓
B1 adaptation | B2 screenplay | B3 production/visual
              | B4 shot | B5 release | B6 asset
```

G1 只定义共享数据、persistence/validation/routing/effective-set 的基元。B1/其它 stage 的 Qwen request integration 和创意 compliance 由后续对应 stage Issue 实现。用户完全不提供方向时必须得到定义明确的 stable **empty effective set**，流水线不因空 guidance 而阻塞。

Stage owner:
- 剧情取舍、角色戏份、结局、fidelity → **B1**；
- 对白和 screenplay narrative action → **B2**；
- 人物外形、发型、衣着、appearance state、production-space staging、performance → **B3**；
- frame-space、camera、composition、shot decomposition/continuity → **B4**；
- concrete visual asset candidate/selection/rejection → **B6**。
- B7/runtime 不能是绕过上述 stages 的 hidden creative editor。

## 2. Contract: UserDirection

最小语义（具体 Python field names 可以随 existing patterns 轻微调整）：

```text
UserDirection
  direction_id, direction_revision
  origin = USER                         # G1 必须保留 origin；不伪造 model origin
  category, strength
  stage_scope, target_scope, target_refs[]
  instruction_zh
  supersedes_direction_refs[]
  status = ACTIVE | SUPERSEDED | WITHDRAWN
  provenance
```

- `MUST | MUST_NOT` 是 hard，`PREFER | AVOID` 是 soft。
- Category、stage_scope、target_scope 必须相互合法，不能让 B4 camera 类型假扮 B1 adaptation。
- `target_refs` 只能是**当前已存在**的 exact stable IDs/ArtifactRefs，不能引用未来尚未生成的 Episode/Scene/Shot；合法替代是更广的 project/character scope。错误的 ref 不能经由 NLP “尽量匹配”。
- User-authored text 原样保留；Qwen 不可在任何 stage 改写用户的 direction record。
- Immutable historical direction revision 始终可核验。Supersession/withdrawal 使用新的不可变 revision / authority record 表达生命周期；**不可就地修改被某个 semantic request 消费过的历史快照**。
- G1 只需支持直接提交 **single-category structured direction**；多类别自然语言分解及 UserDirectionSubmission envelope 可以后续单独设计，不能阻塞 B1。

## 3. Contract: RevisionRequest

```text
RevisionRequest
  revision_request_id
  target_artifact_ref:
     artifact_type + artifact_id + revision + content_hash
  requested_stage
  instruction_zh
  target_refs[]
  resulting_direction_refs[]
  reviewer_provenance
```

它表示 **审查某个 exact artifact revision 后要求新 revision**，与可长期生效的 UserDirection 不同。

- 禁止 target 为文字性的“latest/current”；须 pin exact ArtifactRef。
- Review UI/CLI 不能直接改写被审的 immutable artifact；RevisionRequest 应路由 earliest authoritative stage、然后 downstream revalidation。
- RevisionRequest 可以在 B1.7/B2/B3/B4/B6 使用同一 primitive；**正式 decision/approval 的 authority 仍在原 Stage 的 formal review gate**，G1 不提供新 gate。

## 4. Effective projection and semantic identity

由 Python 对 exact input UserDirectionSet 作 deterministic 投影：

1. Validate all direction refs、owner category、target existence、lifecycle/supersession chain。
2. Filter stage scope、category 与 target scope；`WITHDRAWN/SUPERSEDED` 的 directions 不会作为当前有效输入。
3. Canonicalize stable ordering、exact member revision/hash；不依赖 dict insertion order、chat history 或调用时间。
4. Apply explicit supersession/exception relationships；同级不可兼容的 hard directions 抛出确定性 `DIRECTION_CONFLICT`，不以 last text wins 解决。
5. Emit `EffectiveUserDirectionSet`（带 exact member refs）及 deterministic `effective_user_direction_set_hash`。Hash 包含此 stage 的确切语义方向，不简单复制 project-wide set hash。

```text
new B4 CAMERA direction
  → B4 effective hash changes
  → B1/B2 effective hash unchanged
```

如果 broad global MUST 和 narrow scene MUST 存在表面冲突，**narrow 不自动获胜**。必须有 explicit exception/supersession，或在 semantic generation 前 fail/review，不能交给 Qwen 自行猜用户的真实意图。

Identity 示例（逻辑结构，不是新增永久通用 API）：

```text
SemanticRequestIdentity(stage)
 = exact upstream refs
 + stage effective directions hash
 + stage profile/prompt/output-schema IDs and hashes
 + stage's own deterministic plan/packet hash
```

Runtime endpoint、GPU slot count、timeouts 等不影响 creative semantic identity（除非它们本身改变了实际语义输入/内容）。

## 5. B1.1 raw intent versus G1 directions

`RawAdaptationIntent/Profile/Overrides → ResolvedAdaptationTarget` 属于 **B1.1 target authority**；G1 是共享用户指导记录和 deterministic routing，**不是第二份互相竞争的 resolved target**。

- 数量、时长、fidelity、genre 等改编目标的 hard override 应由 B1.1 产生新 ResolvedTarget（必要时从 G1 direction 路由到 B1.1）。
- 影响全局 narrative choice 但不改变 target constraints 的指导，例如“强化柴郡猫戏份”，由 B1.2/B1.3 消费 stage-relevant direction refs。
- 相互冲突的 B1.1 hard target 与 B1 guidance 必须显式解决，不允许 agent 把 target 降格为 soft direction。
- B2/B3/B4/B6 收到 B1-owned narrative revision request，返回 B1 而不是在下游修改 adaptation truth。

## 6. Provenance and compliance interface

产物需要能够解释 source / model / user 三者分别贡献了什么；可保留 exact `direction_refs[]`、`revision_request_refs[]`。

G1 只定义可引用的 provenance 和 lightweight summary interface（如 satisfied/deviated/unresolved refs）；不在这个 PR 实现各 stage 的 Qwen compliance classification。后续 B1/B2 计算方向合规时，hard MUST/MUST_NOT 未满足不得被当作普通 warning；soft deviation 的 severity 按 stage 明确实施。

## 7. Reuse foundation / minimalism

- `ArtifactRef`, `ImmutableArtifactEnvelope`, `FileArtifactStore`, `LineageRef`, canonical hashes 来自现有 foundation。
- 不建 user guidance 数据库、ORM、RBAC、chat-as-authority、direction-specific LLM transport、全量 stale propagation engine、frontend review wizard。
- 对 immutable status/supersession 可以复用 existing revision/lineage/pointer patterns，但不必为 G1 创造未被需求驱动的新 pointer hierarchy。
- Documentation/B1.1 contracts 可先独立实现；G1 stable API 准备完后 B1.2 才实际引入 stage effective hash。

## 8. Test matrix

| Test | Expected |
|---|---|
| empty directions | stable empty effective hash; fully automatic downstream preparation |
| same set, reordered insertion | exactly same canonical effective identity |
| B4 camera-only addition | B1/B2 effective identity unchanged |
| B1 narrative hard change | B1 effective identity changes |
| USER vs MODEL_PROPOSED | origin remains explicit, model cannot impersonate user |
| same-scope MUST vs MUST_NOT same target | fail-closed conflict |
| broad MUST vs narrow contradictory MUST without exception | conflict, no silent override |
| explicit supersession/withdrawal | old snapshot immutable; current projection excludes old |
| dangling/wrong-revision target ref | rejected |
| nonexistent future shot/scene ID | rejected, do not fabricate target |
| stage/category mismatch | deterministic rejection/routing |
| RevisionRequest exact ref | accepted when target resolvable |
| RevisionRequest "latest" or tampered content hash | rejected |
| compound raw chat request not explicitly normalized | no hidden authority |
| repeat persist same exact artifact | safe/idempotent consistent with FileArtifactStore |
| unrelated effective set mutation | no unintended upstream invalidation |

Focused pytest + relevant foundation regression tests + `git diff --check`；**零真实 Qwen/ComfyUI**。

## 9. Acceptance / non-goals

G1 Done = immutable shared records + exact provenance/revisions + deterministic effective projection + hard conflict detection + exact RevisionRequest target + tests。G1 **不批准任何作品**，不要求开发 B2–B6，不使得每个 stage 等待用户输入。Character visual/asset guidance implementation 的优先顺序（B3 visual → B6 visual → B4 shot guidance）仍由被冻结的 guidance architecture 管理，不在此 Issue 抢先实现。
