# B7.1 — Execution Compilation Contract + Execution Context

状态：**FROZEN**

## 1. 职责

B7.1 建立 Execution Compilation 的正式输入 contract、lineage contract、ExecutionProfile contract 与 failure-routing boundary。

核心定位：

```text
B7 = compiler layer
```

它消费已经批准的 Shot / Release / Asset authority，并把它们绑定为一个可重复、可验证、backend-profile-specific 的 `ExecutionCompilationContext`。

B7 不再创作，不再选 asset，不重新定义 Shot。

## 2. 正式输入

Normal compilation 必须同时 pin exact：

```text
APPROVED EpisodeShotPlan
APPROVED EpisodeReleaseVariant
APPROVED EpisodeResolvedAssetPlan
```

分别至少 pin：

```text
artifact_id
revision
content_hash
approval_record_id
```

B3 `EpisodeProductionPlan` 不作为 B7 direct compilation input；其 authority 通过 B4 lineage保留。B7 不得重新读取 B3 与 B4竞争 Shot semantics。

## 3. Lineage integrity

必须验证：

```text
B5.source_episode_shot_plan
== exact B4 id/revision/hash

B6.source_episode_release_variant
== exact B5 id/revision/hash
```

同时每个 approval record 必须 target exact artifact id/revision/hash。

禁止仅因三个对象都标记 `APPROVED` 就拼装不一致 lineage。

## 4. NORMAL_COMPILE / REPLAY_COMPILE

正式区分：

```text
NORMAL_COMPILE
REPLAY_COMPILE
```

`NORMAL_COMPILE` 要求 exact `APPROVED + current-lineage`。

`REPLAY_COMPILE` 允许使用 historically approved、immutable、但不再 current 的完整 lineage，用于 exact reproduction / historical replay。

核心：

```text
historically approved
≠
currently execution-eligible
```

Replay 必须显式，不得混入 normal generation queue；默认也不得 supersede current execution manifest。

## 5. ExecutionProfile

B7.1 正式引入 backend-specific `ExecutionProfile`。

概念至少包含：

```text
execution_profile_id
revision
content_hash
backend_family
backend_model_family
workflow_template_id/revision/hash
backend_capabilities
reference_layout_policy
prompt_renderer_id/revision/hash
asset_staging_policy
media_execution_constraints
compilation_policy_version
```

ExecutionProfile 描述 backend contract，不是 canonical Shot/Release/Asset semantic object。

因此：

```text
canonical Shot semantics
≠ release semantics
≠ asset authority
≠ backend execution profile
```

## 6. Runtime environment boundary

ExecutionProfile 不应包含当前 machine/runtime state，例如：

```text
127.0.0.1:8188
192.168.x.x
C:\AI\...
/mnt/c/...
GPU UUID
worker PID
queue id
output directory
```

这些属于 GenerationAttempt/runtime provenance，而不是 compiled semantic identity。

## 7. ExecutionProfile 不具有 semantic authority

规则：

```text
ExecutionProfile describes what a backend can accept.
It does not redefine what a Shot should mean.
```

例如 B4 要求 Song + Linsey simultaneous co-visibility，而某 backend只能单角色生成，B7 不得自动改成两个 close-up Shots。

正确结果：

```text
BACKEND_INFEASIBLE
```

随后选择另一个 ExecutionProfile 或 route 回真正 owning stage。

## 8. PlannedShot → ProductionShot 基本 contract

B7.1 冻结：

```text
PlannedShot → 1..N ProductionShots
```

并规定：

- `1 PlannedShot → 0 ProductionShots` 正常情况下非法；
- 每个 ProductionShot 属于 exactly one PlannedShot；
- 多个 PlannedShots 不得合并成一个 ProductionShot；
- 1→N 只能实例化 B4.5 已授权的 generation segmentation。

Backend limitation 是 partition constraint，不是 segmentation authority。

## 9. Timing authority

正式职责：

```text
B4.5 = canonical timing / segmentation authority
B5.4 = release timing realization authority
B7 = projection / compilation authority
```

B7 可以把 release timeline投影到 ProductionShot segments，但不能自行重写 localization、缩短对白、改变 reveal、移动 canonical seam。

## 10. Asset authority

B7 的合法 concrete asset universe只能来自 exact：

```text
APPROVED EpisodeResolvedAssetPlan
```

B7 可以从 approved effective asset universe选择 Shot-specific subset、赋 execution/backend roles 与 reference order。

B7 不得：

```text
query AssetCatalog for replacement
pick a similar file from folder
create missing asset
re-run compatibility evaluation
```

资产 authority不足必须回 B6。

## 11. Semantic role / backend slot 分层

B7.1 冻结总体分层：

```text
AssetRecord
≠ ExecutionAssetRole
≠ BackendReferenceRole
≠ Backend Slot
≠ Picture N
```

`Picture N` 只允许在后续 B7.5 reference-layout compilation正式出现。

## 12. Prompt 分层

B7 应采用：

```text
ExecutionSemanticSpec
↓
BackendPromptSpec
↓
RenderedBackendPrompt
```

Rendered prompt不是 canonical semantic source。Backend切换时应从 structured execution semantics重新 render，而不是 parse旧 prompt猜语义。

## 13. Existing v1.1 ProductionShot

B7 的 downstream target就是已有 v1.1 `ProductionShot`。

禁止为 v1.2 再造平行 hierarchy，例如：

```text
ExecutionShot
CompiledShot
H3Shot
ProductionShotV2
```

B7 可以有 compiler IR，但 B7.8 最终必须 materialize existing `ProductionShot`。

## 14. ExecutionCompilationContext

B7.1 正式输出：

```text
ExecutionCompilationContext
```

概念包含：

```text
execution_compilation_context_id
schema_version
execution_mode
episode_id

episode_shot_plan_ref
episode_release_variant_ref
episode_resolved_asset_plan_ref
approval_refs

release_variant_identity
execution_profile_ref
compiler_policy_version
lineage_verification
content_hash
```

Context hash应覆盖 exact upstream hashes、ExecutionProfile hash 与 execution-affecting compiler policy/schema version，但不包含 local path/runtime endpoint/GPU identity。

## 15. Context scope

一个 `ExecutionCompilationContext` 对应：

```text
1 episode
+
1 exact ReleaseVariantIdentity/revision
+
1 exact EpisodeResolvedAssetPlan
+
1 exact ExecutionProfile revision
```

换 release variant 或 ExecutionProfile 即进入不同 compilation context。

## 16. Failure routing

统一原则：

```text
route to the earliest authoritative layer
whose decision must change
```

典型 routing：

```text
wrong/missing asset authority
→ B6

localization / subtitle / release timing / framing must change
→ B5

Shot segmentation / camera / movement / visibility / Shot boundary must change
→ B4

ProductionUnit semantics must change
→ B3

Picture ordering / slot mapping / prompt rendering / workflow compilation bug
→ B7

current profile cannot implement valid semantics but another can
→ choose another ExecutionProfile
```

## 17. Backend feasibility

Backend infeasibility不自动说明上游错。

例如：

- required refs > backend capacity → profile incompatibility / legal repartition；
- 12s Shot + legal B4 seams → B7可 partition；
- 12s Shot + no legal seam + backend max 6s → fail，不得偷切；
- backend需要把 two-shot改成两个 close-up → route B4。

## 18. Python / Qwen / Human

```text
Python
= normal compilation authority / exact refs / hashes / validation /
  deterministic projection / constraint solving / assembly

Qwen
= failure diagnosis / ambiguity explanation /
  bounded assistance in profile/renderer design

Pi / Hermes
= developer / debugger / operator

Human
= upstream formal semantic approval + downstream QC/operations
```

Normal B7 compilation不依赖 Qwen。

## 19. 冻结原则

1. B7 是 compiler，不是 semantic-authoring stage。
2. B7 consume exact APPROVED B4+B5+B6。
3. NORMAL_COMPILE 要求 current-lineage；历史重放必须显式 REPLAY_COMPILE。
4. B7 不绕回 AssetCatalog。
5. ExecutionProfile backend-specific、semantically subordinate。
6. PlannedShot → 1..N ProductionShots；每个 ProductionShot exactly one PlannedShot。
7. 多 PlannedShots 不得 silent merge。
8. 1→N segmentation只能由 B4.5授权。
9. Backend constraint不创造 seam authority。
10. B5 timing只被投影，不被改写。
11. B6 assets只被投影，不被重选。
12. Asset identity / execution role / backend role / Picture N 严格分层。
13. Normal compilation deterministic，Qwen不是 per-shot compiler。
14. Existing v1.1 ProductionShot remains downstream target。
15. Failure route到真正拥有 required decision 的 stage。
16. B7 本身不调用 H3/ComfyUI generation。
