# 11. Frozen packing algorithm

For every audit candidate and each domain:

```text
1. consume semantic pairs in canonical pair order;
2. greedily append;
3. before appending a pair, close the current block iff:
     pair_count + 1 > max_pairs_per_block
   OR
     unique_candidate_count_after_append > max_candidates_per_block;
4. never split a pair;
5. never reorder pairs;
6. no empty block;
7. deterministic block order;
8. no random / graph / community packing.
```

Candidate refs inside a block:

```text
stable unique union of pair endpoints
ordered by:
  source_order_key
  then candidate_ref
```

Candidate refs are identity/audit/bookkeeping only; semantic context remains pair-local.

# 24. Post-freeze clarification — deferred semantic retry scheduling

本节是对 A5D Event / Relationship semantic-round contract 的**执行时序澄清**。它不改变 Event/Relationship semantic meaning、packing、prompt、schema、semantic profile、request identity、publication/reuse contract 或最多生成轮数。

## 24.1 Shared max-two-round contract

既有约束保持：

```text
max_generation_rounds = 2
```

两轮仍针对**同一个 prepared semantic request**。Round 2 不得修改：

- prompt / rendered prompt；
- output schema；
- semantic profile；
- ordered requested pairs；
- pair-local selector universe；
- request_hash；
- failure-feedback content。

`uncertain` 仍是成功 semantic result，不进入 retry。

Technical A-I3 `LLMError` 保持 A-I3 boundary；provenance mismatch 保持 immediate fail closed。两者均不得转换为 deferred semantic retry。

## 24.2 Per-domain two-stage execution

Event 与 Relationship **各自独立**执行同一 two-stage scheduling：

```text
Phase 1
  all prepared blocks for the current semantic domain
  exactly one semantic generation attempt each
  bounded by configured max_concurrency

domain barrier
  all started Phase-1 provider calls settled
  all Phase-1 futures completed
  Phase-1 bounded executor exited

Phase 2
  only Phase-1 semantic-invalid blocks from that same domain
  same exact prepared request
  serial execution
  ascending original block_ordinal
```

Phase 1 使用 configured `max_concurrency`。当前 A5G3 operator 可配置为 4，但该具体数值不是 semantic identity，也不在本 architecture contract 中硬编码。

Phase 2 retry concurrency 冻结为：

```text
1
```

当前 real-provider evidence 只直接支持 post-barrier isolated retry；没有证据支持 Phase 2 concurrency > 1。

## 24.3 Exact domain ordering / barriers

A5 service domain order 保持：

```text
Fact
→ Event
→ Relationship
```

因此执行顺序是：

```text
Fact Phase 1
→ Fact barrier
→ Fact Phase 2 retries, if any
→ Event Phase 1
→ Event barrier
→ Event Phase 2 retries, if any
→ Relationship Phase 1
→ Relationship barrier
→ Relationship Phase 2 retries, if any
```

不存在跨三个 domain 的 global retry barrier。

Fact 的相同 scheduling contract 由
`docs/v1.2-A5C-fact-semantic-resolution-implementation-plan.md`
的 post-freeze clarification 冻结。

## 24.4 Outcome semantics

Phase-1 semantic-valid：

```text
retain complete validated block result
semantic_rounds = 1
no second generation
```

Phase-1 semantic-invalid（例如 typed payload 可加载但 exact pair/order coverage、selector syntax/range 或其他 host semantic validation 失败）：

```text
record internal retryable semantic-invalid outcome
emit no partial domain decision result
do not yet raise terminal ConsolidationSemanticGenerationError
defer round 2 until the current domain barrier
```

Phase-2 retry valid：

```text
return normal validated block result
semantic_rounds = 2
restore result to original preparation / block_ordinal position
```

Phase-2 仍 semantic-invalid：

```text
raise existing ConsolidationSemanticGenerationError
rounds_attempted = 2
```

若当前 domain 有多个 first-round semantic-invalid blocks：

```text
retry in ascending original block_ordinal
```

Phase 2 为 serial；若某个 retry terminally invalid，不得继续发出更高 ordinal 的 retry provider calls。由此保持 deterministic lowest-ordinal terminal retry failure。

## 24.5 Block atomicity / ordering

Block atomicity 保持：

```text
one complete validated block result
OR
one typed terminal failure
```

First-round invalid payload 的 partial decisions 不得向外暴露、不得进入 whole-domain decision coverage、不得进入 persistence/publication。

Successful outputs 仍按 original preparation / `block_ordinal` 重组，不得让 concurrent completion order 成为 semantic ordering。

## 24.6 Request / reuse identity

Deferred retry 必须使用 exact same prepared request material：

- prompt ID/version/content；
- rendered prompt；
- output schema；
- semantic profile；
- ordered pair inputs；
- request hash。

以下 execution-only material不得进入 semantic request/reuse identity：

- `max_concurrency`；
- barrier / retry timing；
- provider slot；
- backend routing；
- provider attempt count。

不得改变 artifact identity、reuse identity、CURRENT semantics、publication authority 或 persistence boundaries。

不同 scheduling 可能导致 provider 返回不同但 valid 的 output/provenance bytes；这属于 provider-output variability，不是 request identity change。

## 24.7 Evidence boundary

A5G3 real-provider diagnostics 对一个 exact Relationship request 观察到：

- standalone serial generation 可 valid；
- saturated bounded-concurrency first pass 可出现 transport-successful、typed-load-successful 的 semantic-invalid incomplete payload；
- existing immediate in-worker second semantic round 在已观察样本中未形成可靠恢复；
- identical request 在完整 first-pass barrier 后 isolated serial retry 在已观察样本中恢复。

这些观察支持 **post-barrier scheduling isolation** 作为 robustness strategy。

它们不证明：

- concurrency 是根因；
- 某个真实 failure probability；
- Event 或 Fact 已出现同类 provider failure。

A5 对三个 semantic domains 采用同一 scheduling policy，是因为它们已经共享同一 max-two-round semantic retry / fail-closed orchestration contract，而不是把 Relationship provider evidence 外推成其他 domain 的经验事实。

## 24.8 Explicit non-goals

本 clarification 不引入：

- Alice / corpus-specific behavior；
- block-id / ordinal special case；
- sleep / random jitter；
- failure-feedback prompt mutation；
- token budget increase；
- `max_generation_rounds > 2`；
- global first-pass concurrency reduction to 1；
- packing changes；
- selector changes；
- semantic decision enum changes。

本节只冻结 semantic retry scheduling / orchestration；既有 semantic / request / reuse / publication contracts 保持不变。
