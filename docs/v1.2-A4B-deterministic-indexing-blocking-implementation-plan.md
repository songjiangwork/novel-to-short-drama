## 5. Snapshot coherence checks

开始 index 前必须 fail closed 验证：

- SourceDocument project/document identity 与 manifest 一致；
- manifest pins exact source_document_ref；
- manifest `chunk_count == len(chunk_refs)`；
- supplied source-chunk refs 与 manifest `chunk_refs` exact 相等且顺序一致；
- 每个 SourceChunk identity 与对应 chunk ref / manifest/profile 一致；
- CandidateExtraction 数量与 manifest chunk 数一致；
- 每个 CandidateExtraction：
  - project/document exact match；
  - chunk_profile_id exact match；
  - chunk_id exact match对应 SourceChunk；
  - source_document_ref exact match；
  - source_chunk_ref exact match；
  - extraction profile id/hash 与整个 snapshot 一致；
- CandidateExtraction ref 与 supplied typed extraction position exact 对齐；
- A3 ValidationReport refs 数量与 extraction 数量一致。

A4B 不重新计算 A3 validation report；caller 的 production resolver 负责 exact PASS authority。

在 unit tests 中，构造 incoherent snapshot 必须 fail closed。

## 8. Deterministic source_order_key

A4A frozen field为 string。

A4B 使用 exact deterministic key：

```text
{chunk_ordinal:06d}:{paragraph_ordinal:09d}:{category_ordinal:02d}:{candidate_suffix:09d}:{candidate_ref}
```

其中：

```text
chunk_ordinal
= position in ChunkManifest.chunk_refs, starting 1

paragraph_ordinal
= earliest evidence paragraph position in SourceDocument.paragraphs, starting 1

category_ordinal:
  character  = 1
  location   = 2
  unresolved = 3

candidate_suffix
= numeric suffix of local candidate id
```

例如：

```text
000003:000000157:01:000000002:CH002_C001:cand_char_002
```

所有 A3 candidates 已有非空 evidence；若 supplied snapshot 中 evidence paragraph 不存在于 SourceDocument，fail closed。

CandidateEntityIndex.entries 最终按：

```text
source_order_key
```

升序。

## 9. Name normalization v1

policy id：

```text
a4-name-normalization-v1
```

exact algorithm：

```text
Unicode NFKC
→ Unicode casefold
→ strip
→ collapse Unicode whitespace runs to one ASCII space
```

不：

- translate；
- transliterate；
- remove punctuation；
- remove honorifics；
- reorder tokens；
- fuzzy-correct spelling。

Normalization 函数必须 idempotent。

## 10. Identity keys

对于 character/location entry：

```text
identity_keys =
normalized(display_name_original)
+
normalized(each aliases_original)
```

去空、去重、deterministic lexical sort。

descriptors 不属于 identity key。

A3 unresolved 不生成 merge identity keys，因为不进入 merge graph。

---

## 11. Identity tokens for blocking only

token 只用于 **blocking**，不是 merge authority。

从 normalized identity keys deterministic 提取 Unicode alphanumeric runs。

规则：

- split on non-alphanumeric boundaries；
- casefold/NFKC 已先完成；
- drop empty token；
- token 至少 2 Unicode code points；
- pure numeric token 不使用；
- unique lexical sort。

例如：

```text
"John Smith" → ["john", "smith"]
"Mr. Smith"  → ["mr", "smith"]
"林晚"       → ["林晚"]
```

token overlap 只能产生 block signal，不能直接 auto_same。

---

## 12. Strong identity key v1

A4B 的 deterministic auto_same 必须非常保守。

一个 normalized identity key 只有满足以下条件才是 strong：

1. non-empty；
2. 至少包含一个 Unicode alphabetic character；
3. 不是 frozen weak/generic key；
4. 并且满足以下之一：
   - 至少包含 2 个 alphanumeric tokens；或
   - 包含至少 3 个 CJK Unified Ideograph characters。

因此：

```text
"John"       → weak
"Alice"      → weak
"John Smith" → strong
"林晚"       → weak
"林晚晚"     → strong
"the teacher"→ weak/generic
```

这是有意偏保守。

两字中文人名和单 token 英文名会进入 semantic ambiguity，而不是 deterministic auto-merge。

原因：

```text
false merge > extra unresolved/semantic work
```

## 14. Deterministic must-not-merge v1

A4 frozen architecture要求：

```text
hard negative evidence must be deterministic + source-backed
```

对当前 A3 schema，A4B v1 **不自动把** 以下结构升级成 hard negative：

- two refs co-occur in EventCandidate.participant_refs；
- RelationshipCandidate.source_ref / target_ref；
- different descriptors；
- different occupations；
- different appearance；
- source proximity；
- different display names。

原因：这些均不足以 deterministic 证明两个 global candidates 必然是不同实体；尤其 A4 的任务本身就是修正 A3 chunk-local identity fragmentation。

因此 v1：

```text
derive_must_not_merge_constraints(...)
→ empty set
```

除非输入中存在 future versioned explicit hard-distinctness authority。

这不是缺功能，而是 precision-first policy。

A4C 可根据 richer evidence 输出：

```text
different_entity
```

未来若加入 deterministic hard-negative rule，必须 bump：

```text
a4-blocking-v1
或 canonical deterministic policy identity
```

---

## 15. Why A3 event/relationship endpoints are not hard negatives

A3B 确实保证：

- local refs exist；
- ref types legal；
- relationship is not self-reference。

但这只能证明：

```text
A3 payload structurally represented them as distinct local refs
```

不能证明：

```text
global identity must be distinct
```

若 A3 在同 chunk 错误产生两个 local candidates 指向同一人物，A4 正是应该有机会 reconcile 它们。

因此：

```text
local-ref distinctness != global-identity distinctness
```

## 16. Blocking policy v1

policy id：

```text
a4-blocking-v1
```

仅 character↔character、location↔location 产生 pair。

不得 character↔location。

不得 unresolved 进入 pair universe。

A pair 被 block，如果至少满足一个 signal：

### EXACT_IDENTITY_KEY

两个 candidates 有至少一个 normalized identity key exact overlap。

### IDENTITY_TOKEN_OVERLAP

两个 candidates 至少共享一个 blocking token。

### ADJACENT_CHUNK

两个 candidates 的 manifest chunk ordinal distance <= 1。

```text
abs(left.chunk_ordinal - right.chunk_ordinal) <= 1
```

这包括同 chunk 和相邻 chunk。

source proximity 单独只负责 **block generation**，不能 auto_same/different。

## 17. Blocking implementation — no whole-document N²

禁止：

```python
for every candidate:
    for every other candidate:
```

实现使用 inverted/indexed generation：

### exact-key index

```text
(entity_type, normalized_identity_key)
→ ordered candidate refs
```

仅对 bucket 内组合生成 pair。

### token index

```text
(entity_type, token)
→ ordered candidate refs
```

仅对 bucket 内组合生成 pair。

### local chunk window

```text
(entity_type, chunk_ordinal)
```

只连接：

```text
same chunk
adjacent chunk
```

pair 最终放入 set 去重，再 canonical lexical sort。

允许某一个巨大 exact-key bucket 自身产生 O(k²) pairs；禁止的是全 candidate-universe 无差别 O(N²) scan。

必须有测试证明 planner 不依赖全 pair enumeration。

---

## 18. Pair signals

每个 explicit blocked pair 保存 deterministic signal set。

建议 enum/string：

```text
exact_identity_key
identity_token_overlap
adjacent_chunk
hard_must_not_merge
```

signals lexical sort。

不要保存 free-form reason 作为 hash authority。

如需 diagnostics，可从 signals deterministic derive。

---

## 19. Pair state precedence

对每一个 explicit blocked pair：

### 1. must_not_merge

如果 pair 在 hard constraint set：

```text
state = must_not_merge
```

### 2. auto_same

否则，如果：

- same entity type；
- 共享至少一个 exact **strong identity key**；

则：

```text
state = auto_same
```

### 3. needs_semantic_decision

其他 blocked pair：

```text
state = needs_semantic_decision
```

precedence frozen：

```text
must_not_merge
>
auto_same
>
needs_semantic_decision
```

## 27. Required focused tests

### snapshot/lineage

- exact ordered snapshot accepted；
- extraction count mismatch rejected；
- source ref mismatch rejected；
- source chunk mismatch rejected；
- extraction profile mismatch rejected；
- manifest order mismatch rejected。

### candidate index

- char/location/unresolved all indexed；
- fact/event/relationship not indexed；
- unresolved possible refs globalized；
- duplicate global candidate ref rejected；
- source_order_key exact deterministic；
- earliest evidence paragraph controls paragraph ordinal；
- final entries source ordered。

### normalization

- NFKC；
- casefold；
- trim；
- whitespace collapse；
- punctuation retained；
- idempotent。

### strong/weak identity keys

- `John` weak；
- `Alice` weak；
- `John Smith` strong；
- role/title weak；
- 2-CJK key weak；
- 3+-CJK non-generic key strong；
- generic zh key weak。

### blocking

- exact identity key produces block；
- token overlap produces block；
- adjacent chunk produces block；
- distant no-signal pair absent；
- char/location never paired；
- unresolved never paired；
- signals deduplicated/sorted。

### auto same

- shared strong exact key → auto_same；
- shared weak key → needs_semantic_decision；
- token-only overlap → needs_semantic_decision；
- adjacency-only → needs_semantic_decision。

### must-not-merge

- A3 event co-participation alone does NOT become hard negative；
- A3 relationship endpoints alone do NOT become hard negative；
- descriptor disagreement does NOT become hard negative；
- v1 derived hard-constraint set is empty for current A3 shapes；
- injected/synthetic hard constraint in planner test overrides auto_same, proving precedence without adding production inference.

### no N²

测试 monkeypatch/instrumentation 或 code-structure assertion 均可，但必须证明 implementation 使用 bucket/local-window pair generation，而不是全 candidate cartesian scan。

不要写 brittle source-string test unless no better option。

### hash

- same snapshot → same plan_hash；
- input order that violates authority rejected, not normalized away；
- semantic planning material change → hash changes；
- backend/runtime data cannot enter hash。
