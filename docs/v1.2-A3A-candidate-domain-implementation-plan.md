# v1.2 A3A Candidate Domain Contracts + Prompt Assets — Implementation Plan

父级：`#10 — [v1.2] A3 chunk extraction`

## 1. Goal

A3A 只建立后续 A3B–A3E 共同依赖的稳定静态接口：

```text

EvidenceRef
six local candidate models

```

```text
A3B semantic validation
A3C persistence / reuse
A3D LLM orchestration
A3E batch CLI / real-novel smoke
```

## 4. Domain model rules

实现方式继续遵循项目现有风格：

- lightweight frozen dataclasses / enums；
- explicit `to_dict()` / `from_dict()`；
- exact-key/fail-closed parsing；
- deterministic serialization shape；
- 不引入 Pydantic 或新的大型 runtime framework；
- 不引入数据库/ORM。

### 4.1 StoryExtractionProfile

精确字段：

```text
schema_version
profile_id
working_language
prompt_id
prompt_version
output_schema_id
output_schema_version
max_generation_rounds
```

tracked profile：

```yaml
schema_version: 1
profile_id: story-extraction-v1
working_language: zh-CN
prompt_id: a3.chunk-extraction
prompt_version: 1
output_schema_id: a3-candidate-payload
output_schema_version: 1
max_generation_rounds: 2
```

A3A 可以提供 deterministic `profile_hash` helper/property，必须复用现有 canonical `content_hash` authority；不得新造 hash algorithm。

profile 不得包含 runtime endpoint、credential、timeout、model、temperature、reasoning 等 A-I3 semantic/runtime profile 字段。

### 4.2 EvidenceRef

字段：

```text
paragraph_id
role
strength
excerpt
```

枚举：

```text
role: primary | supporting
strength: explicit | implied | uncertain
```

`excerpt` 为 `string | null`。

A3A 只验证**结构和字段类型**。以下属于 A3B，不在本 PR 做：

- paragraph 是否存在；
- paragraph 是否属于 context/ownership；
- excerpt 是否为 source substring；
- 是否至少存在 ownership-primary evidence。

### 4.3 Local candidate namespaces

结构级 regex 固定：

```text
characters           ^cand_char_[0-9]{3,}$
locations            ^cand_loc_[0-9]{3,}$
facts                ^cand_fact_[0-9]{3,}$
events                ^cand_evt_[0-9]{3,}$
relationships        ^cand_rel_[0-9]{3,}$
unresolved_mentions  ^cand_unres_[0-9]{3,}$
```

A3A 可以拒绝错误 namespace / malformed suffix。

以下留给 A3B：

- duplicate IDs；
- continuous numbering / gap；
- cross-reference existence/type；
- canonical sort across payload；
- graph constraints。

- fact_type
- statement_zh

- object_refs

- candidate_id
- summary_zh

- temporal_mode

## 5. CandidatePayload

Provider payload 精确顶层字段：

```text
characters
locations
facts
events
relationships
unresolved_mentions
```

全部为 arrays；允许某个 category 为 `[]`。

Python typed `CandidatePayload` 必须支持：

```text
to_dict()
from_dict()
```

并保持 deterministic category ordering。

A3A 不进行跨 candidate graph closure；A3B 才负责。

## 7. JSON Schema contracts

必须新增：

```text
schemas/story-extraction-profile.schema.json
schemas/candidate-payload.schema.json
schemas/candidate-extraction.schema.json
```

全部使用 JSON Schema Draft 2020-12。

### 7.1 CandidatePayload strict compatibility

`candidate-payload.schema.json` 会直接进入 A-I3 OpenAI-compatible `response_format.json_schema`，当前 adapter 使用 `strict: true`。

因此 provider schema 必须是 strict-compatible：

- every object has `additionalProperties: false`；
- every object property that provider must emit is listed in `required`；
- semantic optionality通过 nullable value (`type: ["string", "null"]`) 或 empty array 表达，不依赖省略 property；
- arrays/items fully typed；
- avoid schema constructs known to require runtime repair or provider-specific behavior unless现有 A-I3 smoke 已证明支持。

不要为了 strict compatibility 修改 A-I3 adapter。

### 7.2 Python/schema parity

同一合法/非法 fixture 应尽量满足：

```text
Python model accepts <=> external schema accepts
```

如果 JSON Schema 不能表达某个 Python object-level invariant，测试中明确记录该 invariant 由 Python authoritative validation 承担。

`candidate-extraction.schema.json` 是 persisted artifact contract，不是 provider response schema，但仍应 `additionalProperties: false`、exact/fail-closed。

## 8. Prompt Registry assets

正式 prompt storage：

```text
prompts/story/a3.chunk-extraction/v1/
  prompt.yaml
  system.txt
  user.txt
```

Prompt identity：

```text
prompt_id: a3.chunk-extraction
version: 1
```

required variables **只允许**：

```text
chunk_id
left_context_json
ownership_json
right_context_json
```

不要加入 runtime/model/provider 字段。

Prompt text 必须明确：

- 只抽取当前 chunk-local candidates；
- source names/mentions 保留 original form；
- semantic summaries/descriptions 使用 zh-CN；
- LEFT/RIGHT 只用于理解；
- primary evidence 必须来自 OWNERSHIP；
- supporting evidence 可以来自 context；
- 不得引用输入之外 paragraph IDs；
- unresolved 是合法结果，不要强猜；
- 不做 cross-chunk reconciliation/global story interpretation/adaptation/screenplay/production；
- 输出只包含 schema 定义的 JSON object，不要 Markdown/解释文本。

`prompt.yaml.content_hash` 必须用现有 A-I3 canonical prompt hash helper 正确 pin；不要手算另一套 hash。

A3A 只验证 PromptRegistry 能 load/render。真正 LEFT/OWNERSHIP/RIGHT deterministic construction 属于 #14 / A3D。

## 9. Canonical-order boundary

A3A 不抢 A3B 的 semantic canonicalization authority。

A3A 只保证自身 serializer deterministic；**不要因为输入数组顺序不同就自动重排 semantic collections**，除非父 contract明确属于 object-level set（例如 unique alias strings可以 deterministic normalize）。

以下正式留给 A3B：

```text
category candidate numeric ordering
cross-reference-aware payload canonicalization
ID gap/duplicate detection
semantic collection canonical order
```

避免 A3A 和 A3B 出现两套 canonicalization。
