# B2.4 — Episode Screenplay Assembly

状态：**FROZEN**

## 1. 职责

B2.4 将已经确定的 `SceneRealization` exact revisions 组合成一版完整、可重建、可验证的 `EpisodeScreenplay`。

B2.4 的核心是 composition / pinning / provenance / structural consistency，不再进行 screenplay 创作。

## 2. EpisodeScreenplay

正式引入：

```text
EpisodeScreenplay
```

它是 versioned canonical structured composition，不是单纯 Markdown / TXT / PDF。

至少包含：

- episode_screenplay_id
- revision
- content_hash
- upstream pins
- ordered scene realization manifest
- materialized screenplay structure
- continuity composition
- episode-level anchors
- duration summary
- provenance

## 3. Exact revision manifest

B2.4 必须明确 pin：

```text
AdaptationPlan id/revision/hash/approval
EpisodeScenePlan id/revision/hash
每个 SceneRealization id/revision/hash
```

禁止 implicit latest / max(revision)。

正式存在 `SceneAssemblyEntry`，至少表达：

```text
scene_id
scene_order
scene_realization_id
scene_realization_revision
scene_realization_hash
```

一个 EpisodeScreenplay revision 中，每个 required ScreenplayScene 必须 exactly one SceneRealization revision。

## 4. Scene order / structure authority

Scene order 完全继承 EpisodeScenePlan。

B2.4 不得：

- 删除 Scene
- 增加 Scene
- 合并 Scene
- 拆分 Scene
- 重排 Scene

若需要 structural change，回 B2.2。

若需要 semantic screenplay change，回 B2.3。

## 5. Canonical structure 与 rendered view 分离

正式区分：

```text
EpisodeScreenplay
= canonical structured composition

RenderedScreenplay
= derived presentation/export
```

RenderedScreenplay 可以是 Markdown、screenplay text、PDF、未来 FDX 等；丢失后应能 deterministic rebuild。

Canonical screenplay 必须保留：

```text
Episode
→ Scenes
→ ordered ScreenplayElements
```

而不是只保存一整块文本。

## 6. Allowed normalization

B2.4 只允许 non-semantic rendering normalization，例如：

- heading formatting
- speaker display-name rendering
- spacing / paragraph layout
- scene display numbering
- punctuation / typography policy

不得为了排版顺手改对白、删 action、补 transition 或改变 semantic content。

Cross-scene connective content 必须来自 B2.3；如需新 Scene 则回 B2.2。

## 7. Episode anchors

B2.4 显式保存：

```text
EpisodeClimaxAnchor
EpisodeHookAnchor
```

二者继续保持独立。

Anchor 指向 scene_id，必要时进一步指向 ScreenplayElement / element range。

B2.4 只能追踪 B1/B2 已定义 climax/hook 的 realization，不能重新定义。

## 8. Continuity composition

按 Scene order deterministic compose：

```text
opening ScreenplayContinuityState
+
SC001 delta
+
SC002 delta
+ ...
=
episode ending ScreenplayContinuityState
```

该机制应由 Python 主导。

正式产生：

```text
EpisodeScreenplayEndingCheckpoint
```

它保存 screenplay-level continuity overlay，供下一集 B2.1 hierarchical context 使用。

Screenplay overlay 不得覆盖 Adapted Continuity truth。

## 9. Duration aggregation

B2.4 聚合 SceneRealization duration estimates，得到 episode-level screenplay duration estimate，并与 EpisodePlan target 对比。

```text
screenplay duration estimate ≠ edit duration ≠ H3/video duration
```

若超出预算，B2.4 不得自动删改内容，只能 route 回 B2.3 或 B2.2。

## 10. Provenance

EpisodeScreenplay 必须能追踪：

```text
EpisodeScreenplay
→ SceneRealization
→ ScreenplayScene
→ BeatSceneMapping / PresentationSceneMapping
→ AdaptedBeat / PresentationEntry
→ AdaptationMapping
→ Canonical Event
→ Source
```

## 11. Revision / immutability

EpisodeScreenplay 拥有独立 revision/hash。

任意 constituent semantic revision、composition、continuity overlay 或 climax/hook anchor 变化，都产生新的 EpisodeScreenplay revision。

Render-only formatting change 不产生新的 semantic revision。

已创建 EpisodeScreenplay revision immutable。

新 SceneRealization revision 不得自动修改已有 EpisodeScreenplay；需要新 assembly revision。

## 12. Structural validation

B2.4 fail closed 检查至少包括：

- upstream pins valid
- exact scene set matches ScenePlan
- scene order valid
- no duplicate realization
- realization hashes match
- referenced IDs resolvable
- callback IDs resolvable
- continuity delta chain resolvable
- climax/hook anchors resolvable
- duration data sufficient

B2.4 不取代 B2.5 integrated semantic validation。

验证职责：

```text
B2.3 = scene-local
B2.4 = composition / structural
B2.5 = episode-integrated semantic
```

## 13. 执行主体

正常 B2.4 assembly 应由 Python deterministic 执行，不依赖 Qwen creative generation。

B2.4 不增加 human approval gate；正式 screenplay approval 留给 B2.6。

## 14. 冻结 contract

1. EpisodeScreenplay 是 canonical versioned structured composition。
2. RenderedScreenplay 是 deterministic derived artifact。
3. 必须 pin exact upstream / SceneRealization revisions；禁止 implicit latest。
4. 每个 required Scene exactly one realization revision。
5. Scene order 完全继承 EpisodeScenePlan。
6. B2.4 不得改变 Scene architecture 或 screenplay semantics。
7. 正式保存 EpisodeClimaxAnchor / EpisodeHookAnchor。
8. deterministic compose ScreenplayContinuityDelta，并产生 EpisodeScreenplayEndingCheckpoint。
9. 聚合 duration estimate，但不自动压缩内容。
10. EpisodeScreenplay 拥有 independent revision/hash 且 immutable。
11. Render-only change 不创建 semantic revision。
12. B2.4 structural validation fail closed。
13. B2.4 不处理 localization / voice / subtitle timing / ProductionLocation / Shot / H3 / ComfyUI。
