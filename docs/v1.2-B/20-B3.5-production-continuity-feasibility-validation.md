# B3.5 — Production Continuity / Feasibility Validation

状态：**FROZEN**

## 1. 职责

B3.5 是 read-only integrated production auditor。

```text
verify / diagnose / route
```

不得 repair、rewrite、re-stage、re-split、增加 requirement、放宽 constraint 或修改 screenplay。

## 2. Exact production candidate bundle

验证对象必须 pin exact：

- APPROVED EpisodeScreenplay
- EpisodeProductionBreakdown revision/hash
- EpisodeProductionRequirements revision/hash
- EpisodeStagingPerformancePlan revision/hash
- ProductionConstraintProfile revision/hash（如有）

正式引入：

```text
validated_bundle_hash
```

任意 constituent semantic revision/hash 改变，旧 validation report 立即不适用。

## 3. ProductionValidationReport

正式输出 immutable：

```text
ProductionValidationReport
```

包含 target pins、validated_bundle_hash、overall result、findings、screenplay fidelity、requirement/continuity/perceptual coverage、constraint、duration/complexity summaries。

Overall result：

```text
FAIL
PASS_WITH_REVIEW_ITEMS
PASS
```

Finding severity：

```text
BLOCKING
REVIEW_REQUIRED
WARNING
```

每个 finding 必须记录 earliest authoritative owner 与 stable-ID evidence。

## 4. Validation domains

B3.5 integrated 检查：

1. reference / revision integrity
2. screenplay fidelity
3. ProductionUnit decomposition integrity
4. requirement completeness
5. requirement compatibility
6. staging realization integrity
7. performance realization integrity
8. perceptual coverage completeness
9. production continuity
10. cross-unit physical / causal continuity
11. ProductionConstraintProfile compliance
12. duration / complexity feasibility
13. unauthorized screenplay/narrative invention
14. architecture-boundary leakage

## 5. Screenplay fidelity

Production design 必须保持 ordered ACTION / DIALOGUE / REACTION / semantically important PAUSE、Scene turn/outcome、DialogueIntent 等。

Production 不得重新分配 speaker、吞掉 required action、提前 reveal、破坏 withholding 或改变 character knowledge。

## 6. Breakdown / requirement integrity

每个 required ScreenplayElement 必须 exactly one primary ProductionUnit owner；无 orphan/duplicate primary ownership。

所有 required participants/settings/props/wardrobe/appearance/environment/effects 必须存在 requirement。

B3.4 不得消费未登记 Requirement。

`EXACT_IDENTITY` 不得由 generic semantic class 替代；narrative-critical requirement 不得错误标为 PREFERRED 以逃避 blocking validation。

## 7. Staging / performance / perceptual validation

Required screenplay action 必须有真实 staging realization；staging 不得制造 unauthorized causal event。

Performance 必须保留 DialogueIntent / subtext / reaction / pause，并不得泄漏角色不应知道的信息。

所有 REQUIRED `PerceptualCoverageRequirement` 必须存在、有 provenance 且可被 current execution semantics 支撑。

B3.5 只验证 perceptual obligation completeness / realizability，不验证具体 Shot coverage。

## 8. Production Continuity

逐 unit reconciliation：

```text
ProductionContinuityContract
vs
planned staging + ProductionContinuityDelta
```

并检查 PU_N ending → PU_N+1 opening 的 important character presence/position、prop state、door/window、wardrobe、appearance、environment、performance carryover。

只检查 meaningful continuity，不要求建模 mundane transitions。

Production overlay 不得覆盖 Adapted / Screenplay truth。

## 9. Constraints / feasibility

Hard constraint violation 默认 BLOCKING；soft/preferred violation 可 WARNING / REVIEW_REQUIRED。

Validator 不得 silent relax constraint；修改 constraint 必须产生新的 profile revision。

B3.5 feasibility 仅指 generic production-semantic feasibility + abstract constraint feasibility，例如明显物理矛盾、action density、duration/complexity overload。

它不检查 concrete asset availability、H3 capability、ComfyUI、GPU、WAV 是否存在。

`Requirement existence ≠ asset availability`。

## 10. Unauthorized invention / leakage

B3.5 主动检测 production design 引入的新 narrative-significant action、possession、knowledge、relationship、causal dependency、reveal、future setup 等。

无 narrative consequence 的 production realization invention合法。

Finding 应区分 `PRODUCTION_REALIZATION_ERROR`、`SCREENPLAY_CHANGE_REQUIRED`、`ADAPTATION_CHANGE_REQUIRED` 等 route。

B3.5 可检测 camera/lens/shot/H3/ComfyUI/concrete asset filename 等 architecture leakage，但不评价 cinematography 美学质量。

## 11. Python / Qwen

Python：revision/hash/reference、ownership、requirement coverage、continuity mechanics、constraint structural checks、duration aggregation、provenance。

Qwen：screenplay fidelity semantics、staging/performance/perceptual reasoning、invention boundary、physical/causal plausibility、soft constraint interpretation。

Qwen 只有 diagnostic authority，没有 repair authority。

## 12. B3.5 → B3.6

`PASS` / `PASS_WITH_REVIEW_ITEMS` 可进入 B3.6；`FAIL` 不得生成 approval-eligible EpisodeProductionPlan。

B3.6 必须 exact materialize 被验证 bundle，并保存 `source_validated_bundle_hash`；B3.6 不得改变 production semantics。

## 13. 冻结 contract

1. B3.5 是 read-only integrated production auditor。
2. 只 verify/diagnose/route，不 auto-fix。
3. 正式存在 immutable `ProductionValidationReport`。
4. 验证 exact candidate bundle，使用 `validated_bundle_hash`。
5. constituent semantic change 使旧 report 失效。
6. result = FAIL/PASS_WITH_REVIEW_ITEMS/PASS；severity = BLOCKING/REVIEW_REQUIRED/WARNING。
7. findings 指向 earliest authoritative owner 并引用 stable IDs。
8. 验证 screenplay fidelity、breakdown、requirements、staging/performance/perceptual obligations、continuity、constraints、feasibility。
9. Production Continuity 不得覆盖上游 truth。
10. Hard constraint 默认 blocking；soft constraint 可人工 review。
11. 不检查 concrete asset/backend/GPU availability。
12. 不使用 backend clip length 作为 unit validity rule。
13. 主动检测 unauthorized screenplay/narrative invention。
14. 可检测 downstream architecture leakage，但不承担 cinematography quality review。
15. Python 主 deterministic checks；Qwen 辅助 semantic checks，无 repair authority。
16. FAIL 不可进入 approval-eligible B3.6；PASS / PASS_WITH_REVIEW_ITEMS 可以。
17. B3.6 必须 exact materialize validated bundle。
18. B3.5 不 formal approve，最终 gate 留给 B3.7。
