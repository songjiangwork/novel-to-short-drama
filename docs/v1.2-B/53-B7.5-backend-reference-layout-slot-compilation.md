# B7.5 — Backend Reference Layout + Slot Compilation

状态：**FROZEN**

## 1. 职责

B7.5 将 B7.4 的 backend-agnostic asset projection 编译成 exact ExecutionProfile 下的 backend reference channels、logical slots、ordering 与 rendered reference tokens（例如 `Picture N`）。

核心：

```text
B7.4 = WHICH approved source assets this ProductionShot needs
B7.5 = HOW this backend references those assets
B7.6 = HOW prompt/workflow/request consume the layout
```

## 2. 正式输入 / 输出

输入：

```text
ExecutionCompilationContext
EpisodeProductionShotSegmentationPlan
EpisodeProductionShotTimingProjectionPlan
EpisodeProductionShotAssetProjectionPlan
exact ExecutionProfile
```

输出：

```text
EpisodeBackendReferenceLayoutPlan
```

每个 ProductionShot 对应：

```text
ProductionShotBackendReferenceLayout
  production_shot_identity
  source_asset_projection_hash
  execution_profile_ref
  backend_reference_bindings[]
  channel_layouts[]
  capacity_validation
  ordering_policy_ref
  content_hash
```

## 3. BackendReferenceRole

B7.5 正式引入 backend-specific `BackendReferenceRole`。

必须保持：

```text
ExecutionAssetRole
= why the ProductionShot needs the asset

BackendReferenceRole
= how this backend can consume that need
```

Mapping必须来自 exact `ExecutionProfile.reference_layout_policy`，不得 hidden hard-code 在 prompt builder/workflow builder 中。

## 4. BackendReferenceChannel

正式建模显式 channel，例如：

```text
VISUAL_REFERENCE_CHANNEL
VOICE_REFERENCE_CHANNEL
PREEXISTING_AUDIO_CHANNEL
```

未来 profile还可声明 init image / mask / control 等 channels。

因此：

```text
projected asset count
≠ Picture count
```

Voice/audio资产通常不占 visual `Picture N` ordinal。

## 5. Picture N 定义

`Picture N` 只属于某个 ProductionShot 的 ordered visual reference channel，是 rendered ordinal token。

严格保持：

```text
Picture N
≠ AssetRecord identity
≠ cross-shot stable identity
```

Picture numbering是 ProductionShot-local，不做 episode-global numbering。

## 6. Picture N 唯一 authority

冻结：

```text
B7.5 BackendReferenceLayout
= sole authority for Picture N numbering
```

以下组件不得自行编号/排序：

```text
prompt renderer
workflow compiler
refs staging
request builder
ComfyUI adapter
```

它们全部消费同一个 authoritative layout。

## 7. BackendReferenceBinding

概念：

```text
BackendReferenceBinding
  reference_binding_id
  asset_ref
  execution_asset_roles[]
  backend_reference_role
  channel_id
  slot_key
  ordinal
  rendered_reference_token
  source_requirement_refs[]
  source_asset_projection_ref
```

`ordinal` 与 rendered token均为 layout-derived property，不是 asset identity。

## 8. Rendered token / logical slot 分离

同一 binding可有不同 representation：

```text
ordinal = 1
rendered token = <Picture 1>
logical backend slot = visual_references[0]
```

显式解决：

```text
1-based prompt numbering
≠ 0-based API array indexing
```

不得靠 developer memory 隐式处理。

## 9. Logical backend slot / ComfyUI node 分离

B7.5 只分配 logical backend slots，例如：

```text
visual_references[0]
voice_reference
utterance_audio
```

具体：

```text
logical slot → ComfyUI node_id/input_name
```

由 B7.6 exact workflow template parameter contract完成。

因此：

```text
BackendSlot
≠ ComfyUI node/input
```

## 10. Duplicate reference policy

同一 AssetRecord承担多个 ExecutionAssetRoles时，默认一个 channel只绑定一次。

原则：

```text
multiple semantic roles
≠ multiple copies of the same reference
```

同 asset重复占多个 slots默认禁止；只有 ExecutionProfile明确要求同一个 source asset在不同 backend roles/channels重复提供时才允许，且必须 deterministic/auditable。

## 11. Ordering authority

Reference ordering必须由 versioned `ReferenceOrderingPolicy` 决定。

以下永远不是 authority：

```text
filesystem order
filename order
glob order
dict insertion order
AssetCatalog order
staging filename order
```

General priority框架：

```text
1 backend hard role/layout constraints
2 primary semantic subject precedence
3 continuity-critical refs
4 execution role precedence
5 authoritative source semantic order（如有）
6 stable asset identity tie-break
```

具体 H3 role precedence属于 H3 ExecutionProfile，不冻结成 universal semantic rule。

## 12. Primary subject / ordering boundary

B7.5可以在 B7.4 已投影 assets中根据 profile调整顺序；不能因 asset排在后面就 drop它。

```text
ordering authority
≠ asset-selection authority
```

## 13. Determinism

相同：

```text
B7.4 asset projection hash
ExecutionProfile hash
ReferenceLayoutPolicy version/hash
```

必须得到相同：

```text
channels
ordinals
Picture N
logical slots
layout hash
```

Ordering改变属于 execution specification改变：same ProductionShotIdentity、new compiled revision，而不是 retry。

## 14. Prompt / workflow atomic consistency

强 invariant：

```text
For every rendered Picture N token,
exactly one authoritative visual binding
occupies ordinal N.
```

Prompt symbolic ref、workflow logical slot、staging bytes必须最终都解析到同一个 `reference_binding_id`。

不允许：

```text
prompt: Picture 3 = classroom
workflow visual_references[2] = Linsey
```

即使“所有图片都传进去了”也属于 hard mismatch。

## 15. Prompt不一定显式提所有 refs

Backend可允许某些 reference只通过 input channel辅助、prompt不 literal mention。

正确规则：

```text
if prompt mentions Picture N,
it must resolve through B7.5 authoritative layout
```

但所有 backend slots仍必须来自同一 layout。

## 16. Workflow template authority boundary

Workflow topology可以约束可用 slots/capacity，但：

```text
Workflow topology does not decide semantic reference ordering.
```

若 workflow存在固定 physical slots，ExecutionProfile必须 pin logical-slot → template-slot mapping。

Template不得自己 sort/dedupe/prepend refs。

## 17. Template production leakage

Known-good GUI export可作为 workflow template来源，但 production template必须参数化 concrete refs。

Template如果残留 hard-coded production ref，例如 `Linsey.png` / old classroom，而 B7.5 layout指向另一资产，应在 B7.6/B7.7视为 `WORKFLOW_TEMPLATE_REFERENCE_LEAKAGE`。

Template也不得 hard-code `<Picture 1> is Linsey` 之类 shot-specific prompt semantics。

## 18. Capacity model

Reference capacity必须由 ExecutionProfile显式声明，可包括：

```text
per-channel max/min
global shared budget
role-specific constraints
mutual exclusion
required slots
```

不能通过运行时“数 workflow大概有几个槽”作为正式 contract。

B7.5 对 capacity做 deterministic hard validation。

## 19. Hard / recommended constraints

Profile可以区分：

```text
hard constraint
recommended constraint
```

Hard violation → FAIL。

Recommended超出但仍在 hard capacity内 → diagnostic；不得为了 recommended值 silent drop required asset。

## 20. Capacity failure / repartition

若：

```text
required refs = 6
backend visual max = 4
```

B7.5不得 drop refs。

如果 B4-authorized alternate partition能让每段需求变成 3+3：

```text
REFERENCE_CAPACITY_EXCEEDED
→ CompilationConstraintFeedback
→ B7.2 legal repartition
→ re-run B7.3–B7.5
```

B7.5不得自行创建 seam。

Compiler必须跟踪 evaluated partition hashes；legal partition space耗尽后返回：

```text
NO_REFERENCE_FEASIBLE_LEGAL_PARTITION
```

## 21. Voice / preexisting audio channels

必须保持：

```text
VOICE_REFERENCE
≠ PREEXISTING_UTTERANCE_AUDIO
```

ExecutionProfile应提供不同 role/channel mapping；backend不支持某 required role时返回 `UNSUPPORTED_BACKEND_REFERENCE_ROLE`，不能 semantic downgrade。

## 22. Staging boundary

B7.5只做：

```text
exact asset identity → logical backend binding
```

实际复制到 ComfyUI input等 staging属于 runtime/B7.6 adapter。

Staging path/filename不是 identity，也不能决定 Picture N。

Authority方向：

```text
B7.5 ordinal
→ optional derived staging filename
```

禁止：

```text
staging filename lexical order
→ Picture N
```

Staging后 bytes必须继续匹配 B6 content hash。

## 23. Cross-segment ordinal stability

同一 PlannedShot被切成多个 ProductionShots且 projected asset set相近时，profile可优先保持：

```text
same asset → same ordinal
```

减少 reference jitter。

这是 layout preference，不是 semantic hard requirement；backend hard layout/order constraints优先。

## 24. Binding identity

`reference_binding_id` 应基于 stable logical dimensions，例如：

```text
production_shot_identity
asset id/revision/hash
backend reference channel
必要的 distinct role discriminator
```

不应包含：

```text
Picture ordinal
filesystem path
ComfyUI node id
```

这样可审计同一 binding从 Picture 2移动到 Picture 3，而不误认为换 asset。

## 25. B7.5 不生成 prompt

B7.5只输出 authoritative symbol/reference table。

例如：

```text
RB_LINSEY → Picture 1
RB_CLASSROOM → Picture 2
```

`Use <Picture 1> ...` 等 prompt prose属于 B7.6。

## 26. Failure categories

典型：

```text
UNSUPPORTED_BACKEND_REFERENCE_ROLE
INVALID_ROLE_TO_CHANNEL_MAPPING
REFERENCE_CHANNEL_CAPACITY_EXCEEDED
GLOBAL_REFERENCE_CAPACITY_EXCEEDED
REQUIRED_SLOT_UNAVAILABLE
REFERENCE_ORDERING_UNRESOLVED
DUPLICATE_REFERENCE_NOT_ALLOWED
REFERENCE_BINDING_COLLISION
PICTURE_TOKEN_COLLISION
LOGICAL_SLOT_COLLISION
REFERENCE_LAYOUT_POLICY_MISMATCH
NO_REFERENCE_FEASIBLE_LEGAL_PARTITION
```

## 27. Python / Qwen

Role mapping、channel mapping、ordering、slot allocation、capacity validation均应 deterministic。

Normal B7.5不需要 Qwen。若每个 Shot还要问 Qwen“Picture 1还是 Picture 3更好”，说明缺少 versioned profile policy。

## 28. 冻结原则

1. B7.5是 backend reference layout/order/slot 的唯一 authority。
2. 只消费 B7.4 projected assets，不添加/替换/drop required source assets。
3. ExecutionAssetRole与BackendReferenceRole严格分离。
4. Mapping由 exact ExecutionProfile定义。
5. Backend refs使用 explicit channels。
6. Picture N只属于 visual ordered channel且 ProductionShot-local。
7. Prompt/workflow/staging/request全部消费一个 B7.5 layout。
8. 下游组件不得独立 reorder。
9. Logical backend slot与ComfyUI node/input分离。
10. Same asset多 role默认只 bind一次/channel。
11. Ordering deterministic/versioned；filename/filesystem order永远不是 authority。
12. Workflow template只提供 receptacles/capacity，不拥有 semantic ordering。
13. Capacity violation不得 silent drop asset。
14. Legal repartition只能反馈回 B7.2，不能在 B7.5 invent seam。
15. Voice ref / utterance audio保持不同 backend roles。
16. Staging path不参与 semantic/reference identity。
17. Picture mapping/order变化需要 recompile/new revision，不是 retry。
18. B7.5不 render prompt prose或 materialize ComfyUI workflow。
19. Normal B7.5 deterministic，不依赖 Qwen。
