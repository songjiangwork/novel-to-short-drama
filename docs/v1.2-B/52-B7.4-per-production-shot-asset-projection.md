# B7.4 — Per-ProductionShot Asset Projection

状态：**FROZEN**

## 1. 职责

B7.4 将 B6 已批准的 episode-level effective bindings 投影为每个 ProductionShot 的 minimum sufficient approved source-asset subset。

核心分层：

```text
B6 = decide WHICH concrete assets are authorized
B7.4 = decide WHICH authorized assets this ProductionShot actually needs
B7.5 = decide HOW this backend consumes them
```

因此：

```text
asset projection
≠ asset selection
≠ backend slot assignment
```

## 2. 正式输入 / 输出

输入：

```text
ExecutionCompilationContext
EpisodeProductionShotSegmentationPlan
EpisodeProductionShotTimingProjectionPlan
exact APPROVED EpisodeResolvedAssetPlan
```

输出：

```text
EpisodeProductionShotAssetProjectionPlan
```

每个 ProductionShot 对应：

```text
ProductionShotAssetProjection
  production_shot_identity
  source_episode_resolved_asset_plan_ref
  source_effective_binding_refs[]
  active_asset_requirement_refs[]
  authorized_asset_universe_ref
  projected_asset_refs[]
  execution_asset_role_bindings[]
  continuity_constraints[]
  projection_decisions[]
  content_hash
```

## 3. Legal asset universe

任何 ProductionShot：

```text
LegalAssetUniverse(ProductionShot)
⊆ exact APPROVED EpisodeResolvedAssetPlan
```

严格禁止：

```text
AssetCatalog search
folder scan replacement
"similar file" substitution
new media inspection to choose a better asset
```

Approved asset缺失或错误必须回 B6。

## 4. B6.6 inheritance authority

B6.6 已经 deterministic 展开 broad binding + specific refinements，生成 `EffectiveAssetBindingIndex`。

因此 B7.4 不重新决定：

```text
episode scope
scene scope
shot scope
override precedence
```

B7.4消费 effective bindings并根据当前 ProductionShot active upstream consumers做 projection。

核心：

```text
B6.6 = binding inheritance authority
B7.4 = execution/temporal projection authority
```

## 5. ProductionShotAuthorizedAssetUniverse

B7.4可先派生 shot-local authorized universe：

```text
ProductionShotAuthorizedAssetUniverse
  production_shot_identity
  source_effective_binding_refs[]
  active_requirement_refs[]
  authorized_asset_refs[]
  authorized_resolved_asset_set_refs[]
  continuity_group_refs[]
  source_episode_resolved_asset_plan_hash
```

它表示“最多可以合法使用哪些 approved assets”，不表示全部都必须进入 backend。

## 6. Authorized ≠ required

例如 B6批准 Linsey：

```text
face_100
full_body
```

某个 close-up ProductionShot在 B6 structured coverage允许的前提下可以只投影 `face_100`。

因此：

```text
approved asset set
≠ backend input list
```

但 B7不能重新看图判断“我觉得 face够了”；必须依赖 B6已有 requirement/capability/binding facts。

## 7. Requirement activation

B7.4 首先确定：

```text
Which existing B6 AssetRequirements are active
inside this ProductionShot?
```

然后从 already-resolved bindings中确定 minimum sufficient subset。

Formal chain：

```text
B6 AssetRequirement
↓
ProductionShot requirement activation
↓
B6 ResolvedAssetBinding
↓
minimum sufficient approved subset
```

`RequirementActivation ≠ RequirementCreation`。

B7不得根据 close-up、backend习惯等创建新的 asset requirement。若 execution semantics真实需要 B6未抽取 requirement，route B6.2。

## 8. Active scope / conservative retention

Character semantic presence不等于 visual requirement一定 active。

例如 Linsey offscreen speaking：

```text
Linsey visual requirement = inactive（若上游语义证明）
Linsey voice identity requirement = active
```

如果 B6 requirement scope不够细，无法证明某 asset在某 segment已不需要：

```text
absence of fine-grained scope
≠ permission to drop
```

默认保守 retain；backend capacity问题由 B7.5 暴露，而不是 B7.4猜测删除。

## 9. Minimum sufficient 定义

目标不是无条件最少 asset count，而是：

```text
minimum sufficient approved asset subset
subject to:
- all active hard requirements
- B6 combination policy
- continuity constraints
- exact approved compatibility/binding relationships
```

优先级：

```text
1 required/active conditional coverage
2 complementary-required sets
3 exact concrete-asset continuity where applicable
4 canonical continuity group
5 minimize redundant asset count
6 B6-proven preferred capability
7 stable deterministic tie-break
```

## 10. Combination policy

### SINGLE_SUFFICIENT

若 B6 final binding已证明一个 selected asset足以满足 active requirement，B7不得为“多点参考”加入其他 decorative assets。

### COMPLEMENTARY_REQUIRED

Requirement active时必须完整携带整个 selected complementary set。B7不能因 close-up 等局部判断删除 member。

### COMPLEMENTARY_ALLOWED

只有 B6 structured coverage已证明一个 subset仍完整覆盖当前 active requirements 时，B7才能减少 member。

### ALTERNATIVE_ONE_OF

必须已由 B6.4/B6.6 在 final approved plan中解决。B7不做 runtime choice。

## 11. Many-to-many coverage

一个 AssetRecord可同时满足多个 requirements，例如：

```text
CHARACTER_VISUAL_IDENTITY
CHARACTER_APPEARANCE_STATE
COSTUME_STATE
```

B7不得因此复制同一个 asset多次；一个 asset可以挂多个 execution roles / source requirement refs。

## 12. ExecutionAssetRole

B7.4 正式引入 backend-agnostic `ExecutionAssetRole`，例如：

```text
CHARACTER_IDENTITY_REFERENCE
CHARACTER_APPEARANCE_REFERENCE
LOCATION_IDENTITY_REFERENCE
PROP_IDENTITY_REFERENCE
VISUAL_TEXT_REFERENCE
VOICE_IDENTITY_REFERENCE
PREEXISTING_UTTERANCE_AUDIO
OTHER_VISUAL_REFERENCE
OTHER_AUDIO_REFERENCE
```

必须保持：

```text
AssetKind
≠ ExecutionAssetRole
≠ BackendReferenceRole
≠ Picture N
```

`AssetKind` 表示 asset是什么；`ExecutionAssetRole` 表示这个 ProductionShot为什么需要它。

## 13. ExecutionAssetRoleBinding

概念：

```text
ExecutionAssetRoleBinding
  asset_ref
  execution_asset_roles[]
  source_requirement_refs[]
  source_resolved_binding_refs[]
  subject_refs[]
  continuity_group_refs[]
  inclusion_reason
```

`inclusion_reason` 可包括：

```text
REQUIRED_REQUIREMENT_COVERAGE
ACTIVE_CONDITIONAL_REQUIREMENT
COMPLEMENTARY_REQUIRED_MEMBER
CONTINUITY_PRESERVATION
PREFERRED_CAPABILITY_WITHIN_APPROVED_BINDING
TIMING_EVENT_DEPENDENCY
```

## 14. Character / location / prop continuity

B6 `AssetContinuityGroup` 继续 authoritative：

```text
same canonical state
≠ exact same file
```

跨不同 PlannedShots可以合法使用同 continuity group内不同 face/full-body assets，只要 B6已授权相应 shot-local binding。

但同一个 PlannedShot被切成多个 ProductionShots时，若 requirement不变，默认应保持 stable concrete asset selection，避免无理由 reference jitter。

只有明确 capability/semantic需求改变且 B6已批准对应资产时，split segments才可以换 concrete asset。

## 15. Voice continuity

Same speaker + locale通常应复用同一 approved voice identity binding，除非 B6有明确 override。

继续严格区分：

```text
VOICE_REFERENCE
≠ PREEXISTING_UTTERANCE_AUDIO
```

`VOICE_REFERENCE` 表示 speaker identity/performance reference，不是该句最终 waveform。

## 16. Preexisting utterance audio

若 B6 asset kind是 `PREEXISTING_UTTERANCE_AUDIO` 并 exact绑定到 utterance U17，B7.4可在 U17 active ProductionShots中引用同一 AssetRecord。

跨 segments时仍然是同一个 source asset；seek/crop/continuous playback属于后续 execution realization。

## 17. Runtime-derived artifacts firewall

以下不是 B6 source assets：

```text
generated utterance audio
previous-segment last frame
previous frame window
runtime-derived mask
continuation latent/frame artifact
```

这些属于 B7.6 `RuntimeDerivedInputRequirement` / downstream execution provenance。

B7.4只投影 approved source assets。

## 18. Optional / decorative assets

没有 active approved semantic requirement的 OPTIONAL/decorative asset默认不包含。

不得用“多给 H3 几张也许更好”作为正式 inclusion reason。

Preferred capability只有在 B6 binding provenance已证明它是 requirement solution的一部分时才可保留。

## 19. Safe drop 条件

仅当全部满足，B7才可 drop一个已授权 asset：

```text
no active requirement depends on it exclusively
removal不破坏 COMPLEMENTARY_REQUIRED
removal不破坏 continuity
remaining coverage已由 B6证明
no explicit effective binding scope requires it
no active B7.3 timing/audio dependency requires it
removal不需要新的 compatibility judgment
```

不确定时保守 retain，而不是猜测最小化。

## 20. Later backend capacity feedback

若 B7.4合法 projection得到 6 required assets，而 profile最多 4 refs，B7.5必须报告 capacity failure；不能擅自删 2 张。

如果另一个 B4-authorized segmentation能使每段所需 refs下降：

```text
B7.5
→ CompilationConstraintFeedback
→ B7.2 repartition
→ B7.3/B7.4/B7.5 recompile
```

若不存在 legal partition则 profile incompatible或回真正 upstream owner。

## 21. Asset identity / locator

正式引用：

```text
asset_id
asset_revision
content_hash
```

Path/URI只是 locator，不进入 semantic role identity。

同 bytes迁移 path不构成新 asset identity；content hash mismatch必须失败。

## 22. Projection trace

B7.4可保留轻量 `projection_decisions`，例如：

```text
INCLUDED_REQUIRED
INCLUDED_CONTINUITY
OMITTED_REQUIREMENT_INACTIVE
OMITTED_REDUNDANT_FOR_THIS_SEGMENT
```

用于解释为何 B6批准 5 个 assets而某 ProductionShot只携带 2 个，但不复制整个 candidate/catalog history。

## 23. Identity / revision boundary

Asset subset不是 ProductionShot logical identity dimension。

因此：

```text
same ProductionShotIdentity
+ different valid asset projection
→ new compiled ProductionShot revision
```

QC期间换 asset/subset不是 retry，而是 recompile。

Reference ordering不属于 B7.4，由 B7.5拥有。

## 24. Python / Qwen

Normal B7.4只基于 approved structured B6 facts进行 deterministic projection，不重新 inspect media。

Qwen只可解释 scope/diagnostic问题；如果还需要 Qwen判断“这张脸够不够像”，说明职责应该回 B6.3/B6.4。

## 25. Failure categories

典型：

```text
ASSET_PLAN_LINEAGE_MISMATCH
EFFECTIVE_BINDING_NOT_FOUND
ACTIVE_REQUIREMENT_UNRESOLVED
AUTHORIZED_ASSET_MISSING
AUTHORIZED_ASSET_HASH_MISMATCH
REQUIRED_COMBINATION_INCOMPLETE
CONTINUITY_CONSTRAINT_VIOLATION
REQUIREMENT_SCOPE_AMBIGUOUS
UNPROVEN_ASSET_DROP
VOICE_BINDING_MISSING
PREEXISTING_AUDIO_BINDING_MISMATCH
ASSET_PROJECTION_NOT_MINIMALLY_SUFFICIENT
```

## 26. 冻结原则

1. B7.4只使用 exact APPROVED EpisodeResolvedAssetPlan assets。
2. 不绕回 AssetCatalog，不做 replacement/enrichment。
3. 消费 B6.6 EffectiveAssetBindingIndex，不重跑 inheritance。
4. 从已有 requirement activation + resolved bindings导出 shot-local subset。
5. 不创建新的 AssetRequirement。
6. Scope不够细时不允许 speculative drop。
7. Target是 minimum sufficient approved subset，而不是无条件最少 asset count。
8. B6 combination policy持续 authoritative。
9. COMPLEMENTARY_REQUIRED不能 drop member。
10. ALTERNATIVE_ONE_OF必须在 B6已解决。
11. B7不重新 inspect media/compatibility。
12. AssetKind / ExecutionAssetRole / BackendReferenceRole / Picture N 严格分层。
13. Split segments默认维持 stable concrete refs，除非有正式 reason。
14. Voice identity稳定；VOICE_REFERENCE与 utterance audio分离。
15. Runtime-derived artifacts不是 B6 assets。
16. Backend ref limit不能造成 silent asset deletion。
17. Path不是 asset identity。
18. Asset subset改变通常是 same identity new revision，不是 retry。
19. Normal B7.4 deterministic，不依赖 Qwen。
