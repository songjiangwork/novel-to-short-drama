# B4.1 — Shot Planning Contract + Shot Context

状态：**FROZEN**

## 1. 职责

B4.1 从 exact `APPROVED EpisodeProductionPlan` deterministic 构建 Shot Planning 所需的 authoritative context。

核心输出：

```text
EpisodeShotPlanningContext
```

B4.1 不创建 PlannedShot，不绑定 asset，不生成 prompt，也不处理 runtime。

## 2. Authoritative input

Shot Planning 只能正式消费：

```text
APPROVED EpisodeProductionPlan exact revision
```

必须 pin：

```text
episode_production_plan_id
episode_production_plan_revision
episode_production_plan_hash
production_approval_record_id
```

DRAFT ProductionPlan、单独 B3 constituent、临时 review note、聊天记忆均不可作为正式 input。无法验证 approval/revision/hash 时 fail closed。

## 3. PlannedShot 与 v1.1 ProductionShot

正式区分：

```text
ProductionUnit
= production execution semantic unit

PlannedShot
= asset-unresolved / backend-agnostic editorial-camera semantic unit

ProductionShot
= downstream asset-resolved / execution-ready generation artifact
```

不冻结 `PlannedShot ↔ ProductionShot` 为 1:1。一个 PlannedShot 以后可以 compile 为一个或多个 ProductionShots，但 generation segmentation 不能改变 editorial Shot identity。

## 4. EpisodeShotPlanningContext

它是 deterministic derived artifact，不是 Shot source of truth。

至少解析：

- ordered ProductionUnits
- PerceptualCoverageRequirements
- StagingDirectives
- PerformanceRequirements
- ProductionRequirements
- ProductionSpaceAnchors
- ProductionContinuity contracts/state
- duration / complexity budgets
- exact production provenance

Shot Planner 不重新阅读小说重新判断 narrative priority；需要追溯时通过 stable provenance 查询上游。

## 5. Coverage contract

`PerceptualCoverageRequirement` 是 B4 的核心 authoritative obligation：

```text
B3.4 = WHAT audience must perceive
B4 = HOW shot coverage makes it perceptible
```

正式引入 `ShotCoverageMapping` 概念，具体 mapping 在 B4.2 建模。

Coverage role：

```text
PRIMARY
SUPPORTING
```

每个 REQUIRED PCR 最终至少必须有一个 PRIMARY PlannedShot coverage；PREFERRED PCR 不要求独立 Shot。

## 6. ProductionUnit / PlannedShot 边界

v1.2 默认：

```text
PlannedShot → exactly one ProductionUnit
ProductionUnit → one or many PlannedShots
```

PlannedShot 不跨 ProductionUnit boundary。若一个真正连续 editorial Shot 必须跨两个 PU 才成立，应优先返回 B3.2 检查 PU boundary。

ShotSequence 必须保持 ProductionUnit order monotonic，但 ShotSequence 与 runtime GenerationSchedule 正式分离。

## 7. PlannedShot identity

`PlannedShot` 必须具有 stable semantic identity，且 stable ID 与 display sequence number 分离。

通常保留 identity 的变化包括 camera realization refinement；以下 fundamental changes 创建新 identity：

- split / merge
- ProductionUnit reassignment
- fundamental PCR ownership change
- fundamental subject / editorial purpose change

可保存 `derived_from / replaces / supersedes` lineage。

## 8. Camera semantic scope

B4 可以开始处理：

- shot size
- viewpoint
- camera-subject relation
- composition intent
- camera movement intent
- screen direction / eyeline continuity

但核心保持 backend-agnostic。v1.2 不要求物理焦距、相机型号或精确 camera x/y/z。

B4.1 只确定这些属于 B4 authority；具体 taxonomy 在 B4.3 冻结。

## 9. Spatial / asset boundary

Shot Planner 可以消费 `ProductionSpaceAnchor`，但：

```text
anchor ≠ concrete asset geometry ≠ pixel coordinate
```

B4 不能假设尚未选择的背景资产中 door/desk 位于具体画面位置。

PlannedShot 引用 semantic character/prop/location requirement IDs，不绑定 concrete image/WAV/reference slots。

## 10. Dialogue / localization / timing

B4 可读取 canonical dialogue、DialogueIntent、performance semantics 用于 coverage，但不得修改对白。

Shot semantics 与 release-specific exact timing 分离。canonical Shot Planning 优先基于 semantic dialogue/performance structure；不同语言的 spoken duration 留 downstream Release Variant refinement。

B4.1 可携带 timing budget，但不决定 exact Shot duration。

## 11. ShotPlanningConstraintProfile

允许独立 `ShotPlanningConstraintProfile`，与 `ProductionConstraintProfile` 分离。其内容应保持 backend-agnostic，例如 preferred subject count、semantic complexity、camera-motion preference、duration preference。

H3/ComfyUI 的具体能力不能直接成为 canonical ShotPlan truth。

## 12. Shot continuity context

B4 可维护 sparse `ShotContinuityState`，用于 camera/editorial overlay，例如：

- screen direction
- active interaction axis
- eyeline relation
- shot-scale progression context
- established spatial coverage

它不得保存 narrative / production truth。Context retrieval 使用 hierarchical / targeted strategy，不加载全部 series Shot history。

## 13. Python / Qwen

Python：approval/pins、ID/ref resolution、context construction、provenance、continuity retrieval、completeness validation。

Qwen：shot-semantic / coverage / camera/editorial reasoning。

Targeted context expansion 继续遵循：Qwen 指出需要的 stable IDs，Python authoritative resolve。

## 14. Non-goals

B4.1 不生成：

- PlannedShot list
- concrete asset refs
- prompt / seed / H3 request
- ComfyUI workflow
- QC attempt
- release-specific aspect-ratio geometry

## 15. 冻结原则

1. B4 只正式消费 exact APPROVED EpisodeProductionPlan。
2. `EpisodeShotPlanningContext` 是 deterministic derived context。
3. `ProductionUnit ≠ PlannedShot ≠ ProductionShot`。
4. PlannedShot 是 backend-agnostic、asset-unresolved Shot semantic contract。
5. REQUIRED PCR 必须最终至少一个 PRIMARY coverage。
6. PlannedShot 默认 exactly one PU owner，不跨 PU boundary。
7. ShotSequence 与 runtime generation schedule 分离。
8. PlannedShot stable identity 与 display number 分离。
9. B4 不重新判断小说 narrative priority。
10. B4 不绑定 concrete asset/backend/release implementation。
11. Shot continuity 是 cinematography/editorial overlay。
12. B4.1 fail closed on unresolved approved production refs。
