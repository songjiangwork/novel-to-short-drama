# B6.1 — Asset Resolution Contract + Asset Context

状态：**FROZEN**

## 1. 职责

B6.1 建立 Asset Resolution 阶段的正式 contract，并把一个 exact `APPROVED EpisodeReleaseVariant` 与可解析的 asset universe、policy 和 availability snapshot 绑定为 deterministic `EpisodeAssetResolutionContext`。

核心分层：

```text
Semantic Entity / AssetRequirement
≠ Concrete AssetRecord
≠ Backend Reference Slot
```

B6 第一次允许 concrete asset 成为正式 workflow object，但仍保持 backend-agnostic。

## 2. 正式输入

只允许正式消费 exact：

```text
APPROVED EpisodeReleaseVariant
```

必须 pin：

```text
episode_release_variant_id
revision
content_hash
release_variant_approval_record_id
```

正常 current-production workflow 还必须满足：

```text
source_lineage_eligibility == CURRENT
```

STALE lineage 不得建立新的 current Asset Resolution lineage。

禁止 `latest/current/default` implicit selector 进入 canonical context。

## 3. EpisodeAssetResolutionContext

正式输出：

```text
EpisodeAssetResolutionContext
```

至少包含：

```text
context_id
revision
content_hash
source_episode_release_variant_ref
source_episode_shot_plan_ref
asset_catalog_refs[]
asset_resolution_policy_profile_ref
asset_availability_snapshot_ref
lineage_resolution_manifest
resolution_constraints
```

同一 exact ReleaseVariant + catalogs + policy + availability snapshot 应生成相同 semantic context content。

## 4. AssetRecord

Concrete asset 使用 stable `AssetRecord` 表示：

```text
AssetRecord {
  asset_id
  asset_revision
  content_hash
  media_type
  asset_kind
  semantic_subject_refs[]
  capability_metadata
  provenance
  availability_state
  locator_metadata
}
```

必须保持：

```text
asset identity ≠ filesystem path / URI
```

Locator 可变化而不改变 asset content identity；content hash 改变则不得冒充旧 revision。

## 5. Asset kind / media type

初始 taxonomy 至少允许：

```text
CHARACTER_VISUAL
LOCATION_VISUAL
PROP_VISUAL
VOICE_REFERENCE
PREEXISTING_UTTERANCE_AUDIO
OTHER_VISUAL
OTHER_AUDIO
```

`media_type` 与 semantic `asset_kind` 分离；不能仅凭 extension 推断全部语义。

禁止使用 backend-specific intrinsic kind，例如 `H3_REFERENCE_IMAGE`。

## 6. Capability

`AssetCapability` 描述 concrete asset 本身可以支持什么，例如：

```text
IDENTITY_REFERENCE
FACE_DETAIL
UPPER_BODY
FULL_BODY
PROFILE_USABLE
THREE_QUARTER_USABLE
```

Capability 不是 Shot semantics。`FULL_BODY` capability 不等于 B4 shot scale `FULL`。

## 7. Voice asset 边界

必须区分：

```text
VOICE_REFERENCE
≠ generated utterance waveform
```

现有 voice reference 可在 B6 resolve；未来 TTS/生成后的具体 utterance audio 属于 execution/output layer，除非它本来就是 `PREEXISTING_UTTERANCE_AUDIO`。

## 8. Asset provenance

AssetRecord 至少允许记录：

```text
USER_PROVIDED
PROJECT_CANONICAL
GENERATED
IMPORTED
DERIVED
```

Derived asset 应可追踪 `source_asset_refs[]`。

B6 不设计完整 DAM，但必须支持 integrity、traceability、compatibility 和 reproducibility。

## 9. Availability

Identity 与 availability 分离。初始状态至少：

```text
AVAILABLE
UNAVAILABLE
MISSING
INVALID
```

正式 resolution context pin `AssetAvailabilitySnapshot`，用于记录 resolution 时 exact asset universe 是否真实可用、hash 是否匹配。

## 10. AssetCatalog

B6 使用 versioned/pinned `AssetCatalog` 作为 formal candidate universe，可以存在多个 catalog refs，例如：

```text
project canonical assets
series/shared assets
release-specific voice assets
```

Physical storage/database implementation 不在 B6.1 冻结范围。

## 11. AssetResolutionPolicyProfile

正式使用 policy profile 表达 governance，例如：

```text
prefer project canonical assets
allow derived assets
allow generated/imported assets
minimum provenance requirement
hash verification requirement
availability requirement
human verification requirement
```

Policy 不得包含 backend-specific ref count / slot rules。

## 12. Requirement chain

B6 正式采用：

```text
APPROVED EpisodeReleaseVariant
↓
AssetRequirement
↓
AssetCandidate
↓
ResolvedAssetBinding
↓
APPROVED EpisodeResolvedAssetPlan
↓
Execution Compilation
```

`AssetRequirement` 表示为什么需要 asset、它必须具备什么能力；不得直接从 semantic subject 跳到 filename。

## 13. Missing asset

B6 保持：

```text
resolution ≠ generation
```

当前 universe 无可用 concrete asset 时，应显式：

```text
UNRESOLVED_ASSET_REQUIREMENT
ASSET_CREATION_REQUIRED
```

不能 invent nonexistent asset 或 placeholder-resolve。

## 14. Backend firewall

B6.1 不绑定：

- Picture N
- H3/ComfyUI ref role / ordering
- prompt / seed
- ProductionShot
- backend ref limit
- workflow node

这些属于 B7 Execution Compilation。

## 15. Python / Qwen

Python：exact pins、catalog resolution、IDs/revisions/hashes、file integrity、availability、provenance、state。

Qwen：后续 semantic compatibility reasoning；不能 invent asset、改变 hash、修改 approved Shot/Release semantics。

## 16. 冻结原则

1. B6 正式输入是 exact APPROVED + current-lineage EpisodeReleaseVariant。
2. B6 第一次允许 concrete asset 成为 canonical workflow object。
3. Semantic Entity / AssetRequirement / Concrete Asset / Backend Slot 严格分层。
4. B6.1 输出 `EpisodeAssetResolutionContext`。
5. `AssetRecord` identity 不等于 path。
6. AssetRecord 以 id/revision/content_hash 保证 identity/integrity。
7. Catalog、policy、availability snapshot 必须 exact pin/version。
8. Capability 表示 asset 能支持什么，不重新定义 Shot semantics。
9. Voice reference 与 generated utterance waveform 分离。
10. Missing asset 显式 unresolved / creation required。
11. Asset fitness failure 不得 silent 修改 B5/B4 semantics。
12. B6 不绑定 Picture N / backend slot/order。
13. Context construction deterministic。
14. Python 管 integrity/state/provenance；Qwen 管 semantic compatibility reasoning。
