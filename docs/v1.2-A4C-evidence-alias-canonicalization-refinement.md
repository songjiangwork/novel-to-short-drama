## 3. New frozen rule: canonical exact-EvidenceRef projection

在某 decision 的所有 selector 已经通过现有 validation 后：

```text
validated selectors
→ canonical selector order
→ resolve each selector to its exact endpoint EvidenceRef
→ canonical exact-EvidenceRef projection
→ ReconciliationDecision.evidence_refs
```

### 3.1 Exact identity

两个 EvidenceRef 只有在完整 persisted identity tuple 完全相等时才视为同一个 evidence：

```text
(
  paragraph_id,
  role,
  strength,
  excerpt
)
```

其中 `excerpt = null` 与字符串值一样参与 exact identity。

不得使用：

- paragraph-id-only；
- excerpt-only；
- case-insensitive；
- whitespace normalization；
- fuzzy matching；
- semantic similarity；
- endpoint/candidate identity

来判断重复。

## 4. Stable exact dedupe

按现有 canonical selector order 逐个解析 EvidenceRef。

维护 `seen_exact_evidence`。

对于每个 resolved EvidenceRef：

- 第一次出现：保留；
- 后续 exact-identical 出现：不再写入 persisted `evidence_refs`；
- 顺序保持第一次出现的位置。

例：

```text
selectors after canonicalization:
  L0
  R0

L0 -> EvidenceRef A
R0 -> EvidenceRef A

persisted evidence_refs:
  [EvidenceRef A]
```

另例：

```text
L0 -> EvidenceRef A
L1 -> EvidenceRef B
R0 -> EvidenceRef A
R1 -> EvidenceRef C

persisted evidence_refs:
  [A, B, C]
```

这是 deterministic canonical projection。

## 5. “Do not silently drop selectors” clarification

A4C §50.6 既有原则：

```text
do not silently drop any selector
```

继续适用于 **provider selector contract**：

- duplicate selector string 仍 invalid；
- illegal selector 仍 invalid；
- out-of-range selector 仍 invalid；
- 每个合法 selector 都必须真正 resolve；
- 不能为了让结果通过而忽略一个 selector。

本 refinement 不删除、跳过或修补 provider selector。

区别是：

```text
multiple valid selectors
may denote the same exact EvidenceRef identity
```

selector 已全部验证并解析后，persisted evidence projection 必须满足既有 A4D invariant：

```text
ReconciliationDecision.evidence_refs contains no duplicate exact EvidenceRef
```

因此 exact alias collapse 是 persisted projection canonicalization，而不是 selector repair。

## 6. Retry semantics

以下情况仍是 semantic-invalid，并消费现有 bounded semantic round：

- malformed selector；
- out-of-range selector；
- duplicate selector string；
- wrong pair/order/ref；
- typed payload invalid。

以下情况**不是** semantic-invalid：

```text
two or more distinct valid selectors resolve to one exact EvidenceRef
```

不得因为 exact alias 而 retry provider。

原因：

- alias 来源是 authoritative endpoint evidence data，不是 provider corruption；
- provider 的 selector 可以完全合法；
- temperature=0 的 deterministic provider 重试很可能返回同一合法 selector set；
- retry 无法消除 underlying endpoint evidence alias。

---

## 7. Decision identity

`compute_llm_decision_id(...)` 必须消费 canonical exact-deduped persisted `evidence_refs`。

因此：

```text
["L0", "R0"] -> A, A -> persisted [A]
```

decision id 必须根据 `[A]` 计算，而不是 `[A, A]`。

不同 selector 排列经现有 selector canonicalization 后，若投影相同 exact EvidenceRefs，必须得到同一个 persisted evidence tuple 与同一个 deterministic decision id。
