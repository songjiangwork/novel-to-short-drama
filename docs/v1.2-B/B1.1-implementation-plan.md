# v1.2-B1.1 — Adaptation Target Implementation Plan

状态：**IMPLEMENTATION REFINEMENT；不改变冻结的 B1.1 contract**  
Tracking: [Issue #109](https://github.com/songjiangwork/novel-to-short-drama/issues/109)；[B1 umbrella #108](https://github.com/songjiangwork/novel-to-short-drama/issues/108)  
Authoritative frozen doc: `docs/v1.2-B/01-B1.1-adaptation-target.md`。本计划仅定义首个小 PR 的合同、边界和测试，实际字段格式以 existing repo serialization/schema conventions 为准。

## 1. First PR outcome

一组可复用、严格校验的 typed domain contracts 和**确定性** resolver：

```text
structured RawAdaptationIntent
         + explicit AdaptationProfile defaults
         + explicit UserOverrides
                       ↓ Python / no Qwen
                 ResolvedAdaptationTarget
         + source/provenance per material field
         + explicit unresolved source references
```

它回答“想改成什么规格/取向”，绝不决定 source event 的命运或具体 episode boundary。B1.1 不创建完整 AdaptationPlan、StorySkeleton 或 B1 CURRENT pointer；初始 Slice 可先在内存生成 typed resolved output、canonical serialization 和 schema validation，正式 B1 constituent publication 在阶段集成时复用同一 contracts。

## 2. External input authority

- **Raw user intent**：第一阶段接受结构化的用户输入或 typed dict；保留原始显式值/可选描述，不能把模型建议伪装为 user。
- **Profile defaults**：明确存在并具有 profile identity/version 的配置；不可从“常识”补无记录 defaults。
- **Explicit overrides**：对指定字段的显式替代，高于 profile defaults；覆盖路径/值应可审计。
- **A6 input**：B1.1 target 绑定 exact `StoryAnalysisManifest` revision/hash 或其规范的 validated input ref；需要解析 target focus 时沿其 A5/A6 refs 建立合法 ID universe，而不是全文 fuzzy scan。
- **Working language** 默认 `zh-CN`，仅约束中间语义材料，不决定最终 spoken dialogue/subtitle/voice。

任何非结构化自然语言（例如“适合手机看，情节快些”）不允许让 Python 通过关键词暗中设定字段。首个 Issue 不新建 Qwen natural-language parser；可保存原文为待解析输入，明确标识 unresolved。后续 semantic parsing 若引入，必须遵守独立 authority、provenance、prompt identity，而非偷渡进 deterministic resolver。

## 3. Minimal contract slices

### 3.1 AdaptationTarget / ResolvedAdaptationTarget

至少表达：
- narrative format/medium、presentation orientation、adaptation genre；
- audience target、working language；
- fidelity profile `high | balanced | aggressive`；
- **独立** pacing profile 和 compression profile；
- primary character/plot/relationship focus（若输入）；
- required/forbidden elements、其 resolved/unresolved refs；
- total narrative duration、per-episode duration、episode count 的约束集合；
- per-material-field provenance：`user | profile_default | derived | model_proposed`；当前 slice 只把由 Python 推导的值记为 derived，**不得假造 model_proposed**；
- canonical upstream snapshot binding。

以上为语义覆盖清单，**不是要求创建一个字段极多的巨型 dataclass**。按已有 dataclass、`to_dict/from_dict`、JSON Schema、严格 key validation 的 repo conventions 最小实现。

### 3.2 Constraint semantics

支持两个独立维度：

```text
cardinality / duration intent:
    fixed | target | range | derived

constraint strength:
    hard | soft
```

`fixed` 表示必须满足的精确值；`target` 是优化偏好；`range` 指可接受/优化区间，hard/soft 决定其约束强度；`derived` 表示尚待下游依其它约束求值。实现不得把 `target` 自动提升为 hard fixed，也不得把所有 `range` 自动当作强制等式。

- 统一内部时长单位（建议 integer seconds，外部格式需有显式单位）；拒绝负数、NaN、Infinity、布尔冒充整数、非法或反向区间；不接受不明浮点误差。
- episode count 是正整数的 domain；它与 total/per-episode duration 是不同 constraint families。
- `fixed(episode_count)` + `fixed(per_episode_duration)` + `fixed(total_duration)` 若算术冲突，**在任何 Qwen 调用前 FAIL CLOSED**。
- 对 hard range 和固定变量执行可确定的 interval feasibility；若范围存在合法交集，不因 target 偏好不一致就错误阻断。
- **不要**从每集目标时长机械计算最终 episode count；`resolved_episode_count` 正式由 B1.5 根据 duration feasibility + meaningful dramatic boundaries 决定。
- 对需要剧情语义才能确定的可行性，只保留 unresolved/pending；不得标记为已满足或以猜测填补。

示例（概念性；不是强制外部 YAML layout）：

```yaml
episode_count: {mode: fixed, value: 20, strength: hard}
per_episode_seconds: {mode: fixed, value: 90, strength: hard}
total_seconds: {mode: fixed, value: 1200, strength: hard}
# rejected: 20 × 90 = 1800, not 1200
```

而：

```yaml
episode_count: {mode: derived}
per_episode_seconds: {mode: target, value: 90, strength: soft}
total_seconds: {mode: range, min: 1500, max: 2400, strength: hard}
# B1.1 structurally valid: B1.5 owns final count resolution
```

不要因为工作名叫“短剧”就私设固定 20 集、90 秒或特定时长；只有经过 profile/user resolved 的值才具有 authority。

### 3.3 Fidelity / pacing / compression

`high | balanced | aggressive` 仅决定 adaptation policy 偏好，不输出 event keep/omit。fast pacing ≠ aggressive compression。类型可保持已有 frozen vocabulary；对暂未冻结的 pacing/compression 子档名称，优先提供 Profile 定义/显式受控值，不私自扩大永久公共 enum。

### 3.4 Focus / required / forbidden

- 已有 ID 的对象优先绑定 exact `char_*` / `evt_*` / `fact_*` / `rel_*` / A6 plot/arc IDs；所引用 ID 必须存在于**同一份已绑定 A5/A6 snapshot**，不可跨 revision 捡 refs。
- 自然语言 focus 或 element 不可 exact match 时保留 `unresolved` + 用户原始 text/provenance，不能 fuzzy guess 或静默删掉该 constraint。
- same normalized exact ID 出现在 incompatible required/forbidden hard constraints 时，执行 deterministic conflict check；语义等价但无 exact ID 的文本不靠 Python 推断冲突。
- Unresolved hard element constraint **不能被宣称 fulfilled**；是否由后续 semantic planning 定向解析或在 B1.6 gate 阻断，要保持 provenance/状态明确。
- 应拒绝不合法的 canonical namespace、missing/tampered target ID；`model_proposed` 绝对不等于 user MUST。

## 4. Error / provenance policy

错误至少区分（可按 repo conventions 收敛为已有类型）：
- malformed/unsupported config；
- deterministic contradictory hard target；
- unsupported or mismatched canonical ref；
- pending/unresolved semantic target（合法保存但非已满足）；
- explicit user/profile source mismatch。

同字段选取优先级：explicit user override > raw structured user requirement > profile default；若**同一 authority level** 出现冲突硬值，禁止 silent last-write-wins。每个 material resolved field 必须保留 source identity；不得把被覆盖的 profile 值误报为 user value。

## 5. Reuse rather than framework duplication

可以直接引用：
- `short_drama.artifacts` canonical JSON + ArtifactRef；
- `short_drama.foundation` validation/lineage conventions；
- A6/A5 existing validated snapshot/reference checks；
- existing Python typed model / JSON Schema patterns。

首个 Slice **不应**创建：新 ArtifactStore、new ApprovalRecord enum、CURRENT_APPROVED / CAS service、G1 UserDirection engine、ComfyUI/H3 config、新 profile DB/ORM、B1.2–B1.7 模型全集。

## 6. Test matrix (first PR)

| Case | Expected |
|---|---|
| user override > profile default | resolved winner + correct field provenance |
| absent field without a default | explicit absent/unresolved; no invented implicit value |
| duplicate/conflicting same-level hard input | fail closed |
| `20 × 90 != 1200` with three hard fixed inputs | fail closed, zero provider |
| compatible hard intervals + off-center soft target | valid/pending, no false contradiction |
| invalid count / negative duration / reversed interval / NaN / bool-int | strict rejection |
| count mode derived | remains derived until B1.5 |
| high/balanced/aggressive | round-trip and exact vocabulary |
| pacing change with unchanged compression | independent, distinct resolved config |
| exact canonical ref exists in bound A5/A6 | accepted |
| dangling/cross-revision ref | rejected |
| unresolved natural-language focus | explicit unresolved, not guessed |
| exact hard required and forbidden same ref | contradiction |
| working language `zh-CN` | no spoken-language obligation |
| same structured input/profile | deterministic bytes/hash |
| modified user/profile | changed content/identity; no hidden last-write-wins |
| A6/A5 store inputs | no writes, no provider calls |

Require focused unit tests + `git diff --check`. Document the actually used baseline/HEAD/test commands/exits. Avoid expensive full A6 real-provider rerun; this is a **zero-provider** PR.

## 7. Review checklist for Codex / Pi

- Is any adaptation narrative decision accidentally executed by Python? Reject.
- Did code allocate episode boundaries or materialize 166 event dispositions? Reject.
- Can provenance distinguish user/default/derived/model-proposed? Require.
- Are hard contradictions resolved before Qwen? Require.
- Are unresolvable references explicit instead of inferred? Require.
- Does every persisted/external contract use existing canonical hash/schema conventions? Require.
- Does PR stay small and Draft, preserve A6 artifacts/CURRENT and keep main runnable? Require.

## 8. Definition of Done

B1.1 is done once deterministic resolution + typed contracts + provenance + contradiction tests work. It is **not** B1 complete, does not need Qwen/Alice regeneration, does not approve an AdaptationPlan, and does not publish a B1 CURRENT pointer.
