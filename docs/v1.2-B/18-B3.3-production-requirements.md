# B3.3 — Production Requirements

状态：**FROZEN**

## 1. 职责

B3.3 回答：每个 ProductionUnit 为了忠实执行 screenplay “需要什么”。

正式输出：

```text
EpisodeProductionRequirements
```

它是 versioned production-planning artifact；B3.4 必须 pin exact revision/hash。

## 2. ProductionRequirement

`ProductionRequirement` 正式成为 stable-identity first-class object。

v1.2 核心类别：

```text
CHARACTER
LOCATION
PROP
WARDROBE
APPEARANCE
ENVIRONMENT
BACKGROUND_POPULATION
PRACTICAL_EFFECT
```

核心边界：

```text
ProductionRequirement ≠ concrete AssetBinding
```

## 3. Character / population

Named `CharacterRequirement` 必须引用 `AdaptedCharacter` stable ID，不绑定演员、face image、LoRA、voice。

unit usage 可区分：

```text
ACTIVE
PRESENT
```

非 narrative-identifiable 人群使用 `BACKGROUND_POPULATION`，不创建大量虚假角色实体。

## 4. Location

`LocationRequirement` 来源于 DramaticSetting / screenplay production semantics，但不绑定 background image 或 concrete reference。

v1.2 暂不额外建立复杂 `ProductionLocation` semantic layer；保持 Implementation Minimalism，后续 Asset Resolution 再解决 concrete representation。

## 5. Prop identity

`PropRequirement` 必须区分：

```text
EXACT_IDENTITY
SEMANTIC_CLASS
```

`Document_X` 等 narrative prop 必须保留 canonical identity；generic chair/pen 等 production-support prop 可以是 semantic class。

Production-support prop 不得未经 upstream revision 升格为 future narrative dependency。

## 6. Wardrobe / Appearance / Environment

Wardrobe 与 Appearance 分开：

- Wardrobe：服装语义与 continuity，可 `CONTINUE_FROM` prior state。
- Appearance：visible injury、blood/dirt、wet/dry、hair 等 persistent visible state。
- Environment：diegetic time/weather/space state，如 day/night、rain、power outage、door/window condition。

Environment 不定义 cinematic lighting ratio / camera lighting design。

`PRACTICAL_EFFECT` 表达 rain/smoke/breaking/spill 等 required visible effect，不绑定实现技术。

## 7. Provenance / authority / strength

每个 Requirement 必须保存 provenance，可引用 ScreenplayScene、ScreenplayElement、ProductionUnit、continuity、production constraint。

正式区分：

```text
source_authority:
  SCREENPLAY
  CONTINUITY
  PRODUCTION_CONSTRAINT
  PRODUCTION_PLANNING

requirement_strength:
  REQUIRED
  PREFERRED
```

Narrative-critical requirement 必须 `REQUIRED`，不能通过 PREFERRED 逃避 validation。

## 8. RequirementCatalog / RequirementUse

正式区分：

```text
ProductionRequirement
ProductionRequirementUse
```

`ProductionRequirementCatalog` 保存 episode 内去重的 requirement identity；每个 `ProductionUnitRequirementSet` 保存 unit-local use/state，例如 presence、visibility、role、condition、holder/location 等。

Identity reuse 不得抹掉 unit-specific state。

## 9. Conflict / continuity

B3.3 必须检测同一 production moment 的 incompatible states，例如互斥 wardrobe、同一 exact prop 同时由不同角色持有、door 同时 open/closed。

Conflict 不得 silent repair：

```text
PRODUCTION_REVISION_REQUIRED
SCREENPLAY_CHANGE_REQUIRED
ADAPTATION_CHANGE_REQUIRED
```

按 earliest authoritative owner route。

RequirementUse 必须与 B3.2 `ProductionContinuityContract` 一致；跨集 persistent visible continuity 从 approved production checkpoint 继承，不依赖模型记忆。

## 10. 非目标

B3.3 不：

- 设计 staging / performance
- 决定 Shot coverage
- 绑定 voice/image/background/H3 reference
- 使用 camera/lens/framing
- 绑定 backend capability

Requirement coverage 不等于 Shot coverage。

## 11. Revision / validation / roles

`EpisodeProductionRequirements` 拥有 id/revision/hash；Requirement identity stable，但不为每个 requirement 建复杂独立 revision graph。

Python 负责 references/dedup/provenance/continuity/conflict/revision mechanics；Qwen 负责 semantic extraction/classification/missing-requirement reasoning。

## 12. 冻结 contract

1. B3.3 回答 production “需要什么”。
2. 正式输出 versioned `EpisodeProductionRequirements`。
3. `ProductionRequirement` 为 stable first-class object。
4. 核心 categories 固定为 CHARACTER/LOCATION/PROP/WARDROBE/APPEARANCE/ENVIRONMENT/BACKGROUND_POPULATION/PRACTICAL_EFFECT。
5. Requirement 与 concrete asset 严格分离。
6. Named character 引用 AdaptedCharacter；background population 独立。
7. LocationRequirement 不绑定 background asset；v1.2 暂不增加冗余 ProductionLocation layer。
8. Prop 区分 EXACT_IDENTITY / SEMANTIC_CLASS。
9. narrative prop identity 不得 generic substitute。
10. Wardrobe / Appearance 分开并支持 continuity carryover。
11. Environment 只表达 diegetic semantic state。
12. PracticalEffect 不绑定实现 workflow。
13. 每个 requirement 有 provenance。
14. source_authority 与 REQUIRED/PREFERRED 分离。
15. `ProductionRequirement` 与 `ProductionRequirementUse` 分离。
16. Catalog 去重 identity，UnitRequirementSet 保存 local state。
17. B3.3 必须检测 incompatible requirements，不 silent repair。
18. 必须覆盖 screenplay-required production resources。
19. RequirementUse 与 continuity contract 一致。
20. 跨集 visible continuity 从 structured checkpoint 继承。
21. 不绑定 staging/performance/camera/asset/backend。
22. B3.4 pin exact requirements revision/hash。
23. Python 负责结构 mechanics，Qwen 负责 semantic extraction。
24. B3.3 无 formal approval，最终 gate 留给 B3.7。
