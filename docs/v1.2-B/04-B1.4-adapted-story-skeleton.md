# v1.2-B1.4 — Adapted Story Skeleton（冻结）

## 职责

B1.3 已决定哪些 source material survive，并建立 AdaptedCharacter / AdaptedStoryBeat identity 与 mappings。

B1.4 负责回答：

> 这些 adapted objects 组合起来以后，改编后的故事怎样完整地发生，并怎样被观众接收？

B1.4 建立完整 adapted narrative skeleton，但仍不是 screenplay。

---

## 输入 / 输出

输入：

```text
ResolvedAdaptationTarget
AdaptationStrategy
Source Dispositions / AdaptationMappings
AdaptedCharacters
Adapted Story Beats
Adapted Continuity Overlay
A6 Global Story Analysis
```

输出：

```text
AdaptedStorySkeleton
```

至少覆盖：

- adapted chronology
- presentation structure
- causal/dependency graph
- continuity-critical state progression
- character knowledge progression
- audience knowledge / reveal progression
- character / relationship arc checkpoints
- setup/payoff graph
- continuity gaps / intentional ambiguity
- global narrative fit

---

## Adapted Chronology vs Presentation Order

必须严格分开：

```text
adapted chronology
= story world 中实际发生顺序

presentation order
= 观众接收 material 的顺序
```

Chronology 不强制 total order；如果只知道 A、B 都发生在 C 前，不必强猜 A/B 谁先。概念上可使用 partial-order DAG。

Presentation structure 必须 deterministic enough for B1.5 episode partitioning。

---

## PresentationEntry

`AdaptedStoryBeat` 表示 narrative occurrence / meaningful state change。

`PresentationEntry` 表示观众何时、以什么 scope 接触该 adapted material。

它用于表达：

- teaser
- partial reveal
- delayed reveal
- flashback
- recap-like presentation semantics

例如同一个重大 Beat 可以先 partial teaser、后 full reveal，而 story world 中只发生一次。

`PresentationEntry != Scene != Shot`；禁止加入 camera、duration frames、blocking、shot instructions。

普通线性 material 可以紧凑地 1:1 reference beat，不强制引入冗余包装。

---

## Causal / Dependency Graph

AdaptedBeat 至少要有明确 outcome；重要 dependency 通过轻量 precondition/outcome 关系连接。

只追踪 narrative-important dependency，例如：

```text
获得关键物品
→ 可以进入某地点
→ 发现关键证据
```

Python 检查 structured dependency integrity；Qwen 检查 motivation、semantic causality 与 narrative coherence。

禁止把 B1.4 扩展成完整 symbolic world planner。

---

## Continuity-Critical State

B1.4 只追踪 downstream screenplay 必须知道的关键状态，例如：

- plot-critical secrets / knowledge
- critical object possession
- major relationship state
- alive/dead/missing/identity status
- major goal / commitment

不追踪低价值 production continuity（服装细节、杯子位置等）。

必须区分：

```text
world truth
character knowledge
audience knowledge
```

事实为真，不代表某角色知道，也不代表观众知道。

---

## Reveal / Withholding

重要 reveal 建模为 information transition：

```text
unknown → suspected → confirmed
```

可分别作用于 audience 和具体 characters。

重要 withholding constraint 可以明确：

```text
must_not_be_confirmed_before <PresentationEntry>
```

后续 episode planning / screenplay 不得提前泄露。

只追踪 plot-critical knowledge，不建立完整 epistemic logic。

---

## Setup / Payoff

B1.4 建立 adapted-level setup/payoff links，与 A6 的 source setup/payoff 分离。

Source setup 被删后，可以用 `adaptation_invented` setup 替代，但必须保持 provenance / purpose。

Python 可验证 dangling references、明显 ordering error；setup 是否自然、payoff 是否成立由 Qwen semantic audit。

---

## Arc Checkpoints

Character / relationship arc 使用稀疏、meaningful checkpoints，不做每 beat emotion labels。

应关注：

- goal
- belief
- trust
- commitment
- relationship stance
- self-understanding

每个重要 transition 绑定 trigger beat。

---

## SkeletonGap / Intentional Ambiguity

Continuity/problem audit 应显式产生 gap object，可分类：

```text
causal gap
knowledge gap
motivation gap
relationship gap
setup/payoff gap
identity/role gap
continuity-state gap
timeline gap
```

Gap 不等于 defect。必须区分 accidental missing information 与 intentional withholding / ambiguity。

Source unresolved 不得因为 repair pressure 被 Qwen 强行猜成答案。

---

## Bridge / Continuity Repair

Python 可以发现 missing structural dependency，但不能自己创造 narrative content。

Qwen 可以在 B1.4 创建 compatible `adaptation_invented` bridge / continuity-repair beat，前提是：

- 正式注册为 AdaptedStoryBeat
- origin = adaptation_invented
- purpose / provenance / anchors 明确
- canon compatibility 明确

如果修复要求：

```text
改变 source disposition
→ 返回 B1.3

改变 global strategy
→ 返回 B1.2
```

B1.4 禁止 silent mutation upstream。

Repair loop 必须 bounded；semantic uncertain 不允许 retry 到模型被迫编答案。

---

## Global Narrative Fit

B1.4 在分集前做整体 narrative-fit 检查：故事 skeleton 是否大致装得进 AdaptationTarget。

Beat 只使用粗粒度 narrative weight 或 estimated duration range；禁止伪精确 timing。

如果 skeleton 明显 overfilled，应回 B1.3/B1.2 做 compression/omission revision；如果明显 underfilled，不允许通过 filler、重复对白或无意义冲突凑时长。

H3 clip length / backend constraint 不属于此处。

---

## Beat Accounting

Every active AdaptedStoryBeat 必须在完整 skeleton 中可达/可解释。

Beat 可以是：

```text
directly_presented
indirectly_revealed
background_only
```

Background story-world event 可以没有直接 PresentationEntry，但必须对 causality / reveal / continuity 有实际作用；否则属于 orphan material。

B1.4 可输出 dramatic hinge / strong boundary candidate，但不正式切 episode。

---

## 冻结原则

1. AdaptedStoryBeat = narrative occurrence / meaningful state change。
2. PresentationEntry = audience delivery of adapted material；不是 scene/shot。
3. Adapted chronology 与 presentation order 严格分离。
4. Chronology 可为 partial-order DAG；presentation 必须足够 deterministic。
5. 只维护 continuity-critical state，不构建 full world simulator。
6. World truth、character knowledge、audience knowledge 分离。
7. Reveal / withholding 是正式 AdaptationPlan semantics。
8. Adapted setup/payoff 与 source setup/payoff 分离但保留 provenance。
9. Character/relationship arcs 使用稀疏 checkpoints。
10. Intentional ambiguity 不等于 continuity defect。
11. Python 可发现 structural gap，但不能发明剧情。
12. Qwen 可创建受控 bridge/continuity-repair beat，并显式登记 provenance。
13. B1.4 不得 silent mutate B1.3/B1.2。
14. Repair bounded；无法解决的 blocking gap 进入 review/failure，而不是无限 retry。
15. Global narrative fit 在 B1.5 前检查，但不进入 backend/H3 feasibility。
16. B1.4 不正式创建 episode boundaries。
