# v1.2-A 冻结设计总览

## 目标

v1.2-A 的正式范围：

```text
TXT / text-based PDF
→ SourceDocument
→ ChunkManifest
→ Candidate Extractions
→ Canonical Entities
→ Canonical Facts / Events / Relationships
→ Global Story Analysis
→ story_bible.yaml
```

v1.2-A 只负责回答：

> 原小说是什么？

不负责：

- 改编成多少集
- 删除/合并哪些剧情
- 编写 screenplay
- scene / shot planning
- canonical production assets
- H3 generation

这些进入 v1.2-B 及后续阶段。

---

## 总体职责划分

### Python / 程序

负责：

- 文件读取
- SHA256 / revision
- 文档规范化
- chapter / paragraph IDs
- chunk planning
- coverage audit
- LLM orchestration
- schema validation
- semantic invariant validation
- stable IDs
- deterministic matching
- graph consolidation
- provenance
- state / resume / cache
- fail-closed gate

### 本地 Qwen

负责：

- chunk-level story extraction
- ambiguous entity reconciliation
- fact/event semantic classification
- relationship-state interpretation
- global character / plot / arc analysis

### Pi / Hermes

不是正式 runtime dependency。

主要用于：

- 开发
- 调试
- review
- semantic inspection
- 人工处理复杂 unresolved case

正式 runtime 理想依赖：

```text
short_drama Python core
+ Qwen server
```

后续 production 再连接：

```text
ComfyUI / MiniMax H3 / ffmpeg
```

---

## Frontend-agnostic 原则

Python core 不依赖 CLI、Pi 或 ComfyUI。

未来允许：

```text
Python core
├── CLI frontend
├── ComfyUI custom nodes
└── Agent frontend
```

ComfyUI 负责阶段级 visual orchestration；复杂 batch、状态、resume、validation 仍由 Python core 内部完成。
