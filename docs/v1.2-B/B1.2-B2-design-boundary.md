# B1.2-B2 最小设计边界

B1.2-B2 只执行已经由 B1.2-B1 完整准备的单一结构化请求，并把通过
`B12SemanticPreparation.decode_and_validate_proposal()` 的策略写成一个不可变
`adaptation_strategy` 制品。它复用 Foundation 的 artifact/pointer/lineage
机制和共享 `LLMClient`，不创建 HTTP adapter、第二套存储系统或 human approval。

执行前、每一语义轮和发布前均重新检查精确 A5/A6 CURRENT 绑定。技术重试仍由
LLM adapter 负责；本阶段仅对 schema-valid 但未通过 B1.2 接受缝的输出最多再生
一次（共两次 provider 调用）。B1.2 的 `CURRENT` 仅是 stage-local generated
strategy locator，绝不是 `CURRENT_APPROVED`。
