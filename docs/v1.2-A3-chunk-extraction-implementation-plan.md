## 1. Stage responsibility

A-I4 实现：

```text
exact SourceDocument
+
exact SourceChunk
+
StoryExtractionProfile
+
versioned PromptSpec
+
SemanticLLMProfile
        ↓
deterministic prompt rendering
        ↓
LLMClient.generate_structured(...)
        ↓
CandidatePayload
        ↓
Python semantic validation
        ↓
validated immutable CandidateExtraction
        ↓
ValidationReport + CURRENT pointer
```

A-I4 只产生 **chunk-local candidate evidence**，不产生任何 A4/A5 canonical identity。

A-I4 不做：

- cross-chunk entity reconciliation；
- canonical character/location IDs；
- fact/event consolidation；
- global story interpretation；
- adaptation / screenplay / production；
- H3 / ComfyUI；
- database / ORM。

原则：

```text
extract first, reconcile/consolidate later
```

## 2. Existing authorities reused

A-I4 不新建第二套 infrastructure authority。

必须复用：

- A1 `SourceDocument` 的 `paragraph_id` 作为 source-location authority；
- A2 `SourceChunk.context_span / ownership_span / paragraph_ids` 作为 context/ownership authority；
- Foundation `ArtifactRef`、`ImmutableArtifactEnvelope`、`FileArtifactStore`；
- Foundation `FilePointerStore` / `CURRENT`；
- Foundation `ValidationFinding / ValidationReport`；
- A-I3 `PromptRegistry / RenderedPrompt`；
- A-I3 `SemanticLLMProfile`；
- A-I3 `OutputSchema`；
- A-I3 `LLMRequestFingerprint / LLMInvocationProvenance`；
- A-I3 provider-neutral `LLMClient.generate_structured(...)`。

不得再定义：

- 新的 source coordinate system；
- 新的 content-hash algorithm；
- generic raw-LLM response cache；
- A3-specific provider transport。

## 3. Source evidence granularity

v1 source evidence authority 固定为 **paragraph granularity**。

每个 evidence reference 使用 A1 已有的：

```text
CH003_P0017
```

不在 A-I4 v1 引入：

- character offsets；
- token offsets；
- sentence IDs；
- page coordinates 作为 semantic authority。

PDF 的 `source_pages` 仍可由 SourceDocument 追溯，但不是 CandidateExtraction identity/reference authority。

### 3.1 EvidenceRef

冻结结构：

```text
EvidenceRef {
  paragraph_id
  role
  strength
  excerpt
}
```

字段：

- `paragraph_id`：必须存在于 exact SourceDocument；
- `role`：`primary | supporting`；
- `strength`：`explicit | implied | uncertain`；
- `excerpt`：`string | null`。

规则：

1. 每个 candidate object 至少一个 evidence。
2. 每个 candidate object 至少一个 `primary` evidence。
3. `primary` evidence 的 `paragraph_id` 必须位于 exact SourceChunk `ownership_span`。
4. `supporting` evidence 可以来自该 chunk 的 left/right context，但必须位于 `SourceChunk.paragraph_ids`。
5. evidence 不得引用当前 chunk context 之外的 paragraph。
6. 若 `excerpt != null`，Python 必须验证它是对应 `text_original` 的 exact substring；不做 Unicode/punctuation/fuzzy normalization。
7. `excerpt` 仅用于 auditability，不作为 source-location authority。

因此：

```text
context may explain
ownership must own the primary evidence
```

## 4. Provider output vs persisted artifact

A-I4 明确分开两个 contract：

### 4.1 CandidatePayload

这是 **LLM structured output schema**，只包含六类 candidate arrays：

```text
CandidatePayload {
  characters
  locations
  facts
  events
  relationships
  unresolved_mentions
}
```

不得让 LLM 生成：

- ArtifactRef；
- source/chunk revision/hash；
- prompt/provenance/hash；
- CURRENT pointer；
- ValidationReport。

这些由 Python 注入或生成。

建议 schema：

```text
schemas/candidate-payload.schema.json
```

A-I3 `OutputSchema` 使用该 schema 约束 provider output。

### 4.2 CandidateExtraction

这是 A-I4 persisted canonical artifact。

冻结顶层字段：

```text
CandidateExtraction {
  schema_version
  project_id
  document_id
  chunk_profile_id
  chunk_id
  source_document_ref
  source_chunk_ref
  extraction_profile_id
  extraction_profile_hash
  generation_provenance
  candidates
}
```

其中：

- `generation_provenance` 使用 A-I3 `LLMInvocationProvenance` 的 canonical shape；
- `candidates` 为 validated/canonicalized CandidatePayload；
- exact source refs 由 Python 从 A1/A2 artifacts 提供，不信任 LLM。

建议 schema：

```text
schemas/candidate-extraction.schema.json
```

## 6. Local candidate namespaces

每个 CandidateExtraction 内使用 chunk-local IDs。

冻结 namespace：

```text
characters           cand_char_001
locations            cand_loc_001
facts                cand_fact_001
events               cand_evt_001
relationships        cand_rel_001
unresolved_mentions  cand_unres_001
```

规则：

1. 每个 category 内 ID 唯一；
2. 必须匹配对应 namespace；
3. 每类从 `001` 开始连续编号，不允许 gap；
4. Python 在 persistence 前按 numeric suffix canonical sort；
5. A-I4 不生成 `char_0001 / loc_0001 / evt_000001` 等 canonical IDs；
6. 跨 chunk/global candidate ref 由 A4 使用：

```text
<chunk_id>:<local_candidate_id>
```

例如：

```text
CH003_C002:cand_char_001
```

A-I4 persisted artifact 内部 cross-reference 只写 local candidate ID，不重复 chunk prefix。

注意：相同 semantic request fingerprint 不承诺 fresh generations 产生 byte-identical candidates 或相同 local IDs。稳定性来自 validated artifact reuse，而不是假设 LLM deterministic。

## 7. Common candidate rules

所有六类 candidate object 必须：

- `additionalProperties: false`；
- 有对应 namespace 的 `candidate_id`；
- 有 `evidence_strength`：`explicit | implied | uncertain`；
- 有 non-empty `evidence`；
- 至少一个 ownership-primary EvidenceRef；
- 所有语义 claim source-backed；
- 工作语言字段优先 zh-CN；
- source names / aliases / mentions 保留 original-language form。

`evidence_strength` 表达该 candidate semantic claim 的整体 evidence strength，不使用 0–1 pseudo-confidence。

## 8. CharacterCandidate

冻结最小字段：

```text
CharacterCandidate {
  candidate_id
  display_name_original
  aliases_original
  descriptors_zh
  summary_zh
  evidence_strength
  evidence
}
```

约束：

- `display_name_original` non-empty；
- `aliases_original` 为 unique strings，可为空；
- `descriptors_zh` 为 unique strings，可为空；
- `summary_zh` non-empty；
- 一个 locally coherent referent 即可成为 CharacterCandidate，不要求已经知道其跨 chunk canonical identity。

例如 `the Captain` 如果在当前 chunk 中明确指向一个局部一致人物，可以成为 character candidate；如果当前文本中连 referent 都无法可靠确定，则应输出 unresolved mention。

A3 不决定：

```text
John == the Captain
```

除非这种 identity 在当前 chunk source evidence 中 explicit，并且即使记录也仍只是 candidate-level evidence；跨 chunk canonical merge 由 A4 决定。

```text
  display_name_original
  aliases_original
  descriptors_zh
  summary_zh
  evidence_strength
  evidence
}
```

与 CharacterCandidate 同样保持 local candidate 语义，不在 A3 做跨 chunk canonicalization。

## 10. FactCandidate

冻结结构：

```text
FactCandidate {
  candidate_id
  fact_type
  statement_zh
  subject_refs
  object_refs
  evidence_strength
  evidence
}
```

`fact_type` 第一版固定枚举：

```text
identity
appearance
possession
knowledge
relationship_state
location_state
world_fact
continuity_relevant
other
```

`subject_refs / object_refs`：

- 可为空；
- 只能引用当前 CandidatePayload 已存在的 `cand_char_* / cand_loc_* / cand_unres_*`；
- 不允许引用 fact/event/relationship candidate；
- world fact 可以没有 subject/object。

A3 只抽取 candidate fact，不判断它与其它 chunks 的 fact 是 same / compatible / state_change / conflict。该工作属于 A5。

## 11. EventCandidate

冻结结构：

```text
EventCandidate {
  candidate_id
  summary_zh
  participant_refs
  location_refs
  temporal_mode
  evidence_strength
  evidence
}
```

`participant_refs`：

- 可为空；
- 只能引用 `cand_char_*` 或 person/unknown `cand_unres_*`。

`location_refs`：

- 可为空；
- 只能引用 `cand_loc_*` 或 location/unknown `cand_unres_*`。

`temporal_mode` 固定枚举：

```text
normal
flashback
flashforward
dream
memory
unknown
```

A3 不创建 global narrative order，也不判断两个 event candidates 是否为同一 canonical event。A5 完成 consolidation/order。

## 12. RelationshipCandidate

冻结结构：

```text
RelationshipCandidate {
  candidate_id
  source_ref
  target_ref
  relationship_type_zh
  state_zh
  direction
  evidence_strength
  evidence
}
```

约束：

- `source_ref / target_ref` 只能指向 `cand_char_*` 或 person/unknown `cand_unres_*`；
- 两者不得相同；
- `relationship_type_zh` non-empty；
- `state_zh` 为 `string | null`；
- `direction` 固定：`directed | symmetric | unknown`。

RelationshipCandidate 记录当前 chunk 的 evidence，不建立跨 chunk relationship history；A5 才做 relationship identity/state transition consolidation。

## 13. UnresolvedMentionCandidate

冻结结构：

```text
UnresolvedMentionCandidate {
  candidate_id
  mention_original
  mention_kind
  reason_zh
  possible_candidate_refs
  evidence_strength
  evidence
}
```

`mention_kind`：

```text
person
location
other
unknown
```

规则：

- `evidence_strength` 固定为 `uncertain`；
- `possible_candidate_refs` 只能引用当前 payload 已存在的 character/location candidates；
- 不允许 unresolved→unresolved chain；
- possible refs 可为空；
- uncertain 是成功结果，不得因为“模型没有选一个身份”而 retry。

## 14. Cross-reference validation

Python 必须在 persistence 前做 exact local graph validation。

至少包括：

```text
A3_LOCAL_ID_NAMESPACE
A3_LOCAL_ID_DUPLICATE
A3_LOCAL_ID_GAP
A3_LOCAL_REF_NOT_FOUND
A3_LOCAL_REF_WRONG_TYPE
A3_RELATIONSHIP_SELF_REFERENCE
A3_UNRESOLVED_REF_CHAIN
```

所有 cross-reference 必须在同一个 CandidatePayload 内闭合。

A-I4 不允许 dangling candidate refs 进入 immutable artifact store。

## 15. Prompt Registry contract

正式 extraction prompt：

```text
prompt_id = a3.chunk-extraction
version   = 1
```

storage：

```text
prompts/story/a3.chunk-extraction/v1/
  prompt.yaml
  system.txt
  user.txt
```

由现有 `PromptRegistry(base_dir="prompts/story")` 加载。

### 15.1 Required variables

v1 prompt 仅使用：

```text
chunk_id
left_context_json
ownership_json
right_context_json
```

变量值全部为 string。

`left_context_json / ownership_json / right_context_json` 由 Python deterministic 构建为 canonical JSON array：

```json
[
  {
    "paragraph_id": "CH003_P0017",
    "text_original": "..."
  }
]
```

顺序必须与 SourceDocument paragraph/source order 一致。

LEFT/RIGHT 可以是 `[]`；OWNERSHIP 必须 non-empty。

### 15.2 Prompt semantic instructions

system/user prompt 必须明确：

- LEFT / RIGHT CONTEXT 只能辅助理解；
- candidate 的 primary evidence 必须来自 OWNERSHIP；
- evidence 使用 paragraph IDs，不发明 source refs；
- 不确定身份输出 `unresolved_mentions`；
- 不进行跨 chunk canonical merge；
- 不输出 adaptation/story-arc/screenplay/production；
- semantic summaries/descriptions 使用 zh-CN；
- names/mentions/quotes 保留 source original；
- 输出必须严格满足 CandidatePayload JSON Schema。

不得把 previous chunks 的 CandidateExtraction 注入 A3 v1 prompt；跨 chunk reconciliation 属于 A4。

---

## 16. Deterministic context partitioning

给定 exact SourceDocument + exact SourceChunk，Python 必须 deterministic 生成三段：

```text
LEFT CONTEXT
OWNERSHIP SPAN
RIGHT CONTEXT
```

算法：

1. 按 `SourceChunk.paragraph_ids` 解析 exact paragraph order；
2. `ownership_span.start..end` inclusive 为 OWNERSHIP；
3. 之前为 LEFT；
4. 之后为 RIGHT；
5. ownership start/end 必须都存在于 `paragraph_ids`，且 order 合法；
6. 所有 paragraph IDs 必须精确解析到 SourceDocument；
7. source/chunk project/document/chapter identity 必须一致。

任何结构矛盾在调用 LLM 前 fail closed，属于 A1/A2 lineage/integrity failure，不消耗 LLM attempt。

---

## 17. Validation layers

成功 CandidateExtraction 必须依次通过：

```text
provider JSON-Schema constraint
↓
A-I3 strict JSON parse + local CandidatePayload JSON Schema validation
↓
A-I4 typed domain loading
↓
A-I4 source/evidence validation
↓
A-I4 local-ID/cross-reference validation
↓
A-I4 canonical ordering validation
↓
CandidateExtraction artifact JSON Schema validation
↓
ValidationReport PASS
```

Provider structured-output validation不是最终 authority。

### 17.1 Blocking semantic findings

至少定义：

```text
A3_SOURCE_REF_NOT_FOUND
A3_EVIDENCE_OUTSIDE_CONTEXT
A3_PRIMARY_EVIDENCE_OUTSIDE_OWNERSHIP
A3_EVIDENCE_EXCERPT_MISMATCH
A3_MISSING_PRIMARY_EVIDENCE
A3_LOCAL_ID_NAMESPACE
A3_LOCAL_ID_DUPLICATE
A3_LOCAL_ID_GAP
A3_LOCAL_REF_NOT_FOUND
A3_LOCAL_REF_WRONG_TYPE
A3_RELATIONSHIP_SELF_REFERENCE
A3_INVALID_UNRESOLVED_REFERENCE
```

这些为 `BLOCKING`，`owner_stage = A3`。

`repair_route` 对 LLM-produced structural/semantic-invalid output 使用：

```text
A3_REGENERATE_CANDIDATE_PAYLOAD
```

上游 exact SourceDocument/SourceChunk integrity 错误不得伪装成“让 Qwen 再试一次”；应 route 到 A1/A2 lineage/integrity repair。

### 17.2 Semantic uncertainty is not a finding

以下不产生 blocking/review-required finding：

- unresolved identity；
- `evidence_strength = uncertain`；
- `temporal_mode = unknown`；
- possible refs 为空。

这些是合法 domain output。

## 18. Retry policy

A-I3 已处理：

- timeout；
- transient transport；
- HTTP 429 / 5xx；
- malformed provider envelope；
- invalid JSON；
- CandidatePayload JSON Schema failure。

A-I4 只为 **通过 A-I3 schema validation、但未通过 A-I4 semantic validation** 的 payload 提供有限 regeneration。

冻结 v1 policy：

```text
StoryExtractionProfile.max_generation_rounds = 2
```

即：

- first generation；
- 最多一次 semantic-regeneration round。

每个 round 使用 **完全相同的 semantic request**；v1 不构造 adaptive repair prompt，不把 validation error 回灌到 prompt。

原因：

- 保持 prompt identity/version 简单；
- 避免 repair prompt 成为未版本化 semantic input；
- 防止模型被 retry 强迫从 uncertain 猜成 certain。

A-I4 不得写无界 retry loop。

注意：A-I3 的 technical retry budget 与 A-I4 semantic generation rounds 是不同层级。实现必须在 tests 中证明总调用有明确上界；不得出现 `while valid == false` 类无界行为。

如果后续发现 nested retry latency 过高，可单独扩展 provider-neutral per-call attempt budget；该优化不属于 A-I4 v1 必要条件。

---

## 19. Candidate canonicalization before persistence

在 A-I4 semantic validation PASS 后，Python 生成 canonical payload：

- 六类 array 顺序固定；
- 每类按 candidate numeric suffix 排序；
- `aliases_original / descriptors_zh / subject_refs / object_refs / participant_refs / location_refs / possible_candidate_refs` 使用 contract 指定的 deterministic order；
- evidence 按 source paragraph order，再按 `role=primary` before supporting，再按 semantic material 稳定排序；
- duplicate list items fail closed 或 deterministic dedupe 的行为必须在 typed model 中明确，不能依赖 JSON parser incidental behavior。

Persisted payload round-trip 后必须与 typed object `to_dict()` exact equivalent。

## 20. Artifact identity and persistence

artifact type：

```text
candidate_extraction
```

逻辑 artifact ID 建议固定：

```text
<project_id>.<document_id>.<chunk_profile_id>.<chunk_id-lower>.<extraction_profile_id>
```

例如：

```text
classroom.src_001.story-analysis-v1.ch003_c002.story-extraction-v1
```

每次 semantic identity 改变，使用同 logical artifact ID 的新 immutable revision。

ValidationReport artifact ID：

```text
<candidate_extraction_artifact_id>.a3-validation
```

revision 与 CandidateExtraction revision 相同。

CURRENT pointer ID：

```text
<project_id>.a3.<document_id>.<chunk_profile_id>.<chunk_id-lower>.<extraction_profile_id>
```

pointer kind：

```text
CURRENT
```

A3 没有 formal approval gate，因此不得使用 `CURRENT_APPROVED`。

### 20.1 Persistence ordering

成功路径：

```text
validate candidate in memory
→ persist immutable CandidateExtraction
→ persist exact ValidationReport
→ verify report result == PASS
→ compare-and-set CURRENT
```

CURRENT 永远不得指向：

- schema-invalid extraction；
- semantic-invalid extraction；
- 缺少 exact matching ValidationReport 的 extraction；
- `ValidationResult.FAIL` / `PASS_WITH_REVIEW_ITEMS` extraction。

A3 v1 的 current eligibility 要求：

```text
ValidationResult.PASS
```

WARNING-only report 仍会按 Foundation summary 规则产生 PASS，因此可 current。

---

## 21. Semantic reuse identity

validated current CandidateExtraction 只有在以下 **全部 exact match** 时可复用：

- exact `source_document_ref`；
- exact `source_chunk_ref`；
- `chunk_profile_id`；
- `extraction_profile_id + extraction_profile_hash`；
- `semantic_profile_id + semantic_profile_hash`；
- `prompt_id + prompt_version + prompt_content_hash`；
- `rendered_prompt_hash`；
- `output_schema_id + output_schema_version + output_schema_hash`；
- `request_hash`；
- exact matching PASS ValidationReport；
- exact current pointer still unchanged after verification。

这些 LLM/prompt/schema fields 通过 `generation_provenance` 验证，不复制第二套 request-hash authority。

仅改变 runtime endpoint / timeout / credential 不 invalidate reuse。

### 21.1 No historical auto-resurrection in v1

v1 automatic reuse 只检查当前 validated CandidateExtraction。

历史 revisions：

- 必须仍可 exact resolve；
- 不因 current 改变而失效；
- 但 service 不扫描历史 revisions 去寻找旧 semantic identity 并自动重新设为 current。

原则：

```text
historically valid != current execution eligible
```

未来如有 replay mode，可显式设计 historical replay，不在 A-I4 v1 实现。

---

## 22. ValidationReport lineage

成功 A3 ValidationReport 至少包含 exact LineageRef：

```text
source_document
source_chunk
candidate_extraction
```

并验证：

- payload identity 与 refs 一致；
- candidate extraction source refs exact match；
- report revision 与 candidate revision 配套；
- report findings 与当前 validator deterministic 结果 exact match。

Reuse 时不能只相信“有一个 PASS report 文件”；必须重新构造 deterministic expected report 并 exact compare，遵循 A1/A2 已有 hardening 模式。

---

## 23. Failed attempts and raw model output

无效 LLM output 不成为 canonical CandidateExtraction。

不得默认永久保存：

- raw provider envelope；
- raw assistant text；
- schema-invalid CandidatePayload；
- semantic-invalid CandidatePayload。

如果 semantic validation 在所有 generation rounds 后仍失败：

- service 返回 structured failure/ValidationReport diagnostics；
- CURRENT 不变化；
- 不制造“失败但 current”的 artifact；
- 不覆盖上一个 validated current extraction。

测试可以保留 in-memory fake payload 用于断言，但不是 production artifact contract。

---

## 24. Error boundary

继续保持：

```text
execution failure != artifact validation finding
```

- A-I3 transport/config/prompt execution error → LLM error taxonomy；
- exact source/chunk lineage/integrity error → Story integrity/persistence error；
- model payload source/evidence/local-ref violation → A3 ValidationFinding / semantic regeneration routing；
- semantic uncertainty → successful domain output。

不得把 credential/config/HTTP 401 等错误包装成 A3 ValidationReport finding。

---

```text
src/short_drama/story/
```

Prompt `content_hash` 必须按 A-I3 Prompt Registry contract pin。

不得在 schema 中复制 ArtifactRef 的不同含义；shape 可 `$defs` 表达，但 Python authority 仍为现有 ArtifactRef typed contract。

## 27. CLI contract

开发阶段新增 stage-specific CLI：

```text
short-drama extract-chunks <project.yaml>
  --runs-root runs
  --chunk-profile <profile>
  --extraction-profile profiles/story_extraction_v1.yaml
  --runtime-config profiles/llm_local.yaml
  --llm-profile profiles/story_llm_qwen_v1.yaml
```

行为：

1. resolve current A1 SourceDocument；
2. resolve current A2 ChunkManifest for exact chunk profile；
3. verify A1/A2 ValidationReports；
4. iterate manifest chunks in deterministic order；
5. reuse exact validated current CandidateExtraction where eligible；
6. generate/validate/persist only missing/stale chunks；
7. fail closed on any chunk that cannot produce validated extraction；
8. return structured summary：

```text
chunks_total
chunks_reused
chunks_generated
chunks_failed
candidate_extraction_refs
validation_report_refs
```

不得因为一个 chunk reuse miss 而重跑所有 chunks。

内部 service 应同时支持 exact single-chunk extraction，方便 unit/integration tests；不必额外暴露第二个 CLI command。

## 29. Real local-Qwen smoke

Merge 前必须做 real A3 semantic smoke，不再只用 `{answer: 42}` synthetic schema。

Smoke 分两层：

### 29.1 Small controlled fixture

使用一个短小 source fixture，至少覆盖：

- 2 characters；
- 1 location；
- 1 fact；
- 1 event；
- 1 relationship；
- 1 ambiguous pronoun / unresolved mention；
- left/right context 至少一侧非空。

验证：

- CandidatePayload schema PASS；
- primary evidence 全在 ownership；
- cross refs closed；
- unresolved 没被强行解决；
- persisted CandidateExtraction + ValidationReport PASS；
- second identical run exact reuse。

复用 A1/A2 smoke 已验证的真实小说 source；不要求 A-I4 PR 跑完整小说所有 chunks 才能 merge，但至少选择 **连续 3 个 chunks**，其中应包含实际人物/事件上下文。

验证：

- extraction semantically plausible；
- source refs 全部可解析；
- ownership primary invariant 100% PASS；
- context evidence 不会冒充 ownership；
- local IDs/cross refs PASS；
- repeated run reuse；
- prompt/profile/source semantic identity change至少人工/测试证明会 invalidate reuse。

真实 smoke 主要验证 pipeline 与 evidence discipline，不把“文学理解完美”作为 merge gate。
