# v1.2 A5B — Relationship exact-safe v2 refinement

Issue #82 — state-independent exact-type relationship identity.

本文件是对冻结的 A5B v1 refinement 的一个小型、版本化补充；它不重释或修改 v1。

## Immutable v1

`a5-exact-safe-v1` 永远表示：

```text
(direction-aware endpoint identity, normalized relationship type, normalized optional state)
```

保留该定义和可测试实现，是为了使既有 plan identity 与历史审计可被准确解释，不能静默改写为 v2。

## Current v2

生产 authority 是 `a5-exact-safe-v2`。Relationship exact-safe key 为：

```text
(direction-aware endpoint identity, normalized exact relationship_type_zh)
```

`state_zh` 不在 identity key 中。relationship identity 不等于 relationship state；state 是 A5E `CanonicalRelationship.state_history` 的候选观察材料。v2 只接受 exact normalized type equality；例如 `朋友`、`好友`、`关系亲近` 之间不做 deterministic synonym merge，仍由 Relationship LLM semantic pass 决定。

## Unchanged authorities

- `consolidation-blocking-v1` 的 explicit pair universe 不变；
- `a5-pair-planning-v1` 的 pair construction、顺序、signals 和 packing algorithm 不变；
- Relationship prompt v1、selector schema v1、semantic packing v1 不变；
- endpoint direction、text normalization、Fact/Event exact-safe 行为不变；
- 同一 `same_relationship` component 内出现 `different_relationship` 仍 fail closed；finalizer 不作 graph repair。

## Identity and reuse

`plan_hash` 继续包含 exact-safe policy id、ordered pair states 和 deterministic decisions。因此 v2 的 policy id 与新增的 auto-same decisions 会产生新的 plan identity；旧 A5 CURRENT 不会 exact-reuse。这里不引入 partial-result caching。

## Non-goals

本 refinement 不改变 A5E state-history finalization、持久化/CURRENT、provider transport，且不执行 Fact/Event provider 工作或完整 A5G3 acceptance。
