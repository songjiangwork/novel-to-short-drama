# v1.2-B1.3 — Source Story Disposition（冻结）

## 职责

B1.3 将 immutable Source Canon 映射成 adapted narrative objects。

核心边界：

```text
Source Canon
≠
Adapted Continuity
≠
Screenplay Realization
```

B1.3 决定 source material 的 structural fate，并建立一等 provenance/mapping；不修改 A 层 canonical truth。

---

## Canonical Event Disposition

每个 CanonicalEvent 必须恰好有一个 disposition：

```text
keep
compress
merge_member
omit
```

### keep

核心 participants、causal function、outcome、dramatic identity 在 adaptation 中仍可辨认。

### compress

该 event 仍保有独立 adapted identity，但内部过程、细节、时间跨度、次要参与者或重复信息显著压缩。

### merge_member

该 source event 不再拥有独立 adapted identity，而成为某个 `source_composite` AdaptedStoryBeat 的组成部分。

### omit

该 source event 在 adapted continuity 中不发生；后续 screenplay 不得偷偷重新使用它。

如果 event 既被压缩又被合并，只使用 `merge_member`；压缩程度属于 mapping-level transformation。

---

## Exhaustive vs Selective Coverage

冻结规则：

```text
Canonical Events
→ exhaustive disposition coverage

Canonical Facts / Relationships
→ selective adaptation materialization, but traceable
```

Facts / relationships 不强制全部做 keep/omit；它们主要承担 continuity constraint、provenance 和 canon-compatibility validation。只有真正影响 adaptation 的部分进入 adapted continuity overlay。

---

## AdaptationMapping

Source → Adapted 之间的 mapping 是一等数据，不只是 Beat 中的一组 source IDs。

Mapping 至少需要能够表达：

- source endpoint
- adapted endpoint
- contribution role
- retained / transformed semantics
- provenance

Source ↔ Adapted 是 many-to-many graph：

```text
1 source event → multiple adapted beats
multiple source events → 1 adapted beat
```

因此不增加 `split` disposition；一对多 mapping 已自然表达 split。

---

## AdaptedCharacter

AdaptedCharacter 与 CanonicalCharacter 分离。

来源允许：

```text
source_single
source_composite
adaptation_invented
```

Composite character 表达的是 narrative-function transfer，不是 source entity merge。

必须保留 source character → adapted character 的 function provenance，避免把 adaptation role change 写回 CanonicalCharacter。

一次性、无 continuity 要求的功能角色可使用受控 `AnonymousRole`；持续/命名/continuity-relevant participant 必须解析为 AdaptedCharacter。

---

## AdaptedStoryBeat Origin

冻结 origin：

```text
source_direct
source_condensed
source_composite
adaptation_invented
```

`adaptation_invented` 仍必须有 adaptation provenance，例如 anchor canonical IDs、purpose、rationale 与 canon compatibility。

Invention purpose 使用受控分类：

```text
bridge
externalization
continuity_repair
setup
payoff
episode_hook
dramatic_escalation
deliberate_divergence
```

必要时允许 `other + rationale`。

---

## Canon Compatibility

Origin 与 canon compatibility 正交。

每个 adapted material 可以标记：

```text
compatible
deliberate_divergence
uncertain
```

即使 `source_direct`，如果真正改变了 source chronology / fact / relationship semantics，也可能是 `deliberate_divergence`。

仅改变观众 presentation order 的 flashback / teaser 不属于 source chronology mutation。

---

## Adapted Continuity Overlay

Adapted Continuity 使用：

```text
Source Canon
+
Adaptation Overlay
=
Effective Adapted Continuity
```

禁止复制全部 canonical facts 后再修改形成第二套 Story Bible。

Overlay 只记录 downstream screenplay consistency 所需的最小内容：

- identity mapping
- adapted factual divergence
- relationship state / arc requirements
- continuity-critical story state

如果改变 source fact，应引用原 fact，并显式记录 adapted assertion + deliberate divergence；不得覆盖 source fact。

---

## Deterministic Invariants

Python 必须验证：

```text
∀ CanonicalEvent:
exactly one disposition
```

以及：

```text
keep / compress / merge_member
→ >= 1 active AdaptationMapping

omit
→ 0 active AdaptationMapping
```

`merge_member` 至少要映射到一个包含多个 source events 的 `source_composite` beat。

Every material beat participant 必须解析为 AdaptedCharacter 或 controlled AnonymousRole。

Disposition 的 semantic 选择由 Qwen 完成；Python 不用文本长度等启发式规则推断 keep/compress。

---

## Windowed Planning

大规模 event disposition 可以按 plot / chronological windows 处理，但每个 window 必须带 global adaptation strategy 与 overlap context。

Cross-window 对同一 event 的冲突：

```text
keep vs omit
```

必须进入 reconciliation，禁止 last-write-wins。

最终正式 AdaptationPlan 仍要 materialize 所有 CanonicalEvent 的 disposition，不能依赖运行时从 plot strategy 临时推断。

---

## 冻结原则

1. Source Canon immutable。
2. CanonicalEvent 恰好一个 `keep | compress | merge_member | omit`。
3. Source ↔ Adapted mapping 是 many-to-many。
4. 不增加 `split` disposition。
5. AdaptationMapping 是一等 provenance。
6. AdaptedCharacter 与 CanonicalCharacter 分离。
7. Composite character = narrative-function transfer，不是 source entity merge。
8. AdaptedStoryBeat origin 与 canon compatibility 正交。
9. Adapted Continuity 是最小 overlay，不是 forked Story Bible。
10. Event coverage exhaustive；Fact/Relationship adaptation selective but traceable。
11. Cross-window conflict 必须 reconcile，禁止 last-write-wins。
12. B1.3 建立 adapted identities/mappings；完整 chronology、presentation 与 narrative coherence 由 B1.4 负责。
