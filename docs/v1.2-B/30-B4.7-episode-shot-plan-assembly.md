# B4.7 — Episode Shot Plan Assembly

状态：**FROZEN**

## 1. 职责

B4.7 是 deterministic canonical Shot Plan assembly stage，只负责 exact materialize B4.6 已验证的 Shot bundle。

正式输出：

```text
EpisodeShotPlan
```

它是 backend-agnostic、asset-unresolved、release-agnostic 的 canonical structured Shot Planning artifact。

## 2. Exact input / bundle binding

只接受：

```text
ShotPlanValidationReport.result = PASS
或 PASS_WITH_REVIEW_ITEMS
```

EpisodeShotPlan 必须保存：

```text
source_validated_shot_bundle_hash
```

且必须等于 B4.6 `validated_shot_bundle_hash`。

同时 exact pin：

- APPROVED EpisodeProductionPlan + ApprovalRecord
- EpisodeShotBreakdown revision/hash
- EpisodeShotSemanticsPlan revision/hash
- EpisodeShotContinuityPlan revision/hash
- EpisodeShotTimingPlan revision/hash
- ShotPlanValidationReport id/hash
- ShotPlanningConstraintProfile revision/hash（如有）

禁止 implicit latest。

## 3. Canonical composition

概念上：

```text
EpisodeShotPlan
├── id/revision/content_hash
├── approved ProductionPlan pin
├── validated bundle pin
├── ordered PlannedShot manifest
├── coverage mappings
├── camera semantics
├── continuity/transitions
├── timing/segmentation contracts
├── derived indexes
├── review-item refs
├── provenance
└── downstream compilation contract
```

## 4. Identity preservation

B4.7 必须继续使用 B4.2 stable `planned_shot_id`，不得创建第二套 authoritative Shot identity。

Display Shot Number 只是 derived presentation metadata。

`PlannedShotAssemblyEntry` 可以作为 composition wrapper，但不能改变 constituent identity。

## 5. No semantic authority

B4.7 不得：

- add/delete/split/merge/reorder Shot
- 修改 ProductionUnit ownership
- 修改 PRIMARY/SUPPORTING mapping
- 修改 shot purpose
- 修改 scale/viewpoint/movement/composition
- 修改 transition/continuity
- 修改 timing/segmentation policy

任何 semantic change 必须返回 authoritative B4.x stage，然后重新 B4.6。

## 6. Derived indexes

可以 deterministic 构建：

- PerceptualCoverageIndex
- ShotObligationIndex
- ShotSemanticsIndex
- ShotTransitionIndex
- ShotTimingIndex

这些都是 derived projections，不是新的 source of truth。

## 7. Provenance

EpisodeShotPlan 必须支持完整回溯：

```text
PlannedShot
→ PCR
→ ProductionUnit
→ ScreenplayElement
→ ScreenplayScene
→ AdaptedBeat
→ Source
```

同时可追：

```text
PlannedShot → StagingDirective / PerformanceRequirement / ProductionRequirement
```

## 8. Downstream canonical interface

Release Variant、Asset Resolution 与 execution compilation 应正式消费 `APPROVED EpisodeShotPlan`，而不是自己重新组合 B4.2–B4.5。

EpisodeShotPlan 仍不得包含：

- concrete images/WAV/LoRA
- Picture slots
- prompt/seed/workflow
- H3/ComfyUI/backend runtime
- exact aspect-ratio pixel geometry
- release-language exact TTS timing

## 9. DownstreamCompilationContract

EpisodeShotPlan 可提供轻量 interface section，区分：

### 不得 silent 改变

- Shot existence / sequence
- ProductionUnit ownership
- Shot purpose
- PRIMARY PCR responsibility
- reveal authority
- required visibility / core camera intent
- required transition semantics
- must-not-cut semantics

### downstream 可 refinement

- concrete aspect-ratio framing within semantic intent
- localized exact timing within allowed contract
- asset binding
- reference ordering
- prompt wording
- backend generation segmentation
- execution parameters / seed / attempts

## 10. ProductionShot lineage

未来每个 v1.1 ProductionShot 必须可追到：

```text
episode_shot_plan_id
revision
hash
planned_shot_id
```

一个 PlannedShot 可 compile 为 1..N ProductionShots；execution artifact 不应在语义上吞并多个 editorial PlannedShots。

## 11. PASS_WITH_REVIEW_ITEMS / FAIL

`PASS_WITH_REVIEW_ITEMS` 可生成 DRAFT EpisodeShotPlan，并把 unresolved REVIEW_REQUIRED findings 带入 B4.8。

`FAIL` 不得生成 approval-eligible canonical EpisodeShotPlan；工具可生成 diagnostic view，但不能混入 lifecycle。

## 12. Lifecycle / revision

B4.7 新建的 EpisodeShotPlan 只能为：

```text
DRAFT
```

它拥有独立 id/revision/content_hash。任意 B4.2–B4.5 semantic revision 或 ShotPlanningConstraintProfile revision 变化，必须创建新的 EpisodeShotPlan revision。

Render-only Markdown/PDF/UI 改动不产生 semantic revision。

## 13. RenderedShotPlan

正式区分：

```text
EpisodeShotPlan = canonical structured artifact
RenderedShotPlan = derived review representation
```

Renderer 必须 faithful，不能省略 REQUIRED coverage、改变 PRIMARY/SUPPORTING、隐藏 segmentation/continuity exceptions 或重排 Shots。

## 14. Deterministic assembly

正常 B4.7 完全由 Python deterministic 执行；同一个 validated bundle 重建结果必须 semantic-identical。

Qwen 只可辅助生成 derived summary / explanation，不得修改 canonical content。

Assembly 遇到 bundle/hash/ref drift 必须 fail closed，不重复 B4.6 semantic adjudication。

## 15. 冻结原则

1. B4.7 正式输出 versioned `EpisodeShotPlan`。
2. 只能 materialize exact B4.6 validated bundle。
3. Preserve stable PlannedShot identities。
4. Derived indexes 不是 source of truth。
5. EpisodeShotPlan 是 downstream 唯一 canonical Shot interface。
6. 保持 asset/backend/release unresolved。
7. Future ProductionShot 必须 pin PlannedShot lineage。
8. PASS_WITH_REVIEW_ITEMS 可生成 DRAFT；FAIL 不可生成 approval-eligible plan。
9. B4.7 deterministic、fail closed、无 creative authority。
10. 正式 approval 留 B4.8。
