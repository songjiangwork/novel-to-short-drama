## 候选 codec v1：封闭证据与绑定

以下是供审查的**精确候选**，不是已批准的生产格式。类型采用 R0D3 的 `ID`、`H`、`T`、`U+` 和 `S`；对象均封闭、表中每字段必填；除明确 `?` 外不允许 null。所有字符串无控制字符或 surrogate、按 UTF-8 长度计，不做 Unicode 归一化；拒绝未知键、重复键、浮点、负数、超 JS safe integer 和非规范编码。每个对象含 `schema_version: 1` 和固定 `codec`，独立 JCS UTF-8、无 BOM/换行；输入限制候选为每个对象 65536 bytes。对象 key 顺序由 RFC 8785 决定，数组保留以下指定顺序，不排序或去重隐藏差异；严格解析并与 JCS 重编码的原始 bytes 比较。`digest = SHA-256(完整原始 canonical bytes)`，以小写 64 hex 表示；`codec` 和版本在被哈希对象内提供类型域区分，不加未写出的前缀，也不含自身 digest。不同 codec 不能仅凭相同 digest 跨类型互换。版本、字段或解释改变须新 codec 版本，拒绝未知版本和降级；不修改现存 R1 content_hash 算法。

| codec 固定值 | 除 `schema_version`, `codec` 外的全部字段（均为候选） |
| --- | --- |
| `b13.provider-config.v1` | `id: ID`（transport ID）, `provider_family: ID`, `request_model: ID`, `transport_binding_ref: ID`, `timeout_decimal_seconds: S`。后两项的安全表达见决策表。 |
| `b13.model-config.v1` | `id: ID`（请求路由模型）, `deployment_ref: ID`, `model_revision_ref: ID`, `context_limit_tokens: U+`, `discovery_method: ID`。revision 必须来自可验证身份来源，显示名相同不够。 |
| `b13.tokenizer-config.v1` | `id: ID`, `implementation_ref: ID`, `version: ID`, `vocabulary_sha256: H`, `special_tokens_sha256: H`, `chat_template_sha256: H`, `discovery_method: ID`。各 hash 对应完整规范化、可独立验证的非秘密资产，codec 与取得途径待决。 |
| `b13.measurement.v1` | `source_ref: ID`, `method_id: ID`, `implementation_ref: ID`, `observation_id: ID`, `observed_at: T`, `provider_config_sha256: H`, `model_config_sha256: H`, `tokenizer_sha256: H`, `profile_sha256: H`, `prompt_sha256: H`, `schema_sha256: H`, `semantic_request_hash: H`, `rendered_prompt_sha256: H`, `packet_sha256: H`, `input_ceiling_tokens: U+`, `effective_n_ctx: U+`, `reserved_output_tokens: U+`, `rounds: Round[2]`。 |

`Round` 封闭为 `kind: "initial" | "regeneration"`、`execution_options: "provider_default" | "disabled"`、`mapped_body_sha256: H`、`provider_request_bytes: U+`、`estimated_input_tokens: U+`、`tokenizer_prompt_tokens: U+`、`budget_result: "PASS"`；数组恰按 initial/provider_default、regeneration/disabled 排列。重算测量输入包含完整 packet、profile、prompt、schema、runtime 配置和执行选项；完整敏感输入只在受保护内存中使用，不写入此记录。server tokenizer 测量须记录模板及特殊 token 参数和实现版本，候选 v1 固定为脚本的 `add_generation_prompt=true`、`parse_special=true`；如实际发送格式或算法不支持相同语义即 DENY。每个对象里的 `source_ref`/`observation_id` 只作关联，不自行建立可信来源；这些 ID 的颁发、观察结果绑定、可信存储和防重放是 OPEN DECISION。

`Runtime.provider_config_id/model_id/tokenizer_id` 与相应完整证据 `id` 逐项相等；其三个 `*_sha256` 与对应完整证据的上述 exact-byte digest 相等，必须取得并校验完整证据，不能只比调用方提供的 hash 字符串。measurement 必须绑定产生该测量的 Provider Config：其 `provider_config_sha256` 必须同时精确等于 `Runtime.provider_config_sha256` 和完整 canonical `b13.provider-config.v1` 原始字节的 SHA-256，不能只绑定 model 和 tokenizer。重建已固定 profile/prompt/schema 资产，按现有各自 codec 算其 ID 和 hash 并与 Runtime 对比；measurement 对各输入身份及两轮测量逐字段绑定。此 hash cross-link 是必要条件，但不能替代对实际 endpoint、认证主体、部署实例和测量来源的独立验证；ID、任意 `source_ref`、时间戳和自报部署元数据均不是证明。具体如何将观测绑定独立验证的精确连接及部署仍是 **OPEN DECISION**，未解决即 DENY。**OPEN DECISION：** R0D3 只有一个 runtime 测量 tuple，无法无歧义携带两轮结果；选择初始值加独立 measurement 引用、双轮字段或新版 preflight，均需冻结迁移和签名绑定，未定时不得将此候选接入真实 preflight。`rendered_prompt_sha256` 的 hash 域也须独立冻结。preflight 自身 SHA-256 是完整 preflight 字节的摘要，既不是 evidence digest，也不是 `b13_window_request_identity` 或 semantic request hash。

`timeout_seconds` 当前为 Python float，而 R0D3 禁止浮点：候选以十进制秒字符串保留精确配置值，**OPEN DECISION** 是 YAML 数值到字符串的无损规范化及范围；不能从 binary float 静默取整。`base_url` 与 credential 环境变量名可敏感，候选以外部受控 `transport_binding_ref` 代替，**OPEN DECISION** 是如何可靠绑定完整 endpoint、认证主体及其变化；不支持该绑定时无法建立完整配置身份，DENY。`provider_family`、`request_model` 当前只要求非空字符串而非 R0D3 ID，若不符合候选限制则拒绝并等待版本决策，不截断或重写。

## 私密性与测量

审批和公开审计制品不得含 API key、token、credential、endpoint secret、原始 URL、小说内容、完整 prompt、packet、请求或响应，也不得输出原始异常、服务端 body、变量名或秘密派生值；未来接口的错误使用有限的固定安全码；现有脚本可能在错误中包含 URL 或服务端响应片段，不能直接作为该安全日志接口。哈希不是加密：小说、模板或配置的低熵内容可被猜测，既有 `semantic_request_hash`、`rendered_prompt_sha256`、`packet_sha256` 也可能泄露关联信息。**OPEN DECISION：** 这些摘要的访问控制、保留期、隐私风险和是否允许公开；未解决时不发布真实证据。禁止以 secret hash 声称 credential 一致；不记录秘密造成的身份缺口必须由独立受信连接/主体绑定解决，未解决 DENY。

packet 是 JCS bytes；`_mapped_provider_request_bytes` 使用 `json.dumps(..., ensure_ascii=False).encode("utf-8")`，且适配器 `_map_request` 使用同一 JSON 表达构造 body。这不是 JCS，也不是含 headers、传输编码的网络 wire 长度；记录的 body 长度和 digest 应覆盖精确 body bytes，决不能对 `str(dict)` 哈希。构建该 body 的现有 `build_request_body` 会经过 `_map_request` 和 `resolve_auth_header`，因此并非可直接视为不接触凭据的纯映射；未来须提供无秘密的纯映射 seam，且验证其与实际发送 bytes 一致，不能调用现有路径来声称无副作用。

`estimate_tokens` 是 `max(1, ceil(UTF-8 bytes/3))` 的启发式，非实际模型 token 数；packet 估算也不是完整 prompt 测量。`count_prompt_tokens` 用服务端 chat template 渲染完整 messages，再 `parse_special` 分词；这是特定服务端自报的 token 数，不自动证明真实模型、模板或请求转换。须核验 tokenizer 实现/词表/模板与部署身份一致、特殊 token 参数、初始和再生成的完整请求；若 Provider 另加系统内容或不可观察模板，不能声称精确计数。对应 profile、prompt、schema 的已固定版本及内容须重新加载、重建 packet、semantic request、两轮映射 body；R0D3 单一 hash 域问题未决，不得猜测。

每轮独立验证：估算值和可信 tokenizer 计数均不超过 input ceiling，各自加 profile `max_output_tokens` 不超过有效 `n_ctx`；保留上限须等于发送 `max_tokens`，预算的 runtime model 必须匹配 request_model，检查现有 profile 限制及 structured output 能力。比较为 `<=`，任何缺失、溢出、身份不一致或超限 DENY，不截断。脚本现有初始和 cache-disabled 再生成 body 的启发式均检查；它对相同 messages 仅测一次服务端 token，不能由此证明未知 provider 实现的完整请求处理。effective context 必须来自可验证的实际部署和可用槽容量，override 只可降低已验证容量；是否有更严格 model/profile 限制及其可信来源仍须决定。

## 发现接口、阶段与失效

未来的独立发现接口须在不发送生成请求的情况下，给出有界、类型化的配置、模型部署、tokenizer/template、容量、观测时间及来源证明，绑定与实际请求相同的连接/部署；分别暴露自报与独立验证结果，不从 preflight 自建信任。它须验证发现源身份与完整性、配置和资产来源、观测事务与可信时钟，并确保数据在采集期间未变化。各阶段重查 measurement 与 Provider Config 的 hash cross-link，并独立验证测量和发现观察所用的精确 transport、endpoint、认证主体与部署实例的绑定；这些验证机制是 **OPEN DECISION**，不能由 hash 一致性推导，缺失即 DENY。现有脚本的 `/v1/models`、`/props`、`/slots`、`/apply-template`、`/tokenize` 是有用的自报接口，不是可信发现机制；服务端响应、显示 ID、进程重启或相同模型名均不能证明实际服务权重。即使获取了认证部署证明，是否能证明每次实际 serving model 仍是 **OPEN DECISION**；证明不足 DENY。

1. **preflight：** 未来获取经独立验证的 claim、source authority、CURRENT/EXPLICIT 和完整 runtime 观察；受可信时钟约束，重建资产和两轮测量，核对全部证据并冻结精确 preflight bytes/hash，供独立 live 签署。可信时钟来源、最大观测年龄和发现事务边界均为 OPEN DECISION；本提案不提供可信时钟。
2. **consumption 前：** 在同一连续 execution guard 下复查原始签署 preflight hash、签名和政策信任、claim、roots、checkpoint、CURRENT/EXPLICIT、固定槽位及所有 runtime 独立证据；重新发现并逐字段比较语义配置、身份、模型、tokenizer、容量、资产、packet、请求和两轮预算。新的 observation ID/time 必须由可信来源重新产生并满足未来明确的新鲜度规则；不能要求它们字节等于旧时间，也不能仅凭新的自报时间证明新鲜。核对 baseline 为 decision/consumption/terminal ABSENT；同一 guard 内合法持久化并验证的本次 decision 依 R0D3 阶段表可存在，不能把实时槽位重写进签署的 baseline。
3. **dispatch 前：** 同一 guard 内，验证本次 decision 和唯一 consumption 的精确关联并再次完整重新发现、重算、逐字段比对所有稳定身份和预算，以及 claim、authority、roots、checkpoint、签名及角色有效性；terminal/checkpoint 仍须 ABSENT。仅未来协议在所有独立门槛满足后才能考虑首次 dispatch。冻结的 baseline preflight bytes/hash 不随预期槽位转换改变，后续 observation 是新证据，不替换签名对象。

漂移、陈旧、错误、模型身份模糊、异常或无法检查均 DENY；保护旧 claim，不把缺失视为一致。仅在固定槽位仍允许新 invocation 时，才可在未来重新冻结新的 preflight 并取得独立新签署；已消费或可能消费后失败即视为已花费，不能重启、重新授权或重试。guard 只协调合作进程，不锁住外部 provider；两次读取相同值不能排除 ABA 或检查后变化。需可验证的部署代际/不可变绑定及连接贯穿至发送点；如无法证明，DENY。信任引导、撤销/时钟、原证据、决策和消费绑定仍分别依 R0D1/R0D3 的未决门槛。

## 合成向量与失败矩阵

仅为 codec 测试，以下完整 synthetic `b13.provider-config.v1` 原始 JCS UTF-8 bytes 无尾随换行；其 SHA-256 为 `02b11b2ad82bafb54440283064fa884e64084208c83b0e9d01126bb622186558`：

```json
{"codec":"b13.provider-config.v1","id":"transport.synthetic","provider_family":"synthetic","request_model":"synthetic-model","schema_version":1,"timeout_decimal_seconds":"30","transport_binding_ref":"synthetic-binding"}
```

此向量只测试编码和精确摘要，`synthetic-binding` 不证明 endpoint、credential 或真实部署；未解决的绑定规则禁止将它作为生产证据。合成完整测试还应固定两轮的 packet、prompt、schema、request bytes 和 tokenizer 结果，验证 `estimated=80`、`tokenizer=80`、`ceiling=80`、`reserve=20`、`n_ctx=100` 恰好满足不等式，再逐项加一产生 DENY。计数、digest 与输入必须由测试独立计算，不能凭下面的预期值冒充真实测量。

| 合成变化或故障 | 预期 |
| --- | --- |
| provider config、profile、prompt、model 或 tokenizer 任一证据漂移；显示 model ID 相同但底层 revision/config 不同 | DENY；不靠名称相同放行。 |
| 将配置 A 下取得的 measurement 移植到配置 B，即使 request_model 和其他摘要均相同 | DENY；measurement 的 `provider_config_sha256` 与 B 的完整证据及 Runtime 绑定不一致，重新计算 hash 也不能替代独立验证测量来源。 |
| 隐藏 credential 或 endpoint 变更，或无法独立验证其绑定 | DENY；不得对秘密值求公开 hash。 |
| `n_ctx` 变化、容量来源不明、观测过期、clock 失信、服务重启或部署身份模糊 | DENY；旧 observation 不能证明现状。 |
| CURRENT、semantic request、prompt、schema、packet 或初始/再生成 body 改变 | DENY 旧签署；分别重建并验证权威及每种字节身份。 |
| 缺失 codec/观察、旧 preflight 与新证据混用、错误版本、重复键、非法 JSON 或发现异常 | DENY，不以不完整结果替代。 |
| 数值超过 input ceiling 一 token，或 input + reserve 超过 context 一 token | DENY；边界相等可通过算术，但仍不构成证据或授权通过。 |
| 声称 hash 碰撞或不同对象仅 hash 相等 | DENY 并调查；比较类型及完整规范证据与可信输入，不接受调用方声称的碰撞或把 hash 相等当信任证明。 |
| 同时出现非本次的 decision/consumption/terminal，或预期槽位转换与同一 guard 内记录不符 | DENY；不能重建 baseline 或从已有 consumption 重启。 |
| observation ABA、检查后部署替换、guard 或连接绑定无法覆盖最后发送边界 | DENY；两次相等的快照不能证明中间未变化。 |

## 待决事项与后续门槛

| OPEN DECISION | 待审窄方案及拒绝的替代 | 实际验证前必须解决 |
| --- | --- | --- |
| 可信发现、服务/模型/部署身份、ABA 和连接绑定 | 独立认证部署代际并将观测绑定实际连接；拒绝仅凭模型显示名、响应或 session 自报。 | 证明来源、覆盖边界和不可证明实际 serving model 时的处理。 |
| endpoint、认证主体及 credential 变更 | 受控非秘密 binding reference 与独立验证接口；拒绝公开 secret hash 或遗漏后宣称完整一致。 | reference 生命周期、路由和主体/轮换的可验证绑定。 |
| tokenizer 资产、模板、测量方法 | 固定实现/词表/特殊 token/template 的完整证据与重测；拒绝只把字节估算称为精确 tokenizer。 | 资产 codec、来源、服务端处理差异及可信验证。 |
| provider config 数值和 ID | timeout 精确十进制字符串、保留原语义；拒绝浮点截断和静默改名。 | YAML 数值规范化、范围和不符合 ID 时的迁移。 |

| 可信时钟、新鲜度、快照原子性 | 可信时钟和受认证 observation transaction；拒绝仅用自报时间或时间间隔建立信任。 | 时钟来源、年龄、时序、故障和 ABA 证明。 |
| 敏感摘要、证据可见性与 retention | 仅受控访问的必要摘要和固定错误码；拒绝将 hash 当匿名化。 | 内容推测风险、访问控制、保留/删除与审批。 |
| policy、信任根、签名角色和 decision/consumption 绑定 | 沿 R0D1/R0D3 分离并独立认证；拒绝以 codec 验证或 PR 合并代替 ratification。 | #172 决策及受审 bootstrap、live 授权和新版本绑定。 |

架构审查通过并解决必要 codec 歧义后，可单独提出 **R0D4C2-B**：仅用合成数据的纯 codec 与证据比较；之后另行设计只读真实证据集成，并以可信 bootstrap、人类批准及剩余门槛为前提。任何阶段均不由本文授予实际执行权限。
