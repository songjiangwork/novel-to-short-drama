# B4.6 — Shot Plan Validation

状态：**FROZEN**

## 1. 职责

B4.6 是 Shot Planning 的 read-only integrated auditor。

```text
verify
+ diagnose
+ route
```

它不得 add/delete/split/merge Shot、修改 camera semantics、repair continuity、改 duration、重新分配 PCR 或 silent relax constraints。

## 2. Exact validation bundle

B4.6 验证 exact：

```text
APPROVED EpisodeProductionPlan
+
EpisodeShotBreakdown revision/hash
+
EpisodeShotSemanticsPlan revision/hash
+
EpisodeShotContinuityPlan revision/hash
+
EpisodeShotTimingPlan revision/hash
+
ShotPlanningConstraintProfile revision/hash（如有）
```

正式输出 immutable：

```text
ShotPlanValidationReport
```

并计算：

```text
validated_shot_bundle_hash
```

任意 constituent semantic revision 改变后旧 report 立即不适用。

## 3. Result / severity

统一使用：

```text
FAIL
PASS_WITH_REVIEW_ITEMS
PASS
```

Findings：

```text
BLOCKING
REVIEW_REQUIRED
WARNING
```

每个 finding 必须标记 earliest authoritative owner 与 recommended route。

## 4. Validation domains

至少覆盖：

- revision/reference integrity
- ProductionPlan fidelity
- Shot breakdown integrity
- PCR coverage completeness
- Shot purpose/provenance
- camera-semantic compatibility
- reveal/withholding/knowledge safety
- cross-shot continuity / transition
- ProductionContinuity reconciliation
- timing / pacing
- GenerationSegmentationContract safety
- ShotPlanningConstraintProfile compliance
- coverage economy / redundancy
- unauthorized upstream semantic change
- architecture-boundary leakage

## 5. PCR coverage

每个 REQUIRED PCR 必须至少一个 PRIMARY mapping，但：

```text
mapping exists ≠ semantic coverage complete
```

B4.6 必须检查 camera scale/composition/timing 等是否真的能够实现 obligation。SUPPORTING coverage 不能冒充缺失的 PRIMARY coverage。

一个 PCR 可由多个 Shots 联合满足，一个 Shot 可满足多个 PCR。

## 6. Shot purpose / economy

每个 PlannedShot 必须具有可解释的 authoritative purpose。

B4.6 应识别：

- decorative/orphan Shots
- template-driven establishing/reaction/SRS overgeneration
- meaningless fragmentation
- redundant coverage
- under-decomposition / attention overload

但重复视觉可能服务 tension、rhythm、emotional hold，因此 coverage economy 依赖 semantic/editorial 判断，不使用简单 Shot count gate。

## 7. Camera semantic validation

检查 ShotSemantics 是否支持：

- shot purpose
- PRIMARY PCR
- staging
- performance
- subject focus

Camera angle/movement 不得重新叙事或要求不存在的 staging。POV/OTS 必须 spatially/narratively valid。

## 8. Reveal / knowledge

继续保护：

```text
world truth
character knowledge
audience knowledge
```

Camera visibility 不等于 reveal authority。未经 approved upstream 授权的 premature reveal / knowledge leakage 为严重 finding。

## 9. Continuity validation

Integrated 检查：

- interaction axis
- screen direction
- eyeline
- entrance/exit
- match-on-action
- POV transition
- intentional discontinuity
- transition semantics
- audio bridge

Intentional 标记不自动免检。

Shot continuity 必须服从 B3 ProductionContinuity，不能用 framing/cut 隐藏 production contradiction。

## 10. Timing / pacing

验证每个 Shot timing 是否足以承载 dialogue/action/reaction/pause/readability，以及 must-hold/no-cut semantics。

同时 reconciliation ProductionUnit 与 episode duration constraints。Shot density/average duration 为 diagnostic，不是单一 quality gate。

## 11. Segmentation contract

B4.6 只验证 semantic segmentation contract：policy、safe candidates、forbidden regions 与 seam continuity 是否合理。

不验证具体 backend 是否能实现，也不实例化 generation segments。

如果所谓 generation seam 必须形成 visible cut，则 route B4.2，而不能隐藏在 ProductionShot 层。

## 12. Constraint profile

Hard constraint violation 默认 BLOCKING；soft/preferred violation 可 WARNING/REVIEW_REQUIRED。Validator 不得 silent relax profile；若 profile 要变，创建新 revision。

## 13. Architecture leakage

以下不应进入 canonical B4：

- concrete image/WAV
- Picture slots
- prompt/seed
- H3/ComfyUI/model/GPU
- backend-specific clip rules
- generation attempt/QC
- release-specific pixel geometry / exact TTS timing

合法 B4 semantics 包括 scale、POV/OTS、movement、screen direction、co-visibility、timing range、segmentation contract。

## 14. Finding schema

至少：

```text
finding_id
severity
category
summary
affected_refs
evidence
violated_contract
earliest_authoritative_owner
recommended_route
```

Evidence 使用 stable IDs，不以 mutable display shot number 作为唯一定位。

## 15. Python / Qwen

Python：pins/hashes、refs、ownership/order、mapping accounting、taxonomy、continuity mechanics、duration arithmetic、constraints、provenance。

Qwen：semantic coverage、camera compatibility、reveal、continuity、pacing、seam safety、coverage economy。

Qwen 没有 repair authority；B4.6 禁止 silent auto-fix。

## 16. Downstream

```text
PASS / PASS_WITH_REVIEW_ITEMS
→ B4.7 eligible

FAIL
→ no approval-eligible EpisodeShotPlan
```

B4.7 必须 exact materialize `validated_shot_bundle_hash`，不得改变 semantics。

## 17. 冻结原则

1. B4.6 是 read-only integrated Shot auditor。
2. `ShotPlanValidationReport` immutable，并绑定 exact bundle hash。
3. Mapping existence 不等于 semantic coverage completeness。
4. Validation 覆盖 camera/continuity/timing/segmentation/constraints/architecture boundaries。
5. Backend feasibility / concrete asset availability 不属于 B4.6。
6. Qwen 无 repair authority。
7. PASS 不等于 human approval。
8. B4.8 保留唯一 formal ShotPlan approval authority。
