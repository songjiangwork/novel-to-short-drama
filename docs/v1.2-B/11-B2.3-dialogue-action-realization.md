# B2.3 — Dialogue + Action Realization

状态：**FROZEN**

## 1. 职责

B2.3 在不改变 `EpisodeScenePlan` 和 B1 adaptation truth 的前提下，将每个 `ScreenplayScene` realization 成 action / dialogue / reaction / pause / subtext。

它不重新拆 Scene、不重新定义 objective/conflict/turn/outcome、不改 presentation order，也不进入 Shot Planning。

## 2. SceneRealization

正式引入：

```text
SceneRealization
```

```text
ScreenplayScene = 这场戏应该完成什么
SceneRealization = 这场戏具体如何完成
```

SceneRealization 至少 pin：

- EpisodeScenePlan id/revision/hash
- AdaptationPlan id/revision/hash/approval
- target scene_id
- relevant mappings / continuity / callback refs

SceneRealization 拥有独立 `realization_id / revision / hash`。

## 3. ScreenplayElement

B2.3 使用 ordered `ScreenplayElement[]`，不以不可验证的大块纯文本作为唯一 canonical 结构。

v1.2 核心 element 类型：

```text
ACTION
DIALOGUE
REACTION
PAUSE
```

ACTION 是观众可理解到的行为或可表现事件，不包含 camera / lens / framing / editing instruction。

REACTION 是 screenplay dramatic reaction，不等于 reaction shot。

PAUSE 表达 dramatic timing intent，不表达毫秒级 timing。

## 4. Dialogue / DialogueIntent

DIALOGUE 至少包含：

```text
speaker_id
surface_text
```

speaker 绑定 `AdaptedCharacter`，不绑定 voice asset。

重要对白可携带 `DialogueIntent`：

- intent
- subtext
- information payload
- emotional stance
- 必要时 truth relation（truthful / lie / belief / uncertain / speculation）

DialogueIntent 是 semantic preservation layer，用于 rewrite / QC / localization；不要求所有普通对白都重 annotation。

## 5. Promise / callback / quoted history

重要 promise、threat、reveal、callback、quoted history 应进入 `ScreenplayContinuityState`，不能依赖 Qwen 聊天记忆。

Callback 主要引用 semantic continuity identity，而不是 exact previous string。

如确需逐字回调，可标记 `wording_sensitive / quote_sensitive`。

## 6. Knowledge 与 truth separation

Character 只能基于当前 knowledge state 说出或行动于其可知信息。

必须保持：

```text
dialogue assertion ≠ world fact
character belief ≠ world truth
lie / speculation ≠ canonical truth
```

Knowledge acquisition timing 可以在 Scene 内动态变化，不能把整 Scene 当静态 snapshot。

## 7. Realization invention 边界

合法：

- minor action
- pause / delivery
- wording / rhetoric
- reaction
- incidental prop
- natural interaction
- small connective behavior

如果 incidental detail 开始产生 persistent causal dependency、future callback、knowledge consequence、relationship consequence 或 plot function，则它越界为 narrative invention，必须 `ADAPTATION_CHANGE_REQUIRED`。

Persistent narrative state change 必须有 B1 authorization。

## 8. Props 与 action consequence

允许 narratively meaningful prop 与 incidental prop。

Incidental prop 不自动升级为 Canonical Asset requirement。

概念上区分：

```text
ephemeral realization effect
persistent narrative effect
```

后者必须与 Adapted Continuity 对齐。

## 9. ScenePlan realization contract

B2.3 不得改变 `BeatSceneMapping` 或 `PresentationSceneMapping`。

每个 realization 必须真正实现 ScenePlan 的：

```text
objective
conflict
turn
outcome
```

并应能记录哪些 screenplay elements 承担这些 dramatic functions。

如果 decomposition 本身有问题，route 回 B2.2。

## 10. Duration / pacing

B2.3 必须消费 B2.2 scene duration budget。

可生成 `RealizationDurationEstimate` 作为 screenplay pacing estimate。

```text
realization duration estimate ≠ final video timing
```

固定字数/秒只能作为 heuristic，不能成为 authoritative timing rule。

## 11. ScreenplayContinuityDelta

每个 SceneRealization 可产生：

```text
ScreenplayContinuityDelta
```

例如：

- new promise
- recurring phrase introduced
- unresolved conversational tension
- callback seed
- recent entrance/exit
- minor realization-only state

Validated delta 可用于更新下一 Scene / 下一集的 screenplay overlay，但不得写入新的 adaptation truth。

Overlay 应能从 validated screenplay revisions 重建。

## 12. Regeneration 与 dependency invalidation

默认推荐 scene-by-scene generation。

单 Scene regeneration 合法，只要 ScenePlan 与 continuity contract 不变。

若 regeneration 改变 callback / promise / overlay dependency，Python 必须标记 downstream screenplay continuity dependency invalidation；不得 silent update downstream canonical artifacts。

## 13. Validation 与失败分类

B2.3 生成后做 scene-local fail-fast validation：

- speaker refs valid
- character knowledge legal
- required turn/outcome present
- mapping coverage realized
- continuity commitments satisfied
- no unauthorized narrative change
- duration plausible
- callbacks valid

失败至少区分：

```text
REALIZATION_RETRY
SCENE_PLAN_CHANGE_REQUIRED
ADAPTATION_CHANGE_REQUIRED
```

Qwen 不得 silent repair upstream semantics。

## 14. Language / production boundary

Canonical action / dialogue 默认 `zh-CN`。

Canonical wording 不是 immutable final spoken wording。

B2.3 不处理：

- voice file / TTS / voice ID
- subtitle timing / SRT layout
- ProductionLocation
- camera / shot / lens / framing
- H3 / ComfyUI

## 15. 职责分工

Qwen：creative semantic realization。

Python：reference resolution、state validation、callback registry、revision pinning、duration/coverage checks。

## 16. 冻结 contract

1. 正式存在 SceneRealization，与 ScreenplayScene 分离。
2. SceneRealization 拥有独立 revision/hash；B2.4 必须 pin exact revision。
3. Canonical realization 使用 ordered ScreenplayElements。
4. 核心 element 类型：ACTION / DIALOGUE / REACTION / PAUSE。
5. 重要 Dialogue 可携带 DialogueIntent。
6. Promise / callback 使用 semantic continuity identity。
7. Character knowledge / audience truth / world truth 分离。
8. Realization invention 合法，narrative invention 不合法。
9. B2.3 不得改变 BeatSceneMapping / PresentationSceneMapping。
10. realization 必须实现 objective / conflict / turn / outcome。
11. Persistent narrative state change 必须有 B1 authorization。
12. ScreenplayContinuityDelta 是 overlay delta，不是 narrative truth。
13. 默认 scene-by-scene generation，支持单 Scene regeneration。
14. 失败区分 REALIZATION_RETRY / SCENE_PLAN_CHANGE_REQUIRED / ADAPTATION_CHANGE_REQUIRED。
15. Qwen 无 silent repair authority。
