# v1.2-B / B6 — Asset Resolution 总览

状态：**FROZEN**

## 1. 目标与边界

B6 将一个 exact `APPROVED EpisodeReleaseVariant` 转换为可供 Execution Compilation 消费的 concrete asset authority。

核心分层：

```text
Semantic Entity / Requirement
≠ Concrete Asset
≠ Backend Reference Slot
```

例如：

```text
CharacterRef(Linsey)
≠ Linsey_full_body.png
≠ <Picture 3>
```

因此：

```text
B1–B5 = semantic world
B6 = concrete asset resolution
B7 = backend/execution compilation
```

B6 决定 **哪些 concrete assets 被授权**；B7 才决定这些已批准资产如何被某个 ProductionShot 以何种 role/order/slot 编译进 backend request。

## 3. Asset identity

Concrete asset 使用 stable `AssetRecord` 表示，至少具有：

```text
asset_id
asset_revision
content_hash
media_type
asset_kind
semantic subject refs
capability metadata
provenance
availability
```

必须保持：

```text
asset identity ≠ filesystem path / URI
```

Path / URI 只是 locator metadata。内容相同但位置变化通常不构成 semantic asset revision；同一路径内容 hash 改变则是不同 asset content。

## 4. Requirement / Candidate / Binding 分离

正式区分：

```text
AssetRequirement
≠ AssetCandidate
≠ ResolvedAssetBinding
```

- `AssetRequirement`：approved release semantics 需要什么 concrete asset capability。
- `AssetCandidate`：catalog 中可能满足 requirement 的 concrete AssetRecord。
- `ResolvedAssetBinding`：B6.4 从已评估 candidate space 中正式选定的 concrete binding。

一个 requirement 可以由 1..N complementary assets 联合满足；一个 AssetRecord 也可以服务多个 requirements。

## 5. AssetEvidence

B6.3 正式使用 `AssetEvidence` 支持 compatibility judgment，例如：

```text
METADATA_EVIDENCE
VISUAL_INSPECTION_EVIDENCE
AUDIO_INSPECTION_EVIDENCE
CONTENT_HASH_EVIDENCE
PROVENANCE_EVIDENCE
HUMAN_VERIFICATION_EVIDENCE
DERIVATION_EVIDENCE
```

Evidence 必须 pin exact asset revision/content hash；content change 后旧 evidence 不自动继承。

Visual/audio capability 在 trusted metadata 不足时应基于实际 content inspection，而不是 filename 猜测。

## 6. Continuity

B6 不只验证单 asset fitness，还必须维护 episode-level asset continuity，例如：

- character identity consistency
- costume / hair / injury / appearance-state continuity
- location identity / spatial landmark consistency
- prop state / localized visual text
- voice identity consistency

同一 canonical state 可以使用 face/full-body/profile 等不同 concrete files，只要它们属于 coherent identity/appearance state；continuity 不等于 exact same file。

## 7. Minimum sufficient asset set

B6 遵循：

```text
minimum sufficient compatible asset set
```

不能因为“多给几张可能更好”就无条件堆 asset。每个 selected asset 必须能解释其 capability contribution。

但这里的 minimality 是 semantic asset economy，不是 backend reference budgeting。H3 的 ref 数量、Picture slot 等不进入 B6 authority。

## 8. Missing asset

B6 保持：

```text
resolution ≠ generation
```

如果 required concrete asset 不存在，应显式产生：

```text
ASSET_CREATION_REQUIRED
CATALOG_EXPANSION_REQUIRED
EVIDENCE_REQUIRED
```

而不是创建 placeholder 并假装 resolved。

新 asset 必须先 register `AssetRecord`、记录 hash/provenance/availability、进入 catalog，再重新经过 evaluation/binding/validation。

## 9. Backend firewall

B6 不绑定：

- `Picture N`
- H3 reference slot / ordering
- ComfyUI node
- prompt wording
- seed / sampler
- backend ref limits
- `ProductionShot`
- concrete execution segmentation

核心：

```text
B6 decides WHICH assets are authorized.
B7 decides HOW authorized assets are compiled.
```

## 10. Validation / Assembly / Approval

```text
B6.5 = read-only integrated validation
B6.6 = deterministic canonical assembly
B6.7 = B6 唯一 formal human approval gate
```

B6.5 生成：

```text
validated_asset_resolution_bundle_hash
```

B6.6 exact materialize 已验证 bundle，并保存：

```text
source_validated_asset_resolution_bundle_hash
```

B6.7 批准 exact：

```text
EpisodeResolvedAssetPlan id
+
revision
+
content_hash
```

## 11. Downstream authority

同一个 exact `EpisodeReleaseVariant` 最多一个 current `APPROVED EpisodeResolvedAssetPlan` revision。

B7 必须 pin exact approved plan，并只能从该 plan 的 effective asset universe 中选择 Shot-specific subset；不得绕回 AssetCatalog 自行重新选择 arbitrary assets。

Backend execution failure 不自动 invalidate B6 approval。只有确认 concrete asset semantic resolution 本身错误时才回 B6。

## 12. Python / Qwen / Human

```text
Python
= refs / IDs / revisions / hashes / catalog membership /
  capability coverage / inheritance / provenance /
  deterministic assembly / lifecycle / validation

Qwen
= semantic asset-fit / visual-audio compatibility /
  continuity coherence / candidate comparison / diagnosis

Human
= B6.7 final concrete asset approval
```

Qwen 可以辅助判断和解释，但不能 invent AssetRecord、绕过 hard incompatibility、repair validator 或 self-approve。

## 13. 状态语义

```text
EpisodeResolvedAssetPlan
→ APPROVED

Generated media candidate
→ ACCEPTED / REJECTED / RETRY
```

`APPROVED EpisodeResolvedAssetPlan` 不等于 backend reference assignment、H3/ComfyUI execution 或最终媒体已经通过。
