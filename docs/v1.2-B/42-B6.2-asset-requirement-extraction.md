# B6.2 — Asset Requirement Extraction

状态：**FROZEN**

## 1. 职责

B6.2 从 exact `APPROVED EpisodeReleaseVariant` 与 `EpisodeAssetResolutionContext` 中 deterministic 提取必须由 concrete assets 满足的 semantic asset contract，但**不选择任何具体 AssetRecord**。

正式输出：

```text
EpisodeAssetRequirementPlan
```

核心边界：

```text
AssetRequirement
≠ AssetCandidate
≠ ResolvedAssetBinding
```

## 2. EpisodeAssetRequirementPlan

建议至少包含：

```text
requirement_plan_id
revision
content_hash
source_asset_resolution_context_ref
source_episode_release_variant_ref
asset_requirements[]
requirement_groups[]
continuity_groups[]
consumer_mappings[]
dependency_graph
extraction_conflicts[]
```

B6.2 应在 asset catalog 为空时仍能完整产生 requirement plan；否则说明与 candidate discovery 混层。

## 3. AssetRequirement

至少包含：

```text
asset_requirement_id
requirement_type
semantic_subject_ref
applicability_scope
source_obligation_refs[]
required_capabilities[]
preferred_capabilities[]
continuity_constraints[]
release_constraints[]
combination_policy
criticality
fallback_policy
provenance
```

Requirement identity 必须稳定，不能依赖 array/display order。

## 4. Requirement taxonomy

初始至少允许：

```text
CHARACTER_VISUAL_IDENTITY
CHARACTER_APPEARANCE_STATE
LOCATION_VISUAL_IDENTITY
LOCATION_DETAIL_SUPPORT
PROP_VISUAL_IDENTITY
VOICE_IDENTITY
PREEXISTING_AUDIO_CONTENT
VISUAL_TEXT_SOURCE
OTHER_SEMANTIC_ASSET
```

禁止 backend-specific `H3_CHARACTER_REF` / `PICTURE_SLOT` 等类型。

## 5. Character identity / appearance state 分离

必须区分：

```text
这是 Linsey
```

与：

```text
这是 school-uniform-A / hair-state-X / injury-state-Y 的 Linsey
```

因此 canonical identity 与 scene/continuity-specific appearance state 可以由不同 complementary requirements 表达。

这允许 face/full-body/profile 等多张 concrete assets 后续共同满足同一角色的不同 capability，而不要求“一张图包办所有需求”。

## 6. Required / Preferred capabilities

Requirement 明确区分：

```text
required_capabilities
preferred_capabilities
```

缺 required capability → candidate 不得作为完整解。

缺 preferred capability → candidate 仍可能有效，但可能产生 limitation/review item。

## 7. Criticality

至少：

```text
REQUIRED
CONDITIONAL
OPTIONAL
```

`CONDITIONAL` 必须具有可解析 trigger；不能把 unresolved conditional 默认为 active/inactive。

## 8. Combination policy

Requirement 可表达：

```text
SINGLE_SUFFICIENT
COMPLEMENTARY_ALLOWED
COMPLEMENTARY_REQUIRED
ALTERNATIVE_ONE_OF
```

因此一个 semantic requirement 可以由 1..N concrete assets 联合满足。

但 multiple assets 是 semantic resolution 能力，不等于 backend multiple refs。

## 9. RequirementGroup

`AssetRequirementGroup` 表示一组必须联合考虑的 logical requirements，例如：

```text
Linsey Character Package
- identity
- face detail
- appearance state
- full-body support
```

必须保持：

```text
RequirementGroup ≠ ResolvedAssetSet
```

前者是需求，后者是后续 concrete resolution。

## 10. Applicability scope

Schema 至少允许：

```text
SERIES
EPISODE
SCENE
PRODUCTION_UNIT
PLANNED_SHOT
UTTERANCE
```

尽量使用最稳定且足够窄的 scope。

Episode-level identity 可被多个 Shots reuse；Shot-specific detail 不应错误提升成 episode-global requirement。

## 11. Provenance

每个 requirement 必须回答“为什么需要它”。

典型链：

```text
AssetRequirement
→ ReleaseShotRealization / LocalizedUtterance
→ PlannedShot / B5 semantic obligation
→ PCR / ProductionUnit / upstream provenance
```

Resolver 不得凭审美自行创造 narrative asset requirement。

## 12. Deduplication

同一 semantic requirement 可能由多个 consumers 触发。B6.2 应 deterministic dedupe，并保留所有 `source_obligation_refs` / consumer refs。

但不同 continuity/appearance states 不得错误合并。

```text
Linsey school_uniform_A
≠ Linsey rain-soaked_state_B
```

## 13. Asset continuity groups

正式支持 `AssetContinuityGroup`，用于表达多个 scopes/consumers 必须保持同一 canonical identity/state compatibility。

必须保持：

```text
asset continuity ≠ exact same file
```

face/full-body/profile 可以是不同 files，只要后续 evidence 证明它们属于同一 coherent identity/state。

## 14. Visual text

普通 subtitle track 不产生 visual asset requirement。

只有 text 作为 scene 中实际可见并具有 semantic obligation 的内容，例如：

- 手机短信
- 信件
- 屏幕 UI
- 门牌/剧情线索文字

才产生 `VISUAL_TEXT_SOURCE` requirement。

Release-specific localized visual text 必须 pin B5 已批准的 localized semantic content。

## 15. Voice requirement

`VOICE_IDENTITY` 表示 reusable character voice reference need，例如：

```text
speaker = Linsey
target locale = zh-CN
```

普通 performance instruction（愤怒、低声、急促）不自动创建新的 voice asset requirement；它通常属于 execution/performance instruction。

必须区分：

```text
VOICE_REFERENCE
≠ PREEXISTING_UTTERANCE_AUDIO
```

只有后者才可以用 concrete clip 的 measured duration 做 timing compatibility。

## 16. Minimum sufficient requirements

正式原则：

```text
Extract the minimum sufficient asset requirement set
needed to realize the approved release semantics.
```

Decorative enrichment 不应成为 canonical requirement。

例如普通教室海报不需要 requirement；若海报文字是剧情线索，则需要。

## 17. Requirement contradiction

如果提取后发现同一 continuity scope 中存在互斥 requirements，应显式：

```text
ASSET_REQUIREMENT_CONTRADICTION
```

并 route 到 B6.2 或更早 authoritative upstream；不得 silent normalize。

## 18. Backend firewall

Requirement extraction 不受 backend ref limits 影响，不包含：

- candidate filenames
- candidate scores
- Picture N
- H3/ComfyUI slots
- prompt/seed

## 19. Python / Qwen

Python：traverse exact ERV、extract refs、stable IDs、dedupe、scope、provenance、consumer mappings、hash。

Qwen：仅用于 ambiguous semantic interpretation、capability wording、continuity implications、conflict diagnosis；不得凭审美创造新 requirement。

## 20. 冻结原则

1. B6.2 只提取 requirements，不选择 assets。
2. 输出 `EpisodeAssetRequirementPlan`。
3. Requirement / Candidate / Binding 严格分离。
4. Requirements deterministic 来源于 APPROVED ERV semantics。
5. 每个 requirement 必须有 exact provenance。
6. 使用 minimum sufficient requirement set。
7. Character identity 与 appearance state 分离。
8. Voice reference 与 generated utterance audio 分离。
9. 一个 requirement 可由 multiple complementary assets 满足。
10. Required / preferred capability 分离。
11. Criticality 至少 REQUIRED / CONDITIONAL / OPTIONAL。
12. Same requirement deterministic dedupe；不同 continuity state 不合并。
13. Continuity 表示 state compatibility，不等于 same file。
14. Ordinary subtitles 不产生 visual asset requirement。
15. Performance instruction 不自动成为 voice asset requirement。
16. Backend ref limits 不影响 requirement extraction。
17. Empty catalog 下仍必须能完整生成 requirement plan。
18. 不包含 candidate filename/score/ranking。
19. Contradiction 显式报告。
20. B6.2 backend-agnostic。
