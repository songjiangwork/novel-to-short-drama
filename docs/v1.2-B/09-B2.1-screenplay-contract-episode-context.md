# B2.1 — Screenplay Contract / Episode Context

状态：**FROZEN**

## 1. 职责

B2.1 不写最终 screenplay。它负责从已批准的 adaptation truth 中，为目标 episode 构建 authoritative screenplay generation context。

正式输入：

```text
APPROVED AdaptationPlan revision
+
target EpisodePlan
```

核心输出：

```text
EpisodeScreenplayContext
```

## 2. Authoritative input 与 fail-closed

B2 只能消费 `APPROVED AdaptationPlan revision`，不能消费未批准 draft、聊天记忆或临时人工总结。

每个 EpisodeScreenplay 必须最终 pin：

```text
adaptation_plan_id
adaptation_plan_revision
adaptation_plan_hash
approval_record_id
```

ApprovalRecord 或 revision/hash 无法确定时必须 fail closed。

## 3. EpisodeScreenplayContext

至少解析：

- episode dramatic goal
- core conflict
- required PresentationEntries
- required AdaptedStoryBeats
- episode climax
- ending hook
- opening continuity state
- required ending state
- reveal constraints
- withholding constraints
- character arc checkpoints
- relationship checkpoints
- relevant AdaptedCharacters
- AdaptedContinuity subset
- relevant Story Skeleton subset

`EpisodeScreenplayContext` 是 deterministic derived artifact，不是 authoritative truth；应能从 approved upstream truth 重新构建。

## 4. Hierarchical context

生成 Episode N 不应加载 Episode 1–N-1 的全部 screenplay。

推荐上下文：

```text
Approved Adaptation Strategy
+
global character / relationship state
+
global reveal constraints
+
target EpisodePlan
+
relevant beats
+
previous episode ending checkpoint
+
recent screenplay continuity
+
selected long-range callbacks
```

适用于 20 / 50 / 100 集长剧。

## 5. B1 checkpoint → B2 opening context

B1.5 的 episode-boundary continuity checkpoint 正式成为 B2 input。

B2 可以维护 `ScreenplayContinuityState`，用于 realization-level continuity，但它只是 overlay，不得违反 Adapted Continuity。

## 6. Realization invention 与 narrative invention

B2 允许 realization invention，例如：

- incidental action
- dialogue wording
- reaction
- minor transition
- dramatic behavior
- small connective action

B2 不允许未经 B1 修订创造 narrative invention。

如果一个 screenplay invention 改变 fact、causality、knowledge、relationship、major motivation、beat outcome 或 future dependency，则必须返回 B1。

B2 不得创建新的 `AdaptedStoryBeat`。

## 7. ScreenplayScene 与 mapping

B2 正式引入 stable-identity first-class object：

```text
ScreenplayScene
```

`AdaptedBeat ↔ ScreenplayScene` 是 many-to-many，不能冻结为 `1 beat = 1 scene`。

必须显式存在：

```text
BeatSceneMapping
```

用于回答某个 Scene 实现了哪些 Beat，以及实现了 Beat 的哪部分 dramatic function。

## 8. Dramatic setting 与 production asset 分离

B2 可以定义：

```text
INT. CLASSROOM - DAY
Linsey's bedroom
hospital corridor
```

这些属于 dramatic setting，不是 ProductionLocation、reference image 或 ComfyUI background。

## 9. Scene dramatic semantics

Scene 至少表达：

```text
scene objective
conflict
turn
outcome
participants
dramatic setting
```

粒度：

```text
Character Arc Goal ≠ Episode Goal ≠ Scene Objective
```

## 10. Dialogue semantic layer

Canonical screenplay 默认工作语言：

```text
zh-CN
```

重要对白可保留：

```text
surface dialogue
+
DialogueIntent
```

`DialogueIntent` 可表达 speaker、intent、subtext、information conveyed、emotional stance。

Canonical dialogue wording 不是 immutable final spoken wording。Localization downstream 可生成 English / French / other variants，同时保持 semantic intent。

Dialogue speaker 绑定 `AdaptedCharacter`，不绑定 WAV / TTS voice / MiniMax voice ID。

Dialogue 也不是 subtitle artifact；SRT/VTT/ASS 在后期 timeline 确定后生成。

## 11. Targeted context expansion

Qwen 可以声明需要哪类 authoritative context，例如：

```text
need REL_CP_004
need prior promise P_012
```

Python 通过 stable ID deterministic retrieval。

原则：

```text
Qwen identifies semantic need
Python resolves authoritative evidence
```

## 12. 防止 dialogue memory hallucination

重要 promise / callback / quoted history 必须进入结构化 `ScreenplayContinuityState`，不能依赖模型聊天记忆。

未知 callback 应在后续 validation 中报错。

## 13. Screenplay revision

EpisodeScreenplay 拥有独立 revision。

合法修改包括 dialogue、action realization、scene decomposition、dramatic pacing，只要不改变 B1 adaptation truth。

若修改改变 narrative semantics：

```text
ADAPTATION_CHANGE_REQUIRED
```

必须回 B1。

## 14. Context build 职责

Python：

- verify approval
- resolve IDs
- build context package
- extract continuity
- enforce episode membership
- resolve reveal constraints
- pin revision/provenance
- validate package

Qwen：

- screenplay semantic realization
- scene reasoning
- dialogue
- action
- subtext
- dramatic pacing

## 15. 冻结 contract

1. B2 只消费 APPROVED AdaptationPlan revision。
2. B2 戏剧化 adaptation truth，不重新定义 adaptation truth。
3. EpisodeScreenplayContext 是 deterministic derived artifact。
4. 使用 hierarchical context，不依赖全部历史 screenplay。
5. B1 episode continuity checkpoint 正式成为 B2 opening context。
6. Screenplay Continuity 是 overlay，不得违反 Adapted Continuity。
7. Realization invention 合法，narrative invention 不合法。
8. B2 不得创建新的 AdaptedStoryBeat。
9. ScreenplayScene 是 stable-identity first-class object。
10. AdaptedBeat ↔ ScreenplayScene many-to-many。
11. BeatSceneMapping 必须显式可追踪。
12. DramaticSetting 是 semantic setting，不是 production asset。
13. Canonical screenplay 默认 zh-CN。
14. 最终 spoken language downstream configurable。
15. Dialogue text 不是 subtitle artifact；speaker 不绑定 voice asset。
16. 每个 EpisodeScreenplay 必须 pin exact approved upstream revision/hash/approval。
17. 无法 deterministic 构建 authoritative context 时 fail closed。
