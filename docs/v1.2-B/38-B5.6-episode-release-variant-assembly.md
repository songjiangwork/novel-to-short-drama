# B5.6 — Episode Release Variant Assembly

状态：**FROZEN**

## 1. 职责

B5.6 只做 **deterministic assembly**。

它不再进行 localization、framing、subtitle、audio 或 timing semantic reasoning，也不修复 B5.5 finding。

正式输入：

```text
ReleaseVariantValidationReport.result
∈ { PASS, PASS_WITH_REVIEW_ITEMS }
```

正式输出：

```text
EpisodeReleaseVariant
```

## 2. EpisodeReleaseVariant 定义

`EpisodeReleaseVariant` 是：

> 一个 episode 面向一个明确 ReleaseVariantIdentity 的、versioned、backend-agnostic、asset-unresolved、经过 integrated validation、可审批的 canonical release-specific semantic artifact。

它仍然不是：

- concrete assets
- ProductionShot
- H3 prompt
- ComfyUI workflow
- generated media

## 3. Exact validated bundle

B5.6 必须保存：

```text
source_validated_release_variant_bundle_hash
```

并满足：

```text
EpisodeReleaseVariant.source_validated_release_variant_bundle_hash
==
ReleaseVariantValidationReport.validated_release_variant_bundle_hash
```

Assembly 前必须重新计算 exact source bundle hash。

若 mismatch：

```text
ASSEMBLY_BLOCKED
SOURCE_BUNDLE_CHANGED_AFTER_VALIDATION
```

即使只修改一句 subtitle，也必须重新 B5.5。

## 4. Deterministic assembly only

B5.6 可以：

```text
resolve
verify
assemble
index
hash
record provenance
```

不得：

- 重新翻译 dialogue
- 选择另一个 localization candidate
- 调整 framing
- 修改 subtitle text/cue
- 修改 release duration/hold
- 修改 audio bridge
- 修改 segmentation realization
- 修改 release profile

```text
B5.6 MUST NOT perform semantic mutation.
```

## 5. EpisodeReleaseVariant 结构

建议至少包含：

```text
EpisodeReleaseVariant
{
  episode_release_variant_id
  revision
  content_hash
  lifecycle_status

  source_episode_shot_plan_ref
  source_release_variant_context_ref
  source_dialogue_localization_plan_ref
  source_release_framing_plan_ref
  source_release_timing_plan_ref
  source_validation_report_ref
  source_validated_release_variant_bundle_hash

  release_variant_identity
  release_target_profile_ref

  localized_utterances[]
  shot_framing_realizations[]
  shot_timing_realizations[]
  subtitle_realizations[]
  audio_semantic_realizations[]

  derived_indexes
  provenance_manifest
  pending_review_items[]
}
```

## 6. Lifecycle

B5.6 创建：

```text
DRAFT
```

EpisodeReleaseVariant lifecycle：

```text
DRAFT
APPROVED
SUPERSEDED
ABANDONED
```

只有 B5.7 human gate 可以产生正式 APPROVE decision。

## 7. Approval scope difference from B4

同一 episode 可以同时存在多个不同 ReleaseVariantIdentity 的 current approved variants。

约束是：

```text
one episode
+
one ReleaseVariantIdentity
→ at most one current APPROVED revision
```

而不是一个 episode 全局只能有一个 approved EpisodeReleaseVariant。

## 8. Variant identity / revision

必须保持：

```text
ReleaseVariantIdentity ≠ revision
```

同一 target definition 下的 localization/framing/subtitle/timing semantic change通常创建同一 variant identity 的 new revision。

Aspect ratio、spoken locale、material subtitle/presentation profile 等 identity-defining target change 是否形成新 identity，由 B5.1 ReleaseVariantIdentity contract 决定；B5.6 只继承，不重新判断。

## 9. Downstream authority

B5.7 approval 后，正式 downstream 应消费：

```text
APPROVED EpisodeReleaseVariant
```

而不是自己重新拼：

```text
B5.2 + B5.3 + B5.4
```

Downstream 可以 inspect constituent provenance，但不能重新选择 localization/framing/timing candidate。

## 10. Canonical snapshot + refs

EpisodeReleaseVariant 应保存足够完整的 deterministic assembled semantic snapshot，使 downstream 不需要动态读取 B5.2–B5.4 才能运行。

同时保留 exact refs/provenance。

原则：

```text
assembled snapshot
= deterministic copy/projection of validated source bundle
≠ new independently editable source of truth
```

如果内容需要变：

```text
change owning constituent artifact
→ B5.5
→ B5.6 new revision
```

不能直接手工编辑 assembled variant。

## 11. ReleaseShotRealization

B5.6 可以 deterministic 派生：

```text
ReleaseShotRealization
```

概念结构：

```text
ReleaseShotRealization
{
  planned_shot_id
  canonical_shot_ref
  framing_spec_ref
  timing_spec_ref
  related_localized_utterance_refs[]
  related_subtitle_cue_refs[]
  related_audio_event_refs[]
}
```

它是 normalized assembled view，不是新的 semantic authority。

## 12. No new editorial Shot identity

B5 不改变 editorial Shot structure，因此一般不需要独立 authoritative release_shot_id。

ReleaseShotRealization identity 可以由：

```text
EpisodeReleaseVariant identity + planned_shot_id
```

派生。

真正的新 execution segment identity 留到 `ProductionShot`。

## 13. Full provenance

EpisodeReleaseVariant 必须保留 canonical + release 双重 provenance：

```text
ReleaseShotRealization
→ PlannedShot
→ PCR
→ ProductionUnit
→ ScreenplayElement
→ ScreenplayScene
→ AdaptedStoryBeat
→ Source
```

同时：

```text
ReleaseShotRealization
→ ReleaseVariantIdentity
→ localization realization
→ framing realization
→ release timing realization
```

## 14. Provenance manifest

正式建议构建：

```text
ReleaseVariantProvenanceManifest
```

至少记录：

- EpisodeShotPlan ref
- ShotPlanApprovalRecord ref
- B5.1/B5.2/B5.3/B5.4 refs
- B5.5 ValidationReport ref
- pinned profiles/registries
- validated_release_variant_bundle_hash

关键 item-level trace 也应保留，例如：

```text
LocalizedUtterance → source screenplay element
SubtitleCue → LocalizedUtterance
FramingSpec → PlannedShot/ShotSemanticSpecification
ReleaseTimingSpec → B4.5 ShotTimingSpecification
```

## 15. Completeness / no implicit inheritance

最终 EpisodeReleaseVariant 必须显式覆盖：

- every PlannedShot
- every selected localized utterance
- every framing realization
- every release timing realization
- every applicable subtitle realization
- every required audio semantic realization

即使 framing/timing 与 canonical 不需要明显变化，也应显式记录 `PRESERVED` realization。

禁止：

```text
missing = inherit/default
```

## 16. Derived indexes

B5.6 可以 deterministic 构建：

```text
ReleaseShotIndex
LocalizedUtteranceIndex
SubtitleCueIndex
AudioEventIndex
ReleaseTimingIndex
CanonicalToReleaseShotIndex
ReleaseToCanonicalProvenanceIndex
```

这些 indexes 是 derived acceleration/projection，不是 source of truth。

## 17. Pending review items

如果 B5.5 是：

```text
PASS_WITH_REVIEW_ITEMS
```

所有 REVIEW_REQUIRED findings 必须进入：

```text
pending_review_items[]
```

B5.6 不得解决、删除或重新解释这些 review items。

WARNING 可进入 validation summary，但默认不要求逐条 formal disposition。

## 18. Validation summary

EpisodeReleaseVariant 可以保存 derived：

```text
validation_summary
{
  result
  blocking_count
  review_required_count
  warning_count
}
```

Authority 仍来自 exact `ReleaseVariantValidationReport`。

## 19. Content hash

`EpisodeReleaseVariant.content_hash` 必须覆盖 canonical assembled release semantic content，例如：

- variant identity
- source refs
- selected localization
- selected framing
- selected timing
- subtitle/audio semantic realization

不应包括 volatile：

- generated_at
- filesystem path
- machine name
- temporary cache id

Canonical serialization / ordering 必须 deterministic。

## 20. Assembly contract version

可以记录：

```text
assembly_contract_version
```

用于说明 deterministic assembly schema/contract 版本，但不把具体 code commit hash 当成唯一 semantic version authority。

## 21. Semantic immutability

APPROVED EpisodeReleaseVariant revision immutable。

任何 release semantic change，例如：

- localized wording
- subtitle text/cue timing
- framing realization
- release timing
- semantic audio realization
- pinned terminology/safe-area profile effect

都必须：

```text
new owning constituent revision
→ B5.5
→ B5.6 new revision
→ B5.7
```

## 22. Render-only change

如果只是：

- codec
- bitrate
- container
- encoder preset
- font rasterization
- exact render implementation

且没有改变 approved semantic release artifact，则不要求 new EpisodeReleaseVariant revision。

但 subtitle wording/cue semantics/timing 不是 render-only。

## 23. Asset Resolution boundary

B5.6 仍然 asset-unresolved。

不选择：

- concrete face/full-body image
- background reference
- voice WAV
- TTS model
- LoRA
- H3/ComfyUI refs

下一阶段 Asset Resolution 根据 APPROVED EpisodeReleaseVariant 解决 concrete assets。

可派生轻量 semantic asset requirements，但不应在 B5.6 再建立一套 mandatory asset-resolution source of truth。

## 24. Execution Compilation boundary

正式链：

```text
APPROVED EpisodeReleaseVariant
↓
Asset Resolution
↓
Execution Compilation
↓
1..N ProductionShots per PlannedShot
```

B5.6 不跳过 Asset Resolution，不直接创建 ProductionShot。

## 25. ProductionShot lineage

未来 ProductionShot 至少应能够 pin：

```text
episode_shot_plan_id
revision
hash
planned_shot_id

episode_release_variant_id
revision
hash
```

同时保留 canonical Shot authority 与 release realization authority。

## 26. Downstream exact pinning

Operator 可以在任务创建前使用 human-friendly selector 选择目标 variant；一旦下游 artifact/job 建立，必须 pin exact：

```text
EpisodeReleaseVariant id/revision/hash/approval record
```

禁止在 canonical execution lineage 内使用 implicit `latest approved en-US 9:16`。

## 27. Review package

B5.6 可以 deterministic derive：

```text
ReleaseVariantReviewPackage
```

可包含：

- source vs localized dialogue
- Shot-by-Shot canonical/release comparison
- framing summaries
- subtitle/timing summaries
- review-required findings
- warnings

它是 human-readable projection，不是 canonical artifact。

Reviewer 在 ReviewPackage 中提出改动时不能直接回写 EpisodeReleaseVariant；应在 B5.7 `REVISION_REQUESTED` 并 route 到 owning stage。

## 28. Assembly error

B5.6 structural failure 可包括：

```text
bundle hash mismatch
missing validated artifact
duplicate PlannedShot realization
missing source ref
schema inconsistency
non-deterministic duplicate identity
```

这类是 `ASSEMBLY_ERROR`，不另建一套 semantic PASS/FAIL taxonomy。

## 29. Generated media boundary

```text
EpisodeReleaseVariant APPROVED
≠ generated media ACCEPTED
```

同一个 approved ERV 可以产生多个 generation attempts；QC/retry 不修改 ERV。

若 execution 暴露 B5 semantic design 本身错误，必须 semantic escalation 回 B5 owning stage，重新 B5.5/B5.6/B5.7；ProductionShot 层不得 silent repair canonical release semantics。

## 30. Source ShotPlan supersession

如果 ERV 基于的 EpisodeShotPlan 后续被新 approved revision supersede：

- 既有 ERV 保持 immutable historical artifact；
- 既有 historical approval 仍是历史事实；
- normal new execution 应检查 source lineage eligibility；
- 默认不应让 stale-source ERV继续作为 current new-execution authority。

不要通过修改旧 ERV content 来“repin”新 ShotPlan。

## 31. Qwen / Python

B5.6 默认不需要 Qwen 参与 canonical assembly。

Python 负责：

- exact refs
- source bundle hash verification
- deterministic serialization
- IDs/revisions/hashes
- indexes
- provenance manifest
- lifecycle initialization
- review package projection

Qwen 如参与 human-readable summary，只能产生 derived presentation，不能影响 canonical artifact。

## 32. 冻结原则

1. B5.6 只做 deterministic assembly，不拥有 semantic reasoning/repair authority。
2. 正式 canonical artifact 为 `EpisodeReleaseVariant`。
3. 仅 B5.5 PASS/PASS_WITH_REVIEW_ITEMS 可进入 B5.6。
4. 必须保存并验证 `source_validated_release_variant_bundle_hash`。
5. Validation 后任一 source change 都必须重新 B5.5。
6. EpisodeReleaseVariant 初始 lifecycle = DRAFT；B5.6 没有 approval authority。
7. 同一 episode 可有多个不同 ReleaseVariantIdentity 的 approved variants；同一 scope 最多一个 current approved revision。
8. Variant identity 与 revision 分离。
9. APPROVED revision immutable。
10. Semantic release change 必须 constituent revision → B5.5 → B5.6 → B5.7。
11. Render-only change 不要求修改 EpisodeReleaseVariant。
12. Downstream 正式消费 APPROVED EpisodeReleaseVariant，不自行重拼 B5.2–B5.4。
13. EpisodeReleaseVariant 保留完整 canonical + release provenance。
14. ReleaseShotRealization / indexes 可 deterministic derive，但不是新的 source of truth。
15. ReleaseShotRealization anchored to PlannedShot，不创建新的 editorial Shot identity。
16. B5.6 保持 asset-unresolved、backend-agnostic。
17. ProductionShot 后续必须能 pin EpisodeShotPlan + PlannedShot + EpisodeReleaseVariant exact lineage。
18. PASS_WITH_REVIEW_ITEMS 的 review items 必须完整进入 assembled artifact/review package。
19. Qwen 默认不参与 canonical assembly；Python 负责 deterministic refs/hash/state/index/provenance。
20. EpisodeReleaseVariant APPROVED 不等于 generated media ACCEPTED。
21. Source ShotPlan 后续 superseded 不 retroactively rewrite old ERV；normal new execution 检查 lineage eligibility。
