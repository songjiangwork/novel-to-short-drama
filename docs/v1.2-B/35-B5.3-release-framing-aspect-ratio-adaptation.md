# B5.3 — Release Framing + Aspect-Ratio Adaptation

状态：**FROZEN**

## 1. 职责

B5.3 将 B4 已批准的 camera/composition semantics 实现到具体 release frame（9:16、16:9、1:1 等），而不重新设计 canonical Shot。

正式输出：

```text
EpisodeReleaseFramingPlan
```

每个 `PlannedShot` exact 对应：

```text
ReleaseShotFramingSpecification
```

核心关系：

```text
ShotSemanticSpecification
+
target release frame
↓
ReleaseShotFramingSpecification
```

## 2. 核心边界

B4.3 定义：

- shot scale
- viewpoint
- orientation
- camera angle
- movement
- primary attention
- required visibility
- co-visibility
- attention progression
- semantic focus transition

但不绑定：

- aspect ratio
- pixel coordinates
- exact crop
- final render resolution
- concrete asset geometry

因此：

```text
ReleaseShotFramingSpecification
≠ new ShotSemanticSpecification
```

正式原则：

```text
Framing adaptation may change geometric realization,
but must preserve perceptual obligations.
```

## 3. EpisodeReleaseFramingPlan

建议至少包含：

```text
framing_plan_id
revision
content_hash
source_release_variant_context_ref
source_episode_shot_plan_ref
source_dialogue_localization_plan_ref
target_frame_profile
shot_framing_specifications[]
framing_conflicts[]
review_items[]
```

所有 source refs 必须 exact id/revision/hash。

## 4. TargetFrameProfile

B5.3 从 B5.1 release target 中解析结构化 `TargetFrameProfile`，可包含：

```text
aspect_ratio
orientation
logical_frame_geometry
safe_area_policy
platform_overlay_zones
subtitle_reserved_zone
```

`9:16` / `16:9` 属于 B5 semantic release target；`1080×1920` / codec / encoder preset 默认属于 downstream execution/render profile。

## 5. Framing 不等于 crop-only

B5.3 发生在 generation 前，因此不是简单：

```text
16:9 rendered video → crop → 9:16
```

而是：

```text
canonical Shot semantics
→ 9:16 semantic framing realization
```

和：

```text
canonical Shot semantics
→ 16:9 semantic framing realization
```

是同一个 PlannedShot 的不同 release realizations。

## 6. B5.3 可以调整的内容

在不改变 canonical semantics 的情况下，可以调整：

- subject horizontal/vertical placement
- headroom / lead room
- relative spacing
- foreground/midground/background distribution
- frame occupancy
- safe-area accommodation
- crop preference
- minor effective scale realization
- composition balance
- depth arrangement

这些是 release geometry/composition realization，不是 Shot redesign authority。

## 7. FrameSemanticObligation

B5.3 可以 deterministic 从 B4 派生：

```text
FrameSemanticObligation
```

例如：

```text
PRIMARY_ATTENTION
REQUIRED_VISIBLE
REQUIRED_COVISIBLE
SPATIAL_RELATIONSHIP
SCREEN_DIRECTION
EYELINE_SUPPORT
REVEAL_VISIBILITY
ACTION_VISIBILITY
REACTION_VISIBILITY
BACKGROUND_CONTEXT
```

它是 derived obligation，不是新的 source of truth。B5.3 不得为了“更漂亮”自行增加 canonical visibility requirement。

## 8. Visibility priority

为 framing solver 可区分：

```text
SEMANTICALLY_REQUIRED
CONTEXTUALLY_PREFERRED
OPTIONAL
```

其中真正 required authority 仍来自 B4/PCR/continuity/provenance。

当 release frame 空间不足时可以牺牲 optional richness，不能牺牲 semantic obligations。

## 9. Required co-visibility

如果 B4 要求：

```text
A action + B reaction
simultaneously perceptible
```

则 9:16 realization 不能改成两个 sequential editorial shots。

```text
REQUIRED_COVISIBILITY_UNSATISFIABLE
→ REQUIRES_B4_REVISION
```

`A at t1` + `B at t2` 不等价于 canonical simultaneous co-visibility。

## 10. Perceptual prominence

Co-visible 不代表同等画面面积。

B5.3 可以派生：

```text
PerceptualProminence
= DOMINANT / SECONDARY / CONTEXTUAL
```

以保持 primary attention / secondary context，而不是 rigid pixel ratio。

## 11. Primary attention / attention progression

B5.3 必须保留 canonical primary attention 与 attention progression。

可以改变角色在 frame 中的位置，但不能把 canonical secondary subject 变成 dominant subject，除非 B4 本身定义 attention transition。

如果 B4 定义：

```text
Song action → Linsey reaction
```

B5.3 必须使 release frame 能支持这一语义顺序，不得反转。

## 12. Shot scale semantic function

B5.3 不重写 canonical shot-scale label，但不同 aspect ratio 可以有 minor geometric tolerance。

必须保持 scale 的 semantic function。例如 MEDIUM 必须仍能让观众读取该 Shot 所需的 face/gesture/context；如果 portrait adaptation 变成事实上的 face-only close-up 并丢失 required gesture/context，则：

```text
SHOT_SCALE_FUNCTION_VIOLATION
```

不得用 label 未变作为放行理由。

可按需要表达 semantic `FramingTolerance`：STRICT / MODERATE / FLEXIBLE，但不得变成固定 pixel ratio。

## 13. Viewpoint / orientation / camera angle

B5.3 不得 silent 改写：

```text
OBJECTIVE / OVER_SHOULDER / POV
FRONT / THREE_QUARTER / PROFILE / REAR / FLEXIBLE
EYE_LEVEL / HIGH / LOW / OVERHEAD
```

例如 OTS 如果把 foreground shoulder 完全裁掉并失去 OTS semantic function，不能仍宣称 preserved。

POV 必须保持 character position / knowledge restriction；不能因 framing 暴露 POV 不可能看到的信息。

## 14. Movement realization

B4 movement semantics：

```text
STATIC
REFRAME
FOLLOW
PUSH_IN
PULL_BACK
LATERAL_TRACK
ARC
OTHER_SEMANTIC
```

B5.3 可以根据 frame geometry refine movement realization，但不能把 canonical FOLLOW 改成 STATIC，或 STATIC 改成明显 semantic PUSH_IN。

应区分：

```text
COMPOSITIONAL_ADJUSTMENT
≠
SEMANTIC_CAMERA_MOVEMENT
```

轻微 safe-area/centering correction 可以是前者；明显 camera behavior 属于 B4 semantics。

## 15. Safe area

正式支持：

```text
SafeAreaConstraint
PlatformOverlayConstraintProfile
```

可使用 semantic zones：

```text
TOP_RESERVED
BOTTOM_SUBTITLE_SAFE
LEFT_UI_EXCLUSION
RIGHT_UI_EXCLUSION
CENTER_PRIORITY
```

而不是把某平台 UI 的具体 pixel coordinates 写死进 canonical B5 docs。

Profile 应 versioned/pinned。

Safe area 可以影响 positioning，但不能遮挡或删除 canonical required subject/action/object。

## 16. Subtitle-aware framing

B5.3 可以预留 `subtitle_safe_area`，确保重要 face/action/required object 有合理展示空间。

最终 SubtitleCue realization 在 B5.4；B5.5 再做 framing × subtitle integrated validation。

## 17. Staging / continuity boundary

B5.3 可以改变 frame placement/depth arrangement，但不得擅自改变 B3/B4 canonical staging truth。

例如：

```text
screen position ≠ physical staging position
```

如果 production continuity 定义 A 在 B 左侧，B5.3 不得仅为 portrait convenience 将两者物理左右关系翻转。

必须消费 B4.4：

- InteractionAxis / AxisSide
- eyeline
- screen direction
- entrance / exit direction
- continuity reset

## 18. Horizontal mirroring

Horizontal mirror 默认不是 SAFE_REFINEMENT，因为它可能改变：

- screen direction
- handedness
- text
- costume asymmetry
- spatial continuity
- interaction axis

必须 explicit semantic compatibility check；多数 continuity-sensitive 情况应禁止。

## 19. Background / establishing semantics

需区分：

```text
semantic background context
≠ decorative background richness
```

如果 classroom door 等背景对象承担 spatial orientation/reveal/setup obligation，则 release framing 必须保留其 perceptual function。

WIDE/EXTREME_WIDE establishing Shot 不能因为 portrait frame 变窄而失去 canonical spatial-establishment function。

## 20. Asset boundary

B5.3 仍然 asset-unresolved。

允许：

```text
CharacterRef(Song)
CharacterRef(Linsey)
LocationElementRef(classroom_door)
```

不允许：

```text
Song_face_100.png
Picture 7
specific image path
H3 reference slot
```

Concrete asset geometry 如果无法满足 B5 framing requirement，应产生 asset-resolution conflict，不能反向 silent 改 canonical framing semantics。

## 21. FramingPhase

动态 composition 可以用 semantic：

```text
FramingPhase
{
  anchor_ref
  composition_state
}
```

优先绑定 B4 timing/action/PCR/performance anchors，而不是具体 frame number。

FramingPhase 不能自行发明新的 story/performance phase。

## 22. Preservation status

每个 Shot 输出：

```text
PRESERVED
PRESERVED_WITH_REFINEMENT
REVIEW_REQUIRED
CONFLICT
```

典型 conflict code：

```text
REQUIRED_VISIBILITY_UNSATISFIABLE
REQUIRED_COVISIBILITY_UNSATISFIABLE
PRIMARY_ATTENTION_DISTORTED
SHOT_SCALE_FUNCTION_VIOLATION
VIEWPOINT_VIOLATION
ORIENTATION_VIOLATION
CAMERA_ANGLE_VIOLATION
MOVEMENT_SEMANTIC_VIOLATION
CONTINUITY_AXIS_CONFLICT
EYELINE_CONFLICT
SCREEN_DIRECTION_CONFLICT
REVEAL_VISIBILITY_CONFLICT
SAFE_AREA_CONFLICT
SPATIAL_RELATION_CONFLICT
```

## 23. Resolution authority

每个 conflict 必须记录 authority：

```text
B5_REFINEMENT
B5_REVIEW
REQUIRES_B4_REVISION
REQUIRES_B3_REVISION
```

Shot-design / editorial-camera change → B4。

Blocking / physical staging / production relation change → B3，再重走 B4/B5。

## 24. 一 PlannedShot 一 framing specification

正式保持：

```text
1 PlannedShot
→ exactly 1 selected ReleaseShotFramingSpecification
  per EpisodeReleaseVariant
```

B5.3 不创建新的 editorial Shot identity。

同一 PlannedShot 在不同 ReleaseVariant 中可以有不同 framing specification，只要均 preserve canonical semantics。

## 25. Local validation

B5.3 local validator 至少检查：

- every PlannedShot covered
- canonical semantic refs exact
- required visibility / co-visibility
- primary attention
- shot-scale function
- viewpoint / orientation / angle
- movement compatibility
- interaction axis / eyeline / screen direction
- reveal safety
- safe-area compatibility
- staging/spatial compatibility

Local PASS 不替代 B5.5 integrated validation。

## 26. Qwen / Python

Qwen：

- portrait/landscape composition reasoning
- attention hierarchy
- co-visibility reasoning
- framing candidate generation
- semantic conflict diagnosis

Python：

- exact refs
- schema/enums
- provenance
- candidate selection recording
- hashes
- structural validation

Qwen framing output 是 candidate；不能自行 split Shot、flip continuity authority、change staging 或 self-approve。

## 27. 冻结原则

1. B5.3 输出 `EpisodeReleaseFramingPlan` 与每 Shot exact 一个 selected `ReleaseShotFramingSpecification`。
2. EpisodeShotPlan 是 canonical camera/editorial authority。
3. Aspect-ratio adaptation 只做 release-specific geometric/composition realization。
4. B5.3 不创建新 PlannedShot，不改变 Shot order/structure。
5. Required visibility/co-visibility/primary attention 必须 perceptually preserve。
6. Shot-scale semantic function必须保持，不能仅依赖 label。
7. Viewpoint/orientation/angle/movement 不得 silent 修改。
8. B4.4 continuity semantics 必须保持。
9. Safe area 可以影响 positioning，但不能覆盖 canonical semantics。
10. Depth/lateral arrangement 可 refinement，但不得改 canonical staging truth。
11. B5.3 保持 asset-unresolved、backend-agnostic。
12. Conflict 必须 explicit，并记录 resolution authority。
13. Shot-design conflict 回 B4；production-staging conflict 回 B3。
14. 16:9→9:16 本身不要求 B4 reapproval，但必须通过 semantic preservation validation。
15. Qwen 负责 semantic framing candidate；Python 负责 refs/state/hash/validation。
