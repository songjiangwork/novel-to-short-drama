# B3.7 — Production Review + Approval Gate

状态：**FROZEN**

## 1. 职责

B3.7 是 Production Planning 阶段唯一正式 human approval gate。

批准对象必须是 exact：

```text
episode_production_plan_id
+
revision
+
content_hash
```

只有 `APPROVED EpisodeProductionPlan` 才允许 Shot Planning 正式消费。

B3.7 不是 editor、repair stage、Shot design stage 或 asset-resolution stage。

## 2. ProductionApprovalRecord

正式引入 immutable：

```text
ProductionApprovalRecord
```

至少绑定：

- approval_record_id
- EpisodeProductionPlan id/revision/hash
- exact ProductionValidationReport id/hash
- source_validated_bundle_hash
- exact APPROVED EpisodeScreenplay id/revision/hash/approval_record_id
- ProductionConstraintProfile id/revision/hash（如有）
- decision
- REVIEW_REQUIRED dispositions
- reviewer reference / review metadata
- production-continuity dependency pins

B3.2–B3.4 constituent exact revisions 通过 EpisodeProductionPlan manifest deterministic 解析，不必在 ApprovalRecord 顶层重复整套内容。

## 3. Validation prerequisite

ProductionValidationReport 必须 exact-match 当前 ProductionPlan 的 validated bundle / plan pins。

```text
FAIL
→ cannot approve
```

`PASS` 或 `PASS_WITH_REVIEW_ITEMS` 可进入 human review。

Validation pass 不等于 human approval；reviewer 仍可要求 revision。

## 4. REVIEW_REQUIRED disposition

每个 `REVIEW_REQUIRED` finding 必须逐项：

```text
ACCEPT_AS_DESIGNED
REVISION_REQUESTED
```

只要任意 finding 为 `REVISION_REQUESTED`，当前 ProductionPlan revision 不得 APPROVE。

WARNING 对 reviewer 可见，但不强制逐项 disposition。

`ACCEPT_AS_DESIGNED` 必须绑定 exact finding + validation report + production plan revision/hash，不跨 revision 自动继承。

## 5. Review decision / lifecycle

正式 decision：

```text
APPROVE
REVISION_REQUESTED
ABANDON
```

不引入 conditional / soft / temporary approval。

EpisodeProductionPlan lifecycle：

```text
DRAFT
APPROVED
SUPERSEDED
ABANDONED
```

`PASS` 后仍是 DRAFT，直到 human APPROVE。

一个 episode 最多只有一个 current APPROVED ProductionPlan revision。新版 APPROVED 后，旧 current approved revision → SUPERSEDED；历史 validation/approval/provenance 永久保留。

## 6. Approval 粒度

B3.7 不支持单个 episode 内 ProductionUnit / requirement / staging / PCR 的 formal partial approval。

```text
EpisodeProductionPlan approval = per-episode atomic
```

整个 series 支持 episode-by-episode incremental approval，不要求全部 production plans 完成后一次性批准。

## 7. Immutability / revision

APPROVED ProductionPlan revision immutable。

任意 semantic change——ProductionUnit decomposition、requirement、staging/performance、perceptual obligation、continuity、constraint lineage 等——都必须：

```text
new B3 constituent revision as needed
→ B3.5 revalidation
→ B3.6 new EpisodeProductionPlan revision
→ B3.7 reapproval
```

Render-only formatting change不需要 reapproval。

ProductionApprovalRecord 本身 immutable。

## 8. Screenplay / constraint lineage

Approval 必须绑定 exact APPROVED EpisodeScreenplay lineage；新 screenplay revision 不 retroactively 修改旧 ProductionPlan approval。

若需要迁移到新 screenplay lineage，必须 rebuild affected B3 artifacts、重新 B3.5/B3.6/B3.7。

同理，新的 `ProductionConstraintProfile` revision 不 reinterpret 旧 ProductionPlan；采用新 constraints 必须形成新 validated bundle / plan revision / approval。

## 9. 跨集 Production Continuity dependency

Episode N 的 production planning 可能依赖 predecessor 的 `EpisodeProductionEndingCheckpoint`。

Draft planning 可以暂时依赖尚未 approved predecessor 以支持并行工作；但当前 EpisodeProductionPlan 正式 APPROVE 时，所有 authoritative production-continuity dependencies 必须已经 APPROVED，并 pin exact：

```text
predecessor_production_plan_id
revision
hash
approval_record_id
ending_checkpoint_hash
```

EP01 无 predecessor production-plan dependency。

B3.7 不强制整个 series 严格串行，只要求实际 dependency graph 在 approval 时稳定。

## 10. Downstream Shot Planning pinning

Shot Planning 只能正式消费 `APPROVED EpisodeProductionPlan exact revision`，至少 pin：

```text
episode_production_plan_id
episode_production_plan_revision
episode_production_plan_hash
production_approval_record_id
```

禁止 implicit latest。

新 Shot Planning 默认不得从 SUPERSEDED ProductionPlan 建立 current authoritative ShotPlan；但可显式用于 historical reproduction / debug / audit。

已有 ShotPlan 不因 ProductionPlan later superseded 而自动 repin；若采用新版 ProductionPlan，应创建新的 downstream revision。

## 11. Reviewer 行为 / revision routing

Reviewer 不得在 approval gate 直接修改 canonical ProductionPlan。

修改必须记录 `REVISION_REQUESTED` 并 route 到 earliest authoritative owner：

```text
B3.4 staging/performance/perceptual realization
B3.3 requirements
B3.2 production breakdown
ProductionConstraintProfile
B2 screenplay
B1 adaptation
```

Human reviewer 可以发现 B3.5 未发现的新问题，并记录 lightweight `HumanReviewFinding`，应尽量引用 ProductionUnit / Requirement / StagingDirective / PerformanceRequirement / PCR 等 stable IDs。

Review note 本身不是 canonical production truth。

## 12. ProductionReviewPackage

允许 deterministic 构建 derived：

```text
ProductionReviewPackage
```

可包含：

- faithful RenderedProductionPlan
- ProductionUnit map / screenplay coverage
- requirement catalog / unit uses
- staging / performance summaries
- perceptual obligations
- ProductionContinuity summary / ending checkpoint
- duration / complexity summary
- ProductionConstraintProfile summary
- B3.5 findings / REVIEW_REQUIRED items
- exact screenplay / validated-bundle / constituent pins

ReviewPackage 是 review surface，不是第二份 authoritative truth。

Reviewed representation 必须能解析回 exact canonical ProductionPlan revision/hash。

## 13. Fail-closed 条件

以下任一情况不得 APPROVE：

- ProductionPlan revision/hash mismatch
- ProductionValidationReport missing / stale / targets different bundle
- source_validated_bundle_hash mismatch
- B3.5 result = FAIL
- unresolved REVIEW_REQUIRED finding
- approved screenplay lineage invalid/unresolvable
- constituent revision/hash unresolved
- ProductionConstraintProfile pin mismatch
- required predecessor production dependency not APPROVED
- predecessor ending checkpoint mismatch
- reviewed representation cannot resolve to exact canonical revision
- target already ABANDONED

Downstream Shot Planning consumption 同样 fail closed。

## 14. Approval scope / non-goals

B3.7 只批准 Production Planning semantic contract。

它不批准：

- Shot list / camera / lens / framing
- concrete character/location/prop/wardrobe asset
- voice / localization / subtitle timing
- H3 / ComfyUI workflow
- generation job / GPU/runtime
- generated video quality / QC candidate

Semantic planning artifact 使用 `APPROVED`；未来 generated media 仍使用 `ACCEPTED`，不混用。

Production feasibility concern 如果需要修改 screenplay/narrative truth，必须产生上游新 revision，不能在 B3.7 silent waive。

## 15. Python / Human / Qwen

Python：

- verify exact ProductionPlan/report/bundle hashes
- collect findings and dispositions
- verify screenplay/constraint/predecessor dependencies
- build review package
- create immutable approval record
- update lifecycle
- enforce one current approved revision
- enforce downstream pins

Human：

- review production semantics / feasibility
- resolve REVIEW_REQUIRED
- raise additional findings
- APPROVE / REVISION_REQUESTED / ABANDON

Qwen：

- explain findings / requirements / staging / continuity
- compare revisions
- show traceability

Qwen 不能 self-approve。

## 16. 冻结 contract

1. B3.7 是 Production Planning 唯一 formal human approval gate。
2. Approval 对象是 exact EpisodeProductionPlan id/revision/hash。
3. 正式存在 immutable `ProductionApprovalRecord`。
4. ApprovalRecord 绑定 exact ProductionValidationReport + source_validated_bundle_hash。
5. B3.5 FAIL 不得批准；PASS / PASS_WITH_REVIEW_ITEMS 可进入 review。
6. 所有 REVIEW_REQUIRED 必须逐项 ACCEPT_AS_DESIGNED 或 REVISION_REQUESTED。
7. decision = APPROVE / REVISION_REQUESTED / ABANDON。
8. Episode Production approval atomic，不支持 unit/requirement/staging/PCR partial formal approval。
9. Series 支持 per-episode incremental approval。
10. lifecycle = DRAFT / APPROVED / SUPERSEDED / ABANDONED。
11. APPROVED revision / ApprovalRecord immutable。
12. semantic change 必须 new revision + B3.5 + B3.6 + B3.7。
13. 每 episode 最多一个 current APPROVED ProductionPlan revision。
14. Approval 绑定 exact APPROVED screenplay lineage。
15. 新 screenplay/constraint revision 不 retroactively reinterpret old ProductionPlan。
16. Draft 可暂依赖 draft predecessor；正式 approval 时 production-continuity dependencies 必须 APPROVED。
17. predecessor dependency pin exact plan/revision/hash/approval/checkpoint hash。
18. Shot Planning 只能正式消费 APPROVED exact ProductionPlan 并 pin approval record。
19. Downstream 禁止 implicit latest。
20. SUPERSEDED plan 默认仅用于 historical reproduction/debug/audit，不用于新 current ShotPlan。
21. 已存在 ShotPlan 不自动 repin 到 later ProductionPlan。
22. Reviewer 不得在 gate 中直接编辑 canonical production semantics。
23. Revision request route 到 earliest authoritative owner（B3.4/B3.3/B3.2/constraint/B2/B1）。
24. Human 可提出 validator 未发现的新 finding，并引用 stable IDs。
25. ProductionReviewPackage / rendered view 都是 derived review artifact。
26. reviewed representation 必须 resolve 到 exact canonical plan。
27. gate / downstream 无法验证 hashes/references/dependencies 时 fail closed。
28. B3.7 不审批 Shot、asset、voice、localization、H3/ComfyUI/runtime 或 generated media。
29. Semantic artifact APPROVED 与 future generated media ACCEPTED 分离。
30. Python 负责 gate mechanics；Human 做 final decision；Qwen 可辅助解释但不能 self-approve。
31. `APPROVED EpisodeProductionPlan` 是 B3 COMPLETE 并允许进入 Shot Planning 的唯一正式出口。
