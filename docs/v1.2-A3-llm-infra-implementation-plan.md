## 1. 职责边界

A-I3 只实现 Story Analysis 后续阶段共用的 LLM infrastructure：

```text
business stage
→ versioned PromptSpec
→ deterministic prompt rendering
→ StructuredGenerationRequest
→ LLMClient.generate_structured(...)
→ OpenAI-compatible transport
→ structured response parsing
→ local JSON / JSON Schema validation
→ StructuredGenerationResult
```

A-I3 不实现 characters、locations、facts、events、relationships、unresolved_mentions、CandidateExtraction、CanonicalEntityMap 或 GlobalStoryBible。这些从 A-I4 开始。

## 2. Provider-neutral boundary

业务代码不得直接依赖 llama.cpp、具体 endpoint、HTTP 字段或 provider response envelope，只依赖统一的 `LLMClient.generate_structured(...)` capability。

首个实现为 `OpenAICompatibleLLMClient`，首个实际 provider 为 local Qwen through llama.cpp，但公共 infrastructure 不得以具体模型或具体 server 命名。

## 3. Runtime config 与 semantic profile 分离

### Runtime transport config

只描述连接信息，例如：

```text
schema_version
transport_id
base_url
credential_environment_name or null
timeout_seconds
```

建议 tracked example：`profiles/llm_local.example.yaml`。

本机实际配置：`profiles/llm_local.yaml`，必须 gitignored。

Runtime config 不得包含 temperature、reasoning mode、prompt version 或 output-token budget 等 semantic generation decisions。

### Semantic LLM profile

建议：`profiles/story_llm_qwen_v1.yaml`。

至少描述：

```text
schema_version
profile_id
provider_family
model
temperature
max_output_tokens
structured_output_mode
reasoning settings
```

Semantic profile 必须 typed、可 canonical serialize、可 hash。

## 4. Semantic identity

参与 semantic identity 的至少包括：

- model；
- semantic profile；
- prompt identity/content；
- rendered prompt；
- output schema identity；
- 其它会影响生成语义的参数。

不包括：

- endpoint；
- timeout；
- credentials；
- hostname；
- timestamp；
- HTTP connection metadata。

仅 runtime endpoint 改变不得 invalidate downstream semantic artifacts。

## 5. Prompt Registry

实现 lightweight deterministic Prompt Registry，不引入 database、remote prompt service、Jinja 或 dynamic code execution。

`PromptSpec` 至少包含：

```text
prompt_id
version
system_template
user_template
required_variables
content_hash
```

Prompt identity：

```text
prompt_id + version + content_hash
```

同一 prompt ID/version 的内容如果改变，必须 fail closed，不能静默接受。

建议 storage：

```text
prompts/story/<prompt-name>/v1/
  prompt.yaml
  system.txt
  user.txt
```

A-I3 tests 使用 synthetic prompt；正式 `a3.chunk-extraction` prompt 可以在 A-I4 加入。

## 6. Deterministic rendering

`PromptSpec + exact variables → RenderedPrompt`。

`RenderedPrompt` 至少保留：

```text
prompt_id
prompt_version
prompt_content_hash
variables_hash
system_text
user_text
rendered_prompt_hash
```

变量替换必须 strict、deterministic、fail closed。missing variable、unexpected variable、duplicate declaration、unsupported placeholder、invalid text 均失败。不得使用 silent default 或 undefined-to-empty。

## 7. StructuredGenerationRequest 与 fingerprint

Provider-neutral request 应是 typed object，至少包括 model、messages、output schema、semantic profile、rendered prompt。

`LLMRequestFingerprint` 至少包含：

```text
schema_version
model
semantic_profile_hash
prompt_id
prompt_version
prompt_content_hash
rendered_prompt_hash
output_schema_hash
request_hash
```

所有 canonical hash 必须复用现有 artifact canonical serialization/hash authority，不得在 A3 再定义第二套 hash 规则。

## 8. Structured output trust boundary

Provider-side structured output 是 generation constraint，不是 validation authority。

```text
JSON Schema
→ provider structured-output constraint
→ generation
→ provider envelope parsing
→ strict JSON parsing
→ local JSON Schema validation
→ downstream semantic validation
```

Python 本地 validation 始终 authoritative。

## 9. OpenAI-compatible v1 adapter

首个 adapter 使用 OpenAI-compatible Chat Completions 风格的 structured request；业务层不知道具体 transport fields。

v1：

- 使用 Python stdlib `urllib.request`；
- 不 streaming；
- 不新增 OpenAI SDK、requests、httpx、aiohttp；
- adapter 内封装 provider request/response mapping。

如果未来需要 async、streaming 或 hosted-provider-specific features，再扩展 adapter/dependency。

## 10. Provider capability

v1 不建立复杂 capability negotiation framework，但 adapter 必须明确 structured JSON Schema capability。

如果 semantic profile 要求 JSON Schema structured output，而 adapter 不支持，则 request 前 fail closed；不得静默 fallback 为 plain text。

## 11. Result 与 provenance

adapter 返回 `StructuredGenerationResult`，而不是 raw provider dict。

至少包括：

```text
parsed_json
provenance
attempts
```

`LLMInvocationProvenance` 至少记录：

```text
provider_family
model
semantic_profile_id/hash
prompt_id/version/content_hash/rendered_prompt_hash
output_schema_id/version/hash
request_hash
optional provider response id
optional finish reason
optional usage
```

provider 未返回的 optional field 使用 null，不得伪造。

完整 raw provider response 默认不作为 canonical artifact 永久保存。

## 12. Retry contract

默认 maximum attempts = 3（initial + 最多 2 retries）。

Retryable technical failures：

- transient connection failure；
- timeout；
- HTTP 429；
- HTTP 5xx；
- temporarily malformed provider envelope。

Retryable invalid structured output：

- empty content；
- invalid JSON；
- JSON Schema violation；
- structurally unusable provider content。

Non-retryable：

- invalid runtime config；
- invalid semantic profile；
- invalid prompt spec；
- missing prompt variable；
- invalid local output schema；
- unsupported adapter capability；
- ordinary request/auth/not-found 4xx failures。

Semantic uncertainty 不是 retry reason。未来 A-I4 的 unresolved/uncertain 是成功的业务结果。

v1 retry 使用同一 semantic request，不实现 adaptive repair prompt。若以后增加 repair prompt，必须 versioned、deterministic、可 hash。

Retry sleeper 必须可注入，unit tests 不等待真实 backoff。

## 13. Cache / resume authority

A-I3 **不建立 generic persisted LLM cache**，不创建 raw-response artifact、response current pointer 或 cache database。

A-I3 只提供：

```text
LLMRequestFingerprint
LLMInvocationProvenance
```

真正 canonical reuse 从 A-I4 CandidateExtraction 开始：

```text
SourceDocument exact ref
+ SourceChunk exact ref
+ prompt identity
+ semantic LLM profile
+ output schema
→ CandidateExtraction identity
```

存在 exact validated CandidateExtraction 时 A-I4 reuse，否则调用 LLM。

同一 request fingerprint 只表示 semantic request identity 相同，不保证重新调用模型会得到 byte-identical response。Pipeline reproducibility 依赖 validated immutable artifact reuse。

## 14. Error model

建议公共异常层级：

```text
LLMError
LLMConfigError
LLMPromptError
LLMTransportError
LLMHTTPError
LLMTimeoutError
LLMResponseError
LLMStructuredOutputError
LLMRetryExhaustedError
```

错误必须支持 machine-readable classification，且不得泄露 credential 或敏感 connection data。

## 15. Secrets / diagnostics

credential 只通过 runtime environment 间接解析；不得 persist、print、hash 或进入 semantic provenance。

允许 diagnostics：provider family、model、profile ID、prompt ID/version、attempt、HTTP status、finish reason、usage、elapsed time、request fingerprint。

默认不得打印完整 source text、完整 prompt、完整 raw provider response 或 credentials。Verbose dump 必须显式 opt-in。

## 16. Package shape

建议：

```text
src/short_drama/llm/
  __init__.py
  client.py
  models.py
  config.py
  prompts.py
  openai_compatible.py
  retry.py
  errors.py
```

职责：

- `client.py`: provider-neutral `LLMClient`；
- `models.py`: semantic profile、prompt/result/fingerprint/provenance typed models；
- `config.py`: runtime config loader；
- `prompts.py`: registry + strict renderer；
- `openai_compatible.py`: urllib transport + request/response mapping；
- `retry.py`: retry orchestration/classification；
- `errors.py`: LLM error hierarchy。

## 17. Schema strategy

External schema 限制在真正的 external/persisted contracts。

A-I3 至少建议：

```text
schemas/llm-semantic-profile.schema.json
schemas/prompt-spec.schema.json
```

可增加 `schemas/llm-runtime-config.schema.json`。

Transient `StructuredGenerationRequest` 不需要变成 immutable artifact。

Prompt content hash 必须覆盖 exact system/user template text、semantic metadata、required variables；不能只 hash metadata file。

Semantic profile hash 必须覆盖所有 semantic fields，但不能受到 endpoint 变化影响。

每个 structured generation 必须 pin output `schema_id + schema_version + schema_hash`。

## 18. Offline deterministic tests

Issue #8 tests 不依赖真实 Qwen。使用 deterministic fake HTTP server 或 injectable transport fixture。

必须覆盖：

- runtime config loading/failure；
- credential isolation；
- prompt loading/hash/rendering/fail-closed variables；
- semantic profile stable hash；
- endpoint change does not affect semantic hash/fingerprint；
- OpenAI-compatible request mapping；
- valid/malformed response envelope；
- retryable/non-retryable HTTP behavior；
- valid JSON + schema pass；
- invalid JSON retry；
- schema violation retry；
- success after retry；
- 3 failures exhausted；
- stable request fingerprint；
- prompt/schema/model/profile changes alter fingerprint；
- no real sleep in tests。

## 20. CLI

A-I3 不要求 production semantic pipeline command。

可选开发命令：

```text
short-drama llm-check <runtime-config> --profile <semantic-profile>
```

只做 reachability/basic structured generation。如果 CLI 会显著扩大 scope，可以留到 A-I4，不是 Issue #8 hard requirement。

## 21. Foundation interaction

A-I3 不创建 CURRENT pointer、ApprovalRecord、CandidateExtraction artifact 或 generic response artifact。

Transport/JSON/schema execution errors 使用 LLM error taxonomy。

从 A-I4 开始，CandidateExtraction semantic validation 才进入现有 Foundation `ValidationReport` / `ValidationFinding`。

原则：

```text
execution failure ≠ artifact validation finding
```

## 22. Explicit non-goals

- ownership/source-ref semantic validation；
- A4/A5/A6；
- adaptation/screenplay；
- ComfyUI/H3 changes；
- database/ORM；
- async/streaming；
- multi-provider routing/fallback；
- distributed cache；
- prompt service；
- generic raw-response artifact store。

## 23. Expected A-I4 usage

Issue #8 完成后，A-I4 应能近似：

```python
prompt = prompt_registry.load("a3.chunk-extraction", version=1)
rendered = prompt.render(...)
result = llm_client.generate_structured(
    rendered_prompt=rendered,
    output_schema=candidate_extraction_schema,
    semantic_profile=story_llm_profile,
)
```

A-I4 不需要知道 HTTP、llama.cpp transport fields、provider envelope、retry loop 或 credentials。
