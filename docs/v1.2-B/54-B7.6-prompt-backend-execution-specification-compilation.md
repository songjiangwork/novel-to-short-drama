# B7.6 — Prompt + Backend Execution Specification Compilation

状态：**FROZEN**

## 1. 职责

B7.6 是 B7 的 backend code-generation stage。它汇合 B7.2–B7.5 的已确定 compiler IR，生成 structured execution semantics、backend-specific prompt structure、exact rendered prompt、render/context realization、workflow/request binding specification 与 runtime-derived dependency declarations。

必须保持：

```text
execution semantics
≠ backend prompt
≠ workflow/request specification
≠ runtime materialization
```

## 2. 正式输入 / 输出

输入：

```text
ExecutionCompilationContext
EpisodeProductionShotSegmentationPlan
EpisodeProductionShotTimingProjectionPlan
EpisodeProductionShotAssetProjectionPlan
EpisodeBackendReferenceLayoutPlan
exact ExecutionProfile
```

输出：

```text
EpisodeBackendExecutionSpecificationPlan
```

每个 ProductionShot 对应：

```text
ProductionShotBackendExecutionSpecification
```

内部至少分：

```text
ExecutionSemanticSpec
BackendPromptSpec
RenderedBackendPrompt
BackendSemanticCoverageMap
RenderEnvelope / ContextEnvelope
RuntimeDerivedInputRequirements
WorkflowBindingSpec
BackendRequestSpec
AttemptVariableContract
```

这些仍是 compiler IR，B7.8才 materialize final v1.1 `ProductionShot`。

## 3. ExecutionSemanticSpec

`ExecutionSemanticSpec` 是 per-ProductionShot canonical execution-semantic representation。

它 deterministic 汇合：

```text
production_shot_identity
semantic window
subjects / actions / staging
camera / composition / framing semantics
continuity semantics
dialogue/subtitle/audio/hold refs
execution asset role refs
preservation constraints
forbidden-drift constraints
provenance
```

这里不出现 local path、actual seed、ComfyUI node、runtime endpoint或自由 prompt prose。

## 4. Semantic authority

冻结：

```text
RenderedBackendPrompt
is NOT the canonical semantic representation.
```

Backend切换应：

```text
same ExecutionSemanticSpec
→ different backend renderer
```

而不是 parse旧 H3 prompt猜 Shot meaning。

B7.6不得重新创作、重新解释或改变 B4/B5/B6 decisions。

## 5. Prompt 分层

正式链：

```text
ExecutionSemanticSpec
↓
BackendPromptSpec
↓
RenderedBackendPrompt
```

`BackendPromptSpec` 是 backend-specific structured representation，可包含：

```text
subject/action/environment sections
camera/composition/continuity sections
dialogue/timing sections
reference_mentions[]
preservation_constraints[]
backend_guardrail_clauses[]
```

它引用 B7.5 `reference_binding_id`，不自己决定 Picture N。

## 6. Picture token substitution

唯一 authority仍是 B7.5。

例如：

```text
BackendPromptSpec: reference_binding = RB_LINSEY
B7.5: RB_LINSEY → <Picture 1>
Renderer: emits <Picture 1>
```

因此：

```text
BackendPromptSpec does not decide Picture N
PromptRenderer does not decide Picture N
```

两者都消费 B7.5 authoritative layout。

## 7. Deterministic PromptRenderer

Normal B7.6使用 versioned deterministic `PromptRenderer`。

相同 exact inputs必须产生 canonical UTF-8/LF/whitespace-normalized identical prompt bytes/hash。

Qwen不作为 per-shot canonical prompt renderer。

否则同一个 approved Shot每次 compilation都可能产生不同 prose，破坏 reproducibility。

## 8. Qwen boundary

Qwen可用于：

- diagnose prompt/backend mismatch；
- 解释某 semantic无法映射的原因；
- 辅助设计/改进 PromptRenderer / ExecutionProfile；
- developer debugging。

但冻结后的 normal compiler：

```text
Python = renderer authority
```

Qwen不得在 compile time自由 paraphrase approved semantics。

## 9. Rendering ≠ creative rewriting

B7.6可以 deterministic 把 structured enum转换成 backend lexical form，例如：

```text
camera_movement=STATIC → "static camera"
```

但不得把 approved semantic text随意改成新的故事/动作事实，也不得为“更自然”改写 localized dialogue。

Release language与 backend instruction language可以不同；例如 English instruction prose + exact Chinese spoken line 是合法的，只要 policy/versioned renderer明确。

## 10. Symbolic reference clauses

Prompt compiler应优先构造 symbolic clause：

```text
REFERENCE_CLAUSE(binding=RB_LINSEY, role=CHARACTER_IDENTITY)
```

最后统一通过 B7.5 layout render `<Picture N>`。

禁止 prompt compiler维护第二套 Picture mapping。

## 11. Preservation / forbidden-drift constraints

B7.6必须把 upstream preservation requirements显式带入 execution semantics，例如：

```text
preserve character identity
preserve approved location identity
do not reverse orientation
do not introduce extra character
preserve required co-visibility
```

H3-specific guardrail wording可以作为 profile renderer tactic，但不得创造新的 story/editorial facts。

例如“canonical classroom must control background”可以是实现 `preserve LOCATION_IDENTITY` 的 backend-specific clause。

## 12. BackendSemanticCoverageMap

B7.6 正式生成：

```text
BackendSemanticCoverageMap
```

它证明每个 required ExecutionSemanticSpec item如何被实现，例如：

```text
character identity
→ REFERENCE_BINDING + PROMPT_CLAUSE

9:16 framing
→ WORKFLOW_PARAMETER

release hold
→ POSTPROCESS_OPERATION

subtitle
→ EXTERNAL_RELEASE_OPERATION
```

允许的 realization path包括：

```text
PROMPT_CLAUSE
REFERENCE_BINDING
WORKFLOW_PARAMETER
BACKEND_REQUEST_PARAMETER
POSTPROCESS_OPERATION
RUNTIME_DERIVED_INPUT
EXTERNAL_RELEASE_OPERATION
```

Required semantic没有 realization path必须 fail；“backend不支持所以忽略”不允许。

## 13. Ordinary subtitles

普通外挂字幕在 CoverageMap 中应属于：

```text
EXTERNAL_RELEASE_OPERATION
```

不要求塞进 H3 prompt。`not present in prompt ≠ not implemented`，但必须明确 downstream ownership。

## 14. Semantic / render / context envelopes

继续严格区分：

```text
SemanticWindow
≠ RenderEnvelope
≠ ContextEnvelope
```

B7.6负责后两者的 backend realization。

例如 semantic duration 4.73s、backend合法 buckets 5/6s，可 deterministic 选择最小合法 5s：

```text
SemanticUseWindow = 0–4.73
RenderEnvelope = 0–5.00
NON_SEMANTIC_POST_TRIM = 0.27
```

5.00s不得反写成 semantic duration。

## 15. DurationRealizationPolicy

Render envelope选择必须来自 versioned ExecutionProfile policy，例如：

```text
smallest legal render envelope that fully covers SemanticWindow
```

Padding/trim/pre-roll/post-roll必须显式标记 non-semantic。

若 backend无法合法覆盖 SemanticWindow：

```text
RENDER_DURATION_UNREALIZABLE
```

不得 silent truncate。

## 16. ContextEnvelope / continuation

Continuation input例如 previous last frame / last N frames 属于 `ContextEnvelope` 与 runtime-derived dependency，不属于 ProductionShot semantic interval。

B7.6正式引入：

```text
RuntimeDerivedInputRequirement
```

典型：

```text
PREDECESSOR_LAST_FRAME
PREDECESSOR_FRAME_WINDOW
PREDECESSOR_AUDIO_TAIL
GENERATED_UTTERANCE_AUDIO
```

这些：

```text
≠ B6 AssetRecord
```

## 17. Runtime dependency declaration / resolution

Compile time只声明：

```text
dependency type
producer ProductionShot identity/revision
extraction/selection policy
hash verification requirement
```

不能提前 pin未来 `attempt_002.mp4`。

GenerationAttempt执行时再 resolve exact producer attempt/artifact/derived byte hash。

如果 resolved bytes变化但 dependency policy不变，通常只是新 attempt provenance；若 dependency policy从 last-frame改 last-8-frames，则必须 recompile/new ProductionShot revision。

## 18. WorkflowTemplate

ExecutionProfile pin exact：

```text
workflow_template_id
workflow_template_revision
workflow_template_hash
```

Known-good GUI export可经过正式参数化、去除 production-specific refs/values后成为 template。

Runtime不得随意使用“当前 GUI里打开的 workflow”。

## 19. WorkflowParameterContract

正式 pin versioned `WorkflowParameterContract`，明确逻辑参数：

```text
PROMPT_TEXT
WIDTH
HEIGHT
RENDER_DURATION
VISUAL_REF_1...
VOICE_REF
...
```

与 exact template target（最终可为 node_id + input_name）的 mapping。

B7.6不得靠“node 104看起来像 prompt”猜语义。

## 20. Logical slot → ComfyUI input

B7.5分配：

```text
logical backend slot
```

B7.6才做：

```text
logical slot
→ exact workflow template parameter target
```

Workflow node id变化属于 template revision，不污染 Asset identity。

## 21. Hidden production constants

如果应动态绑定的字段仍残留：

```text
old asset ref
old prompt
old duration
old dimensions
old dialogue
old seed
```

则 compile/validation fail。

Backend-fixed constants（model/sampler/internal fixed parameter）允许，但必须显式声明为 ExecutionProfile-owned constants，而不是 undeclared accidental defaults。

## 22. Seed boundary

默认：

```text
actual seed = GenerationAttempt property
```

ProductionShot workflow spec只保存：

```text
seed_source = ATTEMPT_SEED
```

或 seed policy ref。

实际 seed变化不产生 ProductionShot revision。

## 23. Compile-time workflow vs attempt materialization

严格区分：

```text
CompiledWorkflowBindingSpec
≠ MaterializedGenerationAttemptWorkflow
```

Compile-time spec保存：

```text
workflow template hash
logical parameter bindings
reference binding IDs
render duration
prompt hash
symbolic runtime-input bindings
attempt-variable declarations
```

真正执行前再加入：

```text
attempt seed
staged source paths
resolved runtime-derived inputs
endpoint/output locator
```

生成 final ComfyUI API JSON。

## 24. Existing v1.1 migration

现有组件不废弃，而是收敛职责：

```text
prompt builder
→ deterministic B7.6 H3 PromptRenderer

refs staging
→ consume B7.5 layout; stage/verify exact bytes only

build-request
→ execution spec / attempt request materializer

build-api-workflow
→ template binder/materializer

comfyui-generate
→ downstream executor
```

## 25. Hash layering

建议至少区分：

```text
backend_prompt_spec_hash
rendered_prompt_hash
workflow_template_hash
compiled_workflow_binding_spec_hash
backend_execution_spec_hash
```

Attempt layer再产生：

```text
materialized_generation_attempt_workflow_hash
generation_attempt_request_hash
```

避免一个模糊 `workflow_hash` 混淆 compile-time 与 runtime state。

## 26. Runtime environment boundary

以下不属于 ProductionShot compiled semantic identity：

```text
runtime endpoint
queue id
local staged path
output path
GPU identity
PID/worker id
```

它们进入 GenerationAttempt provenance。

## 27. Framing realization

B5批准 aspect ratio / framing semantics；B7.6根据 ExecutionProfile选择 exact pixel dimensions。

```text
aspect ratio semantics = B5
pixel dimensions = B7.6 backend realization
```

若 backend resolution无法保持 B5 safe area/co-visibility/framing semantics，应 fail/换 profile/route B5，而不是 silent crop。

## 28. Prompt capacity / compaction

ExecutionProfile可以声明 prompt capacity。

如果超限，只能使用 versioned deterministic `PromptCompactionPolicy` 删除 renderer冗余、缩短等价 enum措辞、消除 duplicate mentions；不得删除 required semantics。

仍超限：

```text
PROMPT_CAPACITY_EXCEEDED
```

不得让 Qwen自由总结。

## 29. AttemptVariableContract

B7.6正式声明哪些字段可在 same ProductionShot revision 的 GenerationAttempt间变化，例如：

```text
seed
runtime endpoint
staged locators
resolved runtime-derived input locator/hash
queue metadata
output locator
```

以下不得 attempt-variable：

```text
prompt semantics
asset selection
Picture ordering
workflow template
timing semantics
segment boundary
```

超出 contract 的变化必须 recompile。

## 30. Manual patch boundary

手工打开 generated prompt/workflow改几个字再跑，只能标记：

```text
EXPERIMENTAL / NON-CANONICAL
```

不能伪装成 current ProductionShot revision正式执行。

正式修复必须修改 upstream / profile / renderer / template并重新 compilation + validation。

## 31. B7.6 不执行 generation

B7.6可以生成 prompt / workflow binding / backend request spec，但不得：

```text
POST /prompt
```

Compilation与execution严格分开。

## 32. Failure categories

典型：

```text
EXECUTION_SEMANTIC_ASSEMBLY_FAILURE
BACKEND_SEMANTIC_COVERAGE_FAILURE
PROMPT_RENDERING_FAILURE
PROMPT_CAPACITY_EXCEEDED
REFERENCE_TOKEN_RESOLUTION_FAILURE

BACKEND_AUDIO_REALIZATION_FAILURE
BACKEND_EXECUTION_SPEC_INCOMPLETE
```

## 33. 冻结原则

1. B7.6是 backend code generation，不是 semantic authoring。
2. ExecutionSemanticSpec是 per-ProductionShot canonical execution meaning；rendered prompt不是 authority。
3. ExecutionSemanticSpec / BackendPromptSpec / RenderedBackendPrompt严格分层。
4. Picture substitution只来自 B7.5。
5. Prompt rendering deterministic/versioned；normal path不需要 Qwen。
6. Renderer不得 creative rewrite/translate/shorten approved semantics。
7. Backend-specific guardrails只能实现已有 preservation semantics。
8. 每个 required semantic必须有 explicit BackendSemanticCoverageMap path。
9. Unsupported semantics不得 silent omit。
10. SemanticWindow / RenderEnvelope / ContextEnvelope严格分离。
11. Padding/trim/overlap均为 non-semantic execution mechanics。
12. Runtime-derived inputs与 B6 source assets严格分离。
13. Compile spec声明 dependency policy；attempt解析 exact runtime bytes。
14. WorkflowTemplate / ParameterContract exact pin/hash。
15. B7.6绑定 logical slots到 workflow params；B7.5仍是 ref-layout authority。
16. Template不能隐藏 production-specific refs/defaults。
17. Actual seed/path/endpoint等属于 attempt scope。
18. Compile-time workflow spec与 attempt materialized JSON分离。
19. Pixel dimensions是 backend realization，不重定义 B5 framing。
20. AttemptVariableContract严格限制 retry-time changes。
21. Manual patch为 non-canonical；正式修改必须 versioned recompile。
22. B7.6不调用 H3/ComfyUI generation。
23. Existing v1.1 components应作为 adapters演化，不重造 parallel stack。
