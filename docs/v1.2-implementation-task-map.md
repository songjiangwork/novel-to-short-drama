## 1. Implementation 总原则

v1.2 implementation 不重写现有 v1.1 H3 / ComfyUI runtime。

采用：

```text
build new canonical pipeline
        ↓
compile into existing runtime
        ↓
gradually remove legacy authority
```

核心原则：

```text
v1.2 = new semantic/artifact/compiler authority

v1.1 =
existing execution adapters
+ ComfyUI transport
+ QC / retry runtime
```

禁止：

- 一次性重写整个项目；
- 先实现 UI；
- 为未来扩展提前引入数据库、ORM 或服务集群；
- 同时维护两套 ProductionShot runtime hierarchy；
- 让旧 selector / prompt builder 继续拥有 canonical authority。

## 3. Phase F — Canonical Artifact Foundation

不能直接从 A1、B1 或 B7 开写。A1–B7 反复使用 artifact identity、revision、content_hash、ArtifactRef、canonical serialization、lineage、approval、validation、immutability、current/historical semantics，必须先统一。

### F1 — Canonical Serialization + Hashing

实现：

- canonical JSON serialization；
- stable SHA-256 content hashing；
- schema version support；
- normalized UTF-8 serialization；
- deterministic key ordering。

必须保证：

```text
same semantic object
→ same canonical bytes
→ same content_hash
```

Acceptance：deterministic hash、Unicode 稳定、内容变化必然改变 hash、round-trip tests。

### F2 — ArtifactRef + Immutable Artifact Envelope

统一实现：

```text
ArtifactRef {
  artifact_type
  artifact_id
  revision
  content_hash
}
```

以及 reusable immutable artifact envelope。每个 stage 不得重新定义 ref 格式。

### F3 — File-backed Artifact Store

MVP 先不引入数据库。实现 lightweight immutable filesystem artifact store：immutable put/get、revision lookup、hash verification、atomic write、overwrite prevention。

### F4 — Lineage + Current Eligibility

统一实现 LineageRef、ApprovalRef、CurrentPointer、SupersessionRecord，明确：

```text
historically valid ≠ current execution eligible
```

支持 NORMAL_COMPILE 与 REPLAY_COMPILE。

### F5 — Validation Framework

将现有 validation 基础演进为 schema validation + cross-artifact validation + structured finding/severity/owner_stage/repair_route。

### F6 — Approval Infrastructure

为 B1/B2/B3/B4/B5/B6 formal gates 提供统一 ApprovalRecord / ApprovalDecision / current approved pointer / supersession primitives。

## 4. Phase A — Story Analysis Pipeline

现有 `docs/v1.2-A/07-v1.2-A-implementation-task-map.md` 继续 authoritative；工程顺序为：

### A-I1 — Source Ingestion

TXT / text-based PDF → immutable SourceDocument。支持 source hash、language metadata、chapter/paragraph parsing、schema、validation。OCR 不进入 MVP。

### A-I2 — Chunk Planning

SourceDocument → ChunkManifest。实现 paragraph ownership、context overlap、token budget、exact-one ownership、coverage validation、deterministic chunk IDs。

### A-I3 — Common LLM Adapter + Prompt Registry

实现 OpenAI-compatible provider adapter、local Qwen support、versioned prompt registry、structured JSON response parsing、request provenance、retry/resume/cache。业务模块不得 hard-code provider transport。

### A-I4 — Chunk Extraction

Chunk → LLM → CandidateExtraction。Python 验证 source refs、schema、range、ID integrity。

### A-I5 — Entity Reconciliation

Candidate entities → deterministic blocking → semantic ambiguity resolution → CanonicalEntityMap。保留 same / different / uncertain / must-not-merge。

### A-I6 — Fact / Event Consolidation

candidate facts/events + entity map → canonical evidence graph，包括 dedupe、event consolidation、relationship history、state transition、conflict tracking、narrative order。

### A-I7 — Global Story Bible

canonical evidence → hierarchical synthesis → GlobalStoryBible。Phase-A gate：`short-drama analyze-story project.yaml` 可执行 A1→A6，并支持 resume、artifact reuse、exact provenance。

## 5. Phase B12 — Adaptation + Structured Screenplay

### B-I1 — B1 Adaptation Domain Objects

实现 AdaptationTarget、AdaptationStrategy、SourceStoryDisposition、AdaptedStoryBeat、AdaptedStorySkeleton、EpisodePartition、AdaptationPlan 及 validation/approval objects。

### B-I2 — B1 Adaptation Pipeline

APPROVED GlobalStoryBible → AdaptationPlan → validation → approval。Qwen 负责 semantic proposals；Python 负责 coverage、IDs、budget、lineage、assembly、validation。

### B-I3 — B2 Screenplay Domain Objects

实现 ScreenplayScene、DialogueUnit、ActionUnit、EpisodeScreenplay、coverage mappings、continuity refs。保持 `AdaptedStoryBeat ≠ ScreenplayScene`。

### B-I4 — B2 Screenplay Pipeline

APPROVED AdaptationPlan → StructuredScreenplay → validation → approval。

## 6. Phase B34 — Production + Shot Planning

### B-I5 — B3 Production Planning

实现 ProductionUnit、ProductionRequirement、StagingRequirement、PerformanceRequirement、ContinuityRequirement、EpisodeProductionPlan，随后实现 APPROVED StructuredScreenplay → EpisodeProductionPlan → validation → approval。保持 `ScreenplayScene ≠ ProductionUnit`。

### B-I6 — B4 Shot Planning Domain

实现 PlannedShot、PCR、camera/composition semantics、continuity、transition、timing anchors、GenerationSegmentationContract、EpisodeShotPlan。保持 `ProductionUnit ≠ PlannedShot`。

### B-I7 — B4 Shot Planning Pipeline

APPROVED EpisodeProductionPlan → EpisodeShotPlan → validator → assembly → approval。

## 7. Phase B5 — Release Variant

### B-I8 — ReleaseVariant Core

实现 ReleaseVariantIdentity、localized dialogue、subtitle cues、release framing、aspect ratio realization、release timing、audio semantic events、release holds。保持 `localized_spoken_text ≠ subtitle_text`。

### B-I9 — ReleaseVariant Validation / Approval

EpisodeShotPlan → EpisodeReleaseVariant → B5.5 validation → B5.6 assembly → B5.7 approval，保护 Shot identity/order、PCR、camera semantics、reveal、continuity 与 B4 segmentation authority。

## 8. Phase B6 — Asset Resolution

### B-I10 — AssetRecord + Catalog

升级 registry 概念为 AssetRecord、AssetCatalog、AssetAvailabilitySnapshot、AssetCapability、AssetEvidence。Asset identity = asset_id + revision + content_hash，而不是 path。

### B-I11 — Requirement + Candidate Evaluation

实现 AssetRequirement、AssetCandidate、AssetEvidence、CandidateCombination、CompatibilityEvaluation。Qwen 可做 semantic compatibility reasoning；Python 管 candidate universe、hash、evidence pins、hard constraints。

### B-I12 — Binding + Validation + Approval

实现 ResolvedAssetBinding、EffectiveAssetBindingIndex、EpisodeResolvedAssetPlan、AssetResolutionValidationReport、AssetResolutionApprovalRecord。完成后 legacy `assets.selector.resolve_references()` 不再是 production canonical selector。

## 9. Phase B7 — Deterministic Execution Compiler

### B-I13 — B7 Compiler Core

实现 ExecutionCompilationContext、ProductionShotSegmentationPlan、ProductionShotIdentity、TimingProjectionPlan、AssetProjectionPlan，对应 B7.1–B7.4。正常路径 deterministic、无 Qwen、无 Picture N。

### B-I14 — Reference Layout Compiler

实现 ExecutionAssetRole、BackendReferenceRole、BackendReferenceChannel、BackendReferenceBinding、ReferenceLayoutPolicy、ProductionShotBackendReferenceLayout。正式接管 Picture N、audio/backend slots、reference ordering、capacity validation。旧 selector 中的 index/order/capacity authority 迁出。

### B-I15 — B7.6 Backend Compiler

实现 ExecutionSemanticSpec、BackendPromptSpec、BackendSemanticCoverageMap、RenderedBackendPrompt、RenderEnvelope、ContextEnvelope、RuntimeDerivedInputRequirement、WorkflowBindingSpec、BackendExecutionSpec、AttemptVariableContract。

迁移：

```text
prompting/builder.py → H3 PromptRenderer
comfyui/api_workflow.py → workflow template binder
workflows/request.py → compiled spec / attempt materializer
```

### B-I16 — B7 Validator + ProductionShot Assembly

实现 ExecutionCompilationValidationReport、validated_execution_compilation_bundle_hash、ProductionShot、compiled_execution_payload_hash、EpisodeExecutionManifest，以及 current manifest pointer、historical manifest、NORMAL_COMPILE、REPLAY_COMPILE、hash-based revision reuse。

## 10. Phase R — Runtime Cutover

### R1 — ProductionShot Execution Preflight

ProductionShot exact revision + EpisodeExecutionManifest → execution preflight。负责 exact asset resolution/hash verification、staging、runtime-derived dependencies、attempt seed、endpoint、output locator；禁止重新 build prompt/reselect refs/reorder refs/change topology。

### R2 — GenerationAttempt

正式引入 GenerationAttempt，pin exact EpisodeExecutionManifest、ProductionShot、attempt、seed、staged input hashes、runtime-derived inputs、materialized request/workflow hash、outputs。

### R3 — Adapt Existing ComfyUI Executor

保留 ComfyUIClient、generate_with_comfyui、media handling，改为消费 materialized GenerationAttempt。

### R4 — QC / Retry Migration

保留 seed-only retry architecture，并正式 enforce AttemptVariableContract。若 QC 需要修改 prompt/asset/Picture mapping/segment/workflow/timing，则返回 RECOMPILE_REQUIRED。

## 11. Phase E — End-to-End Integration

### E1 — Classroom Demo v1.2 Migration

使用现有 classroom_demo / E01_S003_SH002，人工提供 B4/B5/B6 frozen artifacts，验证 B7 compiler → existing H3 generation 与当前 known-good v1.1 path 语义等价。

### E2 — A→B Synthetic Small Story

准备 2–3 characters、1–2 locations、2–3 scenes、1 episode 的 synthetic story，完整走 A1→A6→B1→B7，generation 至少执行一个 Shot。

### E3 — Real Novel Pilot

前两项稳定后，再使用真实小说做 TXT/PDF → StoryBible → Adaptation → Episode → H3 output，验证 context scale、resume、LLM drift、large-artifact performance、human review workload。

## 12. CLI Migration Plan

开发阶段保留 stage-specific CLI；最终再提供高层 orchestration wrapper。高级命令不得绕过中间 artifacts。

## 13. Schema Strategy

继续使用 JSON Schema Draft 2020-12 作为 external artifact contract。Python 内部优先 dataclass / lightweight typed structures + explicit validators。MVP 不为此引入大型 runtime framework。

## 14. Persistence Strategy

v1.2 MVP 使用 file-backed immutable artifacts + content hashes + manifest/index files。暂不引入 SQLite domain DB、PostgreSQL、ORM、migration framework 或 service backend。

## 15. Testing Strategy

每个 implementation batch 至少包含：

- Unit tests；
- Artifact contract tests；
- Legacy/regression tests。

现有 v1.1 reference-order、prompt mapping、retry seed-only、ComfyUI workflow semantics tests 在 v1.2 equivalent coverage 完成前不得删除。

## 16. PR / Batch Discipline

每个 PR 应对应一个清晰 architectural capability、完整 tests、可独立 review，并保持 main runnable。目标约 15–20 个 implementation PR；避免少数超大 PR 或过度碎片化。
