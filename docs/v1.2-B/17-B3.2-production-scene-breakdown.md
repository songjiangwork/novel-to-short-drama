# B3.2 — Production Scene Breakdown

状态：**FROZEN**

## 1. 职责

B3.2 将 `EpisodeProductionContext` 分解为 versioned `EpisodeProductionBreakdown`，核心 first-class object 为：

```text
ProductionUnit
```

`ProductionUnit` 是 coherent production execution unit，不是 `ScreenplayScene`、Shot 或 generation job。

## 2. ScreenplayScene ↔ ProductionUnit

正式允许 many-to-many：

```text
1 ScreenplayScene → many ProductionUnits
many adjacent ScreenplayScenes → 1 ProductionUnit
```

跨多个 ScreenplayScenes 合并只允许在 presentation 相邻、时间/地点/production-state/participants/continuity compatible 时发生；不能抹掉原 ScreenplayScene identity。

## 3. Split / merge 边界

强 split signals 包括：

- meaningful production-state change
- major participant configuration change
- significant entrance/exit
- visible prop / wardrobe / appearance phase change
- environment-state change
- distinct physical-action / performance phase
- abstract production constraint requires decomposition

以下不能单独成为 split 理由：speaker change、reaction、想拍 close-up/insert、shot 数、camera angle、H3 clip length。

若 constraint-driven decomposition 必须改变 screenplay semantics，则返回 `SCREENPLAY_CHANGE_REQUIRED`。

## 4. ScreenplayProductionMapping

正式引入：

```text
ScreenplayProductionMapping
```

mapping 必须能下沉到 `ScreenplayElement` ID/range，回答某 ProductionUnit 承担哪些 screenplay material 以及内部顺序。

每个需要制作实现的 canonical `ACTION / DIALOGUE / REACTION / PAUSE` 必须 exactly one primary ProductionUnit owner。

Multiple camera coverage 属于 Shot Planning，不在 B3.2 创建 multiple primary owners。

## 5. Boundary / order

ProductionUnit boundary 只能落在 ScreenplayElement 之间；B3.2 不得拆 dialogue/action atomic element。若 element 本身无法合理 production-decompose，应回 B2.3 revision。

ProductionUnit 顺序以及 unit 内 screenplay material 顺序必须与 canonical EpisodeScreenplay presentation order monotonic 一致。

正式区分：

```text
ProductionSequence ≠ actual execution / generation schedule
```

为 asset cache 或拍摄方便改变实际运行顺序属于 downstream scheduling，不改变 canonical sequence。

## 6. Stable identity / revision

`ProductionUnit` 使用 stable ID。仅 requirement/staging annotation 微调不改变 unit identity；split、merge、fundamental coverage reassignment 或 boundary 改变必须创建新 unit identity，可保留 lineage。

`EpisodeProductionBreakdown` 拥有独立 id/revision/hash；B3.3 必须 pin exact revision，禁止 implicit latest。

## 7. ProductionContinuityContract

正式引入：

```text
ProductionContinuityContract
```

描述某 ProductionUnit sparse：

```text
required opening production state
+
required ending production state
```

可包含 character presence/important position、prop visible state、door state、wardrobe/appearance/environment 等，但不是 detailed blocking plan。

## 8. Execution purpose / requirements coverage

ProductionUnit 可以有 `execution_purpose` 描述执行范围，但不得创建新的 dramatic objective。

B3.1 提出的 must-be-realized obligations 必须分配给 ProductionUnits。

Background/incidental population 不自动创建 narrative characters。

## 9. 非目标

B3.2 不：

- 修改 dialogue/action/reaction/pause semantics
- 新增 production-only action
- 绑定 concrete location/character/prop/voice asset
- 生成 camera/lens/framing/Shot
- 按 backend clip length 机械拆分
- 增加 formal approval gate

Production-only staging invention 留给 B3.4。

## 10. Validation / Python / Qwen

B3.2 必须 deterministic 检查 element/reference resolution、exact primary ownership、order、boundary、coverage、continuity references、must-be-realized assignment。

Python 负责 IDs/order/ranges/coverage/revision mechanics；Qwen 负责 semantic split/merge、execution coherence、production-state boundary reasoning。

## 11. 冻结 contract

1. 正式输出 versioned `EpisodeProductionBreakdown`。
2. `ProductionUnit` 是 execution unit，不是 Shot。
3. ScreenplayScene ↔ ProductionUnit many-to-many，但 merge 有严格 compatibility 条件。
4. `ScreenplayProductionMapping` 下沉到 ScreenplayElement。
5. 每个 required ScreenplayElement exactly one primary ProductionUnit owner。
6. boundary 只能位于 ScreenplayElement 之间。
7. B3.2 不修改 canonical screenplay elements。
8. Production sequence 保持 screenplay presentation order。
9. Production sequence 与 execution schedule 分离。
10. ProductionUnit stable identity；structural split/merge/reassignment 产生新 identity。
11. Breakdown 有独立 revision/hash，downstream exact pin。
12. `ProductionContinuityContract` 只定义 sparse opening/ending contract。
13. Production Continuity 不升级为 narrative truth。
14. ProductionUnit 可有 execution_purpose，但无新 dramatic objective。
15. Constraint 可影响 decomposition，但不能改变 screenplay truth。
16. must-be-realized obligations 必须被分配。
17. 不绑定 concrete asset、Shot、H3/ComfyUI/runtime。
18. B3.2 无 formal approval，最终 gate 留给 B3.7。
