# B4.4 — Shot Continuity + Transition Planning

状态：**FROZEN**

## 1. 职责

B4.4 负责相邻 PlannedShots 之间的 cinematography/editorial continuity 与 transition semantics。

正式输出：

```text
EpisodeShotContinuityPlan
```

核心对象：

```text
ShotTransitionContract
```

B4.4 不改变 Shot existence、purpose、PCR ownership、camera semantics 或 ProductionUnit ownership。

## 2. Continuity layering

正式分层：

```text
Adapted Continuity
→ Screenplay Continuity
→ Production Continuity
→ Shot Continuity
```

`ShotContinuityState` 只能保存 cinematography/editorial overlay，不能覆盖 production truth。

## 3. Diegetic vs Cinematographic continuity

Diegetic Continuity 来自 B3，例如角色位置、动作、prop/environment state、entrance/exit。

Cinematographic Continuity 由 B4.4 管理，例如：

- interaction axis
- screen direction
- eyeline
- camera side
- shot-scale progression
- picture/audio transition semantics

Camera rules 必须服从实际 production movement/state。

## 4. InteractionAxis

允许轻量 semantic `InteractionAxis`，例如：

```text
Linsey ↔ Song
Song → Door movement
```

使用相对 `SIDE_A / SIDE_B / ON_AXIS / FLEXIBLE`，不建立精确 3D world coordinates。

默认保持可理解的 180° continuity，但允许有明确理由的 intentional axis crossing。Intentional crossing 必须显式记录 rationale，不能作为绕过 validator 的标签。

## 5. Eyeline / screen direction

Eyeline 以 semantic target relation 表达，例如 toward character/prop/anchor，不要求 gaze angle。

Screen direction 可用：

```text
LEFT_TO_RIGHT
RIGHT_TO_LEFT
TOWARD_CAMERA
AWAY_FROM_CAMERA
NEUTRAL
```

Entrance/exit direction 可以成为 continuity constraint。Camera direction 不得修改 B3 中的实际 movement。

## 6. Match on action

正式支持 `MATCH_ON_ACTION`。可用轻量 action phase：

```text
START
CONTINUE
COMPLETE
AFTERMATH
```

或 `before contact / during transfer / after placement` 等 semantic markers。

Match-on-action 不得新增 staging，也不得让动作在 cut 后从头 reset。

## 7. Prop / body continuity

B4.4 必须保证相邻 Shot visual presentation 与 ProductionContinuity 一致，包括重要：

- prop holder/state
- standing/seated
- facing / movement direction
- door/window/environment state
- continuity-sensitive pose/action phase

不建立人体精确角度模型。

## 8. Transition taxonomy

v1.2 核心：

```text
CUT
MATCH_ON_ACTION
JUMP_CUT
DISSOLVE
FADE
OTHER_SEMANTIC
```

CUT 默认。JUMP_CUT / DISSOLVE / FADE 需要 legitimate semantic rationale，不得未经授权制造 time passage、location change 或 chronology implication。

暂不单独引入 MATCH_CUT 巨大 taxonomy。

## 9. Continuity reset

允许有理由的 `ContinuityReset`，例如：

- location change
- significant time jump
- new interaction geometry
- clear spatial re-establishment

Reset 不得用于隐藏 axis/screen-direction bug。

大部分 ShotContinuityState 应为 ProductionUnit/Scene-local sparse state，而非 episode/series 无限积累。

## 10. Multi-subject / POV

多人场景只追踪当前 cut 所需 active interaction relation，不建立完整 3D camera blocking graph。

Wide/two-shot/three-shot 可以重新建立 spatial/axis relation。

POV entry/exit 必须 readable，但不要求机械固定 pattern。

## 11. Audio bridge

B4.4 可以保存轻量 audio bridge semantics，例如：

```text
DIALOGUE_CONTINUES
AMBIENCE_CONTINUES
SOUND_EVENT_BRIDGE
NONE
```

不处理 mix level、asset、exact overlap duration。v1.2 暂不把 J-cut/L-cut 作为 canonical taxonomy；picture/audio timing 由 B4.5 refinement。

## 12. IntentionalContinuityException

允许记录 axis cross、jump cut、direction reversal、scale shock、spatial disorientation 等 intentional exception，但 intentional 不代表 automatically valid；B4.6 仍检查其 editorial legitimacy 与 PCR/production compatibility。

## 13. Revision authority

`EpisodeShotContinuityPlan` 拥有独立 id/revision/hash。

以下通常只产生 B4.4 revision：axis、eyeline、screen direction、transition、reset、exception、audio bridge。

若需要改变 local shot scale/viewpoint/movement，返回 B4.3；若需要 add/delete/split/merge/order 改变，返回 B4.2。

## 14. Python / Qwen

Python：ref/state/normalized-field mechanics、revision/hash、structural checks。

Qwen：axis/eyeline/spatial continuity、transition motivation、POV readability、intentional discontinuity reasoning。

## 15. 冻结原则

1. B4.4 输出 versioned `EpisodeShotContinuityPlan`。
2. Shot Continuity 是 camera/editorial overlay，不覆盖 ProductionContinuity。
3. 180°/eyeline/screen-direction 使用 semantic relation，不建精确 3D model。
4. Intentional discontinuity 必须显式且仍需 validation。
5. Match-on-action 不得新增 staging。
6. Transition 不得创造未经授权的 chronology/time semantics。
7. Spatial re-establishment need 可以诊断，但新增 Shot 必须回 B4.2。
8. ShotContinuityState sparse / local。
9. Audio bridge 仅保存 semantic relation，不做 audio engineering。
10. B4.4 不绑定 assets/backend/runtime，也无 formal approval gate。
