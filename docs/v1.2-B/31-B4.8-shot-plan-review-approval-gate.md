# B4.8 — Shot Plan Review + Approval Gate

状态：**FROZEN**

## 1. 职责

B4.8 是 Shot Planning 阶段唯一正式 human approval gate。

批准对象不是某份 PDF、Shot 编号列表或“当前镜头方案”，而是 exact：

```text
episode_shot_plan_id
+
revision
+
content_hash
```

只有 `APPROVED EpisodeShotPlan` 才允许 downstream Release Variant / Asset Resolution / execution compilation 正式消费。

## 2. ShotPlanApprovalRecord

正式引入独立 immutable：

```text
ShotPlanApprovalRecord
```

至少绑定：

- approval_record_id
- EpisodeShotPlan id/revision/hash
- exact ShotPlanValidationReport id/hash
- `validated_shot_bundle_hash`
- exact approved EpisodeProductionPlan id/revision/hash/approval record
- decision
- REVIEW_REQUIRED dispositions
- reviewer reference
- review metadata

ApprovalRecord 保存 references/hashes/decisions，不复制整份 ShotPlan 内容。

## 3. Entry gate

正式 review 前必须满足：

```text
EpisodeShotPlan lifecycle = DRAFT
matching ShotPlanValidationReport exists
validation result = PASS or PASS_WITH_REVIEW_ITEMS
plan.source_validated_shot_bundle_hash matches report
approved ProductionPlan lineage resolves
all exact constituent refs/hashes resolve
```

`FAIL` 不得进入可批准状态。

Validation pass 不等于 approval；human reviewer 仍可要求 revision。

## 4. REVIEW_REQUIRED dispositions

每个 `REVIEW_REQUIRED` finding 必须逐项：

```text
ACCEPT_AS_DESIGNED
或
REVISION_REQUESTED
```

只要任意 finding 为 `REVISION_REQUESTED`，当前 EpisodeShotPlan revision 不得 APPROVE。

WARNING 必须可见，但不要求逐项 disposition。

`ACCEPT_AS_DESIGNED` 绑定 exact finding + report + EpisodeShotPlan revision/hash，不能跨 revision 自动继承。

## 5. Review decision

正式 decision：

```text
APPROVE
REVISION_REQUESTED
ABANDON
```

不引入 conditional / temporary / soft approval。

## 6. Approval 粒度

B4.8 使用 **per-episode atomic approval**：

```text
no formal per-shot partial approval
no formal per-ProductionUnit partial approval
```

Reviewer 可以逐 Shot 检查并记录 finding，但正式批准针对整个 exact EpisodeShotPlan revision。

Series 可以 episode-by-episode incremental approval；v1.2 不引入 SeriesShotPlanApprovalRecord。

## 7. Lifecycle

EpisodeShotPlan lifecycle：

```text
DRAFT
APPROVED
SUPERSEDED
ABANDONED
```

`PASS` 后仍是 DRAFT，直到 human APPROVE。

一个 episode 最多只有一个 current APPROVED EpisodeShotPlan revision。新 revision APPROVED 后，旧 current approved revision → SUPERSEDED；历史 ApprovalRecord、ValidationReport 与 provenance 永久保留。

## 8. Immutability / revision

APPROVED EpisodeShotPlan revision immutable。

任意 canonical Shot semantic change，例如：

- Shot add/delete/split/merge/order
- PCR mapping
- purpose/focus
- scale/viewpoint/movement/composition
- axis/transition/continuity
- timing/segmentation contract

都必须创建新 revision，并从 earliest authoritative B4 stage rebuild affected downstream，然后重新：

```text
B4.6 validation
→ B4.7 assembly
→ B4.8 approval
```

Render-only formatting change不要求 reapproval。

ApprovalRecord 本身 immutable。

## 9. ProductionPlan lineage

ShotPlan approval 必须绑定 exact approved EpisodeProductionPlan lineage。

若 later ProductionPlan 新 revision 被 APPROVED：

- 旧 ShotPlan approval 仍历史有效；
- 不能冒充新 ProductionPlan lineage；
- 若要迁移为 current authoritative ShotPlan，必须 rebuild/revalidate/reapprove。

已有 historical reproduction 可以显式 pin 旧 approved lineage；禁止 implicit repin。

## 10. Optional cross-episode Shot continuity dependency

v1.2 **不强制**每集 ShotPlan 都依赖 predecessor ShotPlan。大多数 camera axis / eyeline / shot progression 都是 scene/ProductionUnit-local，跨集 production state 已由 B3 continuity 负责。

只有当当前 EpisodeShotPlan 明确声明 authoritative cross-episode cinematography dependency（例如同一场戏跨 episode 无缝继续、必须继承上一集 final camera relation）时，正式 approval 才要求 pin exact predecessor：

```text
predecessor_episode_shot_plan_id
revision
hash
approval_record_id
referenced predecessor shot / continuity refs
```

该 predecessor 必须已经 APPROVED。Draft planning 可暂时引用未批准 predecessor，但 formal approval 时 dependency graph 必须稳定。

## 11. Reviewer 行为边界

Reviewer 不得在 B4.8 gate 中直接编辑 canonical ShotPlan。

如需修改：

```text
REVISION_REQUESTED
→ route earliest authoritative owner
```

典型 route：

```text
B4.5 timing/segmentation
B4.4 continuity/transition
B4.3 camera semantics
B4.2 Shot structure/coverage
B3 production plan
B2 screenplay
B1 adaptation
```

Human 可以发现 B4.6 未发现的新问题，并记录 `HumanReviewFinding`；finding 应尽量引用 stable planned_shot_id / PCR / transition / timing refs。

Review note 不是 canonical Shot truth。

## 12. ShotPlanReviewPackage

可以 deterministic 构建 derived：

```text
ShotPlanReviewPackage
```

建议包括：

- RenderedShotPlan / Shot cards
- ProductionUnit → Shot map
- PCR PRIMARY/SUPPORTING coverage matrix
- camera semantics summary
- transition / continuity chain
- timing / segmentation summary
- reveal/knowledge-sensitive Shots
- constraint summary
- B4.6 findings
- upstream exact pins / provenance

它是 review projection，不是 source of truth。

Reviewer 可以通过 Markdown/PDF/UI 阅读，但正式批准对象始终是 canonical EpisodeShotPlan revision/hash。Reviewed representation 必须能够解析回 exact target。

## 13. Downstream authorization

只有 exact `APPROVED EpisodeShotPlan` 才能正式进入：

```text
Release Variant / Localization
Asset Resolution
Execution Compilation
```

Downstream 至少必须 pin：

```text
episode_shot_plan_id
revision
hash
shot_plan_approval_record_id
```

禁止 implicit latest。

新 downstream artifact 默认不能基于 SUPERSEDED ShotPlan 创建 current authoritative execution lineage；historical reproduction/debug/audit 可以显式使用旧 revision。

## 14. Approval scope

B4.8 只授权 canonical Shot Planning semantics。

它**不审批**：

- release-specific 9:16/16:9 concrete crop/layout
- localization / final spoken timing
- subtitle layout/timing
- concrete image / voice / background assets
- Picture refs / reference-slot ordering
- prompt wording
- concrete ProductionShot segmentation
- H3 / ComfyUI workflow
- seed / generation attempt
- generated video candidate
- QC / Retry result

因此：

```text
EpisodeShotPlan = APPROVED
Generated media candidate = ACCEPTED / REJECTED / RETRY
```

两个生命周期故意分离。

## 15. Downstream execution failure

如果 approved ShotPlan 在某 asset/backend 上难以执行，优先 route：

```text
execution retry
→ asset resolution change
→ backend / execution-profile change
→ generation re-segmentation
```

只要不改变 canonical Shot contract，不需要重新 B4 approval。

只有确认 canonical Shot semantics 本身必须改变时，才 `SHOT_PLAN_CHANGE_REQUIRED`，创建新的 B4 revision 并重新 validation/approval。

## 16. Fail-closed conditions

以下情况不得 APPROVE：

- EpisodeShotPlan id/revision/hash mismatch
- ValidationReport missing / targets another bundle
- B4.6 result = FAIL
- unresolved REVIEW_REQUIRED finding
- `source_validated_shot_bundle_hash` mismatch
- approved ProductionPlan lineage invalid/unresolvable
- constituent revision/hash unresolved
- declared predecessor ShotPlan dependency not APPROVED
- reviewed representation cannot resolve to exact canonical target
- target already ABANDONED

Downstream formal consumption 同样 fail closed。

## 17. Python / Human / Qwen

Python：

- verify exact target / report / bundle hash
- collect findings/dispositions
- verify upstream/dependency pins
- build review package
- record approval
- update lifecycle
- enforce one current approved revision
- enforce downstream pinning

Human：

- accept/reject camera/editorial design
- resolve REVIEW_REQUIRED
- raise HumanReviewFinding
- APPROVE / REVISION_REQUESTED / ABANDON

Qwen：

- explain findings
- summarize Shot Plan
- compare revisions
- show traceability

Qwen 不能 self-approve。

## 18. 冻结原则

1. B4.8 是 B4 唯一 formal human approval gate。
2. Approval 对象是 exact EpisodeShotPlan id/revision/hash。
3. 正式使用 immutable `ShotPlanApprovalRecord`，绑定 exact ValidationReport 与 validated bundle hash。
4. FAIL 不得批准；PASS/PASS_WITH_REVIEW_ITEMS 可进入 human review。
5. 所有 REVIEW_REQUIRED 必须逐项 `ACCEPT_AS_DESIGNED` 或 `REVISION_REQUESTED`。
6. 决策为 `APPROVE / REVISION_REQUESTED / ABANDON`。
7. Approval per-episode atomic，不支持 formal per-shot partial approval。
8. Lifecycle = DRAFT / APPROVED / SUPERSEDED / ABANDONED。
9. APPROVED revision 与 ApprovalRecord immutable。
10. Semantic change 必须 new revision + B4.6 + B4.7 + B4.8。
11. Approval 绑定 exact approved ProductionPlan lineage。
12. Cross-episode ShotPlan dependency 默认不强制；只有明确声明时才必须 pin approved predecessor。
13. Reviewer 不得在 gate 中直接编辑 canonical ShotPlan。
14. ReviewPackage / RenderedShotPlan 均为 derived artifact。
15. Downstream 只能消费 exact APPROVED EpisodeShotPlan，并 pin ApprovalRecord；禁止 implicit latest。
16. ShotPlan APPROVED 不等于 release variant / assets / ProductionShot / generated media 被批准。
17. Generated media 使用 ACCEPTED/REJECTED/RETRY，与 semantic artifact APPROVED 分离。
18. Backend/asset execution failure 不自动 invalidate ShotPlan approval；只有 canonical semantics 改变才新建 B4 revision。
19. Gate 与 downstream 均 fail closed on stale/missing hashes/refs/dependencies。
20. Qwen 可辅助解释，但不能 self-approve。
