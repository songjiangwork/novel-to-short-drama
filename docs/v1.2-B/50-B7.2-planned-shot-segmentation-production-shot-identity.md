# B7.2 — PlannedShot Segmentation + ProductionShot Identity

状态：**FROZEN**

## 1. 职责

B7.2 将 B4.5 `GenerationSegmentationContract`、B5.4 release timing realization 与 exact ExecutionProfile hard constraints 编译成 deterministic ProductionShot temporal partition，并建立 stable `ProductionShotIdentity`。

核心：

```text
segmentation
≠ editorial re-cut

ProductionShot
≠ GenerationAttempt

ProductionShot
≠ backend auxiliary task
```

## 2. 正式输入

B7.2 消费：

```text
ExecutionCompilationContext
exact B4.5 GenerationSegmentationContract
exact B5.4 release timing realization
exact ExecutionProfile segmentation/duration constraints
```

不消费 AssetCatalog，也不决定 Picture/asset/prompt/workflow。

## 3. 正式输出

输出：

```text
EpisodeProductionShotSegmentationPlan
```

其中每个 PlannedShot 有：

```text
PlannedShotSegmentation
  planned_shot_id
  generation_segmentation_contract_ref
  segment_count
  segments[]
```

每个 segment 概念保存：

```text
ProductionShotSegmentSpec
  production_shot_identity
  planned_shot_id
  segment_identity
  segment_ordinal
  segment_count
  start_boundary_ref
  end_boundary_ref
  canonical_time_window
  release_time_window
  segmentation_reason
  predecessor/successor refs
```

B7.2 只生成 compiler IR，不分配 final ProductionShot revision。

## 4. 1→N 的含义

正式定义：

```text
1 PlannedShot → 1..N ProductionShots
```

这里的 1→N 只表示同一个 editorial PlannedShot 的 generation segmentation。

禁止把 backend multi-pass误当多个 ProductionShots，例如：

```text
background pass
character pass
compositing pass
```

这些属于 workflow/backend tasks。

## 5. Temporal interval contract

每个 ProductionShot：

- 属于 exactly one PlannedShot；
- 对应一个连续 semantic temporal interval；
- 同一 PlannedShot segments按时间有序；
- 无 semantic gaps；
- 无 semantic overlaps；
- union == entire PlannedShot release realization range。

Multiple PlannedShots不得合并成一个 ProductionShot。

## 6. Semantic range 与 backend overlap 分离

Continuation backend可能使用 previous frames / overlap / latent state，但这些不改变 semantic segment boundary。

例如：

```text
PS-A semantic = 0.0–4.2
PS-B semantic = 4.2–8.1
```

即使 PS-B runtime 使用 3.9–4.2 的 context，PS-B semantic start仍是 4.2。

因此：

```text
semantic segment boundary
≠ backend generation handle / overlap
```

## 7. Boundary authority

所有 internal boundary identity 必须来自 B4.5，例如：

```text
SHOT_START
GENERATION_SEAM_A
GENERATION_SEAM_B
SHOT_END
```

B7 不以 raw timestamp创建 semantic seam。

职责：

```text
B4.5 = boundary identity / legal seam authority
B5.4 = release-time realization of boundary
B7.2 = legal boundary selection + partition compilation
```

同一 semantic seam在不同 locale/release可映射到不同 exact timestamp，而 seam identity不变。

## 8. Segment identity

Formal segment identity来自：

```text
start_boundary_ref + end_boundary_ref
```

而不是 ordinal。

`SEG01 / SEG02` 只是 human-readable order/display property。

这样在新增前置 seam 后，未变化的 boundary-pair segment不会仅因 ordinal改变而失去 logical identity。

Whole shot同样表示为：

```text
SHOT_START → SHOT_END
```

`WHOLE` 只是 display classification。

## 9. ProductionShotIdentity

正式 logical identity：

```text
ProductionShotIdentity
=
episode_id
+
ReleaseVariantIdentity
+
planned_shot_id
+
segment_identity
+
ExecutionProfile ID
```

ExecutionProfile使用 logical profile ID；profile revision变化在 identity dimensions不变时通常导致 same identity 的新 compiled revision，而不是新 logical Shot。

## 10. Identity change / revision change

必须产生新 identity：

```text
ReleaseVariantIdentity changes
ExecutionProfile ID changes
segment boundary pair/topology changes
```

通常只产生新 ProductionShot revision：

```text
B4/B5/B6 revision changes
ExecutionProfile revision changes
compiler policy changes
prompt/workflow execution content changes
```

前提是 logical identity dimensions与 segment topology不变。

## 11. Human-readable key

为兼容 v1.1，1:1 情况可继续使用：

```text
E01_S003_SH002
```

1:N 可使用：

```text
E01_S003_SH002_SEG01
E01_S003_SH002_SEG02
```

但这些只是 display/execution keys。

必须保持：

```text
PlannedShot("E01_S003_SH002")
≠
ProductionShot("E01_S003_SH002")
```

正式身份使用 typed identity。

## 12. Segmentation algorithm

Normal path deterministic：

```text
B4.5 legal boundary domain
↓
B5.4 release-time mapping + release-specific seam constraints
↓
required seams
↓
ExecutionProfile hard constraints
↓
legal partition solve
↓
versioned deterministic tie-break
↓
EpisodeProductionShotSegmentationPlan
```

默认原则：

```text
satisfy all hard constraints
then minimize ProductionShot count
```

Optional/legal seam只在需要时使用；required seam必须使用。

## 13. Tie-break policy

同样 segment count 下不能随机选 seam。

正式使用 versioned `SegmentationSelectionPolicy`，排序大致：

```text
1. satisfy B4 required boundaries
2. only use B4 legal boundaries
3. satisfy backend hard constraints
4. minimum segment count
5. B4 preferred seam semantics（如有）
6. ExecutionProfile deterministic preference
7. stable boundary-order tie-break
```

具体 backend preference必须进入 pinned policy，而不是 hidden heuristic。

## 14. Backend constraints

Backend max duration等是 partition constraint，不是 seam authority。

例如：

```text
Shot = 12s
legal seams = 4.2 / 8.1
backend max = 6s
```

可合法编译为三段。

若 B4没有任何 internal legal seam：

```text
NO_LEGAL_PARTITION
```

不得在 6.0s 自行切开。

## 15. B5 release timing 对 feasibility 的影响

B4 canonical interval可在某 locale合法，但 B5 localized spoken duration扩展后可能超过 backend duration limit。

B7 不得 truncate/speed-up/rewrite dialogue。

可以：

- 换另一个已授权 seam；
- 换 ExecutionProfile；
- route B5/B4 revision。

不能修改 B5 timing以迁就 backend。

## 16. Semantic duration 与 render duration

B7.2 只定义 semantic segment range。

Backend若只接受固定 duration bucket，例如 semantic 4.7s、backend生成 5s，则 5s 是后续 B7.6 `RenderEnvelope`，不改变 B7.2 identity/range。

## 17. Later-stage constraint feedback

B7.4/B7.5 可能发现某 partition导致 required refs超出 backend capacity。

Later stage可以：

```text
invalidate current segmentation plan
→ CompilationConstraintFeedback
→ restart B7.2
```

但不能原地 split。

新 partition仍只能使用 B4.5 已授权 seams。

Compiler必须跟踪 evaluated partition hashes并终止；legal partition space耗尽后返回 explicit infeasibility。

## 18. GenerationAttempt 分离

关系：

```text
ProductionShot revision
↓
GenerationAttempt 1
GenerationAttempt 2
GenerationAttempt 3
```

`attempt_number`、actual seed不进入 ProductionShotIdentity。

ProductionShot revision表示 compiled execution specification改变；GenerationAttempt表示执行同一个 exact revision。

## 19. Retry vs recompile

仍属于 retry：

```text
transient backend/network error
worker crash
new deterministic seed
queue retry
```

如果修改：

```text
prompt semantic content
reference subset/order
asset
segment boundary
release timing
ExecutionProfile
```

则需要 recompile，而不是继续同 revision retry。

QC不能把 WHOLE Shot拆成两个并称为“retry”；那是 topology recompile。

## 20. Failure categories

典型 deterministic failures：

```text
INVALID_SEGMENTATION_CONTRACT
INVALID_BOUNDARY_ORDER
REQUIRED_BOUNDARY_UNRESOLVED
RELEASE_TIMING_MAPPING_FAILURE
NO_LEGAL_PARTITION
EXECUTION_PROFILE_DURATION_INCOMPATIBLE
EXECUTION_PROFILE_SEGMENTATION_INCOMPATIBLE
```

## 21. Python / Qwen

Python负责 boundary graph、timing mapping、constraint solving、identity derivation、hashing与 validation。

Normal B7.2 不需要 Qwen。Qwen只可解释 `NO_LEGAL_PARTITION` 等失败与 upstream repair options，不能 invent seam。

## 22. 冻结原则

1. B7.2只编译 temporal generation segmentation。
2. PlannedShot → 1..N temporally ordered ProductionShots。
3. ProductionShot exactly one PlannedShot、one continuous semantic interval。
4. Multi-PlannedShot merge禁止。
5. Backend auxiliary passes不是 ProductionShots。
6. Segments完整覆盖 PlannedShot，无 semantic gap/overlap。
7. Backend overlap/context不改 semantic boundary。
8. 所有 internal seams必须由 B4.5授权。
9. B5.4实现 timing并可限制 seam usability，但不创造 seam。
10. ExecutionProfile不能 invent seam。
11. Segmentation deterministic，默认 minimum sufficient decomposition。
12. Segment formal identity来自 boundary pair，不来自 ordinal。
13. ProductionShotIdentity包含 episode + ReleaseVariantIdentity + PlannedShot + segment + ExecutionProfile ID。
14. Later B7 stage可 invalidate plan，但必须回 B7.2 recompile。
15. ProductionShot与 GenerationAttempt严格分层。
16. Retry不改变 compiled specification。
17. Normal B7.2 不依赖 Qwen。
