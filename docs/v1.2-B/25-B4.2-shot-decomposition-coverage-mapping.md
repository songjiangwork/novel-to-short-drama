# B4.2 — Shot Decomposition + Coverage Mapping

状态：**FROZEN**

## 1. 职责

B4.2 首次创建 canonical `PlannedShot`，决定每个 ProductionUnit 需要哪些 editorial Shots、它们的顺序、存在理由与 PCR coverage ownership。

正式输出：

```text
EpisodeShotBreakdown
```

它是 versioned creative Shot Planning artifact，而不是 deterministic derived context。

## 2. PlannedShot

每个 PlannedShot 至少包含：

- stable `planned_shot_id`
- exactly one `production_unit_id`
- unit-local order
- shot purpose
- semantic subject focus
- ShotCoverageMappings
- Staging / Performance provenance
- boundary rationale

B4.2 不决定完整 camera grammar、exact duration、asset 或 prompt。

## 3. Decomposition 原则

```text
ProductionUnit = execution semantic boundary
PlannedShot = perceptual / editorial coverage boundary
```

一个 PU 可以只需要一个连续 Shot，也可以需要多个 Shots。Shot decomposition 不采用：

```text
1 ACTION = 1 Shot
1 DIALOGUE = 1 Shot
1 ScreenplayElement = 1 Shot
```

主要驱动力是：

- PerceptualCoverageRequirement
- attention shift
- performance emphasis
- reveal / withholding
- staging phase
- spatial clarity
- reaction importance
- editorial continuity

## 4. Shot boundary

Shot boundary 可以发生在 atomic ScreenplayElement 内，例如一句 Dialogue 中切到 listener reaction；这不拆分或修改 canonical ScreenplayElement。

可使用轻量 semantic phase 引用，例如：

```text
during DLG_X
before reveal phrase
during reveal
after reveal reaction
```

不创建伪 canonical `DLG_XA / DLG_XB`。

## 5. ShotCoverageMapping

正式使用：

```text
PerceptualCoverageRequirement
↕
ShotCoverageMapping
↕
PlannedShot
```

Coverage role 仅冻结：

```text
PRIMARY
SUPPORTING
```

每个 REQUIRED PCR 至少一个 PRIMARY mapping。一个 Shot 可以覆盖多个 PCR；一个 PCR 也可以由多个 Shots 协作完成。

Mapping existence 不等于 semantic coverage completeness，后者由 B4.6 integrated validation 判断。

## 6. Shot purpose / provenance

每个 PlannedShot 必须具有 authoritative production/editorial purpose，例如：

- satisfy PCR
- preserve performance beat
- cover staging action
- establish necessary spatial relation
- bridge authorized continuity

纯“更 cinematic / 更漂亮”不能成为唯一存在理由。

Establishing、reaction、insert、shot-reverse-shot 都不是机械 mandatory pattern。

## 7. Coverage economy

设计原则：

```text
minimum sufficient coherent coverage
```

不是最少 Shot 数，也不是最大 coverage 数。每个 Shot 应提供新的 perceptual、performance、spatial、continuity 或 editorial value。

重复 subject 不自动等于 redundant；合法 emotional hold / rhythm / tension 可以重复视觉。反之，一个 Shot 承担过多互相冲突的 PRIMARY attention obligations 可能属于 under-decomposition。

## 8. Split signals

Shot split 的强信号包括：

- REQUIRED PCR 需要新的 perceptual focus
- attention 显著转移
- important reaction 成为主要信息
- reveal 需要独立强调
- staging / performance phase 改变
- spatial relation 需要重新建立

以下不能单独触发 canonical Shot split：

- speaker change
- ScreenplayElement boundary
- H3 clip length
- prompt length
- asset change
- GPU/runtime限制

## 9. Subject focus

`subject_focus` 可表示：

- character
- prop/object
- interaction
- spatial relation
- environment state

它定义 attention target，不等于具体 framing；framing 属于 B4.3。

## 10. Ordering

Shot sequence 必须保持 approved ProductionPlan temporal semantics。v1.2 默认不由 B4.2 发明 replay、time reversal 或其它 temporal manipulation。

Intercut 仍用线性 ordered PlannedShots 表达，不引入特殊 Shot graph。

Episode display order 可由 ProductionUnit order + unit-local shot order deterministic derive。

## 11. Stable identity

`planned_shot_id` 与 mutable display number 分离。

以下变化通常产生新 Shot identity：

- split / merge
- ProductionUnit ownership change
- fundamental PCR ownership change
- fundamental shot purpose / subject focus change

可保存 lineage；不得用同一 ID 偷换完全不同 coverage semantics。

## 12. B4.2 revision authority

`EpisodeShotBreakdown` 拥有独立 id/revision/hash。以下变化属于 B4.2 revision：

- Shot add/delete
- split/merge
- order change
- PU ownership change
- PRIMARY/SUPPORTING mapping change
- fundamental purpose/focus change

shot size / camera movement 属于 B4.3；exact duration 属于 B4.5；backend generation segmentation 不属于 B4.2。

## 13. Editorial Split vs Generation Split

```text
Editorial Shot Split
= final viewing contains a real cut
= B4.2

Generation Split
= one continuous PlannedShot split for backend execution
= downstream execution concern
```

如果 generation segments 最终必须产生 visible cut，必须返回 B4.2 创建真正新的 PlannedShots。

## 14. Python / Qwen

Python：IDs、PU ownership、ordering、ref resolution、mapping structure、PCR coverage accounting、revision/hash、provenance。

Qwen：semantic decomposition、cut-boundary reasoning、coverage economy、PRIMARY/SUPPORTING reasoning、attention overload、editorial coherence。

## 15. 冻结原则

1. B4.2 正式输出 `EpisodeShotBreakdown`。
2. 每 PlannedShot exactly one ProductionUnit owner；不跨 PU boundary。
3. Decomposition 由 perceptual/editorial semantics 驱动，不按 ScreenplayElement 机械切分。
4. Shot boundary 可位于 element 内，但不得改 upstream element。
5. REQUIRED PCR 至少一个 PRIMARY mapping。
6. Every Shot needs authoritative purpose，但不要求每 Shot 都绑定 REQUIRED PCR。
7. Establishing/reaction/SRS 不是模板化 mandatory pattern。
8. Stable Shot ID 与 display order 分离。
9. Editorial Split 与 Generation Split 严格分离。
10. B4.2 不增加 formal approval gate。
