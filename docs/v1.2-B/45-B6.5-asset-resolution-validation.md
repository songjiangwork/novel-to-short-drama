# B6.5 — Asset Resolution Validation

状态：**FROZEN**

## 1. 职责

B6.5 是 Asset Resolution 阶段的 **read-only integrated auditor**。

它验证 exact B6.1–B6.4 bundle 是否完整、内部一致、满足 `APPROVED EpisodeReleaseVariant`，并可进入 canonical assembly。

正式输出：

```text
AssetResolutionValidationReport
```

并引入：

```text
validated_asset_resolution_bundle_hash
```

B6.5 不重新选 asset、不修改 requirement/binding、不修 continuity、不生成 missing asset。

## 2. Exact validation bundle

正式验证：

```text
APPROVED EpisodeReleaseVariant
+
EpisodeAssetResolutionContext
+
EpisodeAssetRequirementPlan
+
EpisodeAssetCandidateEvaluationPlan
+
EpisodeAssetBindingPlan
+
all pinned AssetCatalog revisions
+
AssetAvailabilitySnapshot
+
AssetResolutionPolicyProfile
```

所有输入必须 exact pin id/revision/content_hash；禁止 implicit latest/default/current。

## 3. Result / severity

Result：

```text
FAIL
PASS_WITH_REVIEW_ITEMS
PASS
```

Severity：

```text
BLOCKING
REVIEW_REQUIRED
WARNING
```

存在 BLOCKING → FAIL，不得进入 B6.6。

无 BLOCKING、存在 REVIEW_REQUIRED → PASS_WITH_REVIEW_ITEMS，可进入 B6.6，但 B6.7 必须 formal disposition。

## 4. Read-only / no auto-fix

B6.5 可以 detect / compare / trace / diagnose / classify / route，但不能：

- replace/add/remove asset
- change requirement
- change compatibility status
- change continuity group
- choose another CandidateCombination
- generate missing asset

正式保持：

```text
validation ≠ repair
```

## 5. Validation domains

至少包括：

1. revision/reference integrity
2. approved ReleaseVariant lineage integrity
3. AssetCatalog / availability integrity
4. requirement completeness
5. binding completeness
6. required capability coverage
7. candidate eligibility integrity
8. asset content/provenance integrity
9. character identity consistency
10. appearance-state continuity
11. location continuity
12. prop / visual-text consistency
13. voice identity consistency
14. cross-asset set compatibility
15. scope inheritance / override correctness
16. asset economy / redundancy
17. unresolved requirement handling
18. cross-B6 consistency
19. unauthorized semantic adaptation
20. architecture-boundary leakage

## 6. Revision / lineage integrity

B6.1–B6.4 refs 必须 exact match。

例如 B6.3 针对 RequirementPlan rev2，而 B6.4 用 rev3，则：

```text
B6_BUNDLE_REVISION_MISMATCH
BLOCKING
```

必须重新验证 source `EpisodeReleaseVariant`：

```text
status == APPROVED
source_lineage_eligibility == CURRENT
```

正常 current-production 下 stale lineage → BLOCKING。

## 7. Catalog / hash / availability integrity

所有 selected assets 必须属于 pinned catalog universe。

`AssetRecord` identity/integrity 由：

```text
asset_id
asset_revision
content_hash
```

保证，而不是 path。

同 filename 内容被替换、hash变化 → `ASSET_CONTENT_CHANGED`，BLOCKING。

Required selected asset 当前 MISSING/INVALID/UNAVAILABLE → BLOCKING。

Historical AssetRecord 不因 path missing 被删除；这里判断的是当前 asset resolution 是否仍具备 asset-layer execution eligibility。

## 8. Requirement completeness

所有 active `REQUIRED` requirements 必须有有效 resolution。

`CONDITIONAL` 仅在 trigger active 时必须 resolve。

`OPTIONAL` 可以 unresolved；但一旦选择 concrete asset 来满足它，该 asset 仍必须 valid/compatible/non-conflicting。

禁止 missing entry = default。

## 9. Required capability coverage

对每个 binding，selected asset set capability union 必须覆盖所有 required capabilities。

可以派生 `AssetCapabilityCoverageMatrix` 用于审计：

```text
Requirement
→ capability
→ contributing AssetRecord(s)
```

它是 audit projection，不是 source of truth。

## 10. Candidate eligibility / evidence

Selected asset 必须来自有效 B6.3 evaluation：

```text
COMPATIBLE
COMPATIBLE_WITH_SUPPORT
```

或属于已验证 compatible 的 CandidateCombination。

`PARTIALLY_COMPATIBLE` 只有在合法 set 中 gap 明确补齐才可作为成员。

`INCOMPATIBLE` / `INSUFFICIENT_EVIDENCE` 不得进入 valid binding。

Evidence 必须 target exact asset revision/content hash；stale evidence → blocking reevaluation route。

如果 policy 要求 human verification，而当前只有 model evidence，也不能 PASS。

## 11. Character identity / appearance continuity

跨整 episode 检查同一 `CharacterRef` 是否发生无授权 identity family drift。

同时检查 continuity groups 中：

- costume
- hair
- injury
- age/state
- other canonically relevant appearance state

合法 canonical state transition允许 asset state变化；validator检查 asset变化是否与 upstream canonical state transition一致。

## 12. Location / prop / visual-text continuity

Location assets要检查 semantically relevant identity/spatial consistency，例如 door/window/landmark/layout，只在这些对 canonical continuity 有意义时执行。

剧情重要 prop要检查 identity/state。

Release-specific visual text必须与 B5 approved localized semantic content一致；en-US variant 不能 silent 使用 zh-CN text asset。

## 13. Voice consistency

同一 speaker + language/locale 正常应保持同一 voice identity binding，除非 approved semantics明确有 voice-state change。

必须区分：

```text
VOICE_REFERENCE
≠ PREEXISTING_UTTERANCE_AUDIO
```

只有后者使用 concrete measured duration 对照 B5 timing envelope。

Voice reference不得做错误的 utterance-duration validation。

## 14. Cross-asset compatibility

对所有 `ResolvedAssetSet`，individual compatibility 不等于 set compatibility。

必须检查 cross-asset evaluation 是否存在且仍 valid，例如：

- face / body 是否同 identity
- hairstyle/costume/state 是否一致
- location detail assets 是否同 canonical environment

Set 同时必须满足 consistency + capability completeness。

## 15. Scope inheritance / effective binding

Episode/scene/Shot/utterance scope inheritance必须 deterministic。

Shot-specific refinement可以合法增加 capability，但不得无 canonical reason override broad identity/state。

B6.5 应验证 `EffectiveAssetBindingIndex` completeness；禁止依赖 hidden default。

## 16. Asset economy / fragmentation

可检测：

```text
REDUNDANT_ASSET_SELECTION
ASSET_FRAGMENTATION
UNJUSTIFIED_ASSET_VARIATION
```

无害冗余通常 WARNING / REVIEW_REQUIRED；若冗余 asset引入 conflicting identity/state signal，则相关 continuity conflict 为 BLOCKING。

Semantic correctness 永远高于 asset economy。

## 17. Unresolved requirements

```text
REQUIRED unresolved → BLOCKING
active CONDITIONAL unresolved → BLOCKING
OPTIONAL unresolved → allowed / warning by policy
preferred capability missing → WARNING or REVIEW_REQUIRED
```

`ASSET_CREATION_REQUIRED` / `CATALOG_EXPANSION_REQUIRED` 是 repair route，不是 pass condition。

## 18. Provenance integrity

Selected AssetRecord 必须满足 `AssetResolutionPolicyProfile`。

如果 policy 禁止 unverified imported asset，却绑定 imported/unverified candidate → provenance violation。

Derived assets应能解析 source_asset_refs；broken derivation chain 按 policy fail closed。

## 19. Cross-B6 consistency

Local B6.2/B6.3/B6.4 checks 全部 PASS，不代表 B6.5 PASS。

Integrated auditor必须发现：

- individually compatible assets 组合后 identity drift
- binding aggregate 缺 required capability
- release-specific locale mismatch
- broad/specific scope contradiction
- duplicate/current evaluation contradictions

## 20. Resolution authority

Finding 应明确 route，例如：

```text
B6_1_CONTEXT_REVISION
B6_2_REQUIREMENT_REVISION
B6_3_REEVALUATION
B6_4_BINDING_REVISION
ASSET_CREATION_REQUIRED
CATALOG_EXPANSION_REQUIRED
ASSET_METADATA_ENRICHMENT_REQUIRED
B6_HUMAN_REVIEW
REQUIRES_B5_REVISION
REQUIRES_B4_REVISION
REQUIRES_B3_REVISION
REQUIRES_EARLIER_UPSTREAM_REVISION
```

B6.5 自己不执行 repair。

## 21. Report

至少包含：

```text
validation_report_id
revision
content_hash
validated_asset_resolution_bundle_hash
source_bundle_manifest
result
findings[]
blocking_count
review_required_count
warning_count
domain_summaries
repair_routing_summary
validator_contract_version
```

`source_bundle_manifest` exact 列出 ERV、B6.1–B6.4、catalogs、availability snapshot、policy 的 id/revision/hash。

## 22. Bundle hash

`validated_asset_resolution_bundle_hash` 基于 canonical authoritative content/reference identities，不依赖 raw path / hostname / temporary locator。

Availability snapshot identity/hash属于 validation input provenance。

任一 authoritative source revision/hash改变，旧 validated bundle立即失效。

## 23. Backend firewall

B6.5 不检查：

- H3 最大 ref 数
- ComfyUI workflow nodes
- GPU/VRAM
- backend喜欢哪张图

但 image/audio file corrupt、hash mismatch、unreadable 属于 B6 intrinsic asset validity。

## 24. Python / Qwen / Human

Python：exact refs/hashes、catalog membership、availability、coverage matrix、criticality、eligibility、scope/continuity graph、provenance、bundle hash。

Qwen：identity/appearance/location/voice coherence、semantic requirement satisfaction、redundancy diagnosis。

Human：可提供 verification evidence；正式 approval 留给 B6.7。

Qwen 不得 repair 或 self-approve。

## 25. 冻结原则

1. B6.5 是 read-only integrated auditor。
2. 输出 `AssetResolutionValidationReport`。
3. 引入 `validated_asset_resolution_bundle_hash`。
4. Exact resolved bundle，禁止 implicit latest。
5. Result/Severity 与 B4/B5 统一。
6. 不修 requirement/evaluation/binding，不生成 asset。
7. Source ERV 必须 exact APPROVED + current-lineage。
8. Selected assets 必须属于 pinned catalog universe。
9. Asset integrity使用 id/revision/hash，不用 path。
10. Active required requirements全部有效 resolve。
11. Required capabilities必须完整覆盖。
12. Selected candidates必须有有效 B6.3 evaluation/evidence。
13. Evidence exact hash-bound，content change 后不继承。
14. Character/location/prop/visual-text/voice continuity integrated validation。
15. Individual compatibility不等于 set compatibility。
16. Scope inheritance显式 deterministic。
17. Same canonical state不要求 same file，但 representations必须 coherent。
18. Required unresolved必须 FAIL。
19. Creation/catalog expansion是 repair route，不是 pass。
20. 检测 redundancy/fragmentation但不牺牲 semantic correctness。
21. Backend feasibility不属于 B6.5。
22. Findings必须明确 resolution authority。
23. Source change使旧 bundle hash失效。
24. Formal validation per-episode/per-release-variant atomic。
25. Local checks不等于 integrated PASS。
26. PASS/PASS_WITH_REVIEW_ITEMS才允许 B6.6。
