# v1.2-B1.7 — Review + Approval Gate（冻结）

## 职责

B1.7 是 B1 唯一正式 human approval gate。

它针对一个已经完成并经过 B1.6 integrated validation 的精确 AdaptationPlan revision，进行人工审查和正式授权。

核心边界：

```text
B1.7 = review + approve / request revision / abandon

B1.7 != editor
B1.7 != repair stage
B1.7 != adaptation reasoning stage
```

---

## Exact Revision Approval

Approval 必须绑定不可变内容，而不是某个可变文件名。

至少需要 pin：

```text
AdaptationPlan ID
AdaptationPlan revision
AdaptationPlan content hash
B1.6 ValidationReport ID/revision/hash
constituent artifact revision set
```

因此：

> Approval applies to immutable content, not to a mutable filename.

如果被批准 revision 后需要任何 semantic change，必须创建新的 AdaptationPlan revision，旧 revision 不得原地修改。

---

## Lifecycle / Validation / Decision 分离

不要把所有状态塞进一个巨大 enum。

### AdaptationPlan lifecycle

```text
DRAFT
APPROVED
SUPERSEDED
ABANDONED
```

### B1.6 validation result

```text
FAIL
PASS_WITH_REVIEW_ITEMS
PASS
```

### B1.7 review decision

```text
APPROVE
REVISION_REQUESTED
ABANDON
```

`SUPERSEDED` 只表示某个曾被批准的 revision 已不是当前 preferred approved revision，不抹掉其历史有效性或 provenance。

---

## Entry Gate

进入正式 approval 前必须满足：

```text
B1.1–B1.5 complete
B1.6 report exists
B1.6 report matches exact current revision/hash set
B1.6 result != FAIL
no BLOCKING findings
```

任何以下情况 fail closed：

- validation report missing
- validation result = FAIL
- report 与 current revision 不匹配
- content hash mismatch
- unresolved REVIEW_REQUIRED item
- unknown referenced artifact

---

## PASS_WITH_REVIEW_ITEMS

`PASS_WITH_REVIEW_ITEMS` 可以被批准。

含义是 plan 结构上可成立，但存在重大 creative/editorial decision 需要人工明确接受，例如：

- deliberate ending divergence
- critical subplot omission
- major character composite
- high duration risk
- weak but valid boundary

`REVIEW_REQUIRED` 不等于 technical error。

---

## Finding Disposition

每个 `REVIEW_REQUIRED` finding 必须得到显式 disposition：

```text
ACCEPT_AS_DESIGNED
REVISION_REQUESTED
```

不支持模糊 `ignore` / `waive_error`。

`ACCEPT_AS_DESIGNED` 的语义是：

> reviewer 已看见该重大 adaptation decision，并明确接受它成为本 revision 的设计。

WARNING 必须可见，但不要求逐项强制 disposition；reviewer 仍可基于 warning 请求 revision。

---

## AdaptationReviewManifest

B1.7 的主要人类 review surface 来自 B1.6 的 AdaptationReviewManifest。

建议顺序：

1. Resolved target
2. Adaptation thesis / dramatic promise / primary dramatic question
3. Major plot / character / relationship decisions
4. Critical source omissions / compression / merges / reorders
5. Invented material
6. All deliberate divergences
7. Episode overview（goal / climax / hook / estimated duration）
8. Risks / uncertainty / warnings

ReviewManifest 是 summary/index，不是第二份 authoritative truth。

每个重要条目必须引用 authoritative B1 IDs，避免 manifest 与实际 AdaptationPlan 漂移。

---

## ApprovalRecord

正式 approval 使用独立、immutable 的 `ApprovalRecord`，而不是只在 AdaptationPlan 中写 `approved: true`。

逻辑上至少记录：

```text
approval ID
AdaptationPlan ID
approved revision
approved content hash
ValidationReport ID/hash
reviewer identity
review timestamp
REVIEW_REQUIRED finding dispositions
decision
optional reviewer notes
```

ApprovalRecord 保存 references / hashes / decisions，不复制整个 AdaptationPlan 内容。

Reviewer identity 在 v1.2 保持最小，不引入企业 RBAC、PKI 或 digital signature 体系。

---

## Revision Requests

B1.7 不能边 review 边直接修改 plan。

Reviewer 请求变化时产生结构化 `RevisionRequest`，至少表达：

```text
request ID
source AdaptationPlan revision
requested change
rationale
affected IDs
earliest authoritative owner stage
```

Repair route 沿用 B1.6 earliest-owner principle：

```text
B1.1 target
B1.2 strategy
B1.3 disposition/mapping
B1.4 story/reveal/continuity
B1.5 episode partition
```

修复后必须重新生成 affected downstream B1 artifacts、重新跑 B1.6，再进入新的 B1.7 review。

---

## Whole-Plan Approval Only

v1.2 不支持正式 partial approval：

```text
Episodes 1–10 approved
Episodes 11–20 draft
```

B1 的 AdaptationPlan 是全局 narrative contract，存在 global arcs、ending、reveal、cross-episode dependencies。

可以局部 review，但正式 approval 只针对完整 AdaptationPlan revision。

---

## Approval Scope

Approval 只授权 `Adaptation Truth`。

它绝不修改：

```text
Source Truth
Story Bible canonical truth
```

如果 reviewer 接受 deliberate divergence，只表示该变化在这个 adaptation revision 中被接受。

同样，AdaptationPlan APPROVED 不等于 screenplay、production plan、shot、prompt 或 generated media 被批准/接受。

语义 artifact 使用 `APPROVED`；未来 generated media 使用 `ACCEPTED`，两者故意区分。

---

## Downstream Consumption

Production-authoritative Structured Screenplay 只能消费具有有效 ApprovalRecord 的 exact AdaptationPlan revision。

Downstream artifact 必须 pin：

```text
adaptation_plan_id
adaptation_plan_revision
adaptation_plan_hash
approval_record_id
```

后续出现新 revision 时，旧 downstream artifact 的 provenance 永远不自动改绑。

未来 project-level stale engine 可以判断旧 downstream 是否 stale，但 B1.7 本身不实现 stale propagation。

---

## Decisions

冻结正式 review decision：

```text
APPROVE
REVISION_REQUESTED
ABANDON
```

- `APPROVE`：当前 exact revision 成为正式 approved AdaptationPlan。
- `REVISION_REQUESTED`：当前 revision 不批准，生成 RevisionRequest 并回 owner stages。
- `ABANDON`：该 adaptation branch 不再继续。

不使用语义模糊的 `REJECT` 来同时表示“需要修改”和“整条方向放弃”。

---

## Branching

同一个 StoryBible 可以自然派生多个 AdaptationPlan：

```text
StoryBible revision X
├── AP_A high-fidelity
├── AP_B aggressive short-drama
└── AP_C another adaptation direction
```

每个 AdaptationPlan 独立拥有 revision / validation / approval history。

---

## Non-goals

B1.7 不做：

- adaptation strategy regeneration
- source disposition edits
- story skeleton edits
- episode boundary edits
- screenplay writing
- production feasibility
- H3/ComfyUI validation
- generation job management
- candidate acceptance
- project-wide invalidation / stale propagation

---

## B1 Completion Gate

B1 只有在以下全部成立时才完成：

```text
B1.1–B1.5 complete
+
current B1.6 ValidationReport
+
no BLOCKING
+
all REVIEW_REQUIRED findings dispositioned
+
valid immutable ApprovalRecord
```

此时：

```text
AdaptationPlan revision X = APPROVED
```

才允许进入 Structured Screenplay。

---

## 冻结原则

1. B1.7 是 B1 唯一正式 human approval gate。
2. Approval 针对 exact immutable AdaptationPlan revision。
3. Approval pin ID + revision + content hash + matching ValidationReport。
4. B1.6 FAIL / BLOCKING 阻止 approval。
5. PASS_WITH_REVIEW_ITEMS 可批准，但所有 REVIEW_REQUIRED 必须显式 disposition。
6. REVIEW_REQUIRED 只允许 `ACCEPT_AS_DESIGNED` 或 `REVISION_REQUESTED`。
7. WARNING 不要求逐项确认。
8. ReviewManifest 是 review projection，不是 authoritative truth。
9. ApprovalRecord 是独立 immutable provenance artifact。
10. Approved revision 不得原地修改；semantic change 必须新 revision。
11. RevisionRequest route 到 earliest authoritative owner stage。
12. 修复后 affected downstream + B1.6 必须重跑。
13. v1.2 只支持 whole-plan formal approval。
14. Approval 只授权 Adaptation Truth，不改变 Source Truth。
15. Semantic artifact `APPROVED` 与 future generated media `ACCEPTED` 明确分离。
16. 正式 downstream 只能消费有有效 ApprovalRecord 的 exact revision。
17. Downstream pin approved ID/revision/hash；新 revision 不自动改写旧 provenance。
18. B1.7 fail closed on stale/missing validation、hash mismatch、unresolved review items。
19. 正式 decision 为 APPROVE / REVISION_REQUESTED / ABANDON。
20. B1.7 不实现 project-wide invalidation/stale propagation。
21. B1 只有在一个 AdaptationPlan revision 正式 APPROVED 后才算 COMPLETE。
