## 1. Why v2 exists

A4E-C real-novel acceptance 暴露出 A4B v1 blocking recall 过宽的问题。

当前完整 12-chunk A3 corpus：

~~~text
candidate_count     = 139
characters          = 94
locations           = 33
unresolved_unknown  = 11
unresolved_other    = 1

semantic_pairs      = 2103
auto_same           = 38
semantic_blocks     = 351
~~~

大量 pair 不是因为实际 identity ambiguity，而是因为 shared token 只是 function word，或者两个 candidates 恰好来自相邻 chunk。

A4B v2 的目标不是提高 merge aggressiveness，而是提高 **blocking precision while preserving conservative recall**。

2026-09-22 zero-provider audit：

~~~text

~~~

Policy A 删除的 818 个 token-only pairs 在当前 corpus 中全部由以下 shared token sets 构成：

~~~text

("of",)           14
("of", "the")     13
~~~

Policy C 比 B 再删除 398 个 same-chunk adjacency-only pairs。当前没有足够 recall evidence 证明这 398 对可以安全全部删除，因此 v2 采用 **Policy B**，不采用 Policy C。

## 4. Blocking-token exclusion v2

### 4.1 Frozen minimal set

v2 只对 **identity-token blocking overlap** 排除：

~~~text
the
of
~~~

这是 deliberate minimalism。当前 real-novel audit 中，全部 818 个 function-word-only token false positives 都由这两个 token 构成。

本 issue 不引入通用 English stopword library，也不引入频率学习、TF-IDF、embedding 或 corpus-dependent heuristic。

### 4.2 Scope boundary

该 exclusion **只能**影响 blocking token signal。

它不得改变：

- normalized identity key；
- exact identity-key overlap；
- persisted display name / alias；
- strong/weak identity-key classifier；
- deterministic auto_same authority；
- source evidence；
- A4C semantic payload schema。

因此不要通过全局改变现有 extract_blocking_tokens() 的语义来意外改变 strong-key classification。

推荐窄实现：

~~~text
raw identity tokens
        ↓
v2 blocking-only filter
        ↓
effective blocking tokens
~~~

exact helper naming 由实现按现有代码风格决定。

## 5. Exact identity-key blocking remains unchanged

两个同类型 concrete candidates 只要存在 normalized exact identity-key overlap，仍然生成 EXACT_IDENTITY_KEY pair。

function-word exclusion 不得删除 exact key authority。

deterministic auto_same 继续只由 frozen strong exact identity-key policy 决定。

---

## 6. Meaningful identity-token overlap

对于 blocking token overlap：

~~~text
raw shared tokens
→ remove {"the", "of"}
→ effective shared tokens
~~~

只有 effective shared tokens 非空，才产生 identity_token_overlap。

进入 pair plan 的 shared_tokens 应反映 **effective v2 blocking tokens**，不保存已经被排除的 function words 作为 blocking authority。

需要保留的典型语义：

~~~text
White Rabbit
↔
the White Rabbit

effective shared tokens:
rabbit
white
~~~

同理应保留 Cheshire Cat、March Hare、Queen、Hatter 等 meaningful overlap。

---

## 7. Same-chunk adjacency safety net

同类型 candidates 如果：

~~~text
chunk_ordinal(left) == chunk_ordinal(right)
~~~

仍然可以仅凭 source proximity 生成 pair：

~~~text
signal = adjacent_chunk
~~~

即使没有 exact identity-key overlap，也没有 effective token overlap。

这是 v2 deliberate recall safety net。A4 的职责之一是修正 A3 chunk-local identity fragmentation；当前没有证据证明同一 chunk 内不同 local candidate names 在无 lexical overlap 时绝不可能指向同一实体。

因此 v2 不采用 Policy C。

---

## 8. Cross-chunk adjacency is supplemental, not generative

如果：

~~~text
abs(chunk_ordinal(left) - chunk_ordinal(right)) == 1
~~~

且 candidates 来自不同 chunk，则 adjacent_chunk **不能单独生成 pair**。

也就是说：

~~~text
cross-chunk adjacency-only
→ implicit not_compared
~~~

但如果 pair 已经因为其他独立 authority 存在，例如：

- exact identity-key overlap；
- effective identity-token overlap；
- future explicit hard must-not-merge constraint；

那么可以继续附加 adjacent_chunk 作为 supplemental deterministic signal。

推荐 implementation shape：

1. exact-key / token / hard authorities 先生成 pair；
2. same-chunk window 仍可独立生成 pair；
3. cross-chunk adjacency 不做全 bucket Cartesian-product generation；
4. 对已经存在的 pair，如果 ordinal distance == 1，再附加 adjacent_chunk。

这样既保留 diagnostic information，也避免 adjacency 自身制造大量 cross-chunk pairs。

## 12. Required tests

### token filtering

必须证明：

- the 不产生 v2 token-overlap authority；
- of 不产生 v2 token-overlap authority；
- the + of 不产生 v2 token-overlap authority；
- meaningful token 保留；
- filter deterministic / idempotent；
- raw normalization / identity-key behavior不变；
- strong-key classification不因 blocking-only filter 漂移。

### pair generation

必须证明：

- exact-key pair 保留；
- meaningful-token pair 保留；
- same-chunk adjacency-only pair 保留；
- cross-chunk adjacency-only pair absent；
- distant no-signal pair absent；
- adjacent cross-chunk pair 如果因 exact/token authority 已存在，可包含 supplemental adjacent_chunk；
- char↔location 不生成；
- unresolved 不生成。

### deterministic identity

必须证明：

- blocking_policy_id == "a4-blocking-v2"；
- pair ordering deterministic；
- signals deterministic/sorted；
- effective shared_tokens deterministic/sorted；
- plan_hash stable for same inputs；
- v2 identity 与历史 v1 不可静默等价。

### complexity

继续禁止 whole-document N² enumeration，尤其不要为了判断 cross-chunk adjacency 重新枚举 whole candidate universe。
