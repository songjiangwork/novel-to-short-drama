# B6.7 — Asset Resolution Review + Approval Gate

状态：**FROZEN**

## 1. 职责

B6.7 是 B6 唯一正式 human approval gate。

它回答：

```text
这个 exact EpisodeResolvedAssetPlan
是否可以成为后续 Execution Compilation
唯一正式的 concrete asset authority？
```

正式输出：

```text
AssetResolutionApprovalRecord
```

B6.7 不批准 backend slot/order、ProductionShot、H3/ComfyUI execution 或 generated media。

## 2. Approval target

正式批准 exact：

```text
EpisodeResolvedAssetPlan
  id
  revision
  content_hash
```

同时 exact pin：

```text
AssetResolutionValidationReport
  id
  revision
  hash

validated_asset_resolution_bundle_hash

EpisodeReleaseVariant
  id
  revision
  hash
  approval_record_id
```

禁止“当前资产方案 / 最新 plan / 这套素材”之类模糊 target。

## 3. Approval scope

正式约束：

```text
one exact EpisodeReleaseVariant
→ at most one current APPROVED EpisodeResolvedAssetPlan revision
```

不同 ReleaseVariant 可以各自拥有独立 current approved AssetPlan。

B6 v1.2 不引入 backend-specific parallel approved AssetPlans；backend差异属于 B7。

## 4. Decision taxonomy

正式 decision：

```text
APPROVE
REVISION_REQUESTED
ABANDON
```

不引入 conditional / partial / temporary approval。

## 5. APPROVE entry gate

仅当全部满足才可 APPROVE：

```text
EpisodeResolvedAssetPlan.lifecycle_status == DRAFT
matching B6.5 validation exists
validation.result ∈ {PASS, PASS_WITH_REVIEW_ITEMS}
plan.source_validated_asset_resolution_bundle_hash matches report
source EpisodeReleaseVariant remains APPROVED
source ReleaseVariant lineage remains eligible/current
all REVIEW_REQUIRED items formally disposed
all exact refs/hashes resolve
```

B6.7 approval时必须重新验证 target content hash 与 validated source bundle hash。

任何 mismatch → `APPROVAL_BLOCKED`。

## 6. REVIEW_REQUIRED disposition

每个 `REVIEW_REQUIRED` finding 必须逐项：

```text
ACCEPT_AS_DESIGNED
REVISION_REQUESTED
```

任意 item = `REVISION_REQUESTED` → 当前 plan revision 不得 APPROVE。

WARNING 不要求逐项 disposition，但 reviewer可以人工升级为 revision request。

`PASS` 也不等于自动 APPROVE；human可以发现 automated validation 未覆盖的问题。

## 7. Reviewer boundary

B6.7 是 gate，不是 editor。

Reviewer 不得直接：

- 换 face/full-body/location asset
- 增删 ResolvedAssetSet member
- 改 voice binding
- 改 requirement / evaluation
- 改 continuity binding

正确流程：

```text
REVISION_REQUESTED
→ route authoritative owner
→ new B6 revision
→ B6.5
→ B6.6
→ B6.7
```

## 8. Human new evidence

如果 reviewer提供了影响 compatibility 的新事实，例如确认两张 character assets属于同一 canonical appearance state，该信息应正式进入：

```text
HumanVerificationEvidence
→ B6.3 reevaluation
→ B6.4
→ B6.5
→ B6.6
→ B6.7
```

不能仅靠 approval note绕过 evidence model。

## 9. AssetResolutionApprovalRecord

至少包含：

```text
approval_record_id

episode_resolved_asset_plan_ref {
  id
  revision
  content_hash
}

source_episode_release_variant_ref {
  id
  revision
  hash
  approval_record_id
}

source_validation_report_ref {
  id
  revision
  hash
}

validated_asset_resolution_bundle_hash

decision
review_item_dispositions[]
reviewer_notes
decision_timestamp
supersedes_approval_record_ref?
```

ApprovalRecord 本身 immutable。

## 10. Lifecycle

`EpisodeResolvedAssetPlan`：

```text
DRAFT
APPROVED
SUPERSEDED
ABANDONED
```

正常：

```text
DRAFT → APPROVED
```

Replacement：

```text
rev2 APPROVED
rev3 DRAFT
↓ rev3 APPROVE
rev2 → SUPERSEDED
rev3 → APPROVED
```

不得在 replacement成功 approval前提前 supersede旧 current plan。

`REVISION_REQUESTED` 是 approval decision，不单独增加 artifact lifecycle state。

## 11. Approved revision immutability

一旦 APPROVED，plan revision immutable。

任何 concrete asset semantic change，例如：

- asset content change
- set membership change
- voice binding change
- continuity binding change

都必须 new B6 revision。

Locator-only relocation、asset id/revision/hash均未改变时，通常不要求 plan semantic revision。

## 12. Historical approval vs current eligibility

历史 approval 与 current execution eligibility 分离。

如果 source EpisodeReleaseVariant 后来被新 revision supersede：

- 旧 AssetPlan历史 approval仍然是真实事实；
- 不 retroactively erase/rewrite；
- 但 normal new execution不应继续把 stale upstream lineage作为 current authority。

可以 derived：

```text
source_lineage_eligibility = CURRENT | STALE
```

它与 lifecycle_status解决不同问题。

## 13. Runtime availability

AssetPlan APPROVED 不保证几年后 path/NAS永远在线。

Runtime resource unavailable：

```text
approval validity remains historical
current execution eligibility may fail
```

B7启动新的 execution compilation时仍应重新确认 required selected AssetRecords 可解析且 content hash匹配。

## 14. Approval granularity

Formal approval：

```text
per EpisodeReleaseVariant
whole EpisodeResolvedAssetPlan atomic approval
```

不支持：

```text
character package approved / location pending
Shot 1 approved / Shot 2 pending
voice approved / visuals pending
```

作为正式 downstream authorization。

Review UI可以逐 component/Shot标记 reviewed，但 formal target始终是 whole exact plan revision/hash。

## 15. ReviewPackage

B6.7 可以消费 derived `AssetResolutionReviewPackage`，例如显示：

- character face/full-body/profile contacts
- location wide/detail refs
- selected voice refs
- requirement → binding → evidence
- Shot → effective asset set
- continuity groups
- review findings / warnings

Markdown/UI/contact sheet/thumbnail 都只是 projection。

Reviewer必须能从 projection解析回 exact：

```text
EpisodeResolvedAssetPlan id/revision/content_hash
AssetRecord ids/revisions/content hashes
```

Thumbnail本身不是 asset identity。

## 16. Qwen role

Qwen可以：

- explain asset selection
- compare plan revisions
- summarize evidence
- explain visual/audio continuity concern
- trace where each asset is consumed

但：

```text
Qwen ≠ approver
```

Formal `APPROVE / REVISION_REQUESTED / ABANDON` 由 human authority作出。

## 17. Approval scope exclusion

B6.7 APPROVE 只批准：

```text
which concrete assets are authorized
for which semantic roles/scopes
```

不批准：

- Picture N
- reference ordering
- backend role mapping
- prompt wording
- ProductionShot segmentation
- H3 / ComfyUI workflow
- seed / generation attempt
- generated video/media quality

## 18. Downstream authorization

B7 只能消费 exact `APPROVED EpisodeResolvedAssetPlan`，至少 pin：

```text
episode_resolved_asset_plan_id
revision
content_hash
asset_resolution_approval_record_id
```

以及 exact EpisodeReleaseVariant lineage。

禁止 `latest approved asset plan` 等 implicit selector进入 execution artifact。

## 19. B7 asset firewall

B7 可以：

```text
select subset
assign execution/backend roles
order refs
assign Picture N / backend slots
```

但只能从 approved effective asset universe 中选择。

B7 不得绕回 AssetCatalog自行挑 plan 外 arbitrary asset。

若 approved universe不足，必须 route B6。

## 20. Backend failure

Backend-specific generation failure优先处理：

```text
B7 compilation strategy
→ approved subset selection
→ reference ordering/role
→ backend profile/prompt realization
→ generation retry
```

只要 B6 assets仍正确满足 semantic requirements，backend表现不好不自动 invalidate B6 approval。

只有确认 asset semantic resolution本身错误时，才 `ASSET_PLAN_CHANGE_REQUIRED` 并回 B6。

## 21. Catalog/evidence evolution

Catalog后来新增“更好的”candidate不自动 invalidate approved plan。

如果希望采用它：new B6 revision。

Metadata仅增加描述/tag/locator且不改变 asset identity/capability truth，通常无需 reapprove。

如果 metadata correction表明旧 capability/state事实错误，则需要 reevaluation。

Validation/evidence policy未来升级也不 retroactively rewrite历史 ApprovalRecord；revalidation policy以后单独设计。

## 22. Cross-episode dependency

默认不要求 E02 AssetPlan依赖 E01 AssetPlan；series/project canonical asset registry通常足够。

只有确实存在 exact carried visual/voice state（例如跨集无缝承接的受伤服装状态）才声明 predecessor asset-state dependency，并在 approval时验证 predecessor dependency stable/approved。

## 23. Fail-closed conditions

以下情况不得 APPROVE：

```text
target id/revision/hash mismatch
B6.5 report missing
B6.5 result = FAIL
validated bundle hash mismatch
unresolved REVIEW_REQUIRED
source ReleaseVariant no longer eligible
required AssetRecord unresolved
selected asset content hash mismatch
declared predecessor dependency invalid
review representation cannot resolve exact target
target already ABANDONED
```

## 24. Python / Human / Qwen

Python：verify plan/report/hash、review disposition completeness、source ERV eligibility、approval-scope uniqueness、lifecycle/supersession、downstream authorization。

Human：accept/reject concrete asset plan、resolve subjective review items、raise HumanReviewFinding、APPROVE / REVISION_REQUESTED / ABANDON。

Qwen：summary/explanation/comparison/traceability only，不 self-approve。

## 25. State semantics

继续保持：

```text
EpisodeResolvedAssetPlan
→ APPROVED

Generated media candidate
→ ACCEPTED / REJECTED / RETRY
```

AssetPlan approval不等于 generated output accepted。

## 26. 冻结原则

1. B6.7 是 B6 唯一 formal human approval gate。
2. 输出 `AssetResolutionApprovalRecord`。
3. Approval target = exact EpisodeResolvedAssetPlan id/revision/hash。
4. 每 exact ERV最多一个 current approved AssetPlan revision。
5. 不创建 backend-specific parallel approved plans。
6. Decision = APPROVE / REVISION_REQUESTED / ABANDON。
7. PASS不等于自动 APPROVE。
8. REVIEW_REQUIRED逐项 disposition。
9. 任一 REVISION_REQUESTED阻止 approval。
10. Reviewer不得直接编辑 canonical plan。
11. 新 human evidence先回 B6.3 reevaluation。
12. Approval前重验 target hash / report / bundle hash / source ERV lineage。
13. APPROVED revision immutable。
14. New approved replacement atomically supersedes old current revision。
15. 不提前 supersede。
16. Historical approval与 current execution eligibility分离。
17. Source ERV superseded不 erase历史 approval，但 stale lineage不用于 normal new execution。
18. Locator-only change通常不是 semantic change；content hash change必须重新 resolution。
19. Whole-plan atomic approval，不支持 component/Shot partial formal approval。
20. Review projections不是 source of truth。
21. B6 approval不批准 Picture N/ref order/prompt/ProductionShot/H3/ComfyUI。
22. B7 exact pin approved plan，禁止 implicit latest。
23. B7只可选 approved asset universe subset，不得绕回 catalog。
24. Backend failure不自动 invalidate B6 approval。
25. AssetPlan APPROVED ≠ generated media ACCEPTED。
26. Python管 integrity/lifecycle，Human formal approval，Qwen只辅助。
