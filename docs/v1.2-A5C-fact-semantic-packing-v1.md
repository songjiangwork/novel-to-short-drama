# 2. Rationale (Alice zero-provider audit)

Observed zero-provider request shape:

```text
P1 — 6 pairs / 12 candidates
blocks = 353
rendered prompt:
  median = 12082 bytes
  p95    = 13220 bytes
  max    = 14676 bytes

P2 — 12 pairs / 24 candidates
blocks = 177
rendered prompt:
  median = 20917 bytes
  p95    = 22875 bytes
  max    = 25431 bytes

P3 — 24 pairs / 48 candidates
blocks = 89
rendered prompt:
  median = 38589 bytes
  p95    = 42250 bytes
  max    = 46192 bytes
```

Freeze P2 because:

```text
P1:
safe but requires 353 provider blocks.

P2:
cuts provider round trips approximately in half versus P1,
while requiring at most 12 structured decisions per response.

P3:
cuts calls further, but doubles the per-response decision count to 24
and materially increases structured-output completeness risk under the
tracked consolidation-llm-v1 max_output_tokens = 4096.
```

This is a precision / reliability-first v1 choice. P3 is NOT claimed to be
unable to work — it is simply not selected for v1 without evidence that the
larger response surface is worth the added structured-output risk.

# 3. Frozen packing algorithm

```text
1. consume A5B needs_semantic_decision fact pairs
   in canonical (left_ref, right_ref) order;

2. append greedily;

3. before appending the next pair, close the current block iff:
     pair_count + 1 > 12
   OR
     unique_candidate_count_after_append > 24;

4. never split a pair;

5. never reorder for packing efficiency;

6. no random packing;

7. no graph / community clustering.
```

Both limits are independent; a block closes when either would be exceeded.
No pair is split, lost, duplicated, or reordered. Block order is the
deterministic append order.

---

# 4. Candidate refs (frozen)

```text
candidate_refs = stable unique union of the block's pair endpoints

ordered by:
  source_order_key
  then candidate_ref
```

Set iteration order is forbidden. `candidate_refs` is used only for block
identity / audit / deterministic bookkeeping; the provider semantic context
stays pair-local endpoint packets (never a block-wide candidate or evidence
authority).

# 10. Issue #78 — explicit production refinement to v2

The original v1 remains frozen and separately inspectable:

```text
fact-semantic-packing-v1
  historical frozen post-audit policy
  12 pairs / 24 candidates
```

After A5G3 real-provider acceptance evidence, production moves explicitly to:

```text
fact-semantic-packing-v2
  static deterministic production policy
  6 pairs / 12 candidates
```

The evidence boundary is narrow and specific. For the P2 exact production
request below, the same requested pair was stably omitted:

```text
ordinal:      91
block_id:     a5fblk_d28e1b1374585166679a
pair_count:   12
request_hash: c9c51b54d788f747cd66e4786a4fb151f67c15b7db73965ad252338d6905834f

omitted pair:
CH005_C001:cand_fact_026 -> CH005_C001:cand_fact_043
```

Observed results were full production Round 1 = 11/12, production Round 2
with prompt-context reuse disabled = 11/12, and eight independent exact-request
diagnostic samples = 8/8 at 11/12 with that same omission. The isolated target
pair passed 1/1; the first two P2 pairs passed 2/2; the production-prepared P1
target block passed 6/6. Therefore the evidence supports an observed P2
12-pair structured-output adherence boundary, not malformed upstream data or
semantic impossibility.

V2 continues the same greedy canonical algorithm with limits `6` / `12`.
Those behavioral limits already belong to block identity material. Consequently
changed membership/topology naturally changes affected `block_id`, rendered
prompt hash, and request hash; no artificial version salt is added. Explicit
v1 preparation remains reproducible at 12/24.

V2 does **not** introduce provider-failure splitting, runtime packing selection,
or a third semantic round. It preserves the Fact prompt/schema/profile and the
two-stage execution contract: Phase 1 uses configured bounded concurrency and
a domain barrier; only semantic-invalid blocks retry serially in ascending
ordinal with the exact prepared request and prompt-context reuse disabled.

This evidence does not claim that every 12-pair request fails, that 6-pair
packing cannot fail, that llama.cpp is defective, or that Qwen cannot follow
JSON Schema. Prompt-context isolation remains a retry robustness mechanism;
it is not established as the cause of the observed P2 omission.
