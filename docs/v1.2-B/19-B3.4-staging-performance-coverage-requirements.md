# B3.4 — Staging + Performance + Coverage Requirements

状态：**FROZEN**

## 1. 职责

B3.4 回答：ProductionUnit 中的人物/物体如何在 diegetic production space 中执行 screenplay、表演语义如何保留、观众必须感知/理解什么。

正式输出：

```text
EpisodeStagingPerformancePlan
```

每个 ProductionUnit 对应 `ProductionUnitExecutionPlan`。

B3.4 不生成 Shot list。

## 2. 三个核心层

```text
Staging
= 人物/物体/空间的 production execution semantics

Performance
= dialogue/action/reaction 的表演语义

Perceptual Coverage
= 最终视听结果中观众必须感知/理解什么
```

Shot Planning 才决定具体 camera/audio coverage solution。

## 3. Staging / ProductionSpaceAnchor

正式引入 `StagingDirective`；允许使用轻量 `ProductionSpaceAnchor`，如 door/desk/window/bed。

空间关系使用 diegetic semantics：NEAR/BESIDE/AT/FACING/BETWEEN/HOLDING 等，不使用 camera-left、frame third、lens、像素坐标。

`ProductionSpaceAnchor ≠ asset coordinate ≠ image region`。

StagingDirective 必须保留 ScreenplayElement / ProductionRequirement provenance。

## 4. Production realization invention

B3.4 可以补充不改变 screenplay truth 的普通站位、移动、interaction detail。

若 staging 新增 narrative consequence、knowledge、possession、causal event、scene outcome，则越界：

```text
SCREENPLAY_CHANGE_REQUIRED
```

B3.4 不得新增新的 dramatic action 来“改善”剧情。

## 5. PerformanceRequirement

正式引入 `PerformanceRequirement`，保留重要：

- DialogueIntent
- subtext
- emotional stance
- interruption / overlap
- reaction
- pause / silence

Performance contract 只保留 semantically important intent，不做无必要的逐帧微表情微操。

Reaction / silence 如果承担 scene turn、knowledge processing、power shift 等 dramatic function，必须受 production contract 保护。

## 6. PerceptualCoverageRequirement

正式引入：

```text
PerceptualCoverageRequirement
```

定义：最终成片中观众必须能够感知、识别或理解的 production semantic obligation。

正式边界：

```text
PerceptualCoverageRequirement
= WHAT audience must perceive

Shot Plan
= HOW camera/audio coverage realizes it
```

原 `must_be_visually_realized` 泛化为 `must_be_perceptibly_realized`，可通过 visual / auditory / performance 方式实现。

Coverage 概念类别可包括 ACTION、OBJECT_STATE、INFORMATION、REACTION、SPATIAL_RELATION、PERFORMANCE、ENVIRONMENT_STATE。

使用 REQUIRED / PREFERRED criticality，并保存 stable provenance。

## 7. Temporal relations / interaction

B3.4 支持轻量：

```text
before
after
during
concurrent_with
```

用于表达 dialogue 与 action 并行等 execution semantics，但不建立 frame-accurate timeline。

重要 physical / object interaction 可以明确，只要上游已授权或无 narrative consequence。

## 8. ProductionContinuityDelta

正式引入：

```text
ProductionContinuityDelta
```

记录 unit execution 后 production overlay 的 sparse visible/performative change，例如 prop visible position、door/window、wardrobe/appearance、character production-space position、environment state。

它不得成为 narrative state transition source。

B3.5 将把 planned execution 与 B3.2 `ProductionContinuityContract` reconciliation。

## 9. Requirement consumption

B3.4 不得绕过 B3.3 创建新的 prop/character/location/environment requirement。

若 staging 需要新的 resource，返回 B3.3 revision。

Staging / Performance / Coverage objects 应引用其消费的 Requirement IDs，方便后续 Asset Resolution 和 Shot Planning。

## 10. Duration / complexity

B3.4 可更新 execution duration estimate 和 LOW/MEDIUM/HIGH 等 complexity metadata；它们不是 quality score，也不能反向删改 screenplay。

Production duration estimate ≠ Shot duration ≠ H3 clip length ≠ final edit timing。

B3.4 不按 backend clip length 机械拆分 ProductionUnit。

## 11. Failure routing

至少区分：

```text
STAGING_REVISION_REQUIRED
REQUIREMENTS_CHANGE_REQUIRED
BREAKDOWN_CHANGE_REQUIRED
SCREENPLAY_CHANGE_REQUIRED
ADAPTATION_CHANGE_REQUIRED
```

B3.4 不 silent repair upstream semantics。

## 12. Python / Qwen / non-goals

Python 负责 IDs/references/order/state/continuity/provenance/revision structural validation；Qwen 负责 staging/performance/perceptual semantic reasoning。

B3.4 不绑定 concrete asset、voice、H3/ComfyUI/runtime，不生成 camera/lens/framing/Shot，也不增加 formal approval gate。

## 13. 冻结 contract

1. B3.4 输出 versioned `EpisodeStagingPerformancePlan`。
2. 每个 ProductionUnit 对应 execution plan，但不改变 unit ownership/boundary/order。
3. Staging 只描述 diegetic execution，不描述 camera solution。
4. 使用 semantic spatial relations 与轻量 ProductionSpaceAnchor；不使用 camera-relative coordinates。
5. StagingDirective 保存 upstream provenance。
6. Production realization invention 合法，new screenplay semantics 非法。
7. 正式引入 PerformanceRequirement，并保护 DialogueIntent/subtext/reaction/pause semantics。
8. 正式引入 PerceptualCoverageRequirement。
9. perceptual obligation 与 Shot solution 严格分离。
10. must-be-perceptibly-realized 可由 visual/auditory/performance 实现。
11. Coverage 使用 REQUIRED/PREFERRED 并保存 stable provenance。
12. Shot Planning 消费 approved production semantics，不重新判断 narrative importance。
13. 支持轻量 temporal relation，不建立 frame-accurate timeline。
14. 正式引入 ProductionContinuityDelta，但不得覆盖 narrative truth。
15. continuity 保持 sparse representation。
16. B3.4 不得绕过 B3.3 创建新 requirement。
17. objects 显式引用所消费 Requirement IDs。
18. duration/complexity 只是 planning metadata。
19. staging revision 不改变 ProductionUnit identity；boundary 问题返回 B3.2。
20. 不 silent repair；按 owner route。
21. Python 负责 mechanics，Qwen 负责 semantic execution reasoning。
22. B3.4 不生成 Shot / camera / concrete asset / backend workflow。
23. B3.4 无 formal approval，最终 gate 留给 B3.7。
