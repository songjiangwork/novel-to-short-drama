# B6.6 — Episode Resolved Asset Plan Assembly

状态：**FROZEN**

## 1. 职责

B6.6 将 B6.5 已验证通过的 exact asset-resolution bundle deterministic assembly 成正式、完整、可审批的 concrete asset authority。

正式输出：

```text
EpisodeResolvedAssetPlan
```

核心 pattern：

```text
validated requirements
+
validated concrete bindings
+
validated evidence/provenance
↓
deterministic immutable assembly
↓
EpisodeResolvedAssetPlan [DRAFT]
```

B6.6 不拥有 asset selection / semantic repair authority。

## 2. Entry gate

仅允许：

```text
AssetResolutionValidationReport.result
∈ {PASS, PASS_WITH_REVIEW_ITEMS}
```

进入 B6.6。

`FAIL` 必须先 route repair。

## 3. Exact bundle firewall

B6.6 必须保存：

```text
source_validated_asset_resolution_bundle_hash
```

并要求：

```text
EpisodeResolvedAssetPlan.source_validated_asset_resolution_bundle_hash
==
AssetResolutionValidationReport.validated_asset_resolution_bundle_hash
```

Assembly 前重新计算 source bundle hash。任何 mismatch：

```text
ASSEMBLY_BLOCKED
```

Validation 后任一 authoritative B6 source发生变化，都必须重新 B6.5。

## 4. No semantic mutation

B6.6 不得：

- 换 asset
- 增删 selected asset
- 改 requirement
- 改 compatibility evaluation
- 改 continuity grouping
- 换 CandidateCombination
- 修 B6.5 finding
- 重新 inspect image/audio

只能：

```text
verify
materialize
normalize refs
expand effective binding inheritance
build indexes
build provenance
serialize/hash
manage lifecycle
```

## 5. EpisodeResolvedAssetPlan

至少包含：

```text
episode_resolved_asset_plan_id
revision
content_hash
lifecycle_status

source_episode_release_variant_ref
source_asset_resolution_context_ref
source_requirement_plan_ref
source_candidate_evaluation_plan_ref
source_binding_plan_ref
source_validation_report_ref
source_validated_asset_resolution_bundle_hash

resolved_requirements[]
resolved_asset_sets[]
resolved_asset_bindings[]
continuity_asset_bindings[]
effective_asset_bindings
asset_manifest
provenance_manifest
pending_review_items[]
validation_summary
derived_indexes
```

B6.6 创建：

```text
lifecycle_status = DRAFT
```

只有 B6.7 拥有 formal approval authority。

## 6. Downstream canonical authority

B6.7 APPROVE 后：

```text
APPROVED EpisodeResolvedAssetPlan
```

成为 asset layer 唯一正式 downstream authority。

B7 可以 inspect B6 provenance，但不得重新拼 B6.2/B6.3/B6.4 或绕回 catalog自己挑另一套 asset。

## 7. ResolvedAssetManifest

B6.6 deterministic 构建仅包含实际 selected assets 的 manifest：

```text
asset_id
asset_revision
content_hash
asset_kind
semantic_subject_ref
provenance ref
```

不复制整个 AssetCatalog。

Path / URI 可作为 operational locator metadata，但不得决定 semantic content hash。

## 8. ResolvedAssetSet

B6.4 已选定的 `ResolvedAssetSet` 被 exact materialize。

必须保持：

```text
ResolvedAssetSet
= approved semantic concrete asset package

ResolvedAssetSet
≠ ProductionShotReferenceSet
```

例如 approved set 可能含 face/full-body/profile；B7 某个 ProductionShot 只消费其中合法 subset。

B6.6 不做 subset selection。

## 9. Stable set identity

ResolvedAssetSet identity 应 anchor：

```text
semantic subject
scope
resolved binding purpose/state
```

而不是 array index、filesystem folder 或 backend slot。

## 10. EffectiveAssetBindingIndex

B6.6 应 deterministic 展开 B6.4 已定义的 broad binding + specific refinements，形成 explicit effective mapping，例如：

```text
PS018
  Linsey visual → LAS_LINSEY_A
  Song visual   → LAS_SONG_A
  Classroom     → LAS_CLASSROOM_A

LocalizedUtterance U018
  Linsey voice → voice_asset_ref
```

这样 B7 不需要自己实现另一套 inheritance semantics。

但 expansion 只能执行 B6.4 已显式授权的 inheritance；不得对缺失 resolution 自行猜默认值。

## 11. Consumer completeness

每个 asset-relevant consumer 必须可 deterministic resolve 到 effective binding，例如：

- PlannedShot
- LocalizedUtterance
- localized visual-text requirement
- continuity scope

没有 concrete asset requirement 的 Shot 不要求强制有 image binding。

## 12. Asset identity / locator

EpisodeResolvedAssetPlan pin：

```text
asset_id
asset_revision
content_hash
```

而不是 path。

若 asset 从 Windows path 移动到 NAS/WSL path，但 identity/hash不变，通常不构成 plan semantic revision。

如果 path相同但 file content hash变化，则不能冒充旧 AssetRecord，必须重新 ingestion/evaluation/resolution。

## 13. Availability provenance

B6.6 保留 B6.5 所使用 `AssetAvailabilitySnapshot` 的 exact provenance/reference。

Temporary mount path、hostname、signed URL等不进入 canonical semantic truth。

Runtime execution 前仍可以重新确认 locator/resolvability，这属于 execution eligibility，不 retroactively 修改历史 approval。

## 14. Provenance manifest

正式构建 `AssetResolutionProvenanceManifest`，支持：

```text
EpisodeResolvedAssetPlan
→ EpisodeReleaseVariant
→ AssetRequirement
→ ResolvedAssetBinding
→ CompatibilityEvaluation
→ AssetEvidence
→ AssetRecord
→ content hash / provenance
```

还应保留 item-level trace：

```text
selected AssetRecord
→ requirement
→ consumer Shot/utterance
→ release semantic obligation
```

这样 downstream/debug可以精确解释“为什么这张图/这段 voice被授权”。

## 15. Pending review items

如果 B6.5 = `PASS_WITH_REVIEW_ITEMS`，所有 `REVIEW_REQUIRED` finding IDs/refs 必须完整保留到：

```text
pending_review_items[]
```

B6.6 不得解决/隐藏它们。

WARNING 可进入 validation summary / review package，不要求逐项 disposition。

## 16. AssetResolutionReviewPackage

B6.6 可以 deterministic 派生 human-friendly：

```text
AssetResolutionReviewPackage
```

例如展示：

- Character → selected face/full-body/profile
- Location → selected wide/detail assets
- Voice → selected voice reference
- Requirement → binding → evidence
- Shot → effective assets
- continuity groups
- review findings / warnings

它是 review projection，不是 source of truth。

Thumbnail/contact sheet也只是 projection；正式 approval仍绑定 canonical plan hash 与 AssetRecord hashes。

## 17. Qwen role

Qwen 默认不参与 B6.6 canonical assembly。

Python core负责：

- bundle hash verification
- refs
- assembly
- inheritance expansion
- indexes
- provenance
- canonical serialization
- content hash
- lifecycle

Qwen如生成 readable summary，只能是 derived artifact。

## 18. Content hash / determinism

`content_hash` 应覆盖：

```text
source refs
resolved requirements
resolved bindings
selected AssetRecord ids/revisions/hashes
ResolvedAssetSets
scope/continuity bindings
effective resolutions
```

不覆盖：

```text
mount path
hostname
temporary URL
cache id
thumbnail
review UI state
```

正式要求：

```text
same validated bundle
+
same assembly contract version
→ same canonical content/hash
```

必须 canonical serialization + stable ordering。

## 19. Lifecycle / approval scope

Lifecycle：

```text
DRAFT
APPROVED
SUPERSEDED
ABANDONED
```

一个 exact `EpisodeReleaseVariant` 最多一个 current `APPROVED EpisodeResolvedAssetPlan` revision。

B6 v1.2 不引入 backend-specific parallel approved AssetPlans；backend variation留给 B7。

## 20. Approved revision immutability

APPROVED plan revision immutable。

换 concrete asset / set / voice binding / continuity binding 都必须 new B6 revision，然后重新：

```text
B6.3/B6.4 as needed
→ B6.5
→ B6.6
→ B6.7
```

Locator-only change且 asset identity/hash不变通常不要求 semantic revision。

## 21. B7 contract

B7 正式消费 exact `APPROVED EpisodeResolvedAssetPlan`。

B7 可以从 approved effective set 中为具体 ProductionShot选择合法 subset，并分配 backend role/order/slot。

B7 不得绕过 AssetPlan回 catalog独立选 arbitrary asset。

如果发现 approved universe 不足，应 route B6，而不是 silent substitute。

## 22. ProductionShot lineage

Future `ProductionShot` 至少应可 pin：

```text
EpisodeShotPlan id/revision/hash
planned_shot_id
EpisodeReleaseVariant id/revision/hash
EpisodeResolvedAssetPlan id/revision/hash
```

形成完整：

```text
Story/Shot semantics
→ Release semantics
→ Concrete asset authority
→ Execution unit
```

## 23. Assembly error

B6.6 可以因 structural/integrity 问题 fail，例如：

```text
validated bundle hash mismatch
missing source artifact
unresolvable binding
missing AssetRecord ref/hash
review finding lost
schema inconsistency
```

不能在 assembly阶段重新做 semantic compatibility judgment。

## 24. 冻结原则

1. B6.6 deterministic assembly only。
2. 输出 `EpisodeResolvedAssetPlan`。
3. 仅 B6.5 PASS/PASS_WITH_REVIEW_ITEMS可进入。
4. 保存并重算 `source_validated_asset_resolution_bundle_hash`。
5. Source变化必须重新 B6.5。
6. Plan 是 concrete asset canonical artifact，初始 DRAFT。
7. B6.6不改 asset/requirement/evaluation/continuity。
8. Selected AssetRecord exact pin id/revision/hash。
9. Path/URI不是 asset identity。
10. ResolvedAssetSet不是 backend ref list。
11. Deterministic 展开 EffectiveAssetBindingIndex。
12. 禁止 hidden/default inheritance。
13. 只包含实际 selected assets，不复制 catalog。
14. 保留 item-level provenance。
15. Review items完整传 B6.7。
16. ReviewPackage只是 derived projection。
17. Qwen默认不参与 canonical assembly。
18. APPROVED revision immutable。
19. 每 exact ERV最多一个 current approved AssetPlan revision。
20. Backend variation留给 B7。
21. Downstream必须消费 approved AssetPlan，不得绕回 catalog。
22. B7可选 approved subset，但不得用 plan 外 asset。
23. B6.6不创建 ProductionShot、不绑定 Picture N/H3/ComfyUI slot。
24. Future ProductionShot必须 pin exact AssetPlan lineage。
