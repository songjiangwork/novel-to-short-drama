# v1.2-B / B2 — Structured Screenplay 总览

状态：**FROZEN**

## 1. 目标

B2 将已经批准的 `AdaptationPlan` 戏剧化为结构化、可追踪、可验证、可审批的分集剧本。

核心边界：

```text
B1 = 改编后的故事发生什么
B2 = 这些内容如何被戏剧化成 scene / action / dialogue
Production Planning = scene 怎么拍
Shot Planning = 用哪些镜头覆盖 scene
```

因此：

```text
AdaptedStoryBeat ≠ ScreenplayScene ≠ ProductionShot
```

B2 不重新定义 adaptation truth，也不处理 camera、shot、voice asset、subtitle timing、ProductionLocation、H3 或 ComfyUI。

## 2. B2 完整结构

```text
B2.1 Screenplay Contract / Episode Context
B2.2 Scene Decomposition
B2.3 Dialogue + Action Realization
B2.4 Episode Screenplay Assembly
B2.5 Screenplay Continuity / Coverage Validation
B2.6 Screenplay Review + Approval
```

完整链：

```text
APPROVED AdaptationPlan
↓
EpisodeScreenplayContext
↓
EpisodeScenePlan
↓
SceneRealizations
↓
EpisodeScreenplay
↓
ScreenplayValidationReport
↓
ScreenplayApprovalRecord
↓
APPROVED EpisodeScreenplay
↓
Production Planning
```

## 3. 核心 artifact 边界

- `EpisodeScreenplayContext`：deterministic derived context，不是 source of truth。
- `EpisodeScenePlan`：screenplay-level creative planning artifact。
- `ScreenplayScene`：stable-identity first-class dramatic unit。
- `SceneRealization`：某个 ScreenplayScene 的具体 action / dialogue realization。
- `EpisodeScreenplay`：versioned canonical structured composition。
- `RenderedScreenplay`：从 canonical screenplay deterministic 生成的 derived view。
- `ScreenplayValidationReport`：read-only integrated audit artifact。
- `ScreenplayApprovalRecord`：human decision artifact。

## 4. Truth 与 invention 边界

B2 可以进行 `realization invention`，例如：

- incidental action
- dialogue wording
- reaction
- pause
- subtext
- minor transition
- small connective action

B2 不允许未经 B1 修订创造 `narrative invention`。

判断原则：

```text
如果删除某个 screenplay invention 后，B1 narrative truth 完全不变，
通常属于 realization invention。

如果它改变 fact / causality / knowledge state / relationship state /
major motivation / beat outcome / future dependency，
则属于 adaptation-level narrative change，必须返回 B1。
```

B2 不得创建新的 `AdaptedStoryBeat`。

## 5. Presentation 与 Beat traceability

B1 已冻结：

```text
adapted story chronology ≠ presentation order
```

因此 B2 同时保留：

```text
BeatSceneMapping
PresentationSceneMapping
```

以保证：

```text
AdaptedStoryBeat
→ ScreenplayScene
→ downstream Production
```

以及 reveal / withholding / flashback / partial exposure 的 presentation timing 可追踪。

## 6. Continuity 分层

```text
Adapted Continuity
= authoritative narrative state

Screenplay Continuity
= realization-level overlay
```

Screenplay overlay 可包含 promise、recurring phrase、unresolved conversational tension、callback、recent entrance/exit 等，但不得覆盖或篡改 Adapted Continuity。

跨集使用 hierarchical context，不依赖加载全部历史 screenplay。

## 7. Revision 与 pinning

B2 各核心 artifact 均使用 stable identity / revision / hash。

下游不得依赖 `latest` 推断，必须显式 pin exact revision。

任意 semantic change 均产生新 revision；已批准 revision immutable。

## 8. Validation 与 approval

验证分层：

```text
B2.3 = scene-local validation
B2.4 = composition / structural validation
B2.5 = episode-integrated semantic validation
```

B2.5 只允许：

```text
verify / diagnose / route
```

不得 repair / rewrite / regenerate。

B2.6 是 Structured Screenplay 阶段唯一正式 human approval gate。

只有 `APPROVED EpisodeScreenplay` 才允许 Production Planning 正式消费。
