# v1.2-B / B1 — Adaptation Strategy + Episode Planning（冻结）

## 目标

B1 将已经完成 source-grounded 理解的 Story Bible 转换为一个可验证、可审查、可正式批准的 Adaptation Plan。

核心语义边界：

```text
Story Bible
= 小说是什么

Adaptation Plan
= 我们决定改成什么

Production Bible
= 我们决定怎么拍
```

B1 不修改 Source Truth，也不进入 screenplay、scene、shot、asset、ComfyUI、MiniMax H3、generation job 或 QC runtime state。

---

## 输入

B1 正常消费：

```text
story_bible.yaml
Canonical Entities
Canonical Facts
Canonical Events
Canonical Relationships
Global Story Analysis
```

Story Bible 提供全局 reasoning index；A5 canonical evidence 仍是具体 source mapping 的 authoritative evidence，可沿 stable IDs / provenance 回查原始 paragraph。

## 冻结原则

1. Source Canon immutable；adaptation decision 绝不写回 A 层 canonical facts/events/entities。
2. `Source Event != Adapted Story Beat != Screenplay Scene != Production Shot`。
3. B1 可以做 creative adaptation decision，但必须保持 stable identity、provenance、traceability 和 explicit divergence。
4. Adapted Continuity 是 Source Canon 上的最小 overlay，不复制/分叉第二套 Story Bible。
5. 工作语言默认 `zh-CN`；最终 spoken dialogue language 属于后续 Release Variant / Localization，不由 B1 锁死。
6. 字幕 sidecar、voice asset、H3/ComfyUI/backend capability 均不属于 B1 semantic contract。
7. 各层只修改自己拥有的 semantic truth；问题必须回到 earliest authoritative owner 修复。
8. B1.1–B1.5 生成 semantic plan；B1.6 只读审计；B1.7 是唯一正式 human approval gate。
9. 正式 downstream 只能消费带有效 ApprovalRecord 的精确 AdaptationPlan revision。
10. frontend-agnostic：未来可由 CLI、ComfyUI custom nodes 或 Agent frontend 驱动，但业务 contract 不依赖 frontend。

---

## B1 完成条件

B1 不是在 EpisodePlan 生成后完成，而是在以下条件全部成立后完成：

```text
B1.1–B1.5 complete
+
current B1.6 validation report
+
no BLOCKING findings
+
all REVIEW_REQUIRED findings explicitly dispositioned
+
B1.7 ApprovalRecord exists
```

最终 handoff：

```text
Approved AdaptationPlan
        ↓
Structured Screenplay
```

Structured Screenplay 必须 pin 被批准的 AdaptationPlan ID / revision / content hash / approval record，并可沿 adaptation mappings 回溯到 canonical evidence 与 source paragraphs。
