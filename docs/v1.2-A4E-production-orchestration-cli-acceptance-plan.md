## 2. A4E overall production flow

最终 production flow exact：

```text
project.yaml
  ↓
resolve + fully verify current A1 SourceDocument
  ↓
resolve + fully verify current A2 ChunkManifest
  ↓
resolve + fully verify every current A3 CandidateExtraction
in exact manifest order
  ↓
build ReconciliationInputSnapshot
build A3InputIdentity
  ↓
plan_reconciliation()                  # A4B
  ↓
prepare_semantic_resolution()         # A4C, ZERO provider
  ↓
build_a4_semantic_identity()           # A4D
  ↓
try_reuse_current()                    # A4D
  ├─ exact hit
  │    ↓
  │  return reused result
  │  ZERO provider calls
  │
  └─ miss
       ↓
     resolve_semantic_ambiguity()      # A4C
       ↓
     finalize_reconciliation()         # A4D
       ↓
     publish_validated()               # A4D
       ↓
     return fresh result
```

A4E 不复制 A4B/C/D logic。

## 3. Stage boundary — A4 never auto-runs A3

`reconcile-entities` 必须消费：

```text
complete validated A3 CURRENT input set
```

A4E 不自动调用：

```text
extract_chunk
extract_chunks
```

如果任何 manifest chunk缺少合法 A3 CURRENT：

```text
FAIL CLOSED
→ tell operator to run short-drama extract-chunks first
→ ZERO A4 provider calls
```

原因：

- A4 input authority必须明确；
- provider-call accounting不能混入 A3；
- stage ownership不能模糊；
- A4 rerun不能意外改变 A3。

## 16. Upstream CURRENT stability

A4E production snapshot必须记录：

- A1 source current pointer ref；
- A2 manifest current pointer ref；
- every A3 current pointer ref。

提供一个 deterministic helper，例如：

```text
assert_reconciliation_input_heads_unchanged(...)
```

在以下位置检查：

### Before accepting A4 reuse hit

若任一 A1/A2/A3 pointer head changed：

```text
FAIL CLOSED
do not return stale reuse
```

### Before A4D publication after provider generation

再次检查。

若 changed：

```text
FAIL CLOSED
do not publish new A4 CURRENT
```

不自动重新 resolve/retry provider。

这遵循现有 stage 的 upstream-current guard discipline；不引入 cross-stage transaction system。

## 19. Provider-call accounting

A4E-A production orchestrator自己只调用：

```text
resolve_semantic_ambiguity()
```

一次 logical semantic stage。

为了 summary 可准确报告：

```text
semantic_generation_call_count
```

应按 A4C actual block generation rounds统计，而不是 HTTP provider attempts。

Reuse hit：

```text
0
```

Miss成功：

```text
sum(block_result.semantic_rounds)
```

A-I3 technical provider attempts不与 semantic-generation calls混为一谈。
