## 4. Production text normalization v1

仅用于 deterministic exact equality。

算法：

~~~text
Unicode NFKC
→ Unicode casefold
→ strip leading/trailing whitespace
→ collapse each Unicode whitespace run to one ASCII space
~~~

不：

- translate；
- transliterate；
- remove punctuation；
- remove stopwords；
- stem；
- fuzzy-match；
- edit-distance；
- embedding；
- LLM。

Normalization 必须 idempotent。

v1 production blocking **不使用 tokenization**。

Audit 中的 relationship-type token overlap 仅为 diagnostic，不进入 production v1。



# 7. Fact blocking-v1

## 7.1 Fact signals

显式 pair 可携带这些 deterministic signals：

~~~text
same_fact_type
exact_normalized_statement
subject_overlap
object_overlap
bound_entity_overlap
evidence_paragraph_overlap
same_chunk
adjacent_chunk
exact_safe_key
~~~

定义：

~~~text
subject_overlap
= intersection(left.subject_refs, right.subject_refs) non-empty

object_overlap
= intersection(left.object_refs, right.object_refs) non-empty

bound_entity_overlap
= intersection(
    left.subject_refs ∪ left.object_refs,
    right.subject_refs ∪ right.object_refs
  ) non-empty

evidence_paragraph_overlap
= intersection(left evidence paragraph_ids, right evidence paragraph_ids) non-empty
~~~

## 7.2 Fact block predicate

一个 fact pair 进入 explicit plan，当且仅当满足至少一个：

### F1 — exact statement

~~~text
normalized(left.statement_zh)
==
normalized(right.statement_zh)
~~~

### F2 — exact evidence paragraph overlap

~~~text
evidence_paragraph_overlap
~~~

### F3 — same semantic fact type + shared bound entity

~~~text
same_fact_type
AND
bound_entity_overlap
~~~

### F4 — same semantic fact type + local source window

~~~text
same_fact_type
AND
chunk_distance <= 1
~~~

因此：

~~~text
FACT_BLOCK =
  exact_normalized_statement
  OR evidence_paragraph_overlap
  OR (
       same_fact_type
       AND (
            bound_entity_overlap
            OR same_chunk
            OR adjacent_chunk
       )
     )
~~~

不得仅因为 same_fact_type 而 block。


# 9. Relationship blocking-v1

## 9.1 Endpoint identity key

Relationship endpoint key 必须尊重 direction。

### directed

~~~text
("directed", source_entity_ref, target_entity_ref)
~~~

顺序 authoritative：

~~~text
A → B != B → A
~~~

### symmetric

~~~text
("symmetric", min(source, target), max(source, target))
~~~

Python canonicalize endpoint order：

~~~text
(A, B) == (B, A)
~~~

### unknown

~~~text
("unknown", source_entity_ref, target_entity_ref)
~~~

v1 **不**把 unknown 当 symmetric。

原因：

~~~text
unknown direction
!=
evidence that the relationship is symmetric
~~~

## 9.2 Relationship signals

~~~text
same_endpoint_group
exact_normalized_relationship_type
state_equal
evidence_paragraph_overlap
same_chunk
adjacent_chunk
exact_safe_key
~~~

source proximity 可作为 pair metadata/signal，但不改变 v1 endpoint-group universe。

## 9.3 Relationship block predicate

~~~text
RELATIONSHIP_BLOCK =
  same_endpoint_group
~~~

其中 `same_endpoint_group` 的 production authority 是 section 9.1 的
**direction-aware endpoint_identity_key 完全相等**，不是无向 endpoint set。

因此：

- directed A→B 只与 directed A→B 同组；
- directed A→B 与 directed B→A 不同组；
- symmetric A/B 与 symmetric B/A 同组；
- unknown A→B 只与 unknown A→B 同组，unknown 不按 symmetric 处理。

这意味着 Alice：

~~~text
6670 naive
→ at most 845 explicit endpoint-group pairs
~~~

不得使用：

~~~text
direction_equal alone
relationship type exact alone
relationship type token overlap alone
source proximity alone
~~~

## 13.1 Fact generation indexes


### type + bound entity bucket





## 13.2 Event generation indexes

~~~text

~~~

### bound entity + chunk window

~~~text
(bound_entity_ref, chunk_ordinal)
~~~

### participant + location bucket


~~~text
(participant_ref, location_ref)
~~~

# 20. Required focused tests

## normalization

- NFKC；
- casefold；
- trim；
- whitespace collapse；
- punctuation retained；
- idempotent。

## canonical pair identity

- left < right；
- duplicate pair eliminated；
- cross-domain impossible。

## fact blocking

- exact statement alone blocks；
- evidence overlap alone blocks；
- same type + entity overlap blocks；
- same type + same chunk blocks；
- same type + adjacent chunk blocks；
- same type alone distant does NOT block；
- different type + same chunk does NOT block unless another independent signal；
- exact-safe key → auto_same；
- near-but-not-exact → semantic。

## event blocking

- exact summary blocks；
- evidence overlap blocks；
- same chunk blocks；
- adjacent + entity overlap blocks；
- adjacent alone does NOT block；
- distant participant overlap alone does NOT block；
- participant + location overlap blocks at any distance；
- temporal_mode_equal alone does NOT block；
- exact-safe key → auto_same。

## relationship blocking

- directed A→B groups with A→B；
- directed A→B does NOT group with B→A；
- symmetric A/B groups with B/A；
- unknown orientation remains ordered；
- same endpoint group blocks despite different type/state；
- exact type without same endpoints does NOT block；
- direction_equal alone does NOT block；
- exact-safe key → auto_same；
- same endpoints different state → semantic。

## deterministic decisions

- method deterministic；
- prompt/provenance null；
- exact evidence stable dedupe；
- decision_id stable；
- pair order canonical。

## no N²

测试必须证明 production generation 使用 indexes/buckets。

允许 instrumentation/helper-level proof；不要用 brittle full-source grep 作为唯一证明。

## hash

- same input → same hash；
- candidate semantic material change → hash changes；
- pair-policy result change → hash changes；
- deterministic decision change → hash changes；
- runtime/provider metadata无法进入 hash。

# 23. Frozen Phase-B summary

1. consolidation-blocking-v1 is the production blocking identity.
2. Text normalization is exact-only NFKC/casefold/trim/whitespace-collapse.
3. Production v1 uses no fuzzy matching, embeddings, stopwords, or text token thresholds.
4. Fact blocks on exact statement/evidence overlap, or same fact type plus entity overlap/local 1-chunk window.
5. Event blocks on exact summary/evidence overlap, same chunk, adjacent+entity overlap, or participant+location overlap.
6. temporal_mode_equal never blocks by itself.
7. Relationship blocks only inside direction-aware endpoint groups.
8. Directed endpoint order matters; symmetric endpoint order is canonicalized; unknown is not treated as symmetric.
9. Only exact full semantic keys produce deterministic auto-same.
10. There is no deterministic different/unrelated rule in v1.
11. Unblocked pairs are implicit not_compared; do not materialize N² negatives.
12. Production pair generation must be index/bucket based.
13. Pair signals are deterministic, sorted, duplicate-free.
14. Plan hash pins candidate index + policy ids + ordered pair plans + deterministic decisions.
15. #51 ends at zero-provider planning outputs. A5C/A5D own semantic request generation and provider work.
16. Alice Phase-B planner must stay within the corpus-specific acceptance guards before #51 can be declared complete.
