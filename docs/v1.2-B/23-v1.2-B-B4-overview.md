# v1.2-B / B4 — Shot Planning 总览

状态：**FROZEN**

## 1. 目标与边界

B4 将一个已经批准的 `EpisodeProductionPlan` 转换为可供 Release Variant、Asset Resolution 与 execution compilation 消费的 canonical Shot Planning contract。

```text
B3 = production 中必须发生什么、观众必须感知什么
B4 = 用哪些有序 PlannedShot 去覆盖这些 production obligations
ProductionShot = downstream asset-resolved / execution-ready generation unit
```

因此：

```text
ProductionUnit ≠ PlannedShot ≠ ProductionShot
```

`PlannedShot` 是 backend-agnostic、asset-unresolved 的 editorial / cinematography semantic unit；v1.1 `ProductionShot` 保留为 downstream execution-ready artifact。

## 3. 核心原则

### 3.1 Coverage contract

`PerceptualCoverageRequirement` 定义观众必须感知什么；B4 负责决定哪些 `PlannedShot` 以何种 camera/editorial semantics 去满足它。

```text
PCR → ShotCoverageMapping → PlannedShot
```

每个 REQUIRED PCR 至少需要一个 PRIMARY coverage。

### 3.2 Editorial Shot 与 Generation Segment 分离

```text
Editorial Cut
= 观众感知到真实镜头切换
= B4.2 authority

Generation Boundary
= 为 backend execution 对同一 PlannedShot 做技术分段
= downstream execution concern
```

B4.5 只定义 segmentation contract，不实例化最终 segments。

### 3.3 Shot Continuity 是 overlay

```text
Adapted Continuity
→ Screenplay Continuity
→ Production Continuity
→ Shot Continuity
```

Shot Continuity 只能维护 camera/editorial continuity，不能覆盖 production truth。

## 4. Asset / Release / Backend 边界

B4 不绑定：

- concrete images / WAV / LoRA
- Picture N / reference slots
- prompt / seed / workflow
- H3 / ComfyUI / GPU/runtime
- final aspect-ratio pixel composition
- release-language exact TTS timing

这些由 downstream Release Variant、Asset Resolution 与 execution compilation 处理。

## 5. Validation / Assembly / Approval

```text
B4.6 = read-only integrated validation
B4.7 = deterministic canonical assembly
B4.8 = B4 唯一 formal human approval gate
```

B4.6 生成 `validated_shot_bundle_hash`；B4.7 只能 exact materialize 该 bundle；B4.8 批准 exact `EpisodeShotPlan` revision/hash。

只有 `APPROVED EpisodeShotPlan` 才能成为正式 downstream Shot semantic authority。

## 6. Python / Qwen / Human

```text

```
