# B2.6 — Screenplay Review + Approval Gate

状态：**FROZEN**

## 1. 职责

B2.6 是 Structured Screenplay 阶段唯一正式 human approval gate。

批准对象不是模糊的“Episode 8”，而是 exact：

```text
episode_screenplay_id
+
revision
+
content_hash
```

只有 `APPROVED EpisodeScreenplay` 才允许 downstream Production Planning 正式消费。

## 2. ScreenplayApprovalRecord

正式引入：

```text
ScreenplayApprovalRecord
```

至少绑定：

- approval_record_id
- EpisodeScreenplay id/revision/hash
- exact ScreenplayValidationReport id/hash
- AdaptationPlan id/revision/hash/approval
- EpisodeScenePlan id/revision/hash
- decision
- REVIEW_REQUIRED dispositions
- reviewer reference
- review metadata

SceneRealization exact revisions 通过 EpisodeScreenplay manifest deterministic 解析，无需在 ApprovalRecord 顶层重复复制完整 scene manifest。

## 3. Validation prerequisite

ValidationReport 必须 exact-match 被审批的 EpisodeScreenplay revision/hash。

```text
FAIL
→ cannot approve
```

`PASS` 或 `PASS_WITH_REVIEW_ITEMS` 可以进入 human review。

Validation pass 不等于 human approval；reviewer 仍可要求 revision。

## 4. REVIEW_REQUIRED disposition

每个 `REVIEW_REQUIRED` finding 必须逐项：

```text
ACCEPT_AS_DESIGNED
或
REVISION_REQUESTED
```

只要任意 finding 为 `REVISION_REQUESTED`，该 screenplay revision 不得 APPROVE。

WARNING 对 reviewer 可见，但不强制逐项 disposition。

`ACCEPT_AS_DESIGNED` 必须绑定 exact finding + validation report + screenplay revision/hash，不能跨 revision 自动继承。

## 5. Review decision

正式 decision：

```text
APPROVE
REVISION_REQUESTED
ABANDON
```

不引入 conditional / soft / temporary approval。

## 6. Approval 粒度

不支持单集内部 partial approval：

```text
no scene-level formal approval
no dialogue-level formal approval
```

Episode approval 是 atomic 的。

但整个 series 支持 episode-by-episode incremental approval；不要求全部集写完后一次性审批整个 series。

## 7. Lifecycle

EpisodeScreenplay lifecycle：

```text
DRAFT
APPROVED
SUPERSEDED
ABANDONED
```

`PASS` 后仍是 DRAFT，直到 human APPROVE。

一个 episode 最多只有一个 current APPROVED screenplay revision。

新版 APPROVED 后，旧 current approved revision → SUPERSEDED；旧 ApprovalRecord、ValidationReport 与 provenance 永久保留。

SUPERSEDED 表示曾经正式批准、后来被替代，不等于从未批准。

## 8. Immutability / revision

APPROVED EpisodeScreenplay revision immutable。

任意 semantic change——即使只改一句 dialogue / action / reaction / callback——都必须产生新 revision，并重新经过：

```text
B2.5 validation
→
B2.6 approval
```

Render-only formatting change 不产生 screenplay semantic revision，也不要求 reapproval。

ApprovalRecord 本身 immutable。

## 9. AdaptationPlan lineage

Approval 必须绑定 exact approved AdaptationPlan lineage。

若 later AdaptationPlan new revision APPROVED：

- 旧 screenplay approval 仍历史有效；
- 但不能冒充新 AdaptationPlan lineage；
- 若要迁移，必须 rebuild/revalidate screenplay，并产生新的 B2 revision + approval。

## 10. Downstream Production pinning

Production Planning 只能正式消费 `APPROVED EpisodeScreenplay exact revision`。

至少 pin：

```text
episode_screenplay_id
episode_screenplay_revision
episode_screenplay_hash
screenplay_approval_record_id
```

禁止 implicit latest。

新生产默认不能从 SUPERSEDED screenplay 创建 current authoritative Production Plan；但可显式用于 historical reproduction / debug / audit。

已有 Production artifact 不因 screenplay later superseded 而自动 repin。

## 11. 跨集 screenplay continuity dependency

Episode N 的 screenplay 可能依赖 Episode N-1 的 `EpisodeScreenplayEndingCheckpoint` / screenplay overlay。

因此依赖必须 pin exact：

```text
predecessor_screenplay_id
revision
hash
approval_record_id
ending_checkpoint_hash
```

Draft screenplay 可以暂时依赖尚未 approved predecessor 进行并行创作；但正式 APPROVE 时，所有 authoritative screenplay continuity dependencies 必须已经 APPROVED。

EP01 无 predecessor screenplay dependency。

B2.6 不强制整个 series 严格串行创作，只要求 approval dependency graph 稳定。

## 12. Reviewer 行为边界

Reviewer 不得在 approval stage 直接修改 canonical screenplay。

修改意见必须：

```text
REVISION_REQUESTED
→ route B2.3 / B2.2 / B1.x authoritative owner
```

Human reviewer 可以发现 B2.5 未发现的新问题，并记录轻量 `HumanReviewFinding`；finding 应尽量引用 stable IDs。

Review note 本身不是 canonical screenplay truth。

## 13. Review surface

可以 deterministic 构建 `ScreenplayReviewPackage`，包含：

- canonical rendered screenplay
- EpisodePlan summary
- scene map
- climax/hook anchors
- duration summary
- B2.5 findings
- important continuity/callback summary
- upstream revision pins

它是 derived review artifact，不是 source of truth。

Reviewer 可以通过 Markdown / PDF / UI 阅读，但正式批准对象始终是 canonical EpisodeScreenplay revision/hash。

Reviewed representation 必须能够解析回 exact canonical target。

## 14. Fail-closed 条件

以下情况不得 APPROVE：

- EpisodeScreenplay revision/hash mismatch
- ValidationReport missing or targets another revision
- B2.5 result = FAIL
- unresolved REVIEW_REQUIRED finding
- AdaptationPlan approval invalid/unresolvable
- upstream revision pin unresolved
- required predecessor screenplay dependency not APPROVED
- predecessor ending checkpoint mismatch
- reviewed representation cannot resolve to exact canonical revision
- target already ABANDONED

Production consumption 同样 fail closed。

## 15. Approval 与 downstream stages 分离

B2.6 不审批：

- localization
- final spoken variant
- voice asset
- subtitle artifact/timing
- ProductionLocation
- Shot plan
- H3 / ComfyUI artifact

Production feasibility 也不直接改变 B2 approval semantics；若为制作可行性需要修改 screenplay，必须产生新的 B2 revision → validation → approval。

## 16. Python / Human / Qwen

Python：

- verify exact target/hash/report
- collect findings
- verify dispositions/dependencies
- build review package
- record approval
- update lifecycle
- enforce one current approved revision
- enforce downstream pins

Human：

- accept/reject artistic/semantic result
- resolve REVIEW_REQUIRED
- raise additional findings
- APPROVE / REVISION_REQUESTED / ABANDON

Qwen：

- explain findings
- summarize context
- show traceability
- compare revisions

Qwen 不能 self-approve。

## 17. 冻结 contract

1. B2.6 是 Structured Screenplay 唯一 formal human gate。
2. Approval 对象是 exact EpisodeScreenplay id/revision/hash。
3. 正式存在 ScreenplayApprovalRecord，绑定 exact ValidationReport。
4. FAIL 不得批准；PASS / PASS_WITH_REVIEW_ITEMS 可进入 review。
5. REVIEW_REQUIRED 必须逐项 ACCEPT_AS_DESIGNED 或 REVISION_REQUESTED。
6. 决策为 APPROVE / REVISION_REQUESTED / ABANDON。
7. Episode approval atomic，不支持 scene/dialogue partial approval。
8. Series 支持 per-episode incremental approval。
9. Lifecycle = DRAFT / APPROVED / SUPERSEDED / ABANDONED。
10. APPROVED revision / ApprovalRecord immutable。
11. Semantic change 必须 new revision + B2.5 + B2.6。
12. 每个 episode 最多一个 current APPROVED revision。
13. Approval 绑定 exact AdaptationPlan lineage。
14. Production 只能正式消费 APPROVED exact screenplay revision，且必须 pin approval record。
15. 禁止 downstream implicit latest。
16. Draft 可依赖未批准 predecessor；正式 approval 时 authoritative screenplay continuity dependencies 必须 APPROVED。
17. Reviewer 不得在 gate 中直接编辑 canonical screenplay。
18. Review surface / ReviewPackage 均为 derived artifact。
19. Gate / downstream consumption 无法验证 references/hashes/dependencies 时 fail closed。
20. Qwen 可辅助解释，但不能 self-approve。
