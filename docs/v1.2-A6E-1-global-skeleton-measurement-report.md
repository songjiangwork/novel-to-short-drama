## 2. Method

* **Deterministic packet assembly** (`short_drama.story.story_analysis_global_skeleton`):
  the whole-story compressed global-skeleton input packet is the RFC 8785
  (JCS) canonical JSON of exactly:

  ```json
  {
    "character_analyses":    [ /* all 47 A6C CharacterAnalysis, canonical planned order */ ],
    "plot_window_analyses":  [ /* all 14 A6D PlotWindowAnalysis, canonical planned order */ ],
    "global_index":          { /* the complete A5-derived GlobalIndexBase */ }
  }
  ```

  No sampling, no first-N truncation, no omitted later windows, and no
  independent partial-story concatenation. `global_index` is the full
  A5-derived `GlobalIndexBase` (character / location descriptors, unresolved
  entities, event index, relationship summaries, state-transition summaries,
  conflict summaries).

* **Estimator:** the single supported counter `utf8-bytes-div3-v1`
  (`max(1, ceil(utf8_bytes / 3))`), the same authority A6B / A6C / A6D use.

* **Request measured:** the *exact rendered* global-skeleton request
  (frozen prompt `a6.global-skeleton` v1; single variable `global_context_json`
  filled with the canonical packet), so the measured value is the actual
  request the A6E pass would send.

* **Coverage invariants** fail closed if any character / window is missing,
  duplicated, extra, or out of canonical planned order.

## 6. Output reserve + context-window feasibility

* **Output reserve:** `16,384` tokens (the frozen semantic profile
  `max_output_tokens`); the global-skeleton output is a single structured
  payload (event-importance overlay + arc / turning-point / reveal /
  foreshadow-payoff proposals + global structure) bounded by that reserve.

* **Intended semantic context budget:** the live deployment reports
  `n_ctx = 163,840` tokens (the authoritative, *measured* context window of the
  local Qwen deployment -- not an invented constant).

* **Feasibility:** one complete global request needs
  `74,012` (input) + `16,384` (output reserve) = `90,396` tokens, which fits
  within the measured `163,840`-token context window with
  `163,840 - 90,396 = 73,444` tokens of headroom.

* **Recursive compression necessary: NO.** The whole-story compressed
  representation fits in one complete global request, so the A6E pass can
  perform the single whole-story global-skeleton call as the frozen architecture
  intends. No recursive / staged global compression is required.

## 8. A6E-2 identity-transition requirement (follow-up constraint, NOT implemented here)

Freezing the ceiling changes the semantic identity of the upstream A6C / A6D
passes, so it cannot be done silently.

* `global_skeleton_packet_max_estimated_tokens` is a field of
  `StoryAnalysisPlanningPolicy`, which is embedded in
  `StoryAnalysisProfile.to_dict()`. Changing it from `null` to `74000`
  therefore changes **both**:
  * the **`StoryAnalysisProfile` hash** (`profile.content_hash()`), and
  * the **A6B `plan_hash`** (which binds `planning_policy.to_dict()`).

  Measured on the same Alice A5 CURRENT (baseline `null` -> proposed `74000`):

  | field | `null` (current) | `74000` (proposed) |
  |---|---|---|
  | `StoryAnalysisProfile.content_hash()` | `26cdec6773b3b9d9…` | `0d46388127e42ffc…` |
  | A6B `plan_hash` | `db3eb6e6…` | `dfafb9fc…` |

* Every A6C / A6D **request identity hash** binds both
  `story_analysis_profile_hash` (`= profile.content_hash()`) and
  `a6_plan_hash` (`= plan.plan_hash`). The new profile / plan therefore yields a
  **different** request identity for every A6C / A6D request.

* **Consequence:** the A6C / A6D diagnostic outputs cached by this checkpoint
  (61 upstream calls under the `null` profile / `db3eb6e6…` plan) carry the
  *old* semantic identity. They must **not** be silently treated as having the
  new semantic identity once the ceiling is frozen. Before the frozen ceiling is
  relied upon, A6C / A6D must be re-run (or explicitly re-bound) under the new
  profile so their request identity hashes match the frozen identity.

This is an A6E-2 (or later) requirement. It is **not** implemented in this
A6E-1 repair: the tracked profile is not changed, the ceiling is not frozen, and
the measured record in this report remains bound to the `null`-profile identity.

## 11. Subsequent revision: global-skeleton ceiling frozen at 100000 (Issue #102)

The proposed `74000` ceiling from section 7 was frozen in the tracked profile
during A6E-2, then **revised to `100000`** after the real-provider A6E-2
measurement.

* Under the frozen `74000` ceiling, the real-provider A6E-2 acceptance on the
  same exact Alice A5 CURRENT measured the complete global-skeleton input packet
  at **74404** estimated tokens, overflowing `74000` by 404 tokens and failing
  closed (A6E provider calls = 0; all 61 upstream A6C/A6D analyses completed).
  The `74000` value was a single measured output rounded to the next 1000-token
  step; that margin proved too small for nondeterministic LLM-generated
  intermediate outputs.
* The operator authorized a more substantial safety margin. The ceiling was
  revised to **`100000`** — a deliberately selected v1 operational envelope: a
  bounded, intentionally conservative margin above the measured baseline (headroom
  25596 estimated tokens ≈ 34.4% over the 74404 measurement), an upper bound (not
  a target input length), no truncation / sampling, fail-closed. It is NOT a
  statistically established worst-case bound and NOT a universal 100K budget.
* Shared A6 semantic-profile output limit: the first real-provider A6E run
  (100000 ceiling) truncated the whole-story output at
  `max_output_tokens = 16384` (`finish_reason = length`) after 3 technical
  attempts, so the shared A6 semantic profile output limit was raised
  `16384 -> 32768` (preserving temperature / reasoning / schema mode). This
  changes the `SemanticLLMProfile` hash and therefore the A6C/A6D/A6E request
  identities (see the 16384 -> 32768 identity transition below).
* Context feasibility (estimator-based, not authoritative tokenizer counts):
  `n_ctx = 163840`; frozen output reserve `max_output_tokens = 32768`; ≈ 83
  estimated tokens of prompt framing → `100000 + 83 + 32768 = 132851`, leaving
  `163840 - 132851 = 30989` estimated tokens of context headroom.

## 13. Subsequent revision: A6E prompt-only bounded-output revision (Issue #102)

The first real-provider A6E run under `100000` / `32768` still truncated at
`max_output_tokens = 32768` (`finish_reason = length`) on the first attempt. The
root cause is not the input ceiling or the output reserve: the A6E JSON schema
leaves the six collections (`event_importance_overlay`, `arc_proposals`,
`turning_point_proposals`, `reveal_proposals`, `foreshadow_payoff_proposals`,
`global_structure`) unconstrained (no `maxItems`), and every item carries an
unbounded `interpretation.text_zh`, so the model enumerates exhaustively and
produces more than 32768 tokens of JSON.

The fix is an **A6E prompt-only** revision (no schema / profile / model /
context change):

- `prompts/story/a6.global-skeleton/v1/system.txt` now requires a *concise yet
  complete global synthesis* rather than an exhaustive retelling: each
  `interpretation.text_zh` is 1-3 concise sentences pointing at evidence (no
  verbatim repetition of upstream A6C/A6D material); the six collections keep
  only salient / major / meaningful items with restrained size guidance
  (`event_importance_overlay` -> key events only; `arc_proposals` -> major arcs,
  single-digit-to-a-dozen-plus; `turning_point_proposals` -> key turning points;
  `reveal_proposals` -> meaningful reveals; `foreshadow_payoff_proposals` ->
  meaningful relationships; `global_structure.global_sections` -> a small number
  of high-level sections, ~3-8, not one per event). No hard `maxItems` constraint
  is added and no frozen-A6-required field or legitimate reference may be
  omitted.
- `prompts/story/a6.global-skeleton/v1/prompt.yaml` `content_hash` is updated to
  match the revised template (prompt identity = `prompt_id` + `version` +
  `content_hash`).
