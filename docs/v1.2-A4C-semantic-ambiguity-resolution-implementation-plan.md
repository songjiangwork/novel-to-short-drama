## 2. Core semantic rule

LLM 允许的 decision exact：

```text

different_entity

```

其中：

```text

```

是成功 domain result。

不得因为模型返回合法 `uncertain` 而 retry。

核心原则继续：

```text
precision first
false merge > unresolved ambiguity
```

## 6. Deterministic semantic block packing

A4C v1 使用 fixed bounded block packing：

```text
MAX_PAIRS_PER_BLOCK = 6
MAX_CANDIDATES_PER_BLOCK = 12
```

算法：

1. 取全部 `needs_semantic_decision` pair；
2. 按 A4B canonical pair order：
   ```text
   (left_candidate_ref, right_candidate_ref)
   ```
   排序；
3. 顺序 greedy pack；
4. 如果加入下一个 pair 会导致：
   - pair count > 6；或
   - unique endpoint candidate count > 12；
   则 flush 当前 block，再开新 block；
5. 每个 pair exact 出现一次；
6. 不并发执行 blocks。

A4C v1 不做：

- graph-aware dynamic batching；
- token-estimate adaptive packing；
- runtime-context-size probing；
- backend-specific block size；
- provider/model branching。

固定 block bound 是 semantic orchestration policy；实际 rendered request hash 会 capture exact grouping。

---

## 7. Why sequential blocks

A4C v1 blocks 顺序执行。

原因：

- deterministic provider-call order；
- 不依赖 llama.cpp `-np`；
- 不假设 slot 数；
- 更容易 audit retry/provenance；
- A4C pair decision output 较小，无需并行复杂度。

未来若要并行，必须单独设计，不在 v1 偷加。

## 9. Candidate packet v1

A4C 不重新打开小说 source text，也不扩大成 A3 fact/event dump。

candidate packet exact fields：

```text
candidate_ref
candidate_kind
display_name_original
aliases_original
descriptors_zh
source_order_key
evidence_refs
```

来源只能是：

```text
planning_result.candidate_index
```

不得 invent / summarize 新字段。

`evidence_refs` 保留 A3 exact：

```text
paragraph_id
role
strength
excerpt
```

candidate packet 不包含：

- runtime backend；
- full chapter text；
- whole SourceChunk；
- all facts/events/relationships；
- unresolved candidates；
- canonical IDs。

理由：

```text
A4C identity resolution should consume bounded identity/evidence packets.
If evidence is insufficient, uncertain is valid.
```

未来如果 real-novel evidence 证明 packet context 不足，再做 versioned semantic-contract refinement；A4C v1 不预先扩大 prompt。

## 10. Candidate packet ordering


每个 candidate exact 出现一次。

A3 unresolved candidate 永远不会出现在 semantic block，因为 A4B pair universe 已禁止 unresolved pair member。

## 18. A-I3 technical retry vs A4C semantic regeneration

继续严格分层。

一次：

```text
llm_client.generate_structured(...)
```

内部 A-I3 可执行 technical retries。

A4C 将整次成功 return 视为：

```text
1 semantic generation round
```

A4C：

```text
max_generation_rounds = 2
```

理论 provider-attempt ceiling：

```text
2 semantic rounds
×
A-I3 technical-attempt ceiling
```

A4C 不再外包一层 transport retry。

如果 A-I3 抛：

```text
LLMError
LLMRetryExhaustedError
```

直接 propagate。

不得因为 transport failure 开第二 semantic round。

## 21. Exact requested-pair validation

对一个 block，model output decisions 必须：

1. count exact 等于 requested pair count；
2. 输出顺序 exact 等于 requested pair canonical order；
3. 每个 output item：
   ```text
   left_candidate_ref
   right_candidate_ref
   ```
   exact 等于对应 requested pair；
4. no duplicate；
5. no missing；
6. no extra；
7. refs 必须来自 block candidate packets。

即使 pair set 相同但输出顺序改变，也视为 semantic-invalid round。

理由：

```text
prompt v1 explicitly requires no reorder
and exact ordering simplifies deterministic audit.
```

## 22. Evidence validation

provider decision 的每个 `evidence_ref` 必须 exact 等于：

```text
left endpoint candidate evidence
OR
right endpoint candidate evidence
```

中的某一个完整 EvidenceRef。

exact equality 包括：

```text
paragraph_id
role
strength
excerpt
```

不得：

- paraphrase excerpt；
- normalize excerpt；
- cite another pair/candidate；
- invent paragraph；
- alter role/strength；
- use unresolved candidate evidence。

同一个 decision 内 duplicate EvidenceRef rejected。

`evidence_refs = []` 允许，因为 frozen prompt/schema 已明确允许 overall identity material 作为理由。

不要在 A4C v1 新增 “必须至少一个 evidence” 要求。

## 23. Decision validity

合法 decision：

```text
same_entity
different_entity
uncertain
```

typed model负责 enum。

A4C 不使用 heuristic 推翻合法 model decision。

例如：

```text
model returns uncertain
→ ACCEPT
→ no retry
```

A4C 不根据 name similarity 改写为 same/different。

## 24. Semantic-invalid round conditions

成功 provider return 后，以下属于 semantic-invalid，可消耗一个 A4C semantic round：

- typed payload load fails；
- missing pair；
- extra pair；
- duplicate pair；
- reordered pair；
- candidate ref not in exact block；
- evidence ref not exact endpoint evidence；
- duplicate evidence ref。

这些是 model semantic contract failures。

以下不是 semantic retry：

- profile/prompt/schema contradiction；
- provenance/request mismatch；
- A-I3 technical failure；
- invalid planning input；
- corrupted A4B structures。

这些 fail closed / propagate。

## 25. Exhaustion behavior

每个 block 最多 2 semantic generations。

若一个 block 两轮均 semantic-invalid：

```text
raise ReconciliationSemanticGenerationError
```

至少记录：

```text

rounds_attempted
last failure codes/details
expected pair refs
```

不要返回 partial whole-stage success。

前面 blocks 可能已经调用 provider，但 A4C 本身不 persist，所以失败时没有 partially-current A4 state。

## 41. Controlled smoke fixture

一个 block，3 semantic pairs，6 candidates：

### Pair A — same_entity

candidate packets 必须提供 explicit source evidence，明确：

```text
Alice 和 Alicia 是同一人的两个名字
```

例如 source evidence可构造为：

```text
"Alice, also known as Alicia, entered the room."
```

两端 candidate分别使用 Alice / Alicia，并携带 exact source-backed alias/evidence material。

不要仅靠 name similarity。

### Pair B — different_entity

explicit evidence 明确两人为不同人物，例如：

```text
"Bob and Carol are two different people standing beside each other."
```

pair endpoints Bob / Carol。

### Pair C — uncertain

两端：

```text
"The doctor"
"Dr. Chen"
```

分别只有各自独立 evidence，没有任何 source-backed identity link 或 contradiction。

正确结果：

```text
uncertain
```

fixture应足够明确，使 backend capability smoke不依赖文学推理。
