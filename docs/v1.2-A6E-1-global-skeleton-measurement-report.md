## 2. Method

* **Deterministic packet assembly** (`short_drama.story.story_analysis_global_skeleton`):
  the whole-story compressed global-skeleton input packet is the RFC 8785
  (JCS) canonical JSON of exactly:

  ```json
  {
    "character_analyses":    [ /* all 47 A6C CharacterAnalysis, canonical planned order */ ],
    "plot_window_analyses":  [ /* all 14 A6D PlotWindowAnalysis, canonical planned order */ ],
    "global_index":          { /* the complete A5-derived GlobalIndexBase */ }
  }
  ```

  No sampling, no first-N truncation, no omitted later windows, and no
  independent partial-story concatenation. `global_index` is the full
  A5-derived `GlobalIndexBase` (character / location descriptors, unresolved
  entities, event index, relationship summaries, state-transition summaries,
  conflict summaries).

* **Estimator:** the single supported counter `utf8-bytes-div3-v1`
  (`max(1, ceil(utf8_bytes / 3))`), the same authority A6B / A6C / A6D use.

* **Request measured:** the *exact rendered* global-skeleton request
  (frozen prompt `a6.global-skeleton` v1; single variable `global_context_json`
  filled with the canonical packet), so the measured value is the actual
  request the A6E pass would send.

* **Coverage invariants** fail closed if any character / window is missing,
  duplicated, extra, or out of canonical planned order.

passes, so it cannot be done silently.

* `global_skeleton_packet_max_estimated_tokens` is a field of
  `StoryAnalysisPlanningPolicy`, which is embedded in
  `StoryAnalysisProfile.to_dict()`. Changing it from `null` to `74000`
  therefore changes **both**:
  * the **`StoryAnalysisProfile` hash** (`profile.content_hash()`), and
  * the **A6B `plan_hash`** (which binds `planning_policy.to_dict()`).

  Measured on the same Alice A5 CURRENT (baseline `null` -> proposed `74000`):

  | A6B `plan_hash` | `db3eb6e6…` | `dfafb9fc…` |

* Every A6C / A6D **request identity hash** binds both
  `story_analysis_profile_hash` (`= profile.content_hash()`) and
  `a6_plan_hash` (`= plan.plan_hash`). The new profile / plan therefore yields a

## 13. Subsequent revision: A6E prompt-only bounded-output revision (Issue #102)

The first real-provider A6E run under `100000` / `32768` still truncated at
`max_output_tokens = 32768` (`finish_reason = length`) on the first attempt. The
root cause is not the input ceiling or the output reserve: the A6E JSON schema
leaves the six collections (`event_importance_overlay`, `arc_proposals`,
`turning_point_proposals`, `reveal_proposals`, `foreshadow_payoff_proposals`,
`global_structure`) unconstrained (no `maxItems`), and every item carries an
unbounded `interpretation.text_zh`, so the model enumerates exhaustively and
produces more than 32768 tokens of JSON.

The fix is an **A6E prompt-only** revision (no schema / profile / model /
context change):

- `prompts/story/a6.global-skeleton/v1/system.txt` now requires a *concise yet
  complete global synthesis* rather than an exhaustive retelling: each
  `interpretation.text_zh` is 1-3 concise sentences pointing at evidence (no
  verbatim repetition of upstream A6C/A6D material); the six collections keep
  only salient / major / meaningful items with restrained size guidance
  (`event_importance_overlay` -> key events only; `arc_proposals` -> major arcs,
  single-digit-to-a-dozen-plus; `turning_point_proposals` -> key turning points;
  `reveal_proposals` -> meaningful reveals; `foreshadow_payoff_proposals` ->
  meaningful relationships; `global_structure.global_sections` -> a small number
  of high-level sections, ~3-8, not one per event). No hard `maxItems` constraint
  is added and no frozen-A6-required field or legitimate reference may be
  omitted.
- `prompts/story/a6.global-skeleton/v1/prompt.yaml` `content_hash` is updated to
  match the revised template (prompt identity = `prompt_id` + `version` +
  `content_hash`).

## 15. Subsequent revision: A6E prompt semantic-quality refinement (Issue #102)

A targeted **A6E prompt-only** refinement addresses the qualitative findings
above without changing the frozen architecture, schema, profile, or production
execution code. The concise-output behavior from section 13 is preserved; the
refinement adds general-purpose semantic-quality guidance.

### Changes

`prompts/story/a6.global-skeleton/v1/system.txt` now adds:

- **evidence_mode discrimination**: explicit criteria for `explicit` vs
  `inferred`, with the requirement that literary/structural inferences
  (character development, thematic meaning, causal synthesis, power dynamics,
  symbolic meaning, dramatic conflict analysis) use `inferred` even when
  evidence-supported. Both modes still require `supporting_*_refs`.
- **Arc narrative-progression requirement**: arcs must describe sustained
  progression (conflict/relationship/situation evolution), not mere character
  appearance enumeration.
- **Turning-point phase coverage**: encourages spanning narrative phases
  (setup, escalation, conflict development, climax, resolution) without
  mandating one per phase.
- **Foreshadow/payoff discrimination**: requires explicit narrative
  setup→payoff causal or significant-echo relationships; plain temporal
  sequence, broad beginning/end parallels, or mere thematic recurrence do not
  qualify.
- **Major-arc discrimination**: `major_*_proposal_ordinals` should reference
  only genuinely central proposals, not all proposals in the same collection.
- **Restraint / uncertainty principles**: discourages unsupported assertions
  about character roles/authority, rewrites of experience as realization,
  chapter-number references, and presentation of inference as certain fact.

No Alice-specific rules, hard-coded event IDs, hard-coded character names,
story-specific correction tables, arbitrary fixed proposal counts, new LLM
stages, additional provider calls, or new infrastructure abstractions are
introduced.

## 17. Subsequent revision: A6E prompt Quality V3 bounded refinement (Issue #102)

This is the **final prompt-only quality iteration** for A6E. A narrowly
bounded refinement addresses the four V2 remaining findings (A–D) by
clarifying and consolidating existing prompt instructions without adding
new schema fields, new stages, new provider calls, story-specific
corrections, or new infrastructure.

### Root-cause diagnosis

All four findings originate from **ambiguous A6E prompt instructions**
(origin A), not from upstream A5/A6C/A6D evidence quality or contract
limitations:

| Finding | Root cause |
|---|---|
| A | No guidance distinguishing whole-story dominant tension from localized antagonist conflicts. |
| B | Restraint rule covers “经历→意识到” but does not explicitly distinguish reader inference from character cognition. |
| C | Turning-point guidance mentions “高潮” and “收束” as phases but does not explicitly state they are different narrative functions that should not be conflated in one event. |
| D | Existing “直接事实 + 推断性分析成分 → inferred” rule present but model does not clearly separate event (explicit) from narrative-function interpretation (inferred). |

### Changes

`prompts/story/a6.global-skeleton/v1/system.txt` adds:

- **Whole-story conflict guidance** (addresses A): `main_conflict` should
  identify the dominant whole-story tension using evidence from the entire
  narrative (internal, identity, environmental, social, or structural
  conflict); a late antagonist conflict that does not dominate the whole
  story should be listed under `secondary_conflicts`.
- **Climax vs Resolution** (addresses C): in the turning-point guidance,
  states that climax (decisive confrontation or irreversible shift) and
  resolution (aftermath) are different narrative functions that should not
  be borne by the same event; in the restraint section, forbids equating the
  ending event with the climax automatically.
- **Epistemic boundary** (addresses B): extends the restraint section to
  state that a reader’s inferable conclusion is not equivalent to a
  character’s internal cognition; an explanation not explicitly realized by
  the character must not be attributed to the character’s consciousness.
- **Evidence-mode consistency** (addresses D): in the evidence-mode section,
  clarifies that a directly observed event being `explicit` does not make
  the narrative-function judgment about that event (climax, structural
  boundary, main conflict, etc.) also `explicit`.

No Alice-specific rules, hard-coded event IDs, hard-coded character names,
story-specific correction tables, arbitrary fixed proposal counts, new LLM
stages, additional provider calls, or new infrastructure abstractions are
introduced. All V1/V2 improvements (concise output, arc progression,
foreshadow discrimination, evidence-mode distinction, restraint principles)
are preserved.
