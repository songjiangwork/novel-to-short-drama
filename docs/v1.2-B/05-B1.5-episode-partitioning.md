# v1.2-B1.5 — Episode Partitioning（冻结）

## 职责

B1.5 只对已经冻结的 Primary Presentation Sequence 做分集与 episode-level dramatic packaging。

核心边界：

```text
B1.4 决定故事怎么讲
B1.5 决定在哪里断集，以及每一集承担什么戏剧功能
```

B1.5 不是第二个 adaptation rewrite 层。

---

## Episode Partition

假设 B1.4 产生：

```text
PE_001
PE_002
...
PE_120
```

B1.5 将其划分为 contiguous episode ranges。

核心 invariant：

```text
Every primary PresentationEntry
belongs to exactly one episode.
```

因此必须：

- no missing
- no duplicate
- no overlap
- preserve presentation order
- contiguous ranges

B1.5 不能 reorder PresentationEntries。

---

## Boundary Rules

Episode boundary 默认只能落在两个 PresentationEntry 之间。

如果需要在一个 presentation unit 中间断集，必须先回 B1.4 把该 material 重构为多个 PresentationEntry；B1.5 不得自行 split presentation semantics。

支持轻量 partition constraints：

```text
hard no-cut / must_stay_together
strong boundary candidate
ordinary boundary
```

B1.4 可提供 dramatic hinge / candidate；最终是否成为 episode boundary 由 B1.5 决定。

---

## Episode Count Resolution

B1.1 的 episode-count constraint 可以是：

```text
fixed
target
range
derived
```

B1.5 最终产生 `resolved_episode_count`。

Derived/range 模式不能只用总时长除以单集时长机械决定；应结合：

- hard duration constraints
- usable dramatic boundaries
- arc structure
- climax / reveal distribution

Python 提供 deterministic feasibility；Qwen 做 narrative choice。

---

## Python / Qwen 职责

### Python

负责：

- PresentationEntry coverage / ordering
- contiguous partition validation
- must-stay-together enforcement
- duration arithmetic
- episode-count constraints
- hard min/max validation
- duplicate/missing reference detection

### Qwen

负责：

- dramatic coherence
- episode goal / function
- core conflict
- climax
- hook quality
- opening momentum
- arc/reveal pacing
- boundary preference

Hard constraint 必须先于 dramatic optimization。

---

## Episode Semantic Contract

每集至少要有：

- dramatic goal
- defensible narrative function
- core conflict
- opening dramatic state
- progression
- episode climax
- ending dramatic state
- ending hook
- referenced presentation range
- duration estimate/range
- relevant arc/reveal checkpoints

`dramatic goal` 不是 plot summary，而是本集要完成的 dramatic transformation。

并非每集都必须有巨大 state change；setup、escalation、investigation、emotional deepening 都可以成为合法 episode function，但必须说明其 narrative value。

---

## Climax vs Ending Hook

必须分离：

```text
Episode Climax
≠
Episode Ending Hook
```

Climax 可以早于最后一个 PresentationEntry；之后可有 aftermath，再由新的 threat/reveal/question 形成 hook。

Climax 与 hook 都必须引用现有 B1.4 skeleton material；B1.5 不能为了“每集精彩”创造新的 AdaptedStoryBeat。

---

## EpisodeHook

Hook 使用一般化 abstraction，而非强制 Cliffhanger：

```text
cliffhanger
reveal
reversal
threat
question
anticipation
emotional_button
resolution
```

是否要求非最终集必须有 hook 由 profile 控制。

Final episode 可以使用 resolution / emotional_button，且不要求 continuation cliffhanger。

B1.5 不得为了 hook 提前违反 B1.4 reveal/withholding constraints。

---

## Cross-Episode Audit

B1.5 需要从整季角度检查：

- character arc distribution
- relationship arc distribution
- reveal pacing
- setup/payoff distance
- episode density
- opening/ending momentum
- long flat stretches
- over-compressed late arcs

这些是 semantic audit，不用伪精确评分。

若需要移动 reveal、插 reinforcement、增加 story beat，必须返回 B1.4；B1.5 不得直接修改 story semantics。

---

## Duration / Density

Episode duration 保持 planning estimate / range，而不是 frame-level precision。

示例：

```text
low / target / high
```

或等价 range。

如果 estimated minimum 已超过 hard max，则 partition infeasible；如果 range 仅部分越界，则标记 duration risk。

Underfilled episode 不允许通过 filler、重复对白、无意义冲突凑时间；优先移动 boundary、合并 episode、调整 count。需要新增 narrative content 时回 B1.4。

Overfilled episode 也不能推给 screenplay 用“写快一点”解决。

---

## Boundary Quality

Boundary semantic assessment 可以使用：

```text
strong
acceptable
weak
```

禁止用虚假的 8.73/10 精度评分。

Weak 但合法的 boundary 可以保留并进入 review；honest weak boundary 优于为了 cliffhanger 编造不存在的剧情。

同时审查：

```text
previous episode ending
→ next episode opening
```

避免 cliffhanger 后下一集长时间逃避 resolution。

---

## Continuity Checkpoints

每个 episode boundary 建立 sparse continuity checkpoint，覆盖：

- plot-critical knowledge
- major relationship states
- major character goals
- critical object/state
- important unresolved questions

这些 checkpoint 是后续长剧 screenplay generation 的 context interface，可避免生成后期 episode 时必须加载所有前序 screenplay。

---

## Screenplay Handoff

EpisodePlan 固定：

- narrative membership
- dramatic goal
- core conflict
- required beats/material
- reveal constraints
- ending state
- ending hook
- continuity handoff

Structured Screenplay 仍拥有 realization freedom：

```text
1 beat → multiple scenes
multiple small beats → one scene
```

Narrative membership fixed；dramatic realization flexible。

---

## Repair Routing

```text
local partition problem
→ B1.5

presentation / story-structure problem
→ B1.4

source disposition problem
→ B1.3

global strategy / target infeasibility
→ B1.2 / B1.1
```

B1.5 禁止 silent upstream patch。

---

## 冻结原则

1. EpisodePlan 是 frozen Primary Presentation Sequence 的 contiguous partition。
2. Every primary PresentationEntry exactly once。
3. B1.5 不 reorder，不 split presentation semantics，不创造 AdaptedStoryBeat。
4. Boundary 只落在 PresentationEntry 之间，并尊重 hard no-cut。
5. Hard duration constraints 先于 dramatic optimization。
6. Python 负责 deterministic partition feasibility；Qwen 负责 dramatic judgment。
7. 每集有 dramatic goal、narrative function、core conflict、climax、ending state、hook。
8. Climax 与 ending hook 分离。
9. Hook 必须来自现有 skeleton，不能制造 fake drama。
10. Reveal/withholding constraints 在 B1.5 不可改变。
11. Duration 使用 range/estimate，不制造假精度。
12. Underfill 不用 filler；overfill 不推给 screenplay。
13. Weak but valid boundary 可 review，不强行改故事。
14. Episode boundaries 产生 sparse continuity checkpoints。
15. EpisodePlan 固定 narrative membership；screenplay 保留 realization freedom。
16. B1.5 不单独正式批准；最终 approval 属于 B1.7。
